# 26.后台申诉 · 项目索引

> 开工先看：**本页** → `断点记录.md`（在办申诉/下一步）→ `README.md`（流程）→ `验收清单.md`（提交前9项+提交后3项）→ `经验/拼多多后台申诉-提交与举证.md`（全文经验）。
> 总规矩：根 `../AGENTS.md` + `../0.木婉清档案/规矩与红线.md`。最后整理：2026-10-09。

- **干嘛的**：拼多多维权申诉全流程：①找可申诉单 → ②抓证据 → ③写申诉文案（≤300字）→ ④填表/提交 → ⑤查审核结果。
- **命令**：
  ```bash
  cd "D:/桌面/办公软件/26.后台申诉"
  node src/tools/pdd-appeal-list.js --store pdd02                    # ① 清单（只读）
  node src/tools/pdd-appeal-context.js --store pdd02 --order <单号>   # ② 一单取证（只读）
  node src/tools/pdd-appeal-submit.js --store pdd02 --order <单号> --reason "…" --amount <金额> \
    --text-file <文案.txt> --required a.png b.png c.png [--optional d.png] [--submit]   # ④ 默认只填不交
  node src/tools/pdd-appeal-list.js --store pdd02 --records --days 30 # ⑤ 审核结果（只读）
  node --test
  ```
- **口径/坑**：申诉描述**不能超 300 字**（超了接口才回"描述不能超过300字"）；**申诉原因选项随订单场景变化**（按实际下拉选）；每个涉钱申诉项各自一组原因+金额，用不到的项取消勾选；上传后 `(n/3)` 文案被预览图替掉，判成功要数预览项；申诉前先看**下单前聊天**有没有把赠品说满。
- **红线**：**真实提交必须用户先批准**——工具默认 dry-run，`--submit` 是唯一提交开关（这是 29号 README 里"唯一例外"）；滑块/验证码/短信停下叫人；**真实单上不留测试值**（自测用 `--close-after`）；与 24号 同店端口共用（pdd02=9445/pdd03=9446），不要同时开同一家店；失败不自动重试。
