## 二、表单长什么样（提交前逐项核对）

打开：搜订单 → 行内「发起申诉」→ 弹窗「维权申诉」。

| 字段 | 实测规则 |
| --- | --- |
| 申诉订单号 | 自动带出，只读 |
| 申诉项 | ⚠️ **两种版式都见过**：① 复选框（**货款申诉**+**纠纷退款率申诉**，默认两个都勾）；② **单单只有一个标签**（如只有「货款申诉」、没有勾选框）——2026-09-30 实测后者，工具已兼容（核对时看 `itemCheckboxes` 标志位） |
| 申诉原因 | 下拉，必须精确选平台给的 7 个之一（见 `src/lib/appealRules.js`），**不能自己写** |
| 申诉金额 | 数字，**不得超过页面「最多可申诉 X 元」**；少件类一般等于被退款额 |
| 必填凭证 | 「证明商家无责的相关凭证」：图片 ≤3 张、视频 ≤2 条（少件案至少要有 1 张图）。
  ⚠️ 2026-09-30 实战：新版弹窗提示语变成了「**1、商品完整发货视频，可清晰看到商品面单以及打包内物的视频**（查看示例）」——平台倾向要**发货视频**；拿不到视频就交订单快照/物流签收/聊天的截图，并在文案里把事实说满 |
| 选填凭证 | 「其他证明相关情况的有效凭证」：图片 ≤3、视频 ≤2 |
| **申诉描述** | 文本域，**≤300 字**（超了提交直接失败，见坑 1） |

申诉原因 7 个选项（原文）：
1. 消费者反馈未收到商品，但实际已签收
2. **消费者反馈商品空包/少件/漏件，但实际未少发** ← 少件争议用这个
3. 消费者反馈商品错发，但实际未错发
4. 消费者反馈商品存在质量问题，但凭证不足
5. 消费者提供凭证为网图
6. 消费者提供凭证与其他售后订单相同
7. 非以上申诉原因

## 三、证据套路（「少件」争议怎么打）

买家说「少发了 X」，商家要证明**这个订单的规格本来就没有 X**。证据组合（建议必填 3 张）：

1. **订单快照**：`mobile-order-ssr/goods-snapshot` 页面上「已选规格 + 该规格价格」（下单时的商品描述，平台认可的判定依据）；
2. **所购规格的商品主图**：包装清单里**没有**争议赠品（客服聊天里发过的规格图 / 商品详情图）；
3. **对照规格图**：争议赠品属于**另一个（更贵/指定）规格**（如本案「院线血氧款」含血氧仪、「升级轻音款」不含）；
4. 选填：**赠品卡/宣传图**上「**指定规格** 收货后晒图送」的小字（买家投诉截图里通常也有这张卡）；
5. 选填：**客服聊天记录**——客服明确说过「X 是**指定规格**」「您规格是没有的」（截图别只截一半，连同买家原话一起截）；
6. 选填：订单**操作记录/后台备注**（如「已赠送两根吸氧管和一根面罩」——证明实际赠品是什么）。

反向也要看一遍（重要）：**下单前的聊天里客服有没有把话说满**。本案买家截图里客服发过血氧仪赠品卡，
但卡片自带「指定规格」小字、客服也回过「晒单领取的哦」，所以「指定规格」这条线站得住；
如果客服当时明确承诺「买这个也送 X」，那就**不要申诉**——平台大概率维持原判，先内部复盘话术。

## 四、坑（全是实测）

1. **描述 300 字上限**
   `POST /mercury/appeal/apply` 返回 `errorCode 120 / 描述不能超过300字(3000000)`（前端只报「提交失败」）。
   本地先 `validateDescription()` 校验，超长改到 ≤300 再点提交。**已用测试锁死**。
2. **DOM 里的隐藏副本**：申诉弹窗在页面里**存在两份**（一份隐藏）。给隐藏那份的上传 input `setInputFiles`，
   文件不会真正上传（计数还是 `0/3`，缩略图不出现）。正确姿势：只认 `offsetParent !== null` 的可见元素，
   从可见的「上传图片」文案**往上爬**找到它自己的 `input[type=file]`，再 `setInputFiles`（工具里已封装）。
   也可以更懒：先点可见的「上传图片」→ 弹「本地上传/图片空间上传」→ 点「本地上传」→ 走 `filechooser` 事件。
3. **上传后要等计数**：`上传图片 (3/3)` 出来才算传成功；工具轮询到预期张数才继续（超时即失败，不做无输出等待）。
4. **提交按钮要点「可见」的那个**：同样是 DOM 双份；点了没反应/弹窗不关，多半点到了隐藏副本。
5. **金额上限**：页面写「最多可申诉 150.00 元」；填超了会被拦。
6. **申诉入口 30 天**：清单每行自带「N 天后将不可发起申诉」；提交后不能修改。
7. **失败不罚、可复议**：页面「申诉失败次数不限制」「本月申诉复议权益 0/12」——申诉失败还能复议。
8. **办完别急着删痕**：提交结果（appealId、子申诉 ID、截图）留在 `runtime/appeal/<订单号>/`，后续查状态用得上。

## 五、案例实录：260923-***********2914

- **订单**：德达9L制氧机，买家选的是**「C1升级轻音款」（商品价 ¥598，店铺新客立减后实收 ¥398）**；
  血氧仪是**「院线血氧款（C1L+血氧仪）」**规格的晒图赠品。
- **买家主张**：售后说明原文「卖家承诺的发货血氧仪结果不发货，强烈投诉」→ 平台介入）退款 ¥150，计入纠纷退款率。
- **查到的现场**：售后单两条（先申请退货退款 ¥358.20 关闭 → 再申请退款 ¥150 成功）；后台备注「吴十 已添加赠送两根吸氧管和一根吸氧面罩」；
  聊天记录里客服 09-26 明确说「血氧仪是指定规格」「您规格是没有的」，买家坚持「买之前你说的要送」并发了截图。
- **证据 6 张**：订单快照（购买规格无血氧仪）、升级轻音款主图（清单无血氧仪）、院线血氧款主图（含血氧仪）、
  赠品卡（「血氧脉搏仪 指定规格 收货后晒图送」）、聊天记录（客服说明）、买家截图（自证其误读）。
- **文案（239 字，一次过）**：
  > 买家购买的是C1升级轻音款规格（商品价598，实收398），该规格随箱清单为吸氧管、过滤器、电源线、过滤棉、说明书，不含血氧仪；
  > 血氧仪仅为"院线血氧款（C1L+血氧仪）"规格的晒图赠品，赠品卡明确标注"指定规格 收货后晒图送"，客服也说明"血氧仪是指定规格""您规格是没有的"。

  > 诉求：撤销150元退款及纠纷退款率计入。凭证：订单快照、两规格对比图、赠品卡、聊天记录。

## 六、工具联调补遗与教训（2026-09-28 当天）

用工具在**另一张真实单** `251103-***********1995`（退货退款场景）上跑 dry-run 验证时又踩到几条：

1. **申诉原因选项随订单场景变化**——同一家店、同一个入口，两张单的下拉不一样：
   - 仅退款少件单（`260923-…`）：7 个选项，含「消费者反馈商品空包/少件/漏件，但实际未少发」；
   - 退货退款单（`251103-…`）的**货款申诉**段：6 个选项——「消费者提供错误/虚假物流单号，商家未收到退货」「消费者退货空包少件漏件」「消费者退货非本店铺商品」「消费者退货影响二次销售」「消费者提供凭证为网图」「消费者提供凭证与其他售后订单相同」。
   → 工具里**不要硬编码选项**，要点开下拉读实际选项再精确匹配；选不到就报错并列出实际可选项。
2. **每个涉钱的申诉项各有一组「申诉原因 + 申诉金额」**：该单有 货款申诉 / 运费申诉 / 纠纷退款率申诉 三个勾选项，货款段与运费段各自带原因+金额（上限也各算，如该单货款上限 415 元）。
   **申诉项默认全勾**——用不到的（如运费申诉）要在表单里取消勾选，否则「勾了不填」提交校验不过。
3. **上传成功与否别看 `(n/3)` 文案**：上传后文案会被预览图替掉（页面显示 `预览|预览|预览`），计数要数上传区里的预览项（`sortable-item`）。
4. **文件选择走人类路径最稳**：点可见「上传图片」→ 弹「本地上传 / 图片空间上传」→ 点「本地上传」→ Playwright `filechooser.setFiles`。
   （直传隐藏 `input[type=file]` 在有的表单变体会传到重复副本上，页面计数不动——实测踩过。）
5. ⚠ **真实订单上不要填测试值**：为了验证工具，我在真实单 `251103-…` 上 dry-run 试填了**金额 1**（未提交），被用户当场看到并追问。
   教训：工具自测优先用 `--close-after` 试完即关页；能在真实单上避免试填就避免，万一试填也要**照真实金额填**并当场关页。
6. dry-run 就是「只填不交」：`pdd-appeal-submit.js` 不加 `--submit` **绝不会点提交**（真实提交是平台不可修改动作，必须先经用户批准）。

## 六之二、2026-09-30 实战补遗（同一工具，弹窗版式变了）

背景：用户叫「看下是否需要申诉，是的话帮忙申诉」→ 拿 `260925-***********0145`（仅退款 ¥100，买家以「商家发错货」为名要现金）实操，
两处 DOM 变了、工具报两次错，修完才通（提交成功：appealId 8430024206147，子申诉 8489030138915，待处理）：

1. **「货款申诉 表单段没找到（页面结构可能变了）：无」** —— 新版弹窗是**平铺布局**：没有“以申诉项名开头”的段落，`outerWrapper` 链上 innerText 是空的。
   修法（已进代码）：先按老口径找；找不到就**兜底找“同时有『请选择』+『请输入』且含「最多可申诉」的最内层容器”**。
2. **「申诉项没勾：货款申诉」（核对不过）** —— 新版弹窗**根本没有勾选框**，只有一行标签「申诉项：货款申诉」。
   修法（已进代码）：`readFormState` 增加 `itemCheckboxes` 标志（页面真的没勾选框→跳过那两条核对），不再把“没勾选框”当成“没勾”。
3. 取证可以顺手截图存证：用一次性脚本对 `aftersales-ssr/detail?id=<售后单>&orderSn=<单>`、`orders/detail?sn=<单>`、`mobile-order-ssr/goods-snapshot?orderSn=<单>` 各截一张
   （全页 PNG 可能几十 MB、传不上去——商品快照页改存 **JPEG quality≈40**）。
4. 用户已明确“你自己判断要不要申诉、要就帮忙申诉”时：仍按规矩**先 dry-run 看核对输出**，无误再 `--submit`；提交后必须用 `--records` 回读（`statusDesc=待处理`）当验收。
