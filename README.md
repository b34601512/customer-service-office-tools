# 客服主管办公软件

> 面向电商客服主管的一站式本地办公自动化工具集。

本项目用于解决电商客服团队日常工作中的重复操作与数据整理问题，覆盖客服超时督办、发票自动化、响应时间测试、退款提醒、电话漏接分析、客服数据汇总、自动报量、店铺指标采集等场景。

项目以 **本地运行、业务数据不入库、模块独立维护** 为基本原则，并通过 GitHub Issues 持续记录功能改进、缺陷修复、代码重构、安全治理与测试工作。

## 项目特点

- **本地优先**：大部分工具直接在本地运行，减少业务数据外传。
- **多平台覆盖**：涉及京东、天猫、拼多多、抖音等常见电商平台。
- **模块化维护**：每个业务场景作为独立子项目维护，避免不同工具相互耦合。
- **持续改进**：通过 GitHub Issues 记录需求、问题、重构和验收过程。
- **重视可测试性**：多个子项目包含自动化测试，并持续清理重复实现、过时逻辑与高风险脚本调用。
- **AI 辅助维护**：在代码审查、问题分析、测试补全、文档整理和重复实现审计等维护工作中使用 AI 辅助，提高长期维护效率。

## 使用方式

本仓库包含多个相对独立的工具，不建议直接把整个仓库当成一个统一程序运行。

1. 克隆或下载仓库。
2. 进入需要使用的子项目目录。
3. 阅读该目录中的 README 或使用说明。
4. 如项目提供 `*.example.*` 配置模板，请先复制为本地真实配置文件，再填写自己的账号、店铺或接口配置。
5. 按对应项目说明安装依赖并启动程序。

不同子项目可能使用 Node.js、Python、HTML/JavaScript 或 Windows 批处理脚本，具体以各目录说明为准。

## 开发与维护

本项目采用 Issue 驱动的维护方式。GitHub Issues 主要用于记录：

- 功能需求与业务规则调整；
- Bug 定位、复现与修复；
- 自动化测试与回归验证；
- 重复代码、死代码和旧链路清理；
- 浏览器自动化与第三方平台适配；
- 安全风险与本地数据保护；
- 架构收敛和长期可维护性改进。

对于较大的改动，通常会在 Issue 中记录意图、背景、验收清单和边界，尽量让每次修改都有可追踪的原因和验证结果。

## 隐私与安全

仓库只用于保存源代码和可公开的示例配置，不应提交真实业务数据或账号凭据。

- 账号密码、登录会话、浏览器数据、日志与业务数据不进入公开仓库。
- 店铺账号、令牌、座席映射等真实配置只保存在本机。
- 仓库中的 `*.example.*` 文件仅作为配置结构示例。
- 真值配置文件通过 `.gitignore` 和提交过滤规则排除。
- 聊天记录、截图、报表、生成成品等运行数据应保存在本地运行目录中。

如果发现仓库中意外包含敏感信息，请不要在公开 Issue 中重复粘贴敏感内容，应先撤销或轮换相关凭据并清理提交记录。

## 项目状态

项目目前处于持续维护阶段，功能会根据实际客服运营场景不断调整。仓库中的 Issues 同时承担开发记录和工程决策日志的作用，因此会保留较完整的问题分析、验收标准和重构记录。
