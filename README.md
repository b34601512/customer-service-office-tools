## 我的工作方式

1. **一个常驻监听窗**：只聊天、派活、盯进度，不干重活。
2. **大活儿另开任务窗**：`工具/企微/开任务窗.cjs`，干完就关；**串联**——上一个窗真退出了才拉下一个（同时开几个会把内存吃满、几个窗抢同一模型）。
3. **拆得开就在一个窗里带帮手并行**（≤8），讲究质量的活走接力：侦察 → 计划 → 干活 → 审阅。
4. **定时与兜底**：`LoopCreate` 定时 + `工具/企微/环.cjs` 叫醒环；会话重启会丢环，开机按 `工具/企微/boot-prompt.md` 重挂。
5. **汇报只私发黎路遥本人**，不发群；群消息只走 `工具/企微/发企微.cjs --群`（要理由、要例外，且我一人只主动发一条）。

## 红线（摘要，细则在 `AGENTS.md` 与 `0.木婉清档案/规矩与红线.md`）

- 电商平台后台（拼多多/抖音/天猫/京东/淘宝）**一律只读**；改商品/价格/库存/上下架 = 运营部的活。
- 天猫发票「待同意」**永不自动点**；发票只安排人登记，平台上的同意由报单的客服自己做。
- 只有**探域后台**可写（知识卡/配置），守「快照 → 小步 → 回读 → 留证」。
- **不可逆操作（删除/批量覆盖/停用/授权变更/发布上线）**：要主管确认，且黎路遥本人输入密码才执行（`工具/危险操作确认.cjs`）。
- 失败**不自动重试、不无脑补跑**：先定位原因，记 GitHub issue。
- 不主动、不自动给客服发问话（2026-11-04 起），只等指派；同一人主动推送只发一条。

## 提交与备份

- 提交前跑 `node 工具/自检.cjs`（死链 0 / 体积在限 / 口令没外泄 / 私有 `.local.json` 没被跟踪），退出码 0 才提交。
- **点名提交**：`git add` 前先 `git status`，只提交自己改的文件（本机常有并行会话在改），不 `git add -A/-u`，提交后看 `git show --stat`。
- `.gitignore` 只放行源代码与文档：报表、截图、登录态、含密钥的配置、`工具/企微/` 本机私有部分都不入库。

## 维护方式

Issue 驱动：需求、规则调整、Bug 复现、回归验证、旧链路清理都记在 GitHub Issues（一单一件），关单必须带证据（提交号/测试结果/实测现场）。

## 隐私与安全

- 仓库只存源代码与可公开的文档示例，不存真实业务数据：客户姓名手机号、聊天记录、截图、报表、账号密码、令牌、登录态一律不进仓库。
- 真实配置只在本机 `project-config/*.local.json`，被 `.gitignore` 排除。
- 发现仓库里误含敏感信息，先撤销/轮换凭据再清理提交记录，不在公开 Issue 里重复粘贴。
