# 经验包：Windows 目录搬家——用 junction 让旧路径「不断档」

> **一句话**：文件夹换了位置 / 改了名，可旧路径被脚本、快捷方式、配置到处引用？
> 用 **junction（目录联接）**：旧路径变成一个「传送门」，实际指向新位置——程序照旧能用，一个引用都不用改。
> 用法：把本文件夹交给你的 AI，说「照这个包，帮我把 X 挪到 Y，旧路径用 junction 兜底」。

---

## 一、什么时候用

- 目录改名 / 挪盘（D 盘 → E 盘、换目录名），但**一堆地方写着旧路径**；
- 想让迁移「一步到位」，又不想全项目改引用（改漏一个就出鬼故事）；
- 需要「旧路径继续存在」的兼容期（老脚本、快捷方式、IDE 历史记录、注册表里写死的路径…）。

## 二、是什么（30 秒）

junction（目录联接）＝ **文件系统级的「传送门」**：旧路径在，但内容都指向新路径。
读写都**透明**——从旧路径进去，改的其实是新路径里的文件。

- 命令：`mklink /J "旧路径" "新路径"`（**不需要管理员权限**）；
- 建完 `dir /AL` 能看到 `<JUNCTION>`，资源管理器里像个普通文件夹。

## 三、完整迁移流程（照做）

1. **搬数据**：把数据复制到新位置，并核对（文件数、抽查内容）；
   批量复制用 `robocopy "D:\旧" "E:\新" /E /R:1 /W:1`，核对完再清旧位置；
2. **清旧路径**：旧路径必须**不存在**（junction 只能建在新空位上）；
3. **建联接**：`建联接.cmd "D:\旧" "E:\新"`（本包工具，带确认与校验）；
4. **抽查**：从旧路径读一个文件、写一个文件；`查联接.ps1` 看一眼指向对不对。

## 四、删「门」安全吗？（本机全实测过，2026-10-11）

| 删法 | 结果 |
|---|---|
| cmd `rmdir 联接` | ✅ 只删门，目标完好 |
| cmd `rmdir /S /Q 联接` | ✅ 只删门，目标完好 |
| PowerShell `Remove-Item -Recurse -Force 联接` | ✅ 只删门，目标完好 |
| git-bash `rm -rf 联接` | ✅ 只删门，目标完好 |
| 资源管理器右键删除 | （没实测）删完瞄一眼目标在不在——**个别第三方工具会「跟穿」**，养成删完检查的习惯 |

⚠️ **但注意**：从「门里」删文件＝**删真文件**（读写删都透明）。清理时要分清：删的是门，还是门里的东西。

## 五、给 AI 的执行说明（照做）

1. 先确认：目标文件夹存在且数据齐、旧路径已不存在；
2. 建：`工具\建联接.cmd "旧路径" "新路径"`（`--yes` 可跳过确认，供脚本用）；
3. 验：`工具\查联接.ps1 "父目录"` → 看到 `旧路径 -> 新路径`；
   再实测：旧路径里 `dir`、读一个文件、写一个文件，都正常＝修好了；
4. 要撤：`rmdir "旧路径"` 即可（数据都在新位置）。

## 六、坑与边界（都实测/有依据）

- junction **不需要管理员**；符号链接（`mklink /D`）需要管理员（或开发者模式）——**优先用 junction**；
- 本机实测**跨盘可以**（C: 的链接指向 D: 的目标）；目标须在本机（**网络共享路径不行**，用映射盘替代）；
- 备份 / 同步工具可能**跟穿** junction（同一份数据被算两遍）——给备份排除旧路径那侧；
- Git 仓库藏在 junction 后面时，路径显示可能让人困惑——能用，但知道这回事就好；
- cmd 工具的提示文字在 UTF-8 终端下可能显示为乱码（cmd 输出的老毛病）——**以文件系统结果为准**；
- 本包工具守 Windows 脚本编码规范：`.cmd` 纯 ASCII＋CRLF、`.ps1` UTF-8 带 BOM＋CRLF。
