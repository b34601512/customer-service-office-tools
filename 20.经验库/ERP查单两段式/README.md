# ERP 查单两段式：先「订单查询」定日期 → 再按范围导「订单商品明细统计」

> 来源：2026-10-09 黎路遥纠正 + 当日实战（补登记 2 单卡在 ERP 数据）。
> 适用：发票登记/报量要取 ERP 字段（商品明细、买家支付金额、发货时间）时。

## 场景
要登记一单发票，但该单**不在现有「订单商品明细统计」数据源 CSV** 里（默认取最新一份）——金额/商品/发货时间取不到。

## 坑（我们犯过）
直接猜一个时间范围去导报表 → 导不到：

- 猜 `2024-01`（按拼多多单号前缀）→ 导出空表；
- 导 `2026-09-01 ~ 10-10`（22,327 行）→ 两个单号都**没命中**；
- 而**黎路遥在 ERP「订单查询」里按单号，两单都能搜到**。

## 正确路径（两段式）
1. **ERP「订单查询」按单号搜** → 看这单**是什么时候的**（确定日期/时间范围）；
2. 回 **「订单商品明细统计」报表** → 按那个日期**选对应制单时间范围** → 导出 CSV → 取字段登记。

> 顺序不能反：订单查询只用来定日期，字段口径仍以「订单商品明细统计」CSV 为准。

## 工具侧两个已修缺陷（10号 `自动报量CLI/auto_report_erp.py`，2026-10-09）
1. **制单时间日期框**：`fill` 之后必须 `Enter` 提交；只按 `Tab` 不提交，随后填结束时间会把开始时间**还原成表单旧值**（实测填入 10-02/10-09 回读成 `2024-01-01`/`2026-10-09`，跨度>1 年被表单拒绝）→ 导出范围错。
2. **导出前必须点「查询」并等明细网格加载**：只点「查询汇总」不点「查询」时明细网格可能一直是 0 行，此时导出只得 **787 B 表头空表**。修法：`查询汇总 → 查询 → 等明细（合计行或 .ag-row，120s 超时则报错停手）→ 才 CSV导出`。

## 其它已知坑
- ERP 报表「制单时间范围**不能超过 1 年**」（表单红字校验）。
- Edge 在下载收尾 `download.save_as` 会崩（2026-10-06×2、10-09×3、10-09 修完验证×1 = 5 次）：`.crdownload` 结构校验（GBK 可解析 / 86 列 / 字段数分布 / 结尾完整）可恢复，别丢文件。
- 登记侧口径：金额以**平台后台**为准（10-06 拍板）；写表前必须云端查重（两张表都要查）。
