# 多 AI 工具「模型选择总被重置」：配置分层排查与去重

> **一句话**：在工具里选好的模型/推理强度，下次开新窗口又变回默认——大概率不是「没保存」，
> 而是有**更高优先级的配置层**（系统托管默认／环境变量／项目配置）在启动时把它盖掉了。
>
> 修法的方向是**去重**：只留一个官方支持的「个人选择真源」，而不是再加一层启动脚本/兜底变量。
> 把本文件夹交给你的 AI，说「帮我查这台机器上 AI 工具的模型配置为什么总被重置」。

---

## 一、先理解「配置分层」

一次启动里，能参与「用哪个模型」决策的来源通常有这几层（不同工具名称不同，思路一致）：

| 层 | 说明 | 特点 |
|---|---|---|
| 系统托管默认 | 安装器／管理员策略写入（如 `ProgramData` 下的要求文件） | 优先级往往**最高**，会在新线程初始化时重新应用，盖掉个人配置 |
| 环境变量 | 进程级变量（`ANTHROPIC_MODEL`、`PI_MODEL` 之类） | 比配置文件强；**旧终端/旧会话会一直继承旧值**，改完不重开进程等于没改 |
| 用户配置 | 工具官方支持的「个人选择」文件（`config.toml`、`settings.json`…） | 这才是**唯一该留的真源** |
| 项目配置 | 跟目录走，只对某项目生效 | 不要把项目配置当个人默认看 |
| 缓存/状态 | 模型目录缓存、权限、历史、会话数据 | **不是配置**，别当「冗余」删 |

**核心原则**：个人选择只保留一个真源（官方用户配置）。
用启动脚本、环境变量兜底、多份副本来「修复」，只会制造更多覆盖源，问题更难查。

## 二、六步排查流程（可复用）

1. **记录**：工具版本、真实启动命令、界面里看到的结果（截图/原文）。
2. **找文档**：读官方「配置层级/优先级」说明，**别凭文件名猜用途**。
3. **列全分层**：系统托管、用户配置、项目配置、环境变量、启动参数，逐层确认有没有模型相关键。
4. **分类**：个人默认 / 系统策略 / 缓存 / 权限状态——只处理**造成冲突的那一项**。
5. **改前备份**：要动的文件**移动**到备份目录（可恢复），不改客户端源码、不加运行时代理。
6. **验证**：配置文件格式有效、只剩一个模型覆盖源、**全新进程**（新终端）启动结果正确、备份可恢复。

> 用 `工具\查配置分层.cjs` 可一次性列出各层现状（只读）。

## 三、三个实测案例（工具是公开的，做法通用）

### 例 1：系统托管默认盖掉个人配置（Codex CLI）

- **现象**：用户在界面把推理强度改成 `max`，重开新窗口仍显示 `medium`。
- **证据**：个人配置里确实已写入 `max`；但系统要求文件里有一段 `[models.new_thread]`，
  把**新线程默认**设成 `medium`。工具启动新线程时会读取这段并重新应用（显式启动参数可覆盖）。
- **处理**：把冲突的**系统要求文件移动**到备份目录；个人配置保持原样。重启后不再被覆盖。
- **教训**：两套真源并存时，界面里的「保存」看起来就像没生效。

### 例 2：环境变量压过用户配置（Claude Code）

- **现象**：`/model` 保存的选择，新窗口仍回默认。
- **证据**：用户 `settings.json` 的 `env` 区里有一个模型变量；
  系统**用户级环境变量**里还有同名变量＋重复的 endpoint/认证变量。
  同名环境变量优先于 `settings.json` 的 `model` 字段 → 保存的选择永远赢不了。
- **处理**：
  1. 从 `settings.json` 的 `env` 区移除直接覆盖模型的变量；
  2. 清理用户级环境变量里的重复项（备份导出环境变量后再改）；
  3. **保留**用户正在用的网关/代理配置——那不是重复项，不要顺手改；
  4. 改环境变量后**必须关掉旧终端、旧会话**再开新进程。
- **备份**：改前把 `settings.json` 与环境变量导出到备份目录（可恢复）。

### 例 3：「查了没问题、什么都不改」也是结论（Pi）

- 个人 `settings.json` 正常，环境变量里**没有**覆盖项 → 不改。
- `models-store.json` 是官方**模型目录缓存**，不是第二套个人默认，不能为「清理冗余」而删。
- `settings.local.json`（项目/权限类）同理。
- 附带发现：PATH 里同时有包装器和 npm 启动项——那是**启动入口重复**，不是模型配置重复；
  不在「只改配置」的范围内，就不动。

## 四、工具（只读）

`工具\查配置分层.cjs`：扫一遍本机各 AI CLI 的用户配置/系统托管层，
列出存在的文件与**模型相关键**，并检查进程里有哪些相关环境变量——用来定位「谁在盖谁」。

```bash
node 查配置分层.cjs                 # 扫默认用户目录
node 查配置分层.cjs --home <目录>   # 指定用户目录（多账号排查）
```

**只读**：不写、不改、不删，只打印。

## 六、边界（别越线）

- 不改客户端源码、不做升级分支、不加运行时兜底。
- 不删官方缓存、历史、权限、状态文件。
- 不擅自更换用户正在使用的模型供应商或网关。
- 任何不可逆操作（删除/覆盖/回滚）**先确认再动**；本次只有可恢复的「移动＋去重」。
