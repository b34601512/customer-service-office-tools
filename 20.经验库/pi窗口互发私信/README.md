# 经验包：pi 窗口互发私信（本地信箱）

> **一句话**：好几个 pi 窗口各干各的活，想互相通知、叫人？装一个**收信扩展**＋一个**发信脚本**：
> 信投到本地信箱文件（JSONL），对方的扩展秒收、注入成一条用户消息把窗口叫醒；
> 窗口关着也不丢——下次启动自动补投。**不开端口、不碰别人进程、全程可审计**。
> 用法：把本文件夹交给你的 AI：「照这个包，给我的 pi 装窗口互发私信」。

---

## 一、它是怎么工作的（30 秒）

```
窗口A（寄件）                          窗口B（收件）
node 发信.cjs B "你好，帮我查下X"
        │
        ▼
  ~/.pi-信箱/B.jsonl   ←── 一行一封信 {at, from, text}
        │
        ▼（fs.watch 看到新字节）
  窗口B 的「私信收」扩展
        │
        ▼
  pi.sendUserMessage("【私信】收到 1 封信…")  ← 变成 B 的一条「用户消息」＝窗口醒来干活
```

- 寄件人自己写给自己：**不注入**（防死循环）；
- 窗口关着：信留在信箱，下次 `session_start` 按游标（`.已读/<名>.json`）**补投**；
- 窗口名 = **工作目录名**（在哪个目录开的 pi 窗口，就用哪个名字收信）。

## 二、装（三步）

1. **收信端**：把 `扩展\私信收.ts` 复制到 `~/.pi/agent/extensions/`（用户级——本机所有 pi 窗一次到位）；
   只想给某一个窗口装？放到那个窗口的 `.pi/extensions/` 就行。
   （pi 用 jiti 直接加载 TypeScript，不用编译。）
   > ⚠️ **公司内部机器注意**：`~/.pi/agent/extensions/私信收.ts` 已是公司版，**别用本包就地覆盖**。
2. **发信端**：`工具\发信.cjs` 放到顺手的地方（建议每个窗口的工作目录一份）。
3. **老窗口要 `/reload` 或重开一次**——扩展是随会话加载的，之前开的窗口「没长耳朵」。

## 三、用

```bash
node 发信.cjs 窗口B "你好，帮我查下 X"          # 发（默认寄件人=当前目录名）
node 发信.cjs 窗口B "你好" --from 窗口A         # 显式署名
node 发信.cjs 窗口B "你好" --干                 # 干跑：只预览不落盘
```

收信是**自动的**：对方窗口会收到一条「【私信】收到 N 封信（本地信箱）」的用户消息；
回信照上面反向发即可。

信箱目录默认 `~/.pi-信箱`，可用环境变量 `PI_MAILBOX` 改（发信脚本和扩展认同一套）。

## 四、给 AI 的执行说明（照做）

1. 装扩展：复制 `扩展\私信收.ts` → `~/.pi/agent/extensions/`（或指定窗口的 `.pi/extensions/`）；
2. 自测：`node 测试\冒烟测试.mjs` → 应打印 **全部通过**（13 项：注入/游标/自投不注入/重开补投/发信脚本）；
3. 真跑一遍：开两个 pi 窗口（不同目录），用发信脚本给另一个发一封，看它是否收到并回信；
4. 验收标准：冒烟测试通过 ＋ 真发真收一轮。

## 五、坑（都实测过）

- **窗口名 = 工作目录名**：同名两窗会**共用一个信箱和游标、互相抢信**——别开双份；要改名字就改目录名；
- **游标是「名字级」的**：`.已读/<名>.json` 记已投字节；换名字/清游标会导致重复投递；
- **老窗口必须重载**（`/reload` 或重开）才有收信耳朵；
- 信箱文件是**追加写**的 JSONL：写到一半的行会被缓冲、等下一段（代码已处理）；文件被截断会自动从头读；
- **信箱目录别进 git**（放仓库里就把 `信箱/` 加进 `.gitignore`）；信是普通用户消息，**会话里可见、可审计**；
- 只对本机文件生效：**跨机器不通**（要跨机器就换网络通道，那是另一个故事）；
- 想「窗口关着也自动拉起来」？那要在发信侧再加一个「叫醒器」（发现目标窗没开就把它启动起来）——
  各家的开窗方式不同，本包不含这一步；思路是：**看信箱新字节 → 认窗没开 → 调本机开窗器**。
- **忙时可能静默丢信（本包基线版）**：本包扩展是 v2 基线版——「投出即推游标」；会话忙（流式/自动压缩/长回合）时投递失败会被库内部吞掉，游标却已推＝**静默丢**。生产环境需要 v3～v4.3 那套「先确认再记账」（at-least-once）补丁：**见《私信通道-v3v4补丁.md》**（挂账、回执码、steer 等，都是实测修法）。
