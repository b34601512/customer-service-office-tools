# 经验包：企微 AI 员工体系（从零搭建）

> **一句话**：一台常开的电脑 ＋ 企业微信 AI 机器人 ＋ 任意能开「会话窗口」、能挂「后台命令」的 AI 运行时，
> 就能搭起一支「有耳朵、会自己醒、干完自己睡」的 AI 员工队：
> 机器人长连接收信落盘 → 新消息秒级叫醒对应 AI 窗口 → AI 读信、干活、回信；
> 窗口关着信不丢、定点自动拉起；多员工互不干扰。
>
> **用法**：把本文件夹整个交给你的 AI，说一句「照这个包，把企微 AI 员工体系搭起来」。
> 本包讲的是**架构与搭建经验**（含一步步验收标准和实测坑）；两件核心小工具（跟读、游标读）
> 与两个参考骨架（收件守护、直连发送）**可直接跑**，已带 28 项冒烟测试。

### 一条消息的生命周期（老板给 AI 员工发一条消息）

1. 企微 → 守护的唯一长连接收到 → **追加**进 `收件箱/inbox.jsonl`（一行一条 JSON）；
2. 跟读（挂在「后台命令输出」上的监视器）发现新行 → 打印一行 → 触发**输出事件** → 唤醒对应 AI 窗口；
3. 窗口（若刚被拉起则先走开机自检）**查漏**：游标读收件箱 → 处理新消息；
4. 要回信：直连脚本（先 dry-run 预览，再 `--send`）→ POST 守护发送口 → **走同一条长连接**发回；
5. 窗口当时关着？叫醒器看到收件箱出新字节 → 把窗口拉起来 → 窗口自检按游标补读（**不丢**）。

## 二、从零到一：九个台阶

> 每级台阶：🏁 目标 → 🔧 做什么 → ✅ 验收 → ⚠️ 坑。
> 建议**一级一验**，别跳级——这套体系 90% 的故障都出在「以为它好了」。

### 台阶 1：建机器人，拿到 Bot ID + Secret

- 🔧 在企业微信后台创建「智能机器人」（API 模式 → 长连接）→ 扫码授权 → 拿 Bot ID 与 Secret，
  照 `模板\机器人凭据.example.json` 写成 `机器人凭据.local.json`。
  （取 Bot ID / Secret 的官方说明：<https://open.work.weixin.qq.com/help2/pc/cat?doc_id=21677>）
- ✅ **验收**：`node "骨架\守护骨架.mjs" --check` → 打印「自检 OK：长连接已认证并订阅成功」。
- ⚠️ 坑：
  - **同一个机器人同时只许一条有效长连接**：开第二条会把第一条**顶掉**，顶掉的空档平台**不补推**消息。
    所以「收」和「发」都走同一条——本包做法：守护持有连接，另开本机发送口给别的脚本用。
  - 扫码/验证码只能真人做；Secret 只放本机文件，**不进 git、不贴聊天记录**。
  - 官方 CLI（文档/表格那套）另需 `auth init` 授权换 token；手写 JSON 只能骗过 `auth show`，
    真调用报 `853003`。**收发消息不经 CLI，只认 Bot ID + Secret**（两件事分开看）。
  - 机器人只能发给：**授权人本人** / **最近有往来的会话**；群里只收 **@它** 的消息。
    想主动发给某人，先让对方给机器人发一条，「刷进最近会话」。

### 台阶 2：收件守护（常驻一条长连接）

- 🔧 用 `骨架\守护骨架.mjs`（改 `--收件箱` / `--凭据`）；做**开机自启**：
  Windows 用 `骨架\静默启动.vbs`（**纯 ASCII**，运行时自己认路径）→ 把它的快捷方式丢进「启动」文件夹
  （Win+R 输 `shell:startup`）。它调同目录 `骨架\daemon_entry.mjs`（ASCII 入口）拉起守护；
  工作目录 = 脚本所在目录（默认找同目录的 `机器人凭据.local.json` 与 `收件箱\`）。
- ✅ **验收**：守护日志出现「长连接已认证并订阅成功」；手机给机器人发一条 → `收件箱\inbox.jsonl` 多一行。
- ⚠️ 坑：
  - **单实例**：守护发现已有实例要拒开（拿不准就 `--接管`，别同时开两条）。
  - **断线要自己退避重连**：官方 SDK 自带的自动重连实测不一定回来；断线期间消息**不补推**，
    这正是要把守护做成常驻的原因。
  - **开机自启的 vbs 必须纯 ASCII**（中文注释 + UTF-8 存盘会直接编译失败——表面看是「自启没反应」）。
  - **附件要全部存**：一条图文混排可能好几张图，只存第一张会漏（吃过亏）。
  - 日志是**静默启动时唯一的痕迹**：凭据错、依赖缺，都要写进 `收件箱\守护.log`。

### 台阶 3：收发小工具（游标读 + 直连发送）

- 🔧 读用 `工具\读JSONL游标.mjs`（不盖章只看、`--mark` 才推进）；
  发用 `骨架\直连骨架.mjs`（默认 dry-run，`--send` 才真发；自动拆条 ≤100 字）。
- ✅ **验收**：手机发一条 → 读工具能读到 → 回复预览 → `--send` → 手机收到回信。
- ⚠️ 坑：
  - **先预览后发送**是铁的；「已读游标」处理完才盖章——不盖会重复处理，盖早了会漏。
  - 单条渠道约 **100 字**，限频约 **20 条/分钟**（超了报 `45009`）；**失败不自动重发**（重复比漏一条糟）。
  - 收信目标**不手打**：从收件箱归纳（官方只允许最近会话）；打印一律用姓名/群名，**不打印内部 ID**。
  - 半步消息（没换行结尾）不算读掉——两个工具都已处理，别自己再写一套。

### 台阶 4：AI 窗口接线（自检单 + 监听链）

- 🔧 把 `模板\boot-自检单模板.md` 改成自己的版本，登记为**新窗口的首条指令**；
  监听链两条：先挂「**输出事件**」的循环（如 `monitor:output`），再挂「跟读」后台命令
  （`node 跟读JSONL.mjs 收件箱\inbox.jsonl`，timeout=0）。
- ✅ **验收**：窗口开着时给机器人发消息 → 秒级进入处理；把窗口重启 → 照自检单重挂链、查漏，不丢消息。
- 运行时没有「输出事件」机制怎么办：两档兜底——①把跟读当普通后台进程，每隔几秒读一次它的输出；
  ②退一步低频轮询（间隔 ≥ 5 秒）读收件箱游标。能跑，但比事件式慢/费，尽量用支持事件的运行时。
- ⚠️ 坑：
  - **顺序别反**：先事件环、后监视器——反了会有一个真空窗（这段到的消息没人接）。
  - 跟读平时必须**一个字都不输出**（没新行就安静），否则假唤醒、烧额度。
  - 窗口一关，内存里的链全没了；重开必**查漏**（游标在文件里，不会丢）。
  - 图片在对话里堆多了会「无法回复」——到量主动开新会话（自检单里有这条）。

### 台阶 5：叫醒器（按需开窗）+ 闲置收窗

- 🔧 写一个常驻小工具（我们叫**叫醒器**），每 20 秒看两路文件**字节数**：
  ① 各员工的企微收件箱；② 各员工的私信箱。有新字节 **且** 目标窗没开 → 调该窗的**开窗器**拉起。
  窗起来后自检按游标补读；窗口**闲置一段时间（我们定 30 分钟）自动收窗**。
- ✅ **验收**：把窗关掉 → 给对方发一条消息 → 约 1 分钟内窗口自动拉起、处理、回信。
- ⚠️ 坑（都是实战踩出来的）：
  - **拉窗成功/失败要分清**：只有「真拉起来了/窗口活着会自己读」才推进统计；
    **被防刷挡下、开窗器报错时别丢**——留着下轮重试，否则消息搁死（吃过「防刷吞消息」的亏）。
  - **刚拉起别秒收**：收窗前看三样——这个目标 10 分钟内刚拉过？窗进程刚起？有没有未读？
    任一命中就不收（防「新窗被旧时戳骗到、开场即被收」）。
  - **防刷**：同一目标 3 分钟内不重复拉、1 小时最多 5 次；认得出来的窗才拉，认不准就只记日志。
  - **叫醒器自己会死**：装个计划任务每 5 分钟巡查拉起（脚本带单实例守卫，重复实例自己退出）——
    机器重启后它能自己回来。
  - **定时任务关窗不醒**：做「排期环」——各窗把到点的活登记进自己的文件，叫醒器每轮扫，
    到点投一封信拉窗；错过的容忍期内**补发**（信里标「补发」）、同一周期只投一次、登记前的旧点不追发。

### 台阶 6：员工间私信（本地信箱）

- 🔧 不走企微、不开端口：一封信 append 进本地信箱 JSONL；收信端装一个**收信扩展**，
  把信注入成一条「用户消息」直接叫醒窗口；窗关着就留在信箱，**下次启动按游标补投**。
- 现成开源件：同库 `pi窗口互发私信\`（收信扩展 + 发信脚本 + 13 项冒烟测试），拿来即用。
- ✅ **验收**：两个窗口互发互回；把收信窗**关掉**再发一封，重开能收到（补投）。
- ⚠️ 坑：窗口名=目录名（同名共用一个信箱会抢信）；扩展随会话加载，老窗口要重载才「长耳朵」；
  信箱目录不进 git。

### 台阶 7：长期运行（自启 / 看门狗 / 心跳 / 链体检）

- 🔧 三层保底：
  1. **开机自启**：收件守护、叫醒器都要（启动文件夹或计划任务）。
  2. **窗口心跳**：每个窗挂一个轻量写手，每几分钟写一个带 pid/时间的文件；
     **正常关窗顺手清掉**——这样看门狗分得清「正常关」和「崩了」。
  3. **看门狗**（计划任务每 5 分钟）：守护进程在不在 / 断线是否恢复 / 工作时段消息是否长时间静默 /
     心跳是否超时；必要时**自动重启守护**（带冷却与每小时次数上限）；冒烟异常写公告板。
- ✅ **验收**：演练一遍——杀守护 → 看门狗自动拉起；模拟心跳超时 → 只报一次不刷屏；
  正常关窗 → 不误报。
- ⚠️ 坑：
  - 心跳三条误报防线：心跳目录不存在不判；开机 30 分钟内宽限；上次关机残留（心跳早于本次开机）忽略。
  - **自愈要和「开机自启」防撞车**：动手前等 90 秒复查；重开器自带单实例守卫、加次数上限。
  - 告警**节流**（如 60 分钟一条）；**崩溃循环**（1 小时 3 次）必须报，不能也被节流吃掉。
  - 看门狗要能**干跑演练**（假状态、不动真守护、不发公告），先彩排再上生产。

### 台阶 8：记忆与节奏（睡眠整理）

- 🔧 每个 AI 员工**每天夜里定点**「睡一觉」：日志等活文档超阈值就按天切档进归档（**搬家不是扔东西**）、
  当天踩的坑沉淀成「经验」一条一文件、更新交接——第二天轻装继续。
  各员工时间**错峰**（如 23:30 / 23:35 / 23:45），防撞车。
- ✅ **验收**：第二天检查：活文档瘦身、归档有当天、索引更新、没乱码/重复。
- ⚠️ 坑：整理脚本要有 `--dry-run`（只看不写）和 `--now`；
  「有整理窗在跑就跳过」**只认本窗**——跨窗互判会让所有人互相跳过、整晚没整理（踩过）；
  夜里**不吵人**（不发企微），异常才留痕。

### 台阶 9：多员工扩展（一份核心 + 薄配置）

- 🔧 员工多了以后：
  - **代码只有一份**（共享核心），各员工目录里自动分发同名薄壳 → 老习惯命令不变，改一处全员生效；
  - 每人一份**薄配置**（照 `模板\本窗配置.example.json`）：名字、收件箱位置、任务名、时间表；
  - 分发器同步核心（覆盖前把旧件备份到备份区）。
- **每个员工独立机器人 + 独立凭据目录**：互不顶连接、互不串凭据。
- **边界**：机器人只做自己项目的事（别人的活不接、不代发）。
- ✅ **验收**：新人入职＝「拷核心 + 填薄配置 + 扫码建机器人 + 跑六步体检」，
  一套跑通、隔壁不受影响（改完自己的，别人的收件箱/凭据原样）。

## 四、实测坑大全

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 收不到消息 | 长连接被别的进程顶掉；机器人在线但没人听 | **单实例**守护；重启用 `--接管`；守护常驻 |
| 断线后消息丢了 | 平台**不补推**断线期间的消息 | 守护常驻 + 退避重连；重要节点勤对账 |
| 发不出去 | 目标不在「最近会话」/ 凭据错 | 让对方先发一条；`853003` 是 CLI 的 token 问题（收发不走 CLI） |
| `45009` | 触发限频（约 20 条/分钟） | 停一分钟再来；**别自动重发** |
| 自启没反应 | vbs 带中文/UTF-8 → 编译失败 | vbs **纯 ASCII**；失败也要有日志落盘 |
| 窗口开了又马上被收 | 闲置判定拿到旧会话时戳 | 收窗前看「刚拉过/刚起/有未读」三颗钉子 |
| 消息搁死没人理 | 防刷挡下拉窗但游标被推走 | 拉窗**没着落就不推游标**，留下轮重试 |
| 假唤醒/费额度 | 监视器没消息也输出；轮询太密 | 跟读只在**新行**时输出；事件驱动，别拿 `sleep` 轮询 |
| 重复处理消息 | 没盖章就重启、或盖晚了 | 处理完 `--mark`；半步行不算读掉 |
| 多员工互相覆盖 | 每人拷一套代码各自打补丁 | 一份核心 + 薄配置 + 分发器；旧件只搬不删 |
| 同名窗口抢信 | 窗口名=目录名，撞名共用一个信箱 | 别开同名双份；改名即改目录名 |
| 图片多到无法回复 | 上下文图太多 | 到量主动开新会话 |

## 五、红线（安全与规矩，一条都别破）

1. **默认 dry-run**：任何真实发送都先预览，显式 `--send` 才发。
2. **凭据不出门**：Bot ID / Secret / token 只放本机文件——不进 git、不贴聊天记录、不写日志、不打印。
3. **不打印内部 ID**：userid / chat_id / msgid 一律用「姓名 / 群名 / 时间」代替。
4. **只搬不删**：要淘汰的文件移去备份区，不硬删。
5. **不确定就问**：不知道就问，别猜；不可逆操作等人拍板。
6. **各管一摊**：每个机器人只做自己项目的事；别人的活不接、不代发。
