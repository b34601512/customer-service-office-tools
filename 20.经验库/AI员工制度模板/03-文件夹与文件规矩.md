# 03 · 文件夹与文件规矩

> 管什么：东西放哪、文件怎么起名、旧东西怎么处理、怎么备份。

## 一、一个员工一个文件夹

- 每个员工住自己的文件夹（例 `员工\<职务·姓名>\`），里面固定 5 个子文件夹：
  - `档案/` —— 身份材料、老板原话、重要文档
  - `工具/` —— 自己用到的脚本、引擎
  - `经验/` —— 踩过的坑与对策（**一条一文件**）
  - `任务/` —— 接的活（任务单）
  - `回执/` —— 干完的交代
- 另有三个常用的：`工作要点-待办.md`（清单）、启动自检单（开机规矩）、日志/状态目录。

## 二、文件起名

- **日期开头 + 主题**：`2026-10-11-银行组件禁自启.md`。
- 经验**一条一文件**，配 `README.md` 目录索引（一行 = 文件名 + 一句话）。

## 三、旧东西怎么处理

- **只搬不删**：不硬删文件；要弃用的移去备份文件夹（例 `D:\备份文件夹`）。
- **一套标准只留一份**（唯一来源）；确实要多套才分多份；**备份除外**。

## 四、唯一来源（一处改、处处对）——核心文化

> 同一个东西抄好几份 → 改的时候容易漏一处，越改越乱。**相同的东西、共享的，只留一份、只在一处改。**

落地分三层：

| 什么东西 | 唯一的一份（母本）放哪 | 别人怎么用 |
| --- | --- | --- |
| **标准/制度** | 制度管理人的工作台 | 只记**路径**、照做；要改找制度管理人 |
| **共享脚本/套件** | 各有母本（例：消息套件母本在技术负责人的核心目录） | 各人手里是**分发副本**：改只改母本 → 统一同步（同步前备份旧版） |
| **通讯录/归属与路径** | 通讯录表（唯一一份） | 找谁、找东西先看它；**要改只改那一行** |

配套规矩：各人启动自检单**只记通讯录路径**，不抄内容；分发副本要标「母本在哪」，别把副本当母本改；同步要留记录（改了什么、同步给谁、旧版备份在哪）。

## 五、通讯录＝唯一索引

- **找谁、找东西，先看通讯录**：谁管什么、东西在哪，就写在通讯录那一行；别处不再抄路径。
- 东西搬了/换人了，**只改通讯录那一行**。
- 通讯录两节：①成员（谁负责什么、住址）②专项与项目（哪个摊子归谁、现在在哪、什么状态）。

## 六、仓库与双备份

- 公司的东西在**一个 git 仓库**里：员工/规范/人事/共享/交流分区。
- **先改本地 → commit → push** 到私有云端——本地一份、云端一份。
- 交流的归交流、档案的归档案，别写混。
- commit **只按名加文件**（别用 `git add -A`——共用仓库会夹带别人的改动）。
