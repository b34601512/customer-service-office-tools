# 08 · 安全与备份

> 管什么：密钥、隐私、备份、回退——出了事能回来。

## 一、什么绝对不能外放

- **密钥 / 令牌 / 密码 / 客户隐私**：**不进 git、不上公共板、不写消息、不截图外发**。
- 凭据放**单独的凭据文件**（本机目录里，**不进共享仓库**）。
- 公共仓库就算私有，也照样别写敏感信息。

## 二、备份（本地一份 ＋ 云端一份）

- **公司仓库**：先改本地 → commit → push 到私有云端。
- **个人档案**：各自加密备份（AES 加密，仅灾难恢复用）。
- **弃用文件**：不硬删，移去备份文件夹（**只搬不删**）。

## 三、回退（动手前想好退路）

- 改动前：留备份 / 留还原点 / 记下原值。
- 改动后：把「**怎么回退**」写进回执（例：留 `原始状态.json` ＋ 一键恢复脚本）。
- 教训式例子：运行中硬停键盘类安全组件会**堵死输入**——这类操作先研究、先备份、留回退。

## 四、不可逆操作

- 部署、删数据、改线上权限、发版、发布安装包——**等老板口令**，没口令不动。
- 判断不准是不是不可逆？按不可逆对待。

## 五、仓库边界

- 敏感档案（账号/线路记录/个人材料）**不进公共仓库**，只进自己的加密备份。
- 对外分享/发布前过一遍**脱敏检查**：密钥、账号、个人名字、内部编号、内部路径。
- 打码要**彻底**（图里也不能露）；分享包另起「可分享复用版」，别直接发底稿。

## 六、发布流程（有公开仓库的团队）

- 谁负责什么写清楚；发布走**复核**：另一个同学过一遍（脱敏、可用性）再推送。
- 推送后留痕：commit、复核记录；**只按名加文件**，别用 `git add -A`（共用仓库会夹带别人改动）。
