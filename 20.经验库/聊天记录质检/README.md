## 这套事解决什么问题

客服聊天记录量大，靠人抽查只能看表面。要解决的是：**保留完整上下文，用可复核的证据判断客服有没有积极解决问题**（热情、主动跟单、给到下一步），而不是只看回复速度或字数。

## 目录索引（[`客服聊天记录质检经验包.md`](./客服聊天记录质检经验包.md)）

1. **一、判什么、不判什么**：判行为（热情／主动跟单／积极解决问题 + 平台外部事实）；不判售后、不判性格、不猜转接链路。
2. **二、数据源与取数**：独立浏览器实例 + 人工登录；按天全量、逐天列全参数；三道对账（三数对账、落盘对账、平台标记对账）。
3. **三、判断标准（带依据与正反例）**：热情／跟单／解决问题的判定证据；平台口径 vs 内部口径的差异；「判不出」与「没问题」严格分开。
4. **四、踩过的坑与避坑规范**：通读 vs 抽样边界；标准话术 vs 模板复读；同段前后矛盾四要素；高频参数口径卡；值班空档归类；脱敏规范；工具执行坑。
5. **五、标准样例流程（可直接照跑）**：逐天取数 → 三道对账 → 导底稿抓标记 → 逐段三行判定 → 五节固定报告 → 点对点反馈 → 收尾交接。
6. **六、验收判据**：证据可回溯到哪一句哪一秒、覆盖诚实不隐瞒盲区、动作可执行（第二天能改）。
