# 客服聊天记录质检（经验包）

> 状态：**素材收集中**（2026-10-31 黎路遥要「能直接分享给别人」的版本，素材由 12号 宁中则出，木婉清成文）。
> 开源红线：不写账号密码、内部 ID、店铺名、客户姓名手机号、客服真名（一律「客服A／客户1」）。

## 这套事解决什么问题

客服聊天记录量大，靠人抽查只能看表面。要解决的是：**保留完整上下文，用可复核的证据判断客服有没有积极解决问题**（热情、主动跟单、给到下一步），而不是只看回复速度或字数。

## 要写进来的六块（待素材填充）

1. **判什么、不判什么**：判行为（有没有解决、有没有给下一步）；不判语气好不好听、不替业务定政策。
2. **数据源与取数**：会话从哪来、取多少天、怎么证明「取齐了」（漏段怎么发现、怎么标记「没取到」而不是「没问题」）。
3. **判断标准（带为什么）**：热情／跟单／解决问题的证据各是什么；什么算「消极服务」（既不解决也不给下一步）；平台判定与人工判定为什么会不一致。
4. **坑**：通读 vs 抽样怎么选；模板复读怎么识别（同一句反复追问）；同一段前后矛盾怎么记；「判不出」不能写成「没问题」。
5. **样例流程**：取数 → 逐段判 → 出报告（问题＋证据原文）→ 反馈给本人（只发本人、不排名、不发群）。
6. **验收判据**：报告里每一处扣分都能指回原文的哪一句、哪一秒。
