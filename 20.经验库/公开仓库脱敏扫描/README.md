# 公开仓库脱敏扫描

> 配套脚本：`工具/查敏感.py`（只读，不改文件）｜自测：`测试/冒烟测试.py`
> 一句话：**往公开仓库/对外文档推东西之前，先跑一遍这个**——本机用户名路径、手机号、内网 IP、密钥、口令、余额，人工翻是翻不出来的。

## 一、什么毛病

要公开的东西（经验包、工具脚本、交接文档、日志样例）里，最常混进这几类：

- 本机绝对路径带用户名：`D:\Users\<你的用户名>\Desktop\订单.xlsx`
- 客户/同事的手机号、邮箱、身份证、银行卡
- 内网地址：`192.168.x.x`、`10.x.x.x`——等于把内网拓扑摊开
- 密钥与令牌：`sk-...`、`ghp_...`、`AKIA...`、整块私钥
- 口令赋值：`password=xxxx`
- 报价/余额：`¥12,800`

**人工看一遍看不出来**，尤其是长 JSON 日志、几百行的 Markdown。
而 GitHub 上推错一次就是永久留痕：删了还有 fork、还有缓存、还有爬虫。

## 二、怎么用（三步）

```bash
# 1. 扫（文件或目录都行，可给多个）
python 工具/查敏感.py "D:\你要公开的仓库"

# 2. 照行号去改
#    输出长这样：path\file.md:37: [high] 手机号 → 13******78
#    片段是掩码的，别试图反推完整值

# 3. 改完再扫：退出码 0 ＝ 干净
python 工具/查敏感.py "D:\你要公开的仓库" -q
```

常用开关：

| 开关 | 用途 |
|---|---|
| `--min high` | 只看必须改的（密钥/身份证/银行卡/口令），赶时间时用 |
| `--allow 邮箱,金额` | 确属误报的规则临时关掉（关了什么要在项目里写清原因） |
| `--json` | 给程序/CI 读；`{"scanned":…, "hits":[…], "total":…}` |
| `--max-size 5M` | 调大单文件上限（默认 2MB） |

**挂到提交前**：`git config core.hooksPath .githooks` 之类的前置钩子里调一次，退出码非 0 就拦住。

## 四、怎么算修好了（可数判据）

1. `python 工具/查敏感.py <你的目录> --min medium` **退出码 0、命中 0 条**；
2. 单跑 `python 测试/冒烟测试.py` **12 项全 PASS**（见下节台账）；
3. 你项目自己的 README/文档里，凡被 `--allow` 关掉的规则都写了原因。

## 六、给 AI 的执行说明（照这个干）

1. **只读**：这个脚本不写、不改、不移动任何文件；发现命中只报行号。
2. **先扫后改，改完再扫**；两次输出对比，确认条数往下走。
3. 命中逐条判：真值 → 删掉或换占位（密码一律 `<密码>`、密钥 `sk-****`、路径 `<用户名>`）；确属误报 → 用 `--allow` 关该条规则，并在项目文档写明为什么。
4. **别为了过扫把整段内容删光**——保留方法、删掉值。
5. 掩码片段不可反推；不要为了「确认是不是真的」去打印完整值。
6. 报告时给数字：扫了多少文件、达到门槛的命中多少、退出码多少。

## 七、踩过的坑

1. **Windows 管道下子进程默认 GBK**：本包自测第一版就栽在这——父进程按 UTF-8 读、子进程按 GBK 写，中文直接把 JSON 解析打炸。修法：`env PYTHONIOENCODING=utf-8`（脚本里已带）。
2. **18 位身份证会被「16–19 位数字」同时命中**：让位给身份证规则，避免一处泄漏报两条、改起来以为改漏了。
3. **占位符必须放行**：`<密码>`、`***`、`your_password` 一律不报，否则模板类文档天天红。
4. **扫描器会被自己命中**（规则正则的字面量就在源码里）：自扫时排除 `工具/` 与 `测试/` 两个目录，别指望「工具自身 0 命中」。
5. **二进制与超大文件跳过**：图片/sqlite/压缩包里没有可读文本，硬扫只是空转；默认 >2MB 与含 `\x00` 的跳过。
