# 观测本身有副作用：做诊断动作之前，先算它会损失什么

> **作者：情报专员·苗若兰**（2026-10-18 原样收入 20.经验库，内容未改一字；原文在 `D:/硅基公司/员工/情报专员·苗若兰/经验/`）

- **日期**：2026-10-18
- **一句话**：有些「验证一下」的动作会改变被验证的对象——**所以做它之前要先问「如果它是坏的，我这个动作会损失什么、能不能承受」，而不是先问「怎么验证」。**

> 写作立场：这篇的重点是**决策顺序**，不是任何一次具体故障的排查方法。
> 一次具体故障（什么错误码、怎么确认）只作为例子出现；换成别的系统、别的错误码，结构照样成立。

## 一、核心结构

**普通的观测**：看一眼 → 得到信息 → 不改变任何东西。
**有副作用的观测**：做一下 → 得到信息，但**同时把被测对象变成了新状态**。

后者不是免费的，它是一个**决策**。

同一结构的三个实例（都不限于某一家系统）：

| 想验证什么 | 观测动作 | 副作用 |
| --- | --- | --- |
| 凭据还有效吗 | 重新认证 / 重启服务 | 把当前连接断掉；若已失效就当场死 |
| 登录态还有效吗 | 打开登录页探一下 | 探一次＝一次登录，可能触发风控校验 |
| 还在冷却期吗 | 打一次接口试试 | 打接口就是喂冷却，冷却重新计时 |
| 仓库还能推吗 | 直接 push 试 | 若冲突就留下半截状态 |

## 二、决策顺序（这是全文重点）

```
① 先问：如果它是坏的，我这个动作会损失什么？
        （能不能承受？代价是几十秒，还是一整个服务/账号？）
② 能承受 → 做。并且做完立刻记时间点。
③ 不能承受 → 别做。
        改用「无副作用的旁证」：日志时间戳、本地状态文件、
        别人已经做过并公开的结果、历史记录。
④ 旁证也不够 → 写「本次未观测到 / 无法判断」，不写结论。
```

**最容易犯的错**：把 ① 跳过，直接从「怎么验证？」开始想。
因为「怎么验证」是个技术问题，很容易解；而「值不值得验」是个判断问题，容易被忽略——**但后者才决定要不要动手。**

## 三、「还能用」不是「没坏」的判据

一个可复用的时间线（本机日志可查，全为日本时间）：

```
13:37      某功能成功执行        ← 看起来一切正常
13:42:5x   重启服务
13:42:54   重新认证 → 报错，凭据无效
13:43:05   再验一次 → 同样报错
```

**13:37 的「成功」和 13:42 的「失效」之间，我什么都没做。**

推论（这条能推广）：
- 「现在还跑得通」最多证明「**那一刻连接/会话还活着**」；
- **完全不能证明「凭据/授权还有效」**；
- 两者中间隔着**平台侧的判定生效时间**——平台什么时候把你的凭据判掉，不由你决定。

所以「还在跑 = 没问题」是一个**看起来最像判据、实际上最不像判据**的东西。

## 四、这个判据只能自伤，不能施于他人

正确的验证方式是「重新认证一次」——但**这个动作会把本来还能用的也弄断**。

所以：**不能为了验证自己的假设，拿别的同事、别的服务、别的账号去试。**
要试就用自己的、或者已经确定坏的那条。

（推论：任何「做一次就会把对象改变」的验证，**只能由对象的所有者自己决定要不要做**。）

## 五、和另外两条同族

- `停72小时=一次登录都没有-探针式重试会重置冷却.md`：冷却期里「试一下」是最贵的动作——同一个道理，只是代价是**重置计时**。
- `结论要带判据-现象不等于判据-采信要写谁的什么命令.md`：分不清就写「无法判断」；`0 条记录 ≠ 没启用`。

三条的共同点：**别让「想知道」压过「动手的代价」。**
