# 经验包：git 共享工作区——提交要「按路径点名」

> **一句话**：多人（或多个 AI）共用一个工作区时，`git commit` 会把**暂存区里所有人的改动**
> 一起提交——别人的活会被你顺带带走。解法：提交时**带上路径点名**，只交自己那几份。
> 用法：把本文件夹交给你自己的 AI，说「照这个包，改成按路径点名提交」。

---

## 一、坑在哪（真实发生过）

共享工作区＝同一份 checkout，多个人 / 多个 AI 都在改：

1. 甲 `git add`（或 `git rm`）了自己的文件，**还没提交**；
2. 乙这时 `git add` 自己的文件、`git commit`；
3. → 甲暂存的内容被乙的提交**顺带带走**（提交信息里还写着乙的活）。

不是谁手滑，是「共享工作区 ＋ 有人把改动留在暂存区」的固有风险。

## 二、对策：提交时带路径

```bash
# 新文件先点名加：
git add -- 路径1 路径2

# 提交点名（-m 要在 -- 前面）：
git commit -m "说明" -- 路径1 路径2 路径3
```

- 只提交**点名的那几个路径**；暂存区里别人的东西**原样留着**；
- 直觉版对比：`git commit` 不带路径 = 把暂存区**全部内容**一起提交（夹带的来源）。

## 三、给 AI 的执行说明（照做）

1. 提交前：`git status --porcelain` 扫一眼——暂存区里有没有**别人的**东西（`A `、`M ` 条目）；
2. 提交一律点名：`git commit -m "说明" -- <你的文件...>`；
3. **别用** `git add -A`、`git add .`、`git commit -a`——共享工作区里等于事故；
4. 提交后再 `git status --porcelain` 复查：别人的改动应**还**在那里（未提交），不应消失。

## 四、坑

- `-m` 必须放在 `--` **前面**：`git commit -- a.txt -m "…"` 会把 `-m` 当路径报错；
- 改名 / 删除也要点名（`git add -- <新路径>`；`git rm -- <路径>`，再点名提交）；
- 点名的路径若真没改动，会报「没有东西可提交」——正常，别慌；
- 这招对「单人临时仓库」无所谓；**只有共享工作区**才需要。
