# AirScript 脚本拆分：一件事一脚本（32号 补差 2026-10-08 实战）

**结论**：线上脚本（金山 AirScript）**按「大的业务事件」拆成多个脚本**，别把 N 个动作揉进一个几百行的大脚本里。

## 背景
32号 补差原来是**一个 790 行、8 个动作**的大脚本（探针 / 预演 / 写汇总 / 写主体 / 刷新与税金 / 自检图片API / 插图 / 写公式）。
黎路遥 2026-10-08 拍板拆成 **4 个大事件**：① 写数据（探针+预演+写汇总+写主体）② 刷新与税金 ③ 收款图（汇总+主体）④ 店铺-主体对照。

## 为什么（好处）
1. **改哪粘哪**：AirScript 要在文档里手工粘贴，大脚本每次改动都得重贴全文（金山编辑器还会吃 `==`）→ 脚本越小、粘贴风险越小。
2. **定位快**：出问题只看对应脚本，不牵动别的动作（原话：「别牵动所有内容」）。
3. **能灵活组合**（当天就见效的真实案例）：
   把「**清空怀化工厂登记（主体表 M~P 列）**」从「写主体」里拆出来、单独成一个脚本之后——
   - 日常「写数据」**不再**清 M~P → 用户自己填的登记数据不会被冲掉（他当天已填了新数据）；
   - 要清的时候单独跑那个脚本（必须带快照 + 二次确认）。
   反例：原来「写数据 = 换 A~L 十二列 + 顺手清 M~P」这种**捆绑**是危险的，一跑就把人写的东西抹了 ✗。
4. **守卫更容易做严**：一个脚本只管一类表（如「主体收款图」只认 集团/器械，**绝不接受 汇总**），白名单/行域/列域都收得更紧。

## 设计要点
- 粒度 = **业务事件**（人叫得出名字的动作），不是「每个小函数一个脚本」；客户端可以留一个薄调度层。
- 每个脚本自带走查守卫：无 `allowWrite` 不写；写前查表头/末行；写后逐格回读；**失败不重试**。
- 脚本之间**不共享可变状态**；重复一点小工具函数没关系（好过各改各的漂移）。
- **拆的顺序**：新脚本先建，旧脚本继续跑 → 新脚本验证通过再退休（避免断档）；每个新脚本配独立 webhook。
- **危险动作单独成脚本**：清空 / 覆盖 / 删除类一律独立、单独授权、写前快照。

## 踩坑
- 写脚本**不用等号比较**（金山 AirScript 编辑器会吃掉 `==`/`===`）→ 用三元、`instanceof`。
- 脚本文件放统一目录（32号 统一 `kdocs-scripts/`），别一会儿 `project-config/` 一会儿根目录。
