# 接入自检清单（复制即用）

> 用法：把本清单交给你的 AI 助手，或自己逐项跑。**做一样打一个勾**，别跳项——
> 本套 90% 的故障都出在「以为它通了」。对应 README 第二节的六个台阶。

## A. 前置（台阶 1）

- [ ] Node.js ≥ 18：`node -v`
- [ ] 装好 CLI：`npm i -g @tencent-ai/codebuddy-code` → `codebuddy --version`
- [ ] 完成登录（不再报 `Authentication required`）
- [ ] 一发验证出活：
      `codebuddy -p "只回复四个字：接入测试OK" --output-format json`
      → 返回 JSON，含助手回复文本

## B. 派活脚本与退出码（台阶 2–3）

- [ ] 小任务派活成功（退出码 `0`，stdout 是结果文本）：
      `node 工具\派活.cjs "统计当前目录下所有 md 文件的字数，列个表" --工作目录 <某目录>`
- [ ] 两种 JSON 形态都能解（数组 / 单对象），能识别 `is_error`
- [ ] 退出码语义一致：**0 成功 / 2 额度尽 / 3 未登录 / 4 超时 / 5 其它**
- [ ] 参数错误路径返回 `5`（缺任务描述、工作目录不存在）

## C. 回落与调度（台阶 4）

- [ ] `2` → **回落自己干**（不重试）
- [ ] `3` → 记「需重新登录」，本单可回落
- [ ] `4/5` → 最多重试 **1** 次并退避；仍失败则回落
- [ ] 回落**显式投回任务队列**（不丢任务、不空转重试）
- [ ] （可选）收到 `2` 后本轮**全局降级**：后续任务直接窗口自己干

## D. 目录与并发（台阶 6）

- [ ] 派活后文件改动**只**落在 `--工作目录` 指定的目录内
- [ ] 一窗一目录：多窗口同时派活，改动互不覆盖
- [ ] `派活日志.jsonl` 每次调用追加一行（退出码/用时/用量）

## E. 可选：HTTP 模式（台阶 5）

- [ ] `codebuddy --serve --port 8077` 起服务
- [ ] `POST /api/v1/runs` → 拿到 `runId`（头带 `Authorization: Bearer <…>` ＋ `X-CodeBuddy-Request: 1`）
- [ ] `GET /api/v1/runs/{runId}` → 查到结果；知道「跑完再取 `stream` 会 `RUN_NOT_FOUND`」

## F. 红线（收尾必查）

- [ ] 任何**任务描述里没有**密码/密钥/口令/隐私数据（任务会上传云端）
- [ ] 凭据（如 `gateway.password`）**只在**本机文件里，没进代码/日志/仓库
- [ ] 派活一律**显式指定** `--工作目录`
- [ ] 可分享件里没有账号名、额度数字、带用户名的本机路径、截图
