# 经验包：让 AI 窗口把「重活」外包给本地 CLI（CodeBuddy headless 派活）

> **一句话**：AI 窗口当「大脑」——负责编排、上下文、判断；单个耗时的「重活」不自己硬扛，
> 而是外包给**同机跑的 CodeBuddy CLI**（腾讯 CodeBuddy Code，headless `-p` 模式）去执行，
> 消耗的是 CodeBuddy 的订阅额度；额度耗尽（**退出码 2**）就自动**回落**——由窗口自己接着干。
> 一条命令派活，退出码即状态；接进调度/唤醒器即可全自动、多窗口并行。
>
> **用法**：把本文件夹整个交给你的 AI，说一句「照这个包，把窗口的重活外包给本地 CodeBuddy CLI」。
> 本包讲的是**架构与接入经验**（含一步步验收标准和实测坑），`工具\派活.cjs` **可直接运行**。

## 〇、这套架构长什么样（先看全局）

```
         调度 / 唤醒器（定时或事件触发，投一条任务）
                        │
                        ▼
   ┌─ AI 窗口（大脑·编排者）───────────────────────────────┐
   │  拿到任务 → 判断轻重：                                 │
   │      ├─ 轻活 → 窗口自己干（省钱、快）                  │
   │      └─ 重活 → 外包：node 派活.cjs "<任务>"            │
   │                     │                                  │
   │                     ▼（headless 子进程）               │
   │        ┌─ CodeBuddy CLI（同机·烧订阅额度）─────────┐   │
   │        │  codebuddy -p "<任务>" --output-format json │  │
   │        │  · 多单并行（各跑各的进程，互不干扰）        │  │
   │        │  · 干活改动直接落在指定工作目录里           │  │
   │        └───────────────┬───────────────────────────┘   │
   │                        │ 退出码                        │
   │   0 成功 → 拿它的结果文本                              │
   │   2 额度耗尽 → 回落：窗口自己干（别硬重试）            │
   │   3 未登录 → 提示重新登录（可回落）                    │
   │   4 超时 / 5 其它 → 可重试一次，不行回落               │
   └────────────────────────────────────────────────────────┘
```

### 一次派活的生命周期

1. **调度/唤醒器**（或窗口自己判断）决定「这单算重活」；
2. 窗口调 `node 派活.cjs "<任务>" --工作目录 <目标目录>` —— 它在本机起一个 **headless 子进程**；
3. CLI 带 `-p "<任务>" --output-format json` 跑完，把结果按 **JSON** 打在 stdout（`result` / `message` 等节点）；
4. `派活.cjs` 解析 JSON → 把助手回复文本吐在 stdout，并在 **stderr 报诊断**、按情况给出**退出码**；
5. 调用方**只看退出码**决定下一步：`0` 用结果、`2` 回落自己干、`3/4/5` 按规则重试或回落；
6. 每次调用记一行日志（`派活日志.jsonl`），便于事后对账（调用量、退出码分布、用时）。

### 为什么值得做

| 好处 | 说明 |
| --- | --- |
| **烧的是订阅额度，不是自家额度** | 重活跑在 CodeBuddy 的订阅口径上，窗口自己的额度/预算省下来干别的 |
| **并行不抢脑** | 每个派活是独立子进程，多个窗口可同时派活、各跑各的，互不阻塞 |
| **头脑与执行分离** | 窗口专注编排、上下文和判断；把「搬砖型」长任务丢出去，窗口保持轻快 |
| **失败可回落，不空转** | 退出码 `2` 明确告诉你「额度没了」，直接回落，避免对着一个永远失败的接口空重试 |
| **改动落盘可审计** | 重活的文件改动直接落在指定工作目录里，配日志可回放 |

> ⚠️ 反向取舍也要说清：headless 模式**默认带 `-y`**（允许它直接改文件、跑命令），
> 所以「框定工作目录」不是可选项而是硬要求；另外**任务描述会上传到云端**，机密别写进去（见第五节红线）。

### 部件清单

| 部件 | 干嘛 | 本包对应 |
| --- | --- | --- |
| CodeBuddy CLI | 真正干活的执行体（headless `-p` / serve HTTP / SDK） | 官方 npm 包 `@tencent-ai/codebuddy-code` |
| AI 窗口 | 编排者：判断轻重、派活、读退出码、回落 | 你自己的 AI 运行时（能开窗口 + 能挂后台命令） |
| 派活脚本 | 把 CLI 包一层：解析 JSON、归一退出码、记日志 | `工具\派活.cjs` |
| 退出码语义 | 调用方与脚本之间的「合同」 | 第 3 台阶（表格） |
| 回落规则 | 退出码 → 下一步动作（接进调度） | 第 4 台阶 |
| 调度 / 唤醒器 | 定时或事件触发投任务、并行拉起多窗口 | 第 6 台阶（经验描述）；配套开源包另见出处 |
| 派活日志 | 追加型 JSONL 账本：调用量/退出码/用时 | 运行时生成（`派活日志.jsonl`） |

## 一、准备清单

| # | 要什么 | 说明 |
| --- | --- | --- |
| 1 | **Node.js ≥ 18** | npm 全局安装、运行 `派活.cjs`（用到内置 `child_process` / `fs`） |
| 2 | **CodeBuddy Code CLI** | npm 全局装：`npm i -g @tencent-ai/codebuddy-code`，装完提供命令 `codebuddy`（别名 `cbc`） |
| 3 | **登录一次** | 未登录时 `-p` 会报 `Authentication required`；登录是**必须**的一步（凭据落在 `~/.codebuddy/settings.json`） |
| 4 | **一个会「编排」的 AI 运行时** | 能开窗口/会话、能挂后台命令最好——它就是「大脑」 |
| 5 | 网络 | 重活会连 CodeBuddy 云端；本机脚本之间只走 127.0.0.1 |

**先跑一遍一发验证**（确认装好、登录好、能出活）：

```bash
# 装（全局，一次即可）
npm i -g @tencent-ai/codebuddy-code

# 一发验证：让它在当前目录回一句话，JSON 输出便于机器解析
codebuddy -p "只回复四个字：接入测试OK" --output-format json
```

看到 JSON 里带助手回复文本（通常在 `result` 或 `message` 节点）就说明链路通了。
若报 `Authentication required` → 先完成登录再验证。

## 二、从零到一：六个台阶

> 每级台阶：🏁 目标 → 🔧 做什么 → ✅ 验收 → ⚠️ 坑。
> 建议**一级一验**，别跳级——本套 90% 的故障都出在「以为它通了」。

### 台阶 1：装 CLI + 登录 + 一发验证

- 🔧 `npm i -g @tencent-ai/codebuddy-code`，跑一次 CLI 完成登录（按提示做）；
  然后 `codebuddy -p "<小任务>" --output-format json` 验证出活。
- ✅ **验收**：一发命令返回 JSON，含助手回复文本、`model`、用量字段（`usage.credit` 之类）。
- ⚠️ 坑：
  - **未登录必报错**：`Authentication required` / `Please login` / `not logged in`——登录是前置，不是可选。
  - 登录页/Web UI 地址是 **127.0.0.1**，**只能在装了 CLI 的这台机器上用浏览器打开**（外机打不开，属正常）。
  - 命令名有两个：`codebuddy` 与 `cbc`，本质同一个 CLI。

### 台阶 2：跑通 headless 派活，并会解 JSON

- 🔧 核心命令（本包「重活外包」的基本形态）：

  ```bash
  codebuddy -p "<任务描述>" --model <模型名> --output-format json -y
  ```

  关键参数：
  | 参数 | 作用 |
  | --- | --- |
  | `-p "<任务>"` | headless：非交互跑完即退出，把回复打在标准输出 |
  | `--output-format json` | 输出结构化 JSON（另有 `stream-json` 流式；见台阶 5 与第四节坑） |
  | `--model <名>` | 指定模型；可配 `--fallback-model` 兜底 |
  | `-y` | 放行「直接改文件 / 跑命令」——**必须框定工作目录再用** |

- 🔧 **JSON 输出怎么解析**（不同版本可能是数组，下面这套是通用写法）：
  - 顶层可能是 **数组**：遍历它，认 `type === "result"`（拿 `result` 文本、`usage`、`is_error`）与
    `type === "message" && role === "assistant"`（拿 `content` 里的 `text`）；
  - 也可能是**单个对象**或**夹带杂音的文本**：先整体 `JSON.parse`，失败再截取**第一个 `[` 到最后一个 `]`** 之间重试；
  - 兜底：`status === 0` 且没有可解析 JSON 时，直接把 stdout 当纯文本用。
  - `工具\派活.cjs` 里 `解析JSON()` 与主解析循环就是这套，可直接照抄。
- ✅ **验收**：一个「写个文件 / 统计一下」的小任务，stdout 能拿到助手回复文本，
  目标目录里能看到它干的活。
- ⚠️ 坑：
  - **别把 stdout 当纯文本**：`--output-format json` 下 stdout 是 JSON，`result` 之外还有用量/模型字段。
  - 有时**数组里既有 `result` 又有 `message`**：优先级与合并策略要固定（本包：`message` 覆盖文本、`result` 提供元信息并判 `is_error`）。

### 台阶 3：包一层派活脚本 + 退出码语义（调用方的「合同」）

- 🔧 用 `工具\派活.cjs`：它把 CLI 包成一条命令，**把各种失败归一成 5 个退出码**，
  调用方**只看退出码**即可决策，不必去猜 CLI 的报错文本。

  ```bash
  node 派活.cjs "<任务描述>" --工作目录 <目标目录> [--模型 <名>] [--超时 <秒>] [--安静]
  ```

  > 环境变量：`CODEBUDDY_MODEL`＝默认模型；`CODEBUDDY_CLI`＝CLI 的 JS 入口（自定义安装/测试用）；`CODEBUDDY_LOG`＝日志文件路径（运行时产物，不要提交）。

- ✅ **退出码语义**（**本包的合同，务必一致**）：

  | 退出码 | 含义 | 调用方怎么办 |
  | --- | --- | --- |
  | **0** | 成功（stdout＝结果文本） | 直接用它的结果 |
  | **2** | **额度/积分用尽** | **回落：自己干**（别硬重试——重试也没额度） |
  | **3** | 未登录 / 登录失效 | 提示重新登录；可先回落自己干 |
  | **4** | 超时 | 可重试一次（或加长 `--超时`）；不行就回落 |
  | **5** | 其它错误（网络/CLI 故障） | 可重试一次；不行就回落 |

- ⚠️ 坑：
  - **`2` 与 `5` 必须分清**：额度用尽（`2`）重试无意义，只会白等；其它错误（`5`）才值得重试。
  - 判定「额度用尽」靠**关键词**（`insufficient` / `quota` / `credit` / `balance` / `exceeded` / `payment required` …）
    **且没有拿到正常回复**——避免把正文里偶然提到这些词的正常结果误判成失败。
  - 判定「未登录」同理靠关键词（`authentication required` / `please login` / `not logged in` / `unauthorized`）。
  - 超时要靠子进程的 `timeout` 触发（`ETIMEDOUT`），别指望 CLI 自己报。

### 台阶 4：回落规则——接进你的调度

- 🔧 把退出码接到「下一步动作」上，形成闭环：

  ```
  派活 → 退出码 0 ─────────────► 采用结果
        → 退出码 2 ─────────────► 标记「额度耗尽」→ 本单回落（窗口自己干）
        → 退出码 3 ─────────────► 记一条「需重新登录」→ 本单回落
        → 退出码 4/5 ───────────► 重试 1 次（退避）→ 仍失败则回落
  ```

- 🔧 **接进调度/唤醒器**的三条建议：
  1. **回落要显式**：把「派活结果」当状态投回任务队列，让窗口按状态继续，而不是把失败吞掉；
  2. **额度耗尽全局降级**：一旦收到 `2`，可在本轮把派活开关置为「停用」，后续任务直接窗口自己干，
     隔一段时间再探一次（避免每条任务都撞一遍 `2`）；
  3. **重试上限**：`4/5` 最多重试 1 次并退避，**不要**对 `2` 重试。
- ✅ **验收**：人为造三种结局（成功 / 额度耗尽 / 未登录），调度都能正确分流，且**不丢任务、不空转重试**。
- ⚠️ 坑：**回落判断别只看「有没有输出」**——失败时 CLI 也可能在 stdout 留半截文本；以**退出码**为准。

### 台阶 5（可选）：HTTP 派活模式（`--serve`）

不想每次起子进程，也可以让 CLI 常驻一个 HTTP 服务，走接口派活：

- 🔧 起服务：`codebuddy --serve --port 8077`
- 🔧 派活与取结果：
  - 派活：`POST http://127.0.0.1:8077/api/v1/runs`，体 `{"id":"<唯一id>","type":"text","text":"<任务>","sender":{...}}`
    → 返回 `{ "data": { "runId": "...", "status": "accepted" } }`
  - 查状态：`GET /api/v1/runs/{runId}`
  - **所有请求都要带头**：`Authorization: Bearer <gateway.password>` **＋** `X-CodeBuddy-Request: 1`
- ✅ **验收**：`POST` 能拿到 `runId`，`GET` 能查到 `completed` 与结果。
- ⚠️ 坑（详见第四节）：
  - **认证只用 Bearer 头**（或 Web UI 会话 cookie）；`?password=` 查询参数**不认**。
  - `gateway.password` 从 `~/.codebuddy/settings.json` 里读（**字段名，别把值写进任何文件/日志**）。
  - **`stream` 只能实时接**：任务跑完后再去取流，会得到 `RUN_NOT_FOUND`——要么实时读流，要么改用 `runs/{runId}` 查结果。
  - 服务端点很多（sessions / jobs / channels / fs / pty 等），按需用；`X-CodeBuddy-Request: 1` 头**一个都不能漏**。

### 台阶 6：多窗口铺开

- 🔧 每个窗口**各跑各的 `派活.cjs`**：进程相互独立，天然并行——多窗口可同时派活，无需加锁。
- 🔧 约定：
  - **工作目录一人一个**：派活时显式 `--工作目录`，别让两个窗口在同一个目录里同时改文件；
  - **日志可汇总**：各窗口的 `派活日志.jsonl` 可集中到一个目录，统一看「调用量 / 退出码分布 / 用时」；
  - **额度是共享的**：所有窗口烧的是**同一个订阅额度**——一个窗口撞到 `2`，别家的重试也大概率失败，
    所以「`2` 触发全局降级」比每个窗口各自判断更省事。
- ✅ **验收**：同时开 3 个窗口各派一单重活，三单都跑完、改动各落各的目录、互不干扰。
- ⚠️ 坑：**同名/同目录并发写**会互相覆盖——工作目录必须隔离（前面反复强调）。

## 四、实测坑大全

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| `Authentication required` | 未登录 / 登录失效 | 先完成登录；脚本把它归一成**退出码 3** |
| Web UI / 登录页打不开 | 地址是 `127.0.0.1` | **只能在本机浏览器打开**；外机访问不了是正常的 |
| HTTP 请求 401/被拒 | 缺认证头 | 每请求都带 `Authorization: Bearer <…>` **＋ `X-CodeBuddy-Request: 1`** |
| `?password=` 不生效 | 该查询参数不认 | 只用 **Bearer 头**（或 Web UI 会话 cookie） |
| 流式取不到结果 | `stream` 只能在跑的时候实时接 | 跑完再取会 `RUN_NOT_FOUND`：要么实时读流，要么用 `runs/{runId}` 查结果 |
| 文件被莫名改动 | `-y` 放行了「直接改文件/跑命令」 | **派活时显式框定 `--工作目录`**，并说清「只在该目录里干」 |
| 任务带空格在 Windows 被拆词 | 用 shell 拼串执行 `.cmd` 垫片、参数不加引号 → 任务被拆成多个 argv（实测） | **别经 shell**：用 `process.execPath` ＋ CLI 的 JS 入口（`<npm全局>/node_modules/@tencent-ai/codebuddy-code/bin/codebuddy`）直跑（本包工具已如此）；确要经 shell 时给参数逐个加引号 |
| 脚本调起了「隔壁的」可执行文件 | CLI 包的 bin 目录里有多个无扩展名文件（`codebuddy`、`cbc-prewarm`、`codebuddy-lowmem`…），盲扫「第一个」会挑错（实测） | 读 `package.json` 的 `bin` 映射，或按名精确找 `codebuddy`（本包工具已如此） |
| 机密外泄风险 | 任务描述**会上传云端** | 任务里**绝不**放密码/密钥/隐私数据（见第五节） |
| 长任务中途被中断 | 超时 | 调 `--超时`；脚本把超时归一成**退出码 4**，可重试一次 |
| 对着失败猛重试、白烧时间 | 没区分 `2` 与 `5` | `2`（额度尽）**不重试**直接回落；`5` 才值得重试一次 |
| 正常结果被误判失败 | 正文里恰好含 `credit`/`limit` 等词 | 判「额度尽」要**同时**满足「命中关键词」**且**「没拿到正常回复」 |
| 解析不到文本 | 把 JSON 当纯文本 | 认 `type` 节点（`result`/`message`）；解析失败再截 `[`…`]` 重试 |
| 多窗口互相覆盖文件 | 共用一个工作目录 | **一窗一目录**，派活一律显式 `--工作目录` |
| 一个窗口额度尽，别家还在试 | 额度是**共享**的 | `2` 触发**全局降级**（本轮改为窗口自己干），别每家各判各的 |

## 五、红线（安全与规矩，一条都别破）

1. **任务描述不含机密**：任务会走云端，**密码 / 密钥 / 口令 / 隐私数据一律不进任务描述**。
2. **凭据口令不进包、不进日志**：`~/.codebuddy/settings.json` 里的 `gateway.password` 等**只在本机文件里存在**——
   不写进代码、不写进日志、不贴聊天记录、不提交仓库。
3. **工作目录必须框定**：`-y` 会放行直接改文件/跑命令，派活时**显式指定 `--工作目录`**并要求「只在该目录里干」。
4. **`2` 不重试**：额度耗尽就回落自己干，别对同一个永远失败的接口空转重试（省时间也少打扰）。
5. **失败不吞**：回落要显式投回任务队列，**不丢任务**。
6. **对外资产要脱敏**：截图、余额/积分数字、账号名、带用户名的本机路径，**一概不进可分享件**。
