# 经验包：Python 写 Windows 路径的「转义坑」

> **一句话**：路径里的 `\` 在 Python 字符串里是**转义符**——`"C:\2026\7月"` 不报错，
> 但会**静默地**变成一串带怪字符的路径，之后找文件、匹配全对不上。路径一律 `r"…"`，写完 `repr()` 回读。
> 用法：把本文件夹交给你的 AI，说一句「照这个包，帮我扫/修路径转义问题」——它照着就能干。
> 只要装了 Python 3（自带），不用装任何东西。

---

## 一、症状（真事：一天踩了三次）

- 写出来的路径**少字符**：想写 `\2026\`，结果变成 `档案6-10-11-…`；
- 混进**看不见的字符**（0x82、0x07、0x17…），`木婉清.企业微信机器人`、`专项.订单号提取`；
- 程序**不报错**，只是永远「找不到文件 / 匹配不上」——最难查的那种 bug。

## 二、根因（一分钟看懂）

Python 字符串里 `\` 开头的都是转义。路径里「反斜杠＋数字/字母」正好撞上转义表：

| 路径里这么写 | Python 当成 | 实际拿到 |
|---|---|---|
| `\2026`（八进制） | `\202` → 0x82 | 一个 0x82 怪字符，后面剩个 `6` |
| `\27`（八进制） | 0x17 | 看不见的控制字符（ESC 其实是 `\33`，不是 `\27`） |
| `\7`（八进制） | 0x07 | 响铃——屏幕上看不见，还会「嘀」一声 |
| `\t` `\r` `\n` | 制表/回车/换行 | 字符被吃掉，或路径从中间断成两截 |

> 八进制转义只认 `\0`–`\7` 开头、最多 3 位数字——**路径里以数字开头的目录名是重灾区**。

## 三、给 AI 的执行说明（照做）

1. **扫描**（先找嫌疑）：

```bash
python 工具\查转义.py 你的脚本.py             # 扫源码；退出码 1＝有事故
python 工具\查转义.py --文字 "C:\2026\7月"    # 只体检一条
```

2. **修**（三招）：

- 路径字符串一律 `r"…"`（raw 字符串）；
- 拼路径用 `pathlib`：`Path(r"D:\数据") / "2026" / "7月"`；
- 从别处拿到的路径**原样**用，别凭记忆重打（表里一字之差就匹配不上）。

3. **验证**（怎么算修好了）：

- 重扫 → 输出「干净：没发现转义事故。」；
- `print(repr(路径))` → 看不到 `\x82`、`\r`、`\t` 这类东西；
- 实际 `Path(路径).exists()` 或跑一遍流程，通了才算完。

> 附注：脚本自己打印中文给别的程序/日志读时，开头加一行
> `sys.stdout.reconfigure(encoding="utf-8")` 更稳——不然容易撞上 Windows 的 GBK/UTF-8 跨程序乱码。

| `工具\查转义.py` | 扫源码 / 体检字面量；只报可疑的；退出码 0/1（可接检查门禁） |

## 五、实测记录（本机 Python 3.10，2026-10-11）

扫「坏例子」——3 处全报、退出码 1：

```
[发现] 复现/示例/坏例子.py:2
       实际值：'D:\x826\x07'
         · 控制字符（0x82）
         · 控制字符（0x07）
[发现] 复现/示例/坏例子.py:3
       实际值：'C:\temp\task.txt'
         · 制表 TAB（0x09）
[发现] 复现/示例/坏例子.py:4
       实际值：'C:\reports\new'
         · 回车 CR（0x0D）
         · 换行 LF（0x0A）
exit=1
```

扫「好例子」——干净、退出码 0：`干净：没发现转义事故。`

`--文字 "C:\2026\7月"` → 报 0x82＋0x07（exit=1）；`模板\安全路径.py` 自检通过，
`repr 回读` 打印 `'D:\\数据\\2026\\7月\\报告.txt'`（双反斜杠＝真的反斜杠）。
