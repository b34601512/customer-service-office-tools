# 客服数据自动更新（经验包）

> 状态：**素材收集中**（2026-10-31 黎路遥要「能直接分享给别人」的版本，素材由 03号 霍青桐出，木婉清成文）。
> 开源红线：不写账号密码、内部 ID/docid、真实店铺名、客户姓名手机号。

## 这套事解决什么问题

多平台多店铺的客服数据（接待量、响应、应答率、超时…）每天要出，人工逐家抄不现实、口径还会漂。
目标是：**按顺序自动采集各店客服指标 → 落本地汇总表 → 按固定口径出报表**，同一份口径每天重复产出，人能核、机器可复算。

## 要写进来的六块（待素材填充）

1. **数据源与边界**：本地文件才是报表唯一数据源；在线表只同步给人看、不读回来（读回来会把「写不全」变成给老板的错数）。
2. **一次完整跑法**：登录态怎么维持、多久失效、采集顺序、产物落在哪、多久跑一次。
3. **口径与为什么**：每列怎么算（平均首次响应、平均响应、15 秒应答率…）、哪些样本要剔（跨夜单会拉高十倍）、为什么只在写表这层剔。
4. **踩过的坑**：平台登录失效、页面弹层挡住导出、字段口径与平台页不一致、快照目录跟着输出目录走、写表后回读不一致。
5. **样例流程**：一条能照着跑通的最小路径（命令 + 预期产物）。
6. **验收判据**：怎么算这一期真跑成（店数对得上、行数与源一致、回读差异 0、趋势能接上期）。
