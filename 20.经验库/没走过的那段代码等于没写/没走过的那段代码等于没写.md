- **对策**：

## 最值钱的那一条：测试盖不到的地方，就是「真跑一次」

- 木婉清 2026-10-18 说这比「写测试」更实际，我同意，所以单独提出来：
  **很多项目挂在「测试全绿、上线就炸」，就差这一步。**
- 具体的分界线（照着判断自己该做哪一步）：

| 这段代码做什么 | 单测够不够 | 要补什么 |
|---|---|---|
| 纯函数：算金额、拼列、解析文本、转日期 | ✅ 够 | 正常写单测就行 |
| 读**本机文件/配置**（字段名、路径、编码） | ❌ 不够 | **真读一次真文件**，并把 `Object.keys`/`repr(路径)` 打出来看 |
| 走**网络/登录/浏览器** | ❌ 完全不够 | **手跑一次成功全流程**，输出存进 `runtime/` 当证据 |
| 写外部系统（表格/工单） | ❌ 不够 | 先干跑 + 快照，再真写一次并回读 |

- 判据一句话：**这段代码今天有没有真的执行过一次？** 没执行过的那段，等于没写。
- 附带好处：真跑一次往往能扒出比 bug 更值钱的东西——本次就是靠真跑才发现「账号字段名猜错」＋「Python 路径转义」，两个都是单测永远测不到的。
- 反过来也成立（**但有前提**）：**真跑一次成功，就能把那一整条链当作已验证**，后续改上层逻辑时不用重复怀疑底层。
- ⚠ **前提：链路没变**（木婉清 2026-10-18 补，这条很重要）：
  「已验证」不是「测过一次就永远信」。下列任一项变了，**就得重跑**：

  | 变了什么 | 为什么要重跑 |
  |---|---|
  | 字段名 / 配置结构 | 今天这个 `account_name` 就是——代码没变、配置没变，但字段名本来就是猜的 |
  | 配置或数据文件路径 | 搬家、换人维护、`\` 转义都可能让它失效 |
  | 登录态 / 凭据 | 会过期、会被删（如 2026-10-18 企微机器人被砍），通了不等于永远通 |
  | 外部接口版本 / 对端系统升级 | 服务端一改，本地代码一字没动也会崩 |
  | 依赖包 / Node / Python 版本 | 行为差异往往静默发生 |

  → 一句话：**「已验证」要跟着「今天变了什么」一起看**，不是一次性盖章。
  → 具体到登记活的用法：每天早上首次跑巡检/登记前，先确认登录态和配置还在（探针/云端自检那几步就是在干这个），别拿上周的结论直接写表。
