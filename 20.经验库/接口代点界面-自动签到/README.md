# 用接口代替点界面：自动领签到积分（WorkBuddy 实例）

> **配套脚本**：同目录 `签到-接口版.mjs`（模板，两处硬编码已参数化，见文末「文件清单」）

> **一句话**：能用接口就不点界面——一个 POST 请求完成签到，毫秒级、不碰你屏幕、不占你鼠标。
>
> **来源**：2026-10-17 老板令「每天自动领 WorkBuddy 积分」→ 先做了 UI 版（点 DOM），跑了一天发现又慢又脆 → 改成接口版。
> **实测**：2026-10-19 08:20 领到 100 积分，连续第 6 天。

---

## 一、两种做法差在哪（这是本经验的核心）

同一个「领每日签到积分」，两种实现：

| | **UI 版（点界面）** | **接口版（POST 请求）** |
|---|---|---|
| 怎么干 | 给客户端开调试口 `9223` → 每 20 分钟巡一次 DOM → 找到卡片 → 点进去 → 找「签到」按钮 → 点 → 验证 | 直接 `POST` 签到接口，带登录令牌 |
| 耗时 | **几秒到几十秒**（要等页面渲染、元素出现） | **毫秒级** |
| 会不会动屏幕 | **会**（要开客户端、点元素） | **完全不会** |
| 客户端要不要开着 | **要**（还得带调试参数重启它） | **不用** |
| 什么时候会坏 | 客户端改版改文案改结构 → 找不到了 | 接口变更或令牌过期 |
| 失败的样子 | 静默（找不到卡片就当没事） | 有状态码可判（401/403＝要重登，200＝成功） |
| 代码量 | 200+ 行（找元素、点击、等待、容错） | **80 行**（读令牌 → 发请求 → 判结果） |

**结论：能用接口就不要点界面。** 这跟「AI 员工别去操作 GUI」是同一条原则。

## 二、怎么找接口（四步，可照搬）

### 1. 先找到「令牌在哪」

同一账号的客户端，通常把登录令牌明文存在本地。以 CodeBuddy / WorkBuddy 为例：

```
C:\Users\<你>\AppData\Local\CodeBuddyExtension\Data\Public\auth\Tencent-Cloud.coding-copilot.info
C:\Users\<你>\AppData\Local\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info
```

读出来是 JSON，令牌在 `accessToken` 字段（或 `auth.accessToken`）。
**多写几个候选路径按顺序找**，哪台机器装法不同都能兜住。

### 2. 再找到「那个按钮打了什么请求」

客户端开着 `9223` 调试口时，用它的 Network 面板点一次「签到」，把请求抄下来。**只要三样：**

- **URL**：`https://www.workbuddy.cn/v2/billing/meter/daily-checkin`
- **方法**：`POST`，body 是 `{}`
- **请求头**：`Authorization: Bearer <令牌>`、`Content-Type: application/json`、`User-Agent: Mozilla/5.0`

> **`User-Agent` 别省。** 不少接口对没有 UA 的请求直接拒。

### 3. 用 curl 先验一次（别急着写脚本）

```bash
curl -X POST "https://www.workbuddy.cn/v2/billing/meter/daily-checkin" \
  -H "Authorization: Bearer <令牌>" \
  -H "Content-Type: application/json" \
  -H "User-Agent: Mozilla/5.0" \
  -d "{}"
```

**返回 200 + `{"code":0,"msg":"OK","data":{"credit":100,"streak_days":6}}` 就说明通了。**

### 4. 再写脚本

见本目录 `签到-接口版.mjs`。

## 三、接口版脚本的五个必备件

写这类「每日自动签到」脚本，下面五样缺一不可：

### ① 时段门（别半夜乱跑）

```js
const 点钟 = new Date().getHours() + new Date().getMinutes() / 60;
if (点钟 < 6 || 点钟 > 22) { log("不在允许时段（6:00-22:00），跳过"); process.exit(0); }
```

**为什么**：半夜跑没有意义，还会让「今天已领过」的判断跨日错乱。

### ② 记档门（一天只领一次）

```js
const 今日 = new Date().toISOString().slice(0, 10);
if (st.lastSuccess === 今日) { log("今天已领过（记档），跳过"); process.exit(0); }
```

**为什么**：定时器每小时跑一次，没有这道门就会一直打接口——**可能被风控，也可能真的重复领（有些接口会扣积分）**。

### ③ 令牌缺失要说人话

```js
if (!令牌) { log("令牌为空（可能要重登 CodeBuddy），放弃"); process.exit(1); }
```

**别只说「失败」。** 要说**该谁做什么**——这句会出现在日志里，出问题时人能直接看懂。

### ④ 状态码分级，不要一刀切

```js
if (结果.status === 401 || 结果.status === 403) {
  log("令牌被拒（" + 结果.status + "）——需要本人重登一下客户端");
  process.exit(2);            // 2 = 需要人介入
}
```

- `200` → 成功
- `401/403` → **令牌失效，要人重登**（这是唯一需要人动手的情况）
- 其他 → 下轮再试

**退出码分开**，定时器/监控才能区分「暂时失败」和「要人管」。

### ⑤ 成功要报功（不然没人知道它活了）

```js
// 报功方式五花八门（企微机器人、桌面通知、写日志）；模板里做成环境变量，不绑死任何一家：
//   签到报功命令=node D:\工具\企微发消息.cjs --回复 "{msg}"
const 报功命令 = process.env.签到报功命令 || "";
if (报功命令) {
  spawnSync(报功命令.replace("{msg}", "今天积分帮你领了 ✓（接口版：一个请求、毫秒级、没碰你界面）"), { shell: true, windowsHide: true });
}
```

**报功不只是礼貌**——它是这个脚本的**心跳**。
**没消息的时候，你没法区分「今天领了但没说」和「脚本早就死了」。**

## 四、怎么挂成定时任务（Windows）

用 `wscript.exe` 包一层，**不要直接挂 node**——直接挂会闪黑窗。

```vbs
' run-hidden.vbs（UTF-16LE BOM 存）
Set sh = CreateObject("WScript.Shell")
sh.Run "powershell.exe -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File ""C:\...\claim.ps1""", 0, False
```

`claim.ps1` 里调 node 跑脚本。**ps1 必须 UTF-8 带 BOM**，否则 PowerShell 5.1 按 GBK 读，中文全乱。

> ⚠️ **这条踩过坑**：没有 BOM 时 `-match '叫醒器'` 永远匹配不上中文，守卫形同虚设——**脚本没报错、功能静默失效**。
> 中文乱码/编码坑另见本库《Windows批处理中文乱码修复》《PowerShell输出GBK-Python乱码》。

## 五、这套做法能套到哪

**凡是「每天点一下领点什么」的，都能这么办：**

| 场景 | 找什么接口 |
|---|---|
| 每日签到 / 领积分 | `/checkin`、`/sign-in`、`/daily-reward` |
| 每日任务领奖 | `/task/claim`、`/reward/receive` |
| 看广告领会员时长 | `/ad/reward`（有的要 watch token，麻烦些） |
| 每日投票 / 打卡 | `/vote`、`/punch` |

**判断标准：如果这个动作在网页/客户端上「点一下就能完成」，它背后一定有一个请求。找到那个请求，就不用点那一下。**

## 六、什么时候接口版反而不能用

**别硬套。这三种情况还是得走 UI：**

1. **要过验证码 / 人机验证** —— 接口过不去，别绕（绕了就是攻击）
2. **要真点广告等时长** —— 那本身是「看」这个行为换的，伪造等于骗
3. **令牌拿不到（只在内存里、加密存储）** —— 那就老老实实走 UI

**界限：做「你本来就有权做、只是懒得点」的事；不做「绕过对方设的关卡」的事。**

## 七、和「AI 员工」的关系（这条值得往大处想）

老板 2026-10-17 要的是「每天自动领积分」。**UI 版也能完成，但它占着屏幕、耗着时间、还随时会被改版打坏。**

**接口版做完之后，这件事就不再需要「窗口」「鼠标」「等人的时间」了。**

> **能变成一行请求的事，就不该占一个窗口。**
> **能变成一行请求的事，也不该占一个人的注意力。**

**这条对 AI 员工排班同样成立**：
- 能写成脚本定时跑的，不要叫一个窗口起来想
- 叫窗口起来，是留给「需要判断」的活

**（这也回答了老板问的「20 分钟跑一次是否消耗 token」——脚本定时跑不消耗，起窗口才消耗。所以这类活应该做成脚本，不是做成窗口。）**
