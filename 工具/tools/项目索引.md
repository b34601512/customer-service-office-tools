## 这个目录是什么
仓库级**共享小工具**（唯一出处），各项目里的同名实现都只是"壳"（反向断言测试锁死"不许再自带一份"）。

| 块 | 干嘛的 | 入口 |
| --- | --- | --- |
| **打码过滤器** | 公开仓库但不泄露真值：提交时"真值→打码值"、检出时还原 | `打码.js`（`--扫描/--学/--核对/--自检/--体检`）、`打码过滤器.js`、`打码字典.js`；本机对照表 `打码对照.local`（**不入库**） |
| **浏览器引擎** | 受控浏览器拉起/附着/关闭（按店铺 profile 隔离，不含业务判断） | `浏览器引擎/index.js`（22/24/25/26 号薄壳调用；1号 那份不同、不动） |
| **金山表** | 匿名无头读金山分享链接 + 调文档里已保存的只读 AirScript | `金山表/读表核心.js`、`脚本客户端.js`、`读表命令行.js`… |

## 规矩 / 常用命令
- **提交走闸门**（`../0.木婉清档案/规矩与红线.md` §八）：`node tools/提交.js -m "提交信息" <点名文件…>` = 扫描 →（有新的才）`--学` → `git add --renormalize` → 提交 → `--核对`；绕不过去、只允许点名文件（禁 `-A`/`-u`）。
- 手工提交顺序：`node tools/打码.js --扫描` → 提交 → `--核对`；若有「N 个还没进对照表」→ 先 `--学` + `git add --renormalize <文件>` 再提交（`tools/提交.test.js` 锁死）。
- 引擎/金山表的壳测试：`node --test tools/浏览器引擎/引擎.test.js`（8 项）、`node --test tools/金山表/金山表.test.js`（9 项）。

## 红线
- **唯一出处**：新代码不许再往项目里复制引擎/金山表实现；发现复制品 → 改薄壳 + 反向断言。
- `打码对照.local`（真值对照表）**绝不入库**；`项目-config`、登录态、截图、Excel、客户真实身份信息同样不入库（`../开源边界.md`）。
