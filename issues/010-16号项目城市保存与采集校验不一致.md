# 16号项目城市保存与采集校验不一致

## 意图与背景

避免朋友看到城市已经保存，开始采集时才发现不可用。配置页只校验非空，业务仅接受内置24个中文城市名或数字码。

## 证据

- boss_tui.py:618 城市走普通text保存逻辑。
- boss_cdp.py:866 在run_fetch才解析并检查城市。
- 通过真实配置分发路径输入“济南市”，保存成功；调用run_fetch立即ValueError，浏览器启动函数调用0次。
- 错误提示要求使用--city-code，但实际CLI参数为--city；TUI也不存在--city-code操作。

## 验收清单

- [x] 复现“济南市”保存成功但采集失败。
- [x] 城市规范化和校验独立为业务真源，由TUI/CLI统一调用。
- [x] 配置保存时反馈未知城市，明确支持的输入形式。
- [x] 错误提示与实际TUI/CLI操作一致。

## v0.10处理

新增业务normalize_city，配置保存、run_fetch和CLI setup共用。支持已知城市名带“市”及9位ASCII数字城市码；未知城市保留原配置并显示原因。错误提示改为实际参数--city。
回归覆盖济南市、北京市、城市码、空值、未知城市、错误长度；无效输入不启动浏览器。
实际v0.10成品EXE通过真实隐藏控制台验证“济南市”规范化及未知城市立即拒绝，随后岗位编辑、保存取消、返回首页和退出正常。

## 边界

不硬猜未知城市的代码，不在界面复制城市规则。本轮仅诊断，未改生产代码和v10包。
