# 13号项目改造：课件工作台（取数自动化 + AI 解析 + 程序出片）

## 意图

13号"客服培训课件制作"不能零 AI（培训内容不固定），但取数环节应像其他项目一样做成可双击启动的 TUI 自动化程序。目标流水线：

```
[程序] 取数（京东抓取 / 手动导入） → 标准聊天记录文件
[AI]   读标准文件 + 场景意图 → 产出"解析数据文件"（哪句可优化/错在哪/建议话术/要点）
[程序] 渲染 HTML + 铁律自检 → 成品课件
```

AI 从"每次全程陪跑"降为"只填可变内容（点评+话术）"，样式/渲染/自检全部程序化。

## 背景

- 京东抓取已有成熟经验：`kf.jd.com/chatLog/queryList.action`，单日查询，CDP 连已登录 Chrome（Chrome 调试端口 9222），`cdp_exec.js` 提供连接范式。
- 渲染模板已存在：`scripts/make_chat_demo.js`（就地解析、无目录、无结尾总结卡、客户ID脱敏+眼睛按钮等铁律）。
- 仓库政策：业务数据（聊天记录、成品、截图）不入 git 公开仓库，只保留源码 + `*.example.*` 模板。
- 用户补充：旧资料（scripts/旧成品/旧经验模板）在新链路跑通后移入项目内"历史资料备份"归档。

## 架构原则（参考 SoftTalk #2705）

- 真正的业务逻辑与界面分开：一件业务只保留一套实现。
- TUI 只负责输入输出；AI（含未来的无界面自动测试）直接调用同一套服务模块（src/services/*），不经过按钮/菜单。
- 不为架构增加多余层，不留新旧两套，不留测试专用旁路；验证尽量走真实文件读写（隔离目录）。

## 验收清单

- [x] TUI 主菜单：京东抓取 / 导入聊天记录 / 生成课件 / 文件管理 / 设置，样式对齐其他项目（独立最大化窗口启动.bat、chcp 65001）。
- [x] 京东抓取：配置持久化（CDP端口/标题匹配/接口地址，首次配好不再每次提供）；输入查询条件（客户pin/订单号/关键字，进 customer 参数）+ 单日；列出会话供选择；落盘为标准聊天记录 JSON（保留消息时间/角色/文本/图片 imgUrl）。
- [x] 手动导入：粘贴文本（`时间|客服/客户|内容`）或文件（txt / 京东原始 JSON / 标准 JSON），自动转换落盘同一格式。
- [x] 解析数据文件契约：`courseware-review/1`（title/sub/tagline + overlays 挂消息索引 + insights HTML），校验索引越界/重复/悬空 insight。
- [x] 渲染：读标准聊天记录 + 解析文件 → 生成课件 HTML（沿用就地解析单栏气泡样式、无目录、无结尾总结卡），图片自动下载内嵌、客户ID默认脱敏+眼睛按钮；失败项进入自检报告。
- [x] 自检报告：铁律逐条 ✓/✗（insight 数量与引用一致、无字面 `<br/>`、无乱码、顺序=真实顺序、图片全部内嵌等）。
- [x] `npm test`（node --test）覆盖：txt解析、京东原始JSON转换、review校验、渲染+自检全绿（14/14 通过）。
- [x] 文档：README（新 SOP+导入格式）、给AI的解析提示词模板（含铁律速览+契约示例）。
- [x] 旧资料归档：scripts/、旧成品、旧经验模板移入 `历史资料备份/`；根 AGENTS.md 重写为新链路；备份目录与 runtime 加入 .gitignore 不入库。
- [ ] 真机验证：需本机 Chrome 已登录京东后台 + 调试端口，跑通「京东抓取→AI解析→出片」全链路（本机无法代测）。

## 边界

- 第一版平台只做京东；平台选择留扩展位（platform 字段预留）。
- 聊天记录与成品只放本地 runtime/（gitignore 已覆盖），绝不入库。
- 不动"千店话术通"（京东机器人话术配置）等与课件无关的既有功能，仅归档。
- AI 解析质量不由本程序保证：程序只约束格式与铁律，点评水准依赖提示词与人的验收。
