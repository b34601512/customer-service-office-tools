# 16号项目备用调试端口未复用

## 意图与背景

用户要求进一步审查 v10。默认9222被其他服务占用时，登录可能成功启动9223，但下一次抓取仍从9222开始检查，未复用已记录的9223实例。

## 证据

- boss_cdp.py:113 ensure_edge_running只检查requested_port的cdp_ready，未检查_owned_edge_processes里已存在的实例。
- 登录与抓取入口都再次传biz.DEFAULT_PORT。
- 离线复现：模拟9223已就绪并在_owned_edge_processes登记，9222未就绪，调用ensure_edge_running(9222)仍执行Popen并选择9224。
- 新命令仍使用同一PROFILE_DIR。真实浏览器可能因同配置目录已打开而无法在新端口启动；这一浏览器后果未在真实环境执行，不能声称已实测。

## 验收清单

- [x] 定向证明未复用自身备用端口。
- [x] 登录和抓取复用统一的实际浏览器实例/端口。
- [x] 验证默认端口被占用时登录后抓取不重复启动浏览器。

## v0.10处理

ensure_edge_running优先验证并复用_owned_edge_processes中本程序已启动的端口，不扫描任意端口。
回归模拟9222不可用、9223已由本程序启动且就绪，连续两次调用均返回9223，Popen调用0次。

## 边界

不扫描或接管任意外部浏览器；不关闭非本程序拥有的进程。本轮仅诊断，未改v10包。
