# 终端可见字形列宽统一

## 意图

把客服列表已验证有效的“按完整可见字形计算终端宽度”迁移到办公软件目录内其他固定列 TUI，解决特殊符号、组合字符和表情导致的分隔符错位。

## 背景

已修复的客服超时督办按完整字形分段，再判断每个字形占 1 列或 2 列。盘点发现发票自动化、电话漏接分析、客服数据自动更新、店铺指标数据自动更新仍按码点或字符串下标计宽；组合附加符、肤色表情、ZWJ 表情会被重复计算或截断，发票项目还把 Windows Terminal 中按 1 列显示的歧义标点算成 2 列。

## 验收清单

- [x] 盘点办公软件目录内真正使用固定终端列的项目。
- [x] 发票自动化的全部子项目统一走现有共享宽度入口。
- [x] 电话漏接分析的 CLI/TUI 统一走同一宽度与截断入口。
- [x] 客服数据自动更新和店铺指标数据自动更新升级现有宽度入口。
- [x] 组合字符、肤色表情、ZWJ 表情、ANSI 颜色和歧义标点测试通过。
- [x] 截断后的单元格仍精确补到列宽，分隔符位置一致。
- [x] 各受影响项目的现有测试通过。

## 边界

- 不用固定昵称长度、删除特殊字符或错误宽度后的补偿作兜底。
- 每个可独立部署的项目只保留一个终端宽度真源，页面不各写一套。
- 不建立依赖 `D:\桌面\办公软件` 固定路径的跨项目运行时模块，避免便携包搬走即失效。
- 不修改网页、桌面 GUI 和没有固定列布局的普通 CLI。
- 不引入仅为极少见字符服务的第三方运行依赖。
- 不改业务口径，不覆盖其他 AI 或用户的未提交改动。

## 影响范围

- 已正确：`1.客服超时督办`。
- 已迁移：`2.发票自动化/共享CLI`、`5.电话漏接分析`、`9.客服数据自动更新`、`12.店铺指标数据自动更新`。
- 不适用：`3`、`4`、`7`、`8`、`10`、`11`（网页/GUI、普通菜单或无固定列终端表格）。
