## ② 规矩 / 口径（一句话 + 出处）
- **发消息目标必须当次现取**：先 `wecom-cli message aibot sessions list` → 用返回的 `chat_id`；不许手打/用历史 id → `README.md` §5。
- **默认私发黎路遥**；群 chat_id（`wr` 开头）**脚本默认拒发**，要发群得 `--允许发群` 且先问他（黎路遥 2026-10-01）→ [`规矩与红线.md`](../0.木婉清档案/规矩与红线.md) §七。
- **消息不能真 @人**（名字写正文）；**要真 @** 用群机器人 webhook（`发群消息.js --mention-user <userid> --send`）→ `每日自动化流程.md` §三·五。
- **拆条发**：多条短消息、成组加 `(1/3)(2/3)(3/3)`、每条完整句收尾；每条 ≤100 字；**一条消息只带一个问题**；贴原文全文、别只给摘要 → `规矩与红线.md` §七。
- 群内被 @ → 回在群里、开头 `@提问人`；不主动到没让发的群说话 → `README.md` §7。
- **永不发测试消息**（发企微=真发、没有 dry-run）；要验证通道只用只读手段 → `断点记录.md`（2026-10-08 教训）。
- 正文一律用「」，别用反引号/ASCII 双引号；读 offset 要**先写 offset 再发回复**（防跳消息）→ `README.md` §5。
- **长连接唯一**：每个机器人同时只允许一条有效长连接，别开多个守护（会顶掉旧的）→ `断点记录.md`。
- 授权：有人 @木婉清 → **可直接回复**；拿不准/涉红线/业务口径 → 问黎路遥；平台写入仍逐次授权 → `断点记录.md`（2026-09-30 授权）。
- 看门狗：只对**确定性故障**自动重启；**消息静默只报警**（前缀 `[通知]`，确定性才 `[故障]`）→ `README.md`/`断点记录.md`。
- **窗口心跳（2026-10-09）**：每窗写手 150s 一拍；挂窗自动判/自愈（监听窗重开、缺写手补挂），自愈失败才上留言板 → [`经验/窗口心跳与自愈.md`](./经验/窗口心跳与自愈.md)。

## ④ 常用命令
```bash
cd "27.企业微信机器人"
npm run 守护                                   # 常驻收消息（只收不回）
node scripts/读新消息.cjs                      # 唤醒后读全文（ms→游标，不漏不重）
node scripts/发企微消息.cjs --chat-id "<当次现取>" --file 正文.md   # 发前先问；别手拼 JSON
node scripts/写售后待办.cjs --content "…" --owner auto            # 挑不到就 --owner <userid> 并停下问人
node scripts/检查企微环境.js                   # 只读体检（skill/cli/auth）
npm run 看门狗:装 / 看门狗:卸                    # 看门狗计划任务（wecom-daemon-watchdog）
npm test                                       # 单测（含反向断言）
```

## ⑤ 红线
- **扫码/输 Secret 必须本人**；窗口留可见；webhook/Secret/chat_id **不进 Git**、输出里不出现内部 ID。
- 任何真实发送先问用户（有人 @ 的回复除外）；不做测试发送；不自动重试（限频 45009 等人确认）。
- 别杀 `WindowsTerminal`（杀了它所有 pi 窗口全退）；只关具体 pi 进程。
