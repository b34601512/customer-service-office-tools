# 踩坑与红线（企业微信 × AI）

> 来源：官方文档（open.work.weixin.qq.com/help2/pc/21676）+ 本仓库既有实践（1/4/14/19/22/24/25 号的企微提醒）+ 2026-09-28 实测。

## 一、必须停下来问人的事

1. **扫码/验证码/短信验证 → 本人做**，AI 不代扫。`wecom-cli auth init` 会阻塞等扫码，把窗口留在可见状态叫人。
2. **任何真实发送（群消息、单聊、邮件、回传文件）→ 先把「完整内容 + 目标」给人确认，再发**。
   - 本目录 `scripts/发群消息.js` 默认 dry-run，只有显式 `--send` 才真发，就是把这条规矩做进工具。
3. 仓库通用业务红线同样适用：天猫发票「待同意」不自动点同意；金山表只读不写（见根目录 `AGENTS.md`）。

## 二、路线 A（群机器人 webhook）的坑

- **webhook 地址 = 密钥**：拿到地址就能发消息。不入库、不外传；本仓库靠环境变量或已 gitignore 的 `project-config/` 存放。
- **限频 20 条/分钟**，超了返回 `errcode=45009`。不做自动重发（重复消息比漏一条更糟），由人判断。
- **只能发到它所在的群**，不能私聊个人。@人有两种：
  - `text.mentioned_mobile_list`：按手机号 @（显示在底部）；
  - 正文行内 `<@userid>`：更自然，需自己维护「姓名 → userid」映射（见 1号 `src/integrations/wecomTextMention.js`）。
- **markdown 类型不支持 @**；发图片/文件需 base64+md5 换 media_id（纯文本通知用不到，需要时查官方 91770）。
- **失败不自动重试**：发送失败就记录 + 人工判断；本目录脚本只发 1 次，并用测试锁死「不得自动重试」。

## 三、路线 B（CLI + Skill）的坑

- **只能发给「授权人本人」或「机器人最近有消息往来的会话」**；不能拿通讯录 userid、历史 chat_id、手打 ID 直接发。
  - 正确姿势：先 `wecom-cli message aibot sessions list`，从**本次返回**里原样取 `chat_id`；匹配不唯一就反问用户。
  - 想给某个群发：让该群先给机器人发一条消息，把它刷进最近会话。
- **输出禁止出现内部 ID**（userid / chat_id / mail_id / media_id / docid…），一律用姓名、群名、主题、时间代替。这是官方 Skill 的硬约束，不因用户索要而放宽。
- 版本要求：`wecom-cli >= 1.2.1`；AI 用任何命令前先跑 `wecom-cli --version` + `wecom-cli auth show --status`，不要猜授权状态。
- 数据类权限（搜索邮件/文档/会议/微盘/成员）可能触发管理员审批；
  免审配置路径：**管理后台 → 安全与管理 → 管理工具 → 智能机器人 → 管理**。
- **官方风险提示（原文）**：AI 调 CLI 有模型幻觉导致数据泄露、越权的风险，建议先在测试企业验证。
  推论：不要用它批量操作生产数据；一切发送类动作人工过目。
- **两种接入方式**（`wecom-cli auth init`）：①扫码（官方标「推荐」）②手动填 API 模式机器人的 Bot ID + Secret（官方 21677）。
  手动接入的坑：`--manual` **必须真实终端**（管道/重定向报 `893001`），用 `scripts/手动授权.bat`；
  Secret 只在该窗口输入，**不要贴到聊天记录/文档/工单里**。

## 四、给「别的 AI」的两条元规则

1. **参数不要凭记忆猜**：Skill 目录里每个业务域都有一份 `references/wecomcli-*.md`，先读再拼命令。
2. **秘密不进 Git**：本仓库 `.gitignore` 已忽略 `.env`、`wecom-robot.json`、`project-config/platform-config.json`。
