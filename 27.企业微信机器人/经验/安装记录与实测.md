## 实测 4：手动接入的 TTY 限制（重要坑）

CLI 支持两种接入（官方 CLI 参考）：扫码（推荐）/ 手动输入 Bot ID + Secret。手动接入的实测：

```bash
printf 'bot-id\nsecret\n' | wecom-cli auth init --manual
# → {"error":{"type":"ValidationError","code":893001,
#     "message":"手动输入需要终端，非交互环境请使用 --noninteractive 直接扫码接入"}}
```

- 管道/重定向输入不行（要求真实 TTY，实测 code `893001`）；
- `winpty <真实 exe> auth init --manual` 在 AI 的非交互环境里也拿不到 tty（报 `stdin is not a tty`）；
- **结论**：手动接入必须在真实控制台窗口里做 → 本目录备好了 `scripts/手动授权.bat`（双击运行）。

官方取 Bot ID/Secret 步骤（文档 21677，原文 5 步）：工作台 → 智能机器人 → 创建机器人 → 手动创建 →
**API 模式** → 连接方式选「**使用长连接**」→ 复制自动生成的 **Bot ID** + **Secret** → 补可见范围后保存。

## 实测 5：手动接入成功（2026-09-28）

- `wecom-cli auth show` → `Status: authorized`（Bot ID 属凭据信息，不记录进仓库）
- `wecom-cli identity whoami` 只读验证通过：返回机器人身份 + 授权真人身份（含内部 ID，按官方约束不外露）
- `wecom-cli message aibot sessions list` → `sessions_count: 0`：**机器人还没有任何会话往来**。
  此时只能给授权人本人发消息；要给群/别人发，先让该群/人给机器人发一条消息，把它刷进最近会话。
- 体检脚本复跑：Skill OK / CLI OK / **authorized**；仅剩 webhook 未配置（路线 A 才需要）。

### 手动接入步骤（回顾）

1. **扫码接入**：终端里跑 `wecom-cli auth init` → 二维码 → 本人扫码（5 分钟超时）；或
2. **手动接入（API 模式）**：先在企微客户端建好长连接机器人拿到 Bot ID + Secret，
   再双击 `scripts/手动授权.bat` 输入（密文不回显、不进聊天记录）。✔ 本机走的这条。
