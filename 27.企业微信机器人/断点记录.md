```bash
cd 27.企业微信机器人

npm run 守护:自检             # 认证+订阅自检，成功即退
node scripts/跟读收件箱.cjs   # 挂在 Monitor 上跟读新消息（开机窗自动挂）
```

## 发消息正文的引号/符号（2026-10-08 踩坑）
- **正文一律用「」，别用反引号或 ASCII 双引号**：反引号会被 shell 当命令替换（实例：正文里写 `links.local.json` → 消息里变成「（ 里）」）；ASCII 双引号会被吞、消息截断（2026-10-08 也踩过）。

## 别跑「测试发送」（2026-10-08 19:5x 教训）
- **发企微 = 真发，没有 dry-run**：任何时候都不要为了"试试脚本通不通"发 test 类消息（可能落到真人）。
- 事故复盘：主窗把两发消息塞进**一条**命令、且第一发误写错 chat_id（`woFqeqk…`）→ 现场只看到一行「发送成功」，分不清是哪一发。查证：错 id **不在会话列表**、会话列表也**没有新增任何会话**（黎路遥那条 19:53:44 = 真正的回复）→ 判定 `test` **未送达任何人**。
- 规矩：**一发一条命令**、发完核对；要验证通道就用**只读**手段（会话列表/回读），不要发消息试探。
