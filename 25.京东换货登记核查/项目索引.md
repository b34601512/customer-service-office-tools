## 一、这个项目干嘛的
京东「**上门换新**」订单（京东仓直接换新机、平台实付 ¥0）——客户那台故障机要寄回我们工厂，客服必须在金山《湖南怀化售后对接表》→「**换货维修登记表**」登记。本项目**只读检查**：找出「没登记」和「登记不规范」的单，出报告 + 发群话术（**发出去前先问用户**）。

## 二、规矩 / 口径
- **要防的是「填多了」——空着没事**（用户 2026-09-27 拍板）：
  - ✅ 规范 = **客户地址列空** + 三个选项列（质保标准 / 客户寄给厂家的运费 / 厂家寄给客户的运费）**空或「无需处理」**；
  - ⚠ 有风险 = 地址列填了内容（工厂可能照着又寄一台）；🟡 待核 = 选项列填了「无需处理」以外的值；⚠ 未登记 = 表里没这单。
- 「上门换新取件」不是商品名/服务标签（标签叫「可能上门换新」）→ 只能按行里 `pickWareFacetDTO.pickWareTypeName == "上门换新取件"` 本地筛。
- 金山「换货维修登记表」2.8 万+ 行，网页端只读前 1.85 万行 → 用 **AirScript 按订单号查行带列号**（`kdocs-scripts/AirScript-只读查行带列号.md`，2026-09-27.3）；没配 webhook 会退回老脚本并标「**粗判**」——**粗判不能出结论**。
- 时间窗默认**最近 3 个月**（用户已拍板）；判定逻辑 `src/features/exchange/registrationCheck.js`，被 `tests/exchangeRegistration.test.js` 锁死。
