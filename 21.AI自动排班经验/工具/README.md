# 工具（单一用途，可组合）

排班**不做一键脚本**。需要动手时按需挑一个跑：每个工具只干一件事，中间产物是 JSON / TSV，
方便人工看一眼、替换、重跑——**脚本是手脚，不是模板**。

| 工具 | 用途 | 读写 |
| --- | --- | --- |
| `读排班表.py` | 读一份排班 xlsx（或 TSV），打印结构 / 班次 / 底色 / 每日覆盖 | 只读 |
| `验排班表.py` | 按 `验收清单.md` 逐项判：跨月、覆盖、晚接早、连上、值班、底色、统计公式 | 只读 |
| `写排班表.py` | 把「计划 JSON」写回 xlsx：班次 + 底色 + 公式统计 + 缓存值 + TSV | 写 |
| `对比排班表.py` | 对比两张表（改前/改后、AI 版/人工版、快照对真表）：班次/底色/覆盖/统计/值班次数 | 只读 |
| `解排班示例.py` | 2026-10 案例的求解过程（**模板**：下月复制，改顶部「案例配置」） | 只读，输出计划 JSON |
| `推应休天数.py` | 从上月表「星期行周六红标」推本月大小周休息天数（法定节假日仍要问人事/用户） | 只读 |
| `AirScript-写售前排班.txt` | 在线写入脚本：粘贴到金山排班表文档的「文档共享脚本」（写售前 5 人名单内的班次 / 值班底色 / 只读诊断） | 模板 |
| `写在线排班表.cjs` | 调 AirScript 把售前排班写进在线表（只写目标月表售前 5 人；写后在线回读+保存） | 写在线 |
| `写在线值班底色.cjs` | 调 AirScript 把售前值班浅绿底色写进在线表（只写目标月表 duty 指定的值班格；写前核对班次、写后回读+保存） | 写在线 |

## 在线写入（金山排班表，AirScript 通道）

排班表在金山在线文档里，**本地 xlsx 工具只是对拍样例**。要在线上表写班次，走 AirScript（复刻 9 号项目 `9.客服数据自动更新/src/kdocsSync` 的「文档共享脚本 + 同步 webhook + AirScript-Token」机制）：

1. **一次性准备**（在排班表在线文档里）：新建「文档共享脚本」→ 把 `工具/AirScript-写售前排班.txt` 全文粘进去 → `Ctrl+S` 保存；为该脚本生成**脚本令牌**、复制**同步 webhook**（形如 `https://www.kdocs.cn/api/v3/ide/file/<file_id>/script/<script_id>/sync_task`）。脚本升级过版本：在线报「脚本版本不匹配」时，把该文件全文重新粘贴覆盖保存即可。
2. 把 webhook 和令牌填进 `project-config/platform-config.json`（模板见 `platform-config.example.json`；**该文件已 gitignore，令牌等同密码，不入库、不打印**）。
3. 写入（**先 `--dry-run` 看一眼载荷；真正写入前必须用户批准**）：

```powershell
cd "D:\桌面\办公软件\21.AI自动排班经验"
node "工具\写在线排班表.cjs" --plan "测试数据\2026年10月-计划.json" --sheet "2026年10月" --dry-run
node "工具\写在线排班表.cjs" --plan "测试数据\2026年10月-计划.json" --sheet "2026年10月"

# 售前值班浅绿底色（计划 JSON 的 duty 字段；同样先 dry-run / diagnose，用户批准再写）
node "工具\写在线值班底色.cjs" --plan "测试数据\2026年10月-计划.json" --sheet "2026年10月" --dry-run
node "工具\写在线值班底色.cjs" --plan "测试数据\2026年10月-计划.json" --sheet "2026年10月" --diagnose
node "工具\写在线值班底色.cjs" --plan "测试数据\2026年10月-计划.json" --sheet "2026年10月"
```

边界与验收：
- 在线脚本**只认售前 5 人名单**（韩欢欢/麦诺谦/叶炳辉/徐佳楠/刘秀文）：班次操作只写他们那一行的 `C..(天数)` 列（不改底色）；**值班底色操作只写 `duty` 指定的值班格**（写前逐格核对「当前班次 = 值班班次」，不符一格都不写），两者都**不改统计列、不碰其他月表**。
- 在线脚本写后会**回读校验 + Save**，并把版本/行地址/格数/校验和返回给本地工具核对；失败**不自动重试**。
- 写完用 20 号只读脚本读回对拍（值+底色），确认只有目标月表售前区域变化。

## 典型组合（排新月份）

```powershell
cd "D:\桌面\办公软件\21.AI自动排班经验"

# 1) 先看现状/上月 + 推本月大小周（应休的法定节假日部分要问人事/用户！）
python "工具\读排班表.py" --xlsx "测试数据\2026年10月客服排班表.xlsx"
python "工具\推应休天数.py" --prev "上月表.xlsx"            # 出本月 weekend_red_days + 大小周天数
python "工具\推应休天数.py" --prev "上月表.xlsx" --holidays 3  # 问过人事后带上节假日天数

# 2) 求解：复制 解排班示例.py 改配置（上月末状态、休息、政策休息天数 = 大小周+节假日、weekend_red_days），输出计划
python "工具\解排班示例.py" --out "测试数据\2026年11月-计划.json"

# 3) 写回表（值+底色+公式统计+缓存值+TSV）
python "工具\写排班表.py" --xlsx "测试数据\2026年11月客服排班表.xlsx" `
    --plan "测试数据\2026年11月-计划.json" --tsv "测试数据\2026年11月客服排班表.tsv"

# 4) 验收（✗ 必须清零，再到 验收清单.md 勾人工项）
python "工具\验排班表.py" --xlsx "测试数据\2026年11月客服排班表.xlsx" `
    --prev "…\2026-10-31-2026年10月.tsv" --lead 李守耀

# 5) 改过表？和改前/上一步对拍，确认只改了你想改的
python "工具\对比排班表.py" --a "改前.xlsx" --b "改后.xlsx"

# 6) 改了校验工具？拿反例表回归一遍（该抓的一个都不能漏）
python "工具\验排班表.py" --xlsx "测试数据\反例\bad.xlsx"  --lead 李守耀   # 期望 14 项 ✗
python "工具\验排班表.py" --xlsx "测试数据\反例\bad5.xlsx" --lead 李守耀   # 期望  8 项 ✗（大小周/横幅）
python "工具\验排班表.py" --xlsx "测试数据\反例\month30.xlsx" --lead 李守耀 # 期望 30 天全过
```

## 计划 JSON 格式（`写排班表.py` 的输入）

```json
{
  "meta": {
    "days": 31,
    "policy_rest": 6,
    "policy_note": "大小周",
    "lead": "李守耀",
    "carry": {"韩欢欢": "0", "缪婷婷": "-1天"},
    "annual": {"韩欢欢": 0, "麦诺谦": "1天3小时"},
    "codes": {},
    "weekend_red_days": [4, 10, 11, 18, 24, 25],
    "month": "10月",
    "white": ["麦诺谦|15"],
    "carry_width": 4
  },
  "seller": {"韩欢欢": ["早", "早", "晚", "", "…31 个…"]},
  "after":  {"李守耀": ["", "早", "早", "…31 个…"]},
  "duty":   {"韩欢欢|1": "早", "刘秀文|1": "晚"},
  "duty_after": {"邓远祥|1": "早", "柯紫婷|1": "晚"}
}
```

- `seller` / `after`：每人一格，`""` = 休；长度 = `days`。
- `carry`：**上月结转的剩余假**（数字 = 天数，或 `"3天4小时"`/`"-3小时"`）。工具会算 **剩余 = 上月结转 +（本月应休 − 实休）× 8 小时**，写成 `x天x小时`：**少休要补回来**（实休 5、应休 6 → +1 天，不欠他的），**超休写负数**（自动加「（下个月）」，下月扣）。
- `annual`：**上月结转的年假余额**（如 `"1天3小时"`），原样写进年假列（不是本月计数；本月真休了年假要自己扣）。
- `codes`：特殊标记（如 `"缪婷婷|8": "行"`）。**「行」日常排班不要排**（一般只在新员工入职时人工安排），排了就是多一个人上班（扎堆）；只有确实需要时才写。
- `weekend_red_days`：**星期行要标红的日期**（大小周：周日永远红 + 大周的周六红；字体颜色）。用 `工具/推应休天数.py` 从上月表推出来，可直接粘。不写则星期行不动。
- `month`：月份横幅文字（如 `"10月"`）；不写就从标题「2026年10月客服排班表」里取。写表时会把 1 号~当月最后一天在横幅行上**合并成 1 格**（红底白字，避免客服看错月份）。
- `duty`：售前值班（浅绿），键 `姓名|日`，每天早、晚各 1 人。
- `duty_after`：售后值班（浅蓝），键 `姓名|日`，**每班只 1 人**；**组长上班时早班名额是他的，不用列进来、也不涂色**（真表他那一行就是白底），所以组长在班的日子这里只会有晚班那 1 条。
- `carry_width` 可省略：省略时剩余列宽**跟随每日排班的格宽**（默认取列 C）。
- 2026 年 10 月的成品计划在 `../测试数据/2026年10月-计划.json`，可直接拿来试跑。

表里颜色含义（写表工具按这个涂）：
| --- | --- |
| 绿 `E2F0D9` | 售前值班：每天早、晚各 1 人 |
| 蓝 `BDD7EE` | 售后值班：每班只 1 人（组长上班时早班名额是他的，**不涂色**） |
| 白 `FFFFFF` | 无标记（售后非值班格、组长在岗格） |

> 黄/浅蓝/橙底（`FFFF00`/`DEEBF7`/`FBE5D6`）**不排**：那是**人工手标**的（真表里只出现在休息格上，如临时请假），排班工具不涂也不判（验收工具看到只会 info 提一句）。

## 注意

- 工具是幂等的：同一份计划重跑，结果一样。
- `写排班表.py` **直接改原表**（就地写）；跑前先备份，或在 git 里确认有 TSV 兜底。
- 「剩余」列是**结转值**（上月剩余 + 应休 − 实休，含小时折算）；「年假」列是**上月结转的余额**。两列都是值/文本，工具不猜、也不改你的写法（只把列宽设成跟每日排班一样）。
- 统计列写公式的同时会写入**缓存值**，这样不重算的程序（openpyxl 等）也能读到数字；
  用金山 / WPS / Excel 打开时会自动重算（表里已置 `fullCalcOnLoad`）。
