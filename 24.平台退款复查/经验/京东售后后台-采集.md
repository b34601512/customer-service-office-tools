## 二、判漏口径（与天猫同理）
- **「即将超时」= 0 且「待处理」= 0** ⟹ 没有临近超时/积压的售后单 = 售后无漏；
- **「待收货」** = 客户已寄回、等商家签收（在途，不算漏）；「催收」= 催客户寄回，同样不算漏；
- **纠纷**：看 待回复 / 待举证 / 待执行 三个 tab，每单带「还剩X小时Y分」——**未到期不算漏，但要在时限内处理**。

1. **一个店一条通知，不合并**（用户原话：「一个店一个店通知，别攒到一起通知，不然阅读压力很大」）；
2. 消息**必须带店名**（如「【京东1店 · 德达官方旗舰店】」），让人一眼知道是哪家店；

5. 发之前先 `--file` 预演，确认无误再 `--send`（企微发送要用户点头）。

## 十二、漏退回复查必须查的三个来源（2026-09-27 教训：少查一个就把安全的判成风险）

京东「仅退款 + 已出库」的单，要判「货有没有回来」，**三个来源都要查**（按顺序，先便宜的）：

| 顺序 | 来源 | 命中含义 | 怎么查 |
| --- | --- | --- | --- |
| ① | **京东仓退货表** | 已退京东仓 = 安全 | `src/tools/jd-warehouse-returns.js`（本地 JSON，12h 缓存） |
| ② | 金山《售后对接表》 | 已登记退货 = 安全 | `kdocs-query.js`（AirScript 全表，10 个关键词/批） |
| ③ | **金山《撕单表》** | 「已撕」= 货没发走 = **安全** | `src/features/review/tornSheet.js`（网页整表 5606 行，12h 缓存） |
| ④ | ERP（只查 ①②③ 都没命中的） | 作废 = 安全 | `erp-order-status.js` |

**为什么第③步容易漏**：撕单是**仓库/客服在金山登记的动作**，平台侧完全看不到；
京东后台这单显示「已出库」，但快递面单被撕掉、货根本没发走 → 货其实还在仓库。

**实测数字（2026-09-27，五店 440 单）**：
- 京东仓 287 / 怀化表 109 / 撕单表 28 → **三处都没命中只有 16 单**（¥4,474）
- 这 16 单再查 ERP：1 单已作废（安全）、15 单已发货 → 重点看 15 单（¥4,392）
- 只查京东仓+怀化表时会得出「44 单漏退回」，**多报 28 单**（全是撕过单的）

**撕单表结构**：`matrix`（不是 rows），17 列；「平台单号」列可能塞多个单号（用 `、` `，` `/` 空格分隔）→ 要拆开逐个归一化比对；
「撕单状态」是自由文本（已撕 / 货发走了，通知客服拦截 / …），**原文交模型读，脚本不判关键词**。

| 物流状态 | 含义 | 怎么办 |
| --- | --- | --- |
| **运输中** | 包裹在途 | **不用管**（等它到，到了会进京东仓或怀化表） |
| **物流异常** | 运输异常/拦截/停滞 | **不用管**（同上，还回来的路上） |
| **拒收** | 客户拒收，往回走 | **不用管**（同上） |
| **已出库** | 只是出了库，没有后续 | 不用管（含「邮费补差」这类无实物单） |
| **已签收** | **货在客户手里** | ⚠ **真风险**：客户签收了又仅退款、货没退回来 → 要追 |

判定做成纯函数 `src/features/review/deliveryState.js`（`classifyDelivery`），
反向断言测试 `tests/deliveryState.test.js` 把「在途=不用管、已签收=风险、未知状态不许放过」钉死。

**字段从哪来**：京东自主售后列表响应里现成就有，**不用另外查询**：
```
deliveryWareFacetDTO.deliveryWareStateName          // 运输中 / 物流异常 / 已签收 / 拒收 / 已出库
deliveryWareFacetDTO.deliveryWareLogisticsFacetDTOList[].logisticsTrackFacetDTOList[]
    → { title: "运输中", processInfo: "您的订单已到达京东【湛江赤坎站】", processDate }
```
采集工具 `jd-refund-list.js` 已把它提成顶层字段 `deliveryState` / `deliveryStateName`；
老清单没有这个字段时，`scripts/复查京东仅退款.js` 会从原始行 `raw` 里兜底取。

**实测（2026-09-27 京东仅退款五店 440 单）**：
- 京东仓 287 / 怀化表 109 / 撕单表 28 → 三处都没命中 16 单
- 这 16 单：ERP 已作废 1（安全）、**在途 13（不用管）**、**已签收 2（真风险，¥36 + ¥13）**
- 结论：加了这一步，真正要追的从「15 单 ¥4,411」缩到 **2 单 ¥49**（都是小配件）
