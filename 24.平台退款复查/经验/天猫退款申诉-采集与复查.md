# 天猫退款申诉页：怎么采集待申诉订单（2026-09-27 实测）

## 一、入口与登录
- 页面：`https://qn.taobao.com/home.htm/appeal/portal/appealable/D/1`
- 登录态：复用天猫店铺 profile（本项目 `runtime/state/browser-profiles/tmall/<店>`，从 22号 拷来）。
  失效时跑 `node src/tools/tmall-login.js --store tmall1`：账号密码**运行时**从 9号/12号 的
  `project-config/platform-config.json` 读（用户 2026-09-27 明确"直接从别的项目复制"）。
- 三店实测都能自动填表登录，无滑块；tmall1=9441 / tmall2=9442 / tmall6=9443。

## 二、类型 tab（四个）
| tab | 字母 | 实测 |
| --- | --- | --- |
| 纠纷 | D | 三店都有待申诉单（tmall1 12 / tmall2 13 / tmall6 2） |
| 赔付 | P | 三店均 0 |
| 处罚 | C | 三店均 0 |
| 投诉 | T | 三店均 0 |

**坑（实测）**：直接 `goto /appealable/P/1` **不会切换 tab** —— 微应用加载时默认还是 D，
所以 P 页返回的却是 D 的数据。**必须点页面上「纠纷/赔付/处罚/投诉」文字元素**，
页面才会发 `appealSource=<字母>` 的请求。

## 三、数据来源 = 页面自己的 mtop 接口（别逆向签名）
- 列表：`mtop.taobao.appealcenter.list.get`，请求 data：
  `{"pageNo":1,"pageSize":10,"serviceName":"taoBao","appealStatus":"appealable","appealSource":"D"}`
- 计数：`mtop.taobao.appealcenter.list.count.get` → `{appealableCount, preparingCount, processingCount, endCount}`
- 采集方式（`src/tools/tmall-appeal-list.js`）：让页面自己加载/点 tab/点「下一页」，
  我们从 `page.on('response')` 里原样取 JSON。**不要自己拼 mtop 签名**。
- **翻页坑**：点下一页后接口返回的 `resultData.pageNo` 仍是 1（服务端 bug），
  不能靠 pageNo 判断翻页成功；要用「点击后是否出现新的 list 响应 + 有没有新条目」判断。

## 四、字段含义（判货物安全只用这几个）
| 字段 | 含义 |
| --- | --- |
| `objectId` | 退款编号 |
| `relatedObjectId` | **订单编号** ← 去 ERP / 金山核对就用它 |
| `handleType` | 退货退款 / 仅退款 / … |
| `violationType` | 纠纷申诉 / … |
| `appealTime` | 处置时间（退款结束时间） |
| `leftTime` | 可申诉剩余毫秒（÷3600000 = 小时） |
| `disputeId` | 纠纷 ID |
| `supportAppeal` | 是否可发起申诉 |

## 五、页面上的辅助信息（不用点进去）
- 顶部看板：待申诉/待举证/审核中/已完结 计数；
- 「编号搜索」可按编号搜；「退款结束时间/申诉提交时间」筛选；
- 列表操作列有「我要申诉」——**红线：24号 不自动点它**。

## 六、命令
```bash
node src/tools/tmall-appeal-list.js --store tmall1 --tabs D,P,C,T
# 产物：runtime/tmall/申诉清单-<店>-<时间>.json
```
