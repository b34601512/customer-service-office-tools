# 超时自动转接值班售前

## 意图

运营账号负责接待的客户，在首次超时或 10 倍阈值漏回复时，若当前处于售前工作时间，自动转给当日排班表中标记背景色的值班售前。

## 背景

- 当日值班售前以排班表单元格背景色为唯一标记依据。
- 多名售前均有背景色时，按排班表从上到下的顺序取第一名。
- 当前排班表已能读取单元格有效背景色；2026-09-09 早班验证结果为叶炳辉。
- 现有超时提醒、计时、绩效归属和人工转接监控需要继续保留。

## 验收清单

- [x] 读取排班单元格有效背景色，并按排班顺序选首个有色售前。
- [x] 首次超时和 10 倍漏回复均触发自动转接判断。
- [x] 颜色读取失败、无值班目标或转接失败时，继续原有提醒。
- [x] 不重置待回复计时，不改变原运营账号绩效归属，不触发现有人工转接提醒。
- [x] 配置、业务策略和接口适配分层；补充单元测试与定向验证。

## 落地记录（2026-09-16，扩展为通用转接引擎）

**根因**：原实现走 `POST /api/chat/assign`，该路径从未存在（2026-09-16 09:19 实测 HTTP 404）→ 自动转接从未成功。平台把“分配会话”做成 **socket.io 事件**：页面只有一条 `wss://<域名>/ws/socket.io/`，上面挂 `/client`（聊天与分配）与 `/notify`（只收通知）两个命名空间，事件帧形如 `42/client,["assignChat",...]`；已用只读探针实测捕获真实帧。

**现在生效的口径**：

- “没上班” = 排班休息/年假/无班次，或当天班次与当前应值班次不符（如 10:00 排晚班、17:00 排早班）；**运营账号一律按不在班**。
- 目标 = **同组**（售前→售前、售后→售后，绝不跨组兜底）+ 当天该班次 + 有值班背景色 + **在线**（售前看「可被转接」、售后看「自动分配」），按排班表从上到下取首个可用。
- 无可用目标（没人开开关/没人有背景色/背景色读不到）→ 不转并向主管告警；非工作时段（售前 23:45 后、售后 22:30 后）不转也不发群。
- **指令发出 ≠ 成功**：发帧后按联系人快照核对 `assignedTo` 真的变成目标才算成功，成功发群简报、失败@主管，杜绝“转失败了谁都不知道”。
- 在线数据来自上班监控每轮发布的共享快照（TTL 90 秒），转接策略只读快照，不重复读页面。

**验收（应有 vs 实有）**：
