# 客户明确解决应关闭待回复责任

## 意图

客户明确表示问题已经解决时，真正关闭此前的待回复责任；不能依赖后续 AI 客套回复结案。

## 背景

- 「兔子么么哒【客户】」在人工排查后回复「嗯找到问题了」「谢谢」，AI 随后回复「不用客气」，现场却仍产生漏回复提醒。
- 「德行天下」收到客服「我帮您跟领导反馈一下看看吧」后回复客套话，但申请结果仍未反馈，必须继续督办。
- 现有客户弱收尾规则只是不新增责任，不能表达“客户主动关闭旧责任”。

## 验收清单

- [x] 客户命中“明确解决”配置时关闭当前待回复责任。
- [x] 客户弱收尾只忽略自身，不关闭已有待办。
- [x] 客服承诺向领导反馈按临时回复处理，继续计算漏回复。
- [x] AI/机器人客套回复始终不能结案。
- [x] 两段现场会话回归结果分别为“已结案”和“继续漏回复”。
- [x] 自动化测试通过。

## 边界

- 不让 AI 回复成为正确回复依据。
- 不把所有“谢谢/好的”升级为结案，避免掩盖尚未完成的反馈或申请。
- 业务裁决只保留在统一待回复责任状态机，Web/TUI 仅维护同一份关键词配置。

## 验证记录

- 现场回放：「兔子么么哒【客户】」= 已结案；「德行天下」= 临时回复后继续督办。
- `npm test`：345 项通过，0 项失败。
- `git diff --check`：无差异错误，仅有仓库既有的 LF/CRLF 提示。
