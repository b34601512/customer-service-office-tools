# 已读与 AI 不得改变待回复责任

## 意图

超时只由真实人工回复改变；客服标记已读或平台 AI 回复不能逃避配置好的提醒。

## 背景

现策略把“出现过人工事件”当成首次响应，并把“AI 回复后人工标记已读”直接结案。定向测试确认这正是当前明确写入代码的行为。

## 验收清单

- [x] 已读事件在消息标准化层按系统消息过滤，不进入业务状态。
- [x] AI 回复不算人工回复，也不能结案。
- [x] 标点、表情及无效占位不能跳过首次超时。
- [x] 配置内“稍等”等真实临时回复只免首次超时，仍计算漏回复。
- [x] 只有人工实质回复才能结案。
- [x] 删除已读和 AI＋已读的特殊分支、字段与旧测试口径。

## 边界

- 不保留旧行为兼容分支。
- 消息接口是真源；界面和提醒工作流不得另写业务判断。
- 不覆盖当前工作区内其他 AI 的未提交改动。
