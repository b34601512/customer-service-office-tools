# 绩效累计与平均按漏回复时长封顶

## 意图

单个客户长期漏回复不能无限拉高客服累计与平均超时，导致报表失去横向参考价值。

## 背景

- 绩效账本按事件保存首次超时阈值；生产账本现有 86 次超时均保存为 150 秒。
- 漏回复阈值的唯一业务规则是首次超时阈值的 10 倍，因此当前单次计分上限为 1500 秒（25 分钟）。
- 现报表把未解决事件持续累计到当前时间，最长一笔已超过 11 小时。

## 验收清单

- [x] 每次事件对累计超时的贡献不超过该事件当时的漏回复阈值。
- [x] 平均超时基于封顶后的累计值计算。
- [x] 最长单次保留真实时长，用于识别严重漏回复。
- [x] 汇总累计与按累计排序复用同一封顶口径。
- [x] 报表明确展示封顶口径，避免累计小于最长时产生歧义。
- [x] 定向自动化测试通过。

## 边界

- 不新增绩效专用配置；复用漏回复阈值唯一业务规则。
- 不改写历史账本，报表读取时计算。
- 不封顶超时次数和最长单次真实值。
- 不覆盖当前工作区内其他 AI 的未提交改动。

## 验证记录

- 绩效与 TUI 定向测试：26 项通过，0 项失败。
- 生产账本复算：86 次超时均带 150 秒事件阈值；封顶后无单次贡献超过 1500 秒。
- 当前最大异常客服的累计由 `24:35:12` 降为 `01:40:28`，平均由 `59:00` 降为 `04:01`，最长真实值仍为 `11:23:53`。
