这个项目通过「本地控制台」启动独立 Microsoft Edge，无头后台监控，人工登录时才显示浏览器。无需 Chrome，业务规则与界面分离。

## Edge 版本与分享

- 本机从旧版升级后需重新「首次登录」一次；旧 Chrome 资料目录保留，不会迁入 Edge，也不会被清理。
- 控制台继续显示客户倒计时、实时日志和资源使用。无头不是免浏览器，也不保证修复网络白屏或显著提速。
- 分享给其他主管时，只分享新生成的干净分享包；不要直接压缩正在使用的项目。分享包内含 Node 和依赖，不需收件人安装 Node、npm 或 Chrome。
- 新主管首次登录后，在「4 配置」填写主管姓名、自己的排班表链接，在「5 企微」填写通知群及同名主管/客服成员信息，再后台启动。排班表须符合现有月份工作表和人员班次格式，不能接受任意表格。
- 目标环境为 Windows 11 x64 + 现代 Edge；Windows 10 的具体版本还需实机验证，不能保证老旧、精简版或企业策略受限系统可用。
- 开发环境先 `npm ci`；制作分享包：`node scripts/build-portable.js <输出父目录> --node-license <当前Node版本官方LICENSE文件>`。每次创建新目录，不覆盖旧分享包；Node 许可证随包提供，Playwright 自带许可证保留。
- 开发源码验证用 `npm test`，测试会复制到临时目录运行，不读写真实 runtime。不要直接在生产目录执行 `node --test`。历史3项失真断言已修正，完整回归379项通过，见 issues 010–014。分享包不含开发脚本和测试。

持续监控主管端真正关心的四件事：

1. 当同一客户连续达到平台超时阈值后，以联系人接口的 `assignedTo` 作为当前接待唯一依据，并向企微群发送升级提醒；未分配时由主管认领。
2. 当客户被重新分配/转接给新的客服后，独立监控页会直接识别分配状态变化，并在群里提醒被分配客服及时回复。
3. 从上次结案后的首条需处理客户消息开始计时；客户追问、已读和 AI 回复都不重置责任，只有人工实质回复或客户明确表示问题已解决才能结案。
4. 下班监控启动后立即检查一次，之后默认每 5 分钟检查今天和昨天的排班，只要客服不在其上班时间窗内（上班开始前或下班后），就自动静默关闭「自动分配」和「可被转接」开关，避免客户转给未到岗的晚班客服后无人回复；即使第二天才启动，也能补处理前一天漏关的客服。

## 使用步骤（TUI 终端界面，推荐）

1. 双击「启动中心.bat」，会弹出一个控制台窗口，进入终端界面。
2. 在「1 总览」页按回车选择「首次登录」，在程序弹出的独立浏览器里完成登录，并进入需要监控的聊天工作台（支持新标签页）。
3. 回到「1 总览」，↑↓选中「完成登录并继续」按回车。等待登录任务结束、登录态显示有效后再后台启动。未进工作台可以继续操作后再次确认；取消可选择「取消首次登录」。
4. 在「5 企微」页确认 webhook 和成员目录，在「4 配置」页确认客服工作台地址等参数（首次换电脑时必做）。
5. 在「1 总览」页选择「后台启动」，开始督办轮询。
6. 日常看「2 客户」倒计时、「3 日志」实时过程、「6 资源」占用、「7 报表」绩效。

「7 报表」默认查看近 30 天，按首次超时提醒次数从多到少排列；`[` / `]` 切换自然月，`s` 切换次数或累计超时排序。只有提醒时平台已明确分配的客服才计入个人绩效；未分配和成员映射缺失分别统计。累计超时从超时阈值算到人工实质回复，每次最多按该事件当时的漏回复阈值（首次超时阈值的 10 倍）计入。旧 HTML 报表数据不迁移。

### TUI 快捷键

| 键 | 作用 |
| --- | --- |
| 数字 1-7 | 切换页面（总览/客户/日志/配置/企微/资源/报表） |
| ↑ ↓ 回车 | 列表选择与执行 |
| 报表页 `[` `]` / `s` / `r` | 切换范围 / 排序 / 刷新 |
| q | 返回总览 |
| Ctrl+C | 退出确认（再次按 y 彻底退出） |
| 登录确认时 | 在1总览选中「完成登录并继续」后回车，不影响其他页面编辑 |

### 网页界面（可选）

- 终端里执行 `npm run panel:web`，或在无黑窗模式下使用 `scripts\hidden-launcher.ps1`。
- TUI 运行期间本地服务仍在监听，可用浏览器查看运行状态和日志；客服绩效只在 TUI「7 报表」展示。

## 启动方式对照

| 入口 | 说明 |
| --- | --- |
| 启动中心.bat（推荐，双击） | 一个纯脚本文件，打开控制台窗口并进入 TUI |
| `npm run panel` | 有终端时自动进入 TUI，无终端时退回网页模式 |
| `npm run panel:tui` | 强制 TUI（需要真实终端） |
| `npm run panel:web` | 强制网页模式（自动打开浏览器） |
| `npm run login` / `npm start` | 仅执行首次登录 / 仅后台督办，供排障 |
| `scripts\hidden-launcher.ps1` | 无黑窗网页模式（旧启动方式） |

## 当前能力

- 使用程序自己的独立 Edge 资料目录，不影响日常浏览器。
- 只监控平台明确显示为「超时」的客户。
- 达到升级阈值后，才点开会话读取接待客服。
- 按接待客服分组，把提醒发送到对应企微群。
- 独立转接监控页直接轮询分配状态变化，只在启动时初始化页面，不再逐个点开客户。
- 未回复引擎覆盖接口完整联系人快照并分批读取消息；待回复客户暂时离开快照也不会被直接清除。
- 已读和 AI 回复完全不参与业务判断；稍等类真实临时回复只免首次超时，纯标点不免超时，人工实质回复或客户明确解决才结案。
- 漏回复阈值、稍等类关键词、客户主动结案关键词、客户弱收尾关键词、无效人工回复关键词都可以在配置中心维护；弱收尾只忽略本条客套话，不关闭已有待办。
- 全程在控制台（TUI 日志页 / 网页日志页）和 `runtime/current-run.log` 输出中文结构化日志。
- 客服绩效使用 `runtime/timeout-performance/ledger.jsonl` 作为唯一事实源，不生成 HTML 或派生报表快照。

## 注意事项

- 首次登录时会显示独立 Edge 窗口，日常后台运行不会显示业务浏览器窗口。
- 登录失效时停止监控并提示重新「首次登录」，不会在隐藏页面等待你按回车。
- 项目 Edge 目录被占用会明确拒绝启动，不会强杀个人浏览器或递归删除锁文件。
- 直接关闭 TUI 控制台窗口后，清理看门狗会自动结束项目自带的浏览器和后台子进程。
- 更换电脑后，需要重新做一次「首次登录」生成浏览器登录态。
- 如果有赞提示 redirectUrl 错误，优先把「配置中心」里的客服工作台地址换成自己手动可正常进入的地址。
- 如果页面结构改了，可能需要调整选择器逻辑。
