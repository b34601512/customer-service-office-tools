# 1.客服超时督办 · 项目索引（开工先看）

> 本地控制台（TUI）盯「平台显示超时」的客户：达阈值→企微群提醒→按排班**同组**自动转接当班在线客服；下班监控自动关接单开关。
> 最后更新：2026-10-09。**程序化已成型，用户明确「不动」**——没事别改结构。

## ① 开工先看什么
1. 本索引 → [`断点记录.md`](./断点记录.md) → [`README.md`](./README.md)（转接规则、使用步骤）。
2. 口令「日常巡检」的 1号 步骤与验收（**新鲜度 ≥ 90%，写清分子/分母**）→ [`每日自动化流程.md`](../0.木婉清档案/日常流程/每日自动化流程.md) §一。

## ② 规矩 / 口径（一句话 + 出处）
- **不加自愈/自动重启**：有时要主动关监控「给大家喘口气」，窗口被关=监督停，是预期行为（黎路遥 2026-10-06）→ `断点记录.md`。
- 转接核心一句话：**客户消息必须有人回** —— 只看「当天排这个班次 + 接单开关开着」（售前看「可被转接」，售后看「自动分配」）；**不跨组**；原接待在班但没上线一样转走；每 5 分钟交班补判 → `README.md` §当前能力。
- 只监控平台明确显示「超时」的客户；**已读和 AI 回复不算处理**，人工实质回复/客户明确解决才结案 → `README.md`。
- 登录失效→**停止监控并提示重新首次登录**（不在隐藏页等待按回车）→ `README.md` 注意事项。
- 关法：直接关 TUI 控制台窗口 → 清理看门狗自动结束自带 Edge + 后台子进程（2026-10-08 实测关干净）→ 根 `断点记录.md`。

## ③ 经验 / 踩坑
- 规律（3 天连续）：「读取成员状态」超时（每天 4~6 组，70→104s/轮，不影响主功能）→ [`待拍板.md`](../0.木婉清档案/待拍板.md) ⑥ + [`失败台账.md`](../失败台账.md) 10-08。
- Edge 占用检测（中文路径）、启动前 preflight、黎经理→运营→售前自动转接 → `断点记录.md`。
- 新版 Edge 升级后要重新「首次登录」；旧 Chrome 资料目录不迁移 → `README.md`。

## ④ 常用命令
```bash
cd "1.客服超时督办"
npm run panel                 # 控制台（TUI，推荐；= 双击 启动中心.bat）
node src/main.js run          # 仅后台督办（勿与控制台重复点「启动后台」）
node scripts/test-isolated.js # 单测（系统 Node；基线 427）
```

## ⑤ 红线 / 勿混用
- 不要用 `hidden-launcher.ps1`、旧 VBS、`--tui`/`--web`；**不要用浏览器打开 39360**（那是控制台本地 API）。
- 联调浏览器前先停督办（与项目共用 `edge-user-data`）。
- 本机 **9371 是银行 USBKey 的**，与本项目无关（2026-10-09 实测修正）。
- 平台后台只读；失败不自动重试。
