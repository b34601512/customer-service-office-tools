## 一、这个项目干嘛的
客服主管 AI 经验库 + **探域后台**（客服 AI 知识卡/配置）的采集、调优与写入。结构分两层：`01.通用/`（换公司也成立的方法/工具/模板）+ `02.业务专用/德达医疗/`（公司政策、店铺、卡 ID、执行记录）。

## 二、规矩 / 口径
- **方法尽量通用，业务事实尽量专用**；不得把 A 公司业务事实带到 B 公司；别再为每家公司复制一套同逻辑脚本（`README.md`）。
- 弱 AI 强制执行顺序（`AGENTS.md`）：明确公司/店铺/授权范围 → 先读通用方法再读本公司资料 → **默认只读采集** → 事实不确定记录待确认 → 写入必须有 **before/after/范围/依据** → 保存前**再读一次**（与 before 不一致就停）→ 写入后完整回读 → 分别报告草稿/已保存/已核验/已模拟。
- **只有探域后台可写**（客服知识卡），写入照规矩：快照 → 小步 → 回读 → 证据落盘；**删除/批量改写/绑店范围/发布 = 破坏性操作，须客服主管或经理确认**。
- **「待审核」标记只允许模型亲自读上下文判断**（买家问+AI答+召回知识），**禁止关键词/规则命中直接标**；高危不标交人（黎路遥 2026-10-06，`01.通用/平台适配/探域/调优记录日常任务与接口.md` §8）；判过「不标」的记基线。
- **探域卡绑店：一个店一张，别多店共用**（以后要变不牵连别家）；共用卡要拆时「新建+解绑」，**不删卡**（`../0.木婉清档案/规矩与红线.md` §九）。
- 探域 `batch-save` 每次保存会**重生成 planId**（比对时忽略该字段，断点记录）。

## 三、经验 / 踩坑
- 通用方法论：`01.通用/方法论/`（AI工作手册、在线文档完整读取）；工具：`01.通用/工具/`；探域日常口径：`01.通用/平台适配/探域/调优记录日常任务与接口.md`。
- 德达医疗业务事实/任务/历史脚本：`02.业务专用/德达医疗/`；旧结构只追溯：`99.旧结构迁移来源/`。
- **调 API 两个坑**（断点 2026-10-08）：① Git Bash 里裸 `/api/...` 会被 MSYS 转成 Windows 路径 → 前面加 `MSYS_NO_PATHCONV=1`；② 大响应（全库 7592 卡）别用 `探域API只读调用模板.cjs`（撞 SPA 导航 "Execution context destroyed"）→ 用 `探域知识卡巡检.cjs` 或自己等 `networkidle`。
- 空运词回流：每天例检顺手扫，发现即改「顺丰24小时速发」并报（详情页不改会反复回流）。
- 失败/事故先查 `../失败台账.md`；重要提案/待拍板：`../0.木婉清档案/待拍板.md`。

## 五、红线
- **电商平台后台（拼多多/抖音/天猫/京东）只读**——只动探域；天猫「待同意」不点。
