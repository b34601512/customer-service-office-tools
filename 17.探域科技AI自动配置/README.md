# 客服主管AI经验库

目标：把主管的实际操作经验沉淀成可复用能力，让能力较弱的AI也知道“先做什么、怎么判断、怎么安全执行、怎么验收”。

## 新结构

```text
17.探域科技AI自动配置/
├─ AGENTS.md
├─ README.md
├─ 01.通用/
│  ├─ README.md
│  ├─ 方法论/
│  ├─ 平台适配/
│  │  └─ 探域/
│  ├─ 工具/
│  └─ 模板/
└─ 02.业务专用/
   └─ <公司名>/
```

## 怎么理解“通用”和“专用”

**通用：换一家公司仍然成立。**

例如：完整读取知识库、判断冲突、生成before/after计划、备份、写入、回读、范围核验、SKU核验、图片绑定、在线文档读取、探域接口调用。

**专用：换一家公司就可能不成立。**

例如：公司政策、活动、商品型号结论、真实店铺ID、知识卡ID、当前配置、待拍板事项、执行记录。

## 给AI的启动要求

> 先读AGENTS.md和01.通用/README.md。先确认本次公司、平台、店铺和授权范围，再进入对应的02.业务专用目录。不要采用其他公司的政策。先只读采集并生成计划；业务事实不确定就记录待确认。所有写入都要before/after、写前再读、保存、回读核验，并明确报告草稿/已保存/已核验/已模拟。

## 重构原则

旧项目里大量脚本实际上只是“公司、店铺、型号、正文、对象ID不同”。这类脚本应优先抽成参数化通用工具，而不是每家公司复制一份。

理想状态：

- 大多数“怎么做”都在 `01.通用/`
- `02.业务专用/` 只保留少量业务事实和任务参数
- AI读取通用能力后，再加载当前公司的专用信息即可执行
