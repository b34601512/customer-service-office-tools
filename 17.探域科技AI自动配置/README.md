## 怎么理解“通用”和“专用”

**通用：换一家公司仍然成立。**

例如：完整读取知识库、判断冲突、生成before/after计划、备份、写入、回读、范围核验、SKU核验、图片定点处理、在线文档读取、探域接口调用。

**专用：换一家公司就可能不成立。**

例如：公司政策、活动、商品型号结论、真实店铺ID、知识卡ID、当前配置、待拍板事项、任务参数和执行记录。

## 给AI的启动要求

> 先读AGENTS.md和01.通用/README.md。先确认本次公司、平台、店铺和授权范围，再进入对应的02.业务专用目录。不要采用其他公司的政策。先只读采集并生成计划；业务事实不确定就记录待确认。所有写入都要before/after、写前再读、保存、回读核验，并明确报告草稿/已保存/已核验/已模拟。

## 新的脚本思路

旧项目里大量脚本只是“公司、店铺、型号、正文、对象ID不同”。现在改成：

```text
通用方法
  +
通用执行器
  +
某公司的任务JSON/业务事实
  =
本次可执行任务
```

目前通用区已经提供：

- `规则任务生成器.cjs`：从快照和业务规则生成before/after任务
- `探域知识卡任务执行器.cjs`：检查、写入、回读、核验
- `图片定点编辑器.py`：参数化图片遮盖/文字替换
- 对应的空白任务模板

德达原35个可执行历史脚本已移入 `02.业务专用/德达医疗/历史脚本/`，不再作为新任务入口；其中绝大多数逻辑已可由通用工具承担。

## 维护原则

- 方法 → `01.通用/`
- 平台操作 → `01.通用/平台适配/`
- 可复用代码 → `01.通用/工具/`
- 空白结构 → `01.通用/模板/`
- 某家公司真实事实 → `02.业务专用/<公司>/`
- 旧文件 → `99.旧结构迁移来源/`

以后不要再建立“某公司专用版通用手册”或复制一套同逻辑脚本。
