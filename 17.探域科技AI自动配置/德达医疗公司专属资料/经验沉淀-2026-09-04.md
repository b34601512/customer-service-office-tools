# 探域科技 AI 配置经验沉淀（增量）

> 本文件只补充 `README.md`、`AI工作手册.md`、`金山在线Word文档读取经验.md` 尚未完整记录的经验；已有方法不重复抄写。

## 1. 无 GUI 读取后台：先确认真实路由

- `curl` 能拿到网页壳，不代表页面没有数据；后台是 JavaScript 应用时，用独立 Edge 画像配合 Playwright 读取。
- 用户要求“不用 GUI”时，统一使用 `headless:true`，不要拉起可见窗口，也不要操作用户原来的 Edge。
- 页面验收至少保留：`title`、最终 `url`、关键 `body.innerText`、接口请求/响应摘要。不要把 Cookie、Authorization、session token 写入日志或笔记。
- 同一个持久画像不能并行启动两个浏览器上下文；否则会锁画像。脚本必须用 `try/finally` 关闭上下文，异常时先确认是否有自己启动的无界面进程。

### 飞书密码墙

- 直连飞书常只能拿到约 91KB 的 JavaScript 壳，不能据此判断文档为空；未解锁时标题通常是“没有权限访问 - 飞书云文档”。
- 用页面真实交互解锁：定位 `input[type="password"]`（必要时兼容首个文本框），填入用户临时提供的密码，点击名称匹配“确定”的按钮，等待页面完成渲染。
- 解锁后同时记录标题、URL、正文前段和本地截图；密码只作为本次运行时变量，不能写入项目文档或上传。
- 读取页面和读取探域后台都应先监听真实网络请求，再决定是否调用接口；不要凭经验猜 Cookie、CSRF 或请求体。

## 2. 调优工坊为空的判定方法

### 正确页面

- 新版入口：`/v2/diagnostic-optimization/optimization-workshop`。
- 旧路径 `/diagnostic/fine-tuning`、`/v2/diagnostic/fine-tuning` 不是当前调优工坊入口，可能跳转或进入 404/空壳页面。

### 先看筛选上下文，再看数据

1. 页面若显示“选择店铺”且表格为“暂无数据”，先检查当前店铺上下文，不要先判断数据丢失。
2. 未选店铺时，页面不会发起列表请求 `POST /api/im/agent-trace/paginateV2`，所以“暂无数据”只是查询条件未形成。
3. 选中已绑定店铺后，才会带 `thirdShopId` 查询；本次当前账号选中“德达医疗旗舰店”后，接口返回 HTTP 200、`total=197`。
4. 店铺选择可能保存在本机浏览器 `localStorage.shopMap`，属于可逆的本机筛选状态，不是线上知识或调优记录配置。
5. 两台电脑显示不同，按此顺序比较：登录账号/集团、店铺、起止时间、客服、订单状态、话术类型、发送/处理状态、Agent。不要只比较页面截图。

### 查询请求的证据模板

```text
POST /api/im/agent-trace/paginateV2
{
  thirdShopId: "当前店铺ID",
  pageIndex: 1,
  pageSize: 20,
  beginTime: "开始时间",
  endTime: "结束时间"
}
```

只记录脱敏后的筛选条件、HTTP 状态、`total` 和前两条摘要即可。

## 3. 话术知识的范围与订单阶段（本轮补充）

- QA 格式和“店铺/商品/订单阶段范围”原则已有记录；本轮补充可执行的审计细节：同时核对知识类型、店铺、商品/商品组、平台，保存后重新拉取原始字段，避免只相信标题或 UI 显示。
- 只有一个店铺时也要明确绑定该店铺，不能依赖默认值；商品专属参数仍需绑定商品，不能因店铺单一而扩大成全店知识。
- 订单阶段按语义判定，不按标题关键词机械归类：
  - 售前：未下单咨询、选型、参数、发货前问题；
  - 售中：已下单/待发货/物流等订单执行问题；
  - 售后：收货后使用、维修、退换货、退款、投诉等；
  - 一问同时覆盖两个阶段时才使用组合范围；无法判断时先列为待确认，不强行扩大范围。
- 本轮验证过的订单状态映射（下次仍须先从当前页面/API核对枚举）：`preSale=[0,100,105,106]`、`sale=[102,101,107]`、`afterSale=[103,104]`。不要复制旧的重复/错误状态映射。
- 修改范围或阶段后，要做数量守恒、错误阶段抽样、正文/标题/其他字段不变三项复核。

## 4. 删除与批量修改的安全流程

- 本轮额外确认：备份必须包含正文、类型、范围、启用/可信状态等完整原始字段；只备份截断正文无法恢复。
- “非话术/内部规则”先形成候选清单；只有用户明确回复确认口令 `161323` 才能执行删除，没有口令时只报告不落库。
- 批量修改后记录数量守恒、关键字段不变、抽样语义正确三项验收，不以接口返回成功代替业务验收。

## 5. 培训文档转知识库的增量规则

- `金山在线Word文档读取经验.md` 已完整记录 KDocs/WPS 的网络读取、图片提取和正文验收方法，本文件不重复。
- 本轮实际流程是“先提取 5 条候选→用户确认→只写入第 1 条”；未获确认的候选不得顺手导入。新增卡的接口返回 ID 和最终范围应留在验收记录中。

## 6. 给后续 AI 的最短执行顺序

```text
复述意图 → 读项目现有文档 → 采集真实页面/API → 记录证据
→ 生成变更计划 → 对不确定项提问 → 取得 161323 才做不可逆操作
→ 批量定向验证 → 更新 issue/笔记与验收清单
```

不要把“看到一点就改一点”当作排查流程；先完整读清业务结构，再一次性做定向验证。
