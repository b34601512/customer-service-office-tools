# 售前政策咨询被按售后处理

## 意图

让模型依据交易状态和业务事实理解问题：售前了解售后政策时直接说明原则，进入具体订单处理后再核对订单，不把“需要订单核实”扩大为“没有订单号不能解释政策”。

## 背景与证据

- 调优工坊记录 `6a9e597b45fa052e8e56ea72`：买家先表达“现在购买”“后期万一”，随后咨询“寄回厂家运费谁付”；商品仅有 `spuId=582414503778`，没有订单号和SKU。
- 原回复要求提供订单号核实，属于具体售后处理口径，不适合售前政策了解。
- 后台原卡 `6a9a3c4f644e354d71a3fb40` 名为“运费谁承担”，原阶段仅为 `AFTER_SALE`，正文为泛化的订单核实话术。

## 已确认业务原则

- 买家原因（无理由退货、拒收、拦截包裹、使用不当等）退回运费由买家承担。
- 商品本身有问题，购买1年内寄回及寄回后的来回运费由本店承担；购买超过1年，来回运费由买家承担。
- 本店承担范围限中国大陆；海外及港澳台超出部分由买家承担。

## 已执行

- [x] 将原卡改为“运费承担原则”，适用阶段扩展为 `PRE_SALE`、`AFTER_SALE`，正文改为原则式规则。
- [x] 两个正式Agent均加入交易状态与政策咨询原则，正式内容回读一致。
- [x] 自然表达模拟通过：未下单询问维修运费时，直接回答1年内/超过1年及地区限制，未要求订单号。
- [x] 完整备份与回读记录：`D:/备份文件夹/探域问答审核-20260907-pre-sale-after-sale-policy`。

## 边界

- 不按客户具体问法建立QA触发卡。
- 订单号仍用于具体订单、购买时间、责任判断和处理进度核实。
- 未核实具体订单前，不承诺已登记、已付款或具体金额。
