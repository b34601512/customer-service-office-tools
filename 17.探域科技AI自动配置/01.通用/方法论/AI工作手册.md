# 客服主管AI通用执行手册

这份手册只讲“怎么做”，不包含任何公司的业务政策。

> 核心顺序：先确认范围 → 完整读取 → 区分事实与方法 → 生成计划 → 写前再读 → 执行 → 回读 → 验收。

## 1. 先确认本次任务

开始前确认：

- 公司
- 平台
- 店铺
- 要处理的对象
- 只读、允许修改，还是另有明确授权
- 当前AI是否能读文件、看图片、访问后台、运行脚本

可使用 `../模板/公司接入与拍板.md`。

不同公司不得继承其他公司的店铺、ID、登录画像、政策或历史授权。

## 2. 先读通用，再读公司专用

先读取：

1. `../README.md`
2. 本手册
3. 需要时读取 `../平台适配/`
4. 最后进入 `../../02.业务专用/<当前公司>/`

判断标准：

- 换家公司仍然成立 → 通用
- 换家公司可能不成立 → 业务专用

## 3. 默认先只读

首次接入先采集，不边看边改。

至少确认：

- 当前账号和目标店铺一致
- 当前知识、商品/SKU、策略或Agent已读到需要的范围
- 资料来源、日期、型号、平台和适用范围明确
- 图片实际看过，不只看文件名或OCR

在线文档读取可参考 `./在线文档完整读取.md`。

停止条件包括：登录失效、店铺不明确、数据未读全、权限不足、接口形状变化、资料冲突无法判断。

## 4. 把内容分成四类

| 类型 | AI动作 |
|---|---|
| 表达问题 | 有授权时可优化，但不改变事实 |
| 商业规则 | 没有明确依据就待主管确认 |
| 技术/合规事实 | 查对应型号和可靠资料，不能猜 |
| 内部操作内容 | 不直接写成买家答复 |

不要因为“多数旧卡都这样写”就认为事实正确，也不要因为文件日期较新就自动覆盖当前规则。

## 5. 每次修改先形成任务计划

一个可执行任务至少要有：

- 对象ID
- 修改前完整内容 before
- 修改后完整内容 after
- 适用范围
- 修改依据
- 是否已获得当前授权

业务事实放公司专用目录；执行代码不要复制到公司目录。

知识卡任务优先写成JSON，格式参考：`../模板/知识卡修改任务.example.json`。

## 6. 脚本尽量通用

如果两个脚本只差：

- 公司名
- 店铺ID
- 商品/型号
- 知识卡ID
- 正文
- 图片路径
- 备份目录

那么这些都应变成参数，不应该复制一份新脚本。

通用知识卡执行器：`../工具/探域知识卡任务执行器.cjs`。

它默认只检查；写入需要显式 `--action apply --allow-write true`。执行时必须使用本次公司的登录环境、任务JSON和备份目录。

## 7. 写入必须防覆盖

安全写入最短流程：

```text
读取当前对象
→ 与任务before比较
→ 已经等于after：记为已完成，不重复写
→ 与before不一致：停止该项
→ 写前再次读取
→ 只改批准字段
→ 保存
→ 回读完整正文和业务范围
→ 一致才标记已核验
```

不能因为请求超时就假设“肯定没写”；先回读。

## 8. 图片也用“通用工具 + 专用参数”

图片算法属于通用能力；坐标、文字、源图属于公司任务数据。

使用 `../工具/图片定点编辑器.py`，任务格式参考 `../模板/图片定点编辑任务.example.json`。

要求：

- 不覆盖源图
- 修改区域外像素不变
- 保存源文件和输出文件SHA256
- 上传后台后再回读实际引用

## 9. 探域平台适配

探域接口经验统一放 `../平台适配/探域/`。

接口路径、字段和返回形状只能作为历史实测线索，实际执行前要核对当前后台。平台操作方法可以通用，但业务正文和对象ID不能放进平台适配区。

## 10. 弱AI不会时怎么处理

弱AI不需要强行完成所有动作。

遇到以下情况，先输出草稿或待确认项：

- 无法验证当前账号/店铺
- 不知道某业务事实是否成立
- 不知道接口字段含义
- before与当前后台不同
- 图片型号无法确认
- 写入后无法回读

不会核验时，不得声称“已配置完成”。

## 11. 状态必须说清楚

只使用能证明的状态：

- `draft`：本地草稿
- `ready`：计划完整，可执行
- `saved`：请求已保存，但尚未完整核验
- `verified`：后台回读一致
- `simulated`：模拟场景已通过
- `conflict`：当前状态与计划不一致，已停止
- `pending`：等待主管或证据

不要把这些状态混在一起。

## 12. 历史脚本不是执行入口

公司目录中的 `历史脚本/` 仅用于追溯以前做过什么。

新任务应先问：这个旧脚本的“方法”是否能抽成通用工具？如果能，就只保留公司业务参数，不继续复制一次性代码。

## 13. 维护原则

以后新增经验：

- 方法 → `01.通用/`
- 平台操作 → `01.通用/平台适配/`
- 可复用代码 → `01.通用/工具/`
- 空白结构 → `01.通用/模板/`
- 某家公司真实事实 → `02.业务专用/<公司>/`

最终目标不是让AI记住某次德达操作，而是让AI学会遇到同类任务时自己按正确流程完成。
