# 表格知识与技能工具（尺码表/报价计算器）

来源：手册引用的三份飞书文档——《表格知识教程》（2025-07-24）、《工具集-尺码表功能使用教程 0930》（2025-09-30）、《报价计算器使用教程》（内测版，3-01），2026-09-28 全文采集（四件套+快照自检通过）。
只记平台配置方法；示例里的行业话术不搬进通用区，落地时按本公司业务事实重写。

## 1. 表格知识

用途：① 商品信息查询（精准回答库存/规格/材质等）；② 商品推荐/适配型号查询。

### 场景 1：商品信息查询

1. 准备 CSV 表格（从“新建表格”下载模板编辑后上传，必须 csv）。
2. 关键列：必须包含 商品ID / 商家编码 / 货号 **至少一列**，用于识别焦点商品。
3. 其余列补充库存、颜色、材质、发货地等；每行一个独立商品。
4. 上传后自动启用；买家在商品页提问时，智能体自动识别焦点商品并查表回复。
5. **此场景无需创建自定义 Agent**，系统自动关联查询。

### 场景 2：商品推荐 / 适配型号查询

1. 准备推荐表：不需要 ID 列；每行一个推荐对象（商品/型号/款式/适用范围），每列一个属性。
2. 需要给链接时，确保表格内链接和自定义 Agent 属于同一店铺（避免 A 店提问发 B 店链接）。
3. 创建自定义 Agent，在提示词里 `@` 引用该表格，并写清：查询时机、查询逻辑（买家哪些关键词 → 查哪些列）、回复格式、结合反问（先收集信息，再查表，再追问或回复）。

### 表格知识通用规则

- 列名不混淆：不设含义相似的列，**严禁重复列名**。
- 表头设计：查询列尽量详细细分（“长10cm宽5cm”不如拆成“适配长度/适配宽度”）；回复列尽量集中（卖点、备注可合并成“商品介绍”）；既查又回的列按查询标准设计。
- 描述列名用大白话 + 内容示例，避免内部术语（如 `SKU-Atr`）。
- 数据类型：文本=描述性信息（大部分列）；数字=要大小比较的列（如“重量<1.2kg”“价格<500”），该列必须纯数字，上传后在页面标注单位。
- 暂不支持商品对比场景：买家发多个商品对比时，系统只会按最新焦点商品查询。

## 2. 尺码表（服饰尺码计算器）

路径：工具集 → +新建工具 → 服饰尺码计算器。

1. 基本信息：工具名称（只作管理，不被智能体识别）；匹配条件可选，逻辑与知识库一致（指定商品/商品分组/客服组）；同一商品匹配多个尺码工具时，**优先用最新更新的**，所以要严谨设置匹配条件。
2. 尺码参数定义：新增参数（身高、体重等有常用可选）；参数名、类型（数字/文本）、单位（如 cm、市斤）。买家单位不同会**自动换算**（“我一米7”→170cm），建议用买家常用单位。
3. 参数描述非常重要：用于引导智能体从口语化对话里提取信息。
4. 录入尺码表：点“生成尺码表”后按供应商数据填写；数字类型填范围（左小右大），文本类型（如罩杯 A/B/C）直接填文本。
5. 套装/亲子装/情侣装等多款式商品：在同一工具下新增多个尺码表，并**写清每个尺码表的描述**（如“成人款/儿童款”），智能体按买家咨询的款式匹配。
6. 保存并启用。
7. 联动自定义 Agent 处理特殊情况（卡码、超范围、身高体重分属不同码）：完全符合→直接推荐；同时符合多码→告诉买家宽松/修身各选什么；没有完全符合→按体重推荐；超最大码→按最大码，小于最小码→按最小码；不能直接说“穿不了”，要委婉引导看其他款式。
8. 实践建议：不同版型/品类建不同工具并设匹配条件；结合自定义 Agent；创建后用“调试机器人”模拟买家验证。

## 3. 报价计算器（内测版）

适用：批发、定制类目（地毯、装修材料、打印等）。智能体对话中结构化收集需求（尺寸/材质/数量/工艺等），按预设规则自动算总价并报价。

配置流程：

1. 整理报价逻辑：先写清需要买家提供的信息、单价规则（如长度区间 × 材质）、总价公式、接待流程。
2. 准备报价表：区间用“最小值/最大值”两列表示（长度<2 → 0~2；长度>10 → 最小值5、最大值填 100/1000/999 等具体极大值）；参与计算的数字**必须纯数字、不带单位**。
3. 上传表格（表格知识）。
4. 新建工具，类型选“定制报价计算器”；设置参数：**列的数据类型和单位必须正确**（长宽高/数量=数字+单位；材质/款式=文本）。参数只能设“对话里能直接获取的信息”（买家给长和宽，就不要把“面积”设成参数）。
5. 设置计算逻辑：用【】框住参数和报价表表头；必须用**完整参数名/表头名**（参数叫“宽度”就写“宽度”，不要写“宽”）；参数名与表头同名时保持一致；尽量用 `+ - * /` 公式表达，可要求“保留 x 位小数”“向上取整”等。
6. 设置自定义 Agent：触发场景要覆盖整个定制流程；提示词只写“怎么接待买家”，**不要写计算逻辑**；用 `@` 引用报价计算器。
7. 测试并验证（示例：2.3*3.4*80=625.6；进阶含数量与附加费：7.6*12.5*100*10+50*10+100*10=96500）。

注意：内测版，功能迭代可能变化，开通与优化需联系官方对接人。
