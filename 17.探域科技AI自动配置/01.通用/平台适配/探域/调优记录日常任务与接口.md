# 调优记录（调优工坊）日常任务与接口笔记

来源：2026-10-03 实测（前端接口 + 抽样）。黎路遥当日拍板：「调优坊（调优记录）就是以后日常任务」——**每次醒来都看，范围最近 30 天**；接口以本文为准。
只记平台操作与接口，不含公司话术、客户信息。

## 1. 两个别搞混的队列

| 队列 | 接口 | 说明 |
| --- | --- | --- |
| **调优记录（日常任务就是这个）** | `POST /api/im/agent-trace/paginateV2` | 每行 = 一次买家咨询 + 智能体生成的话术；`reviewStatus`：1=待处理、2=已处理 |
| 调优工坊「聊天知识审核」的待审核 | **同上一个接口** | UI 路径：`诊断优化 → 调优工坊 → 聊天知识审核`，选店 + 日期（默认近 30 天）→ 表格「待审核」= `paginateV2` 结果里 `reviewStatus===1`（2026-10-04 实测抓包：body 就是 `{thirdShopId,pageIndex,pageSize,beginTime,endTime}`，无额外参数；搜索框/买家昵称是前端或另一套过滤）|
| 知识审核（旧小队列） | `GET /api/copilot/v1/knowledge/chat-log-review/paginate` | 聊天记录提炼的 Q&A 审核；2026-10-03 全站仅 17 条，已处理完（不是日常那个）|

## 2. 接口清单

- **列表**：`POST /api/im/agent-trace/paginateV2`
  - body：`{ thirdShopId, pageIndex, pageSize, beginTime, endTime }`（时间格式 `YYYY-MM-DD HH:mm:ss`；`pageSize` 5000 可一次拉全，实测 2628 行 ✓）
  - 返回：`{ total, currentPageSize, results[] }`
  - 行字段：`id, time, platform, thirdShopId, shopName, sellerAccount, buyerAccount, question, topicName, productInfo, status(COMPLETED/FAILED), ifSend, sendType, content, reviewStatus, ifWithdraw, ifLabel`
- **明细**：`POST /api/im/agent-trace/trace`，body `{ cardId: <行 id>, thirdShopId }`
  - 返回含：`noSendReason`、`noSendReasonName`、`snapShots`（召回的知识卡）、`traceList`、`prohibitedWordHitDetail`、`riskRating`、`logIsCredible`、`orderState/orderId`、`agentId` 等
- **完整聊天记录**：`GET /api/im/agent-trace/get-chat-list?thirdShopId=<店 id>&cardId=<行 id>`（2026-10-05 抓包实测：详情抽屉右上「查看全部记录」触发的就是它）
  - 返回：`{ code:1, data:{ list:[…] } }`，**无分页**，一次给整段会话（实测 22 / 84 / 194 条；按 msgTime 升序）
  - 消息字段：`chatLogId, msgId, personType, buyerNick, sellerNick, content, feature(JSON 字符串), contentType(0=文本,1=图片), innerMsgType, msgTime, type, ifCardContext, ifTriggerMessage`
  - `personType`：`0`=智能体回复（`feature.agentType`/`autoAgent`）、`1`=客服侧、`3`=买家
  - 参数口径：`cardId` 取 paginateV2 行的 `id`（=抽屉里的「追踪ID」）；它只用来定位**买家整段会话**——同一买家两条不同记录返回**同一份消息**（实测两条 hash 相同）；缺参报 `code:0 参数thirdShopId缺失 / 参数cardId缺失`；cardId 与 thirdShopId 不匹配报 `code:0 消息记录不存在`
  - 对比 `get-card-chat-context`（**打开详情时**就调）：只给卡片附近窗口（同记录 18 条 vs 84 条），且字段不全（`chatLogId/contentType` 为 null），看全文不够用
  - **什么时候要拉完整上下文**：单条复核需要买家/客服前后原话时（如 `110 回复来自非可信知识`、风控/违禁词误伤、答非所问判断）；日常批量分拣仍只吃 `paginateV2` 行数据，别每条都拉（避免请求量放大）
  - **2026-10-05 抽查（16 条）实证**：`question` 与完整记录里的买家消息一致（±2s）；空 question 的商品卡事件记录常有同秒「兄弟」`CONSULT_REPLY` 承接文字（别单看一条得出「无提问」）；**片段型提问（好/可以/太贵了/推荐一个吧）与留审定性、非可信标可信、答非所问必须先拉本接口**——前后文（气切医疗、故障排查、促销是否被客户问过）会改变结论。
  - **边界**：本接口只给「当前会话段」，跨会话前文（如「你说的赠品」的出处）仍看不到——是必要补充、不是全史。
- **标记已处理**：`POST /api/im/agent-trace/review`，body `{ cardId, thirdShopId }`（字段名与明细一致；空载荷报「店铺ID不能为空,ID不能为空」；**一次一条**，未发现批量入口）
  - 返回码坑（2026-10-04 实测）：成功 = `code:1 "操作成功"`；**已审过** = `code:0 "卡片已审核"`；**卡片已删**（孤儿记录）= `code:0 "卡片不存在"`。后两者要当**跳过**处理，不能当失败（否则脚本会卡死在第一条）；但别当成 code:1 反复重试。
- **未发送原因字典**：`GET /api/im/agent-trace/no-send-reason-list`（26 条，`value/label`）
- 其他：`GET /api/im/agent-trace/get-card-chat-context?thirdShopId&cardId`（详情抽屉默认「对话上下文」，卡片附近窗口）；`GET /api/im/agent-scene-replay/latest?thirdShopId&cardId`（场景回放，无回放时 `data:null`）

## 5. 日常动作（每次醒来）

1. 拉近 30 天各店列表，取 `reviewStatus=1`。
2. 对「未发送」的看明细原因：
   - `话术未生成` → 补 QA 知识卡（走建卡流程：dry-run → 写 → 回读）→ 标记已处理；
   - `回复来自非可信知识` → 取 trace 召回卡逐张核对内容：**内容对 → 把该卡标「可信」**（黎路遥 2026-10-04 10:18「要，不然回复不了」）；有疑问/矛盾/医疗承诺类 → 不标、列回执问人；
     - ⚠️**标可信前额外扫一遍「物流/时效/承诺」类细节**（2026-10-04 教训：标了含「顺丰空运」的商品卡，AI 直接照答被黎路遥判错 → 全库 61 张去「空运」）——这类没核实过的细节先列出来问人，别直接标。
   - 风控/违禁词 → 核查话术措辞或知识写法；
   - 其他原因 → 默认无需动作（可批量标记，口径待黎路遥定）。
3. 处理一条标记一条（`review`，一次一条）；证据落 `02.业务专用/德达医疗/任务/<日期>-调优记录/`。
4. 拿不准 → 停下问黎路遥。
5. 口径（黎路遥 2026-10-03 17:16）：「应该只看未标记已处理的吧，处理后标记已处理」——**只处理 `reviewStatus=1`，处理完一条标一条；不去批量标没动过的**。

## 6. 工具

- 知识审核队列：`01.通用/工具/探域调优坊审核.cjs`（`--list --all` / `--approve "<id>" --commit`）。
- 调优记录：列表/明细用 `01.通用/工具/探域只读批量调用.cjs`（`--allow-post true`）；标记走 `review`（一次一条，写入前先跑 dry-run 清单）。
- 扫描/标记工具：`01.通用/工具/探域调优记录扫描.cjs`（`--scan` / `--review [--commit]` / `--review --verify`）。
  - **`--since/--until` 必须带秒**（`"2026-10-03 20:30:00"`）；只写到分（`20:30`）时 `paginateV2` 返回 `http=200 code=0`（2026-10-03 21:14 实测 1 次）。
  - `--review` 的 id 用 **cardId**（扫描 JSON 的 `id` 字段，非 `time`）。

## 8. 每日必做：清空所有店铺的「待审核」（黎路遥 2026-10-04 定）

> 原话：「然后这里每个店铺都要筛选一下，然后选择待审核，每个店都有很多待处理的，**每天都要处理完毕所有店铺的待审核的**」+「做好笔记，这是以后日常工作」。

**范围**：8 家店 × 最近 30 天，`reviewStatus===1` 的记录（= 调优工坊表格里「待审核」的行）。
> ⚠️ 别被 UI 计数骗：调优工坊表格底部「共 N 条」= **该店该时间段全部记录数**（含已审），**不是待审核数**（2026-10-04 实例：PDD德达显示 2696，真实待审只有 481）。待审核数必须用 `paginateV2` 拉全后筛 `reviewStatus===1` 统计。
> ⚠️ UI「对话上下文」要点右上的 **「查看全部记录」** 才展开完整聊天（2026-10-05 黎路遥提醒）；默认显示「暂无对话上下文」时**不代表没有上下文**——看详情/人工核对时先点它；批量判断走接口记录（不点界面）。要完整聊天不用点 UI：直接调 `get-chat-list`（见 §2）。
> 起点库存（2026-10-04 16:1x 实测）：8 店 30 天共 **3664 条记录**，其中待审核 **1026 条**（PDD德达 481、PDD DEDAKJ 217、德迩杰 70、淘宝 ?、京东德达 ?…）；当天已清 949 条（绿+黄 672、红里可标 277），剩 77 条留审 + 后续新增。

**步骤（每店循环）**：
1. `POST /api/im/agent-trace/paginateV2` 分页拉全（pageSize 500~1000）→ 筛 `reviewStatus===1` → 存证据。
2. 🚩 **逐条真读上下文（红线，黎路遥 2026-10-06）**：每条都要**模型亲自读**「买家问 + AI 答 + 召回的知识」再决定标不标；**禁止用关键词/规则命中直接标**。
   > 原话：「对，不能用规则标，记录下这个要求红线，**只允许模型亲自阅读上下文判断**」+「只有你模型去真实阅读上下文才行，否则你发现不了问题」。
   > 原「三色分拣（绿直接标）」口径 **2026-10-06 作废**；关键词命中只能当**初筛提示**，不能当标记依据。判定理由要落盘（每条一行）。
   > **质量优先（黎路遥 2026-10-06 09:44「慢一点不怕，就怕低质量放水」）**：宁可慢；每条都要留判定理由（可回查）；拿不准的一律不标；批量读的每批要抽查复核，防走过场。
   - 🟥 高危（承诺/已备注/已登记/已安排/已加急/已发出/保证/价格数字/血氧/疾病/用药/推荐升数/快递时效/电话微信/退换政策/运行时长…）→ **不标**，写清单交人复核。
   - 拿不准 → 不标，进「存疑」清单。
   - **判过「不标」的记基线，以后不再重复判**（黎路遥 2026-10-06 10:04「行，那就不标」拍板）：基线文件 `17号/02.业务专用/德达医疗/任务/不标基线/不标-ids.json`（累加：新一批判完把新 id 并进去）；每日优化先排除基线里的 id，只判**新到**的。
   - 所以「每日清空待审核」的实义 = **新到的处理完**；留审/不标的挂着不重复折腾（它们是真风险项或待人工口径）。
3. 标记：`POST /api/im/agent-trace/review {cardId, thirdShopId}`（**一次一条**，未发现批量入口）→ 写后回读=2。
4. 每店标完复拉一遍，报「剩几条 1」；总账：起点 → 剩量。
**红线**：标记**不改知识**（只动审核状态）；高危一律人工；**只允许模型亲自阅读上下文判断（禁止规则标）**；失败不自动重试；只碰探域。
**删卡红线**（2026-10-04 / 10-05 两次实测）：删知识卡会把它的调优记录变成**无法标记的孤儿**（`review` 报 code:0「卡片不存在」）——**删卡前先看一眼该卡名下有没有待审 trace**；孤儿记录无法清理、等 30 天窗口自然过期。
**工具**：`探域调优记录扫描.cjs --scan / --review "id1,id2" --commit --shop <id> / --review --verify --shop <id>`；窗口/脚本直连时可用 CDP（见 §6）。
