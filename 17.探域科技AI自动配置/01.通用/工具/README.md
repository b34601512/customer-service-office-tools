# 通用工具规范

目标：让弱AI不需要理解旧项目历史，也能按参数安全执行。

## 一个工具应该满足

- 不写死公司、店铺、型号、正文、对象ID、账号和本机路径。
- 默认只读；写入动作必须显式指定。
- 输入来自任务参数或业务专用区文件。
- 写前保存before，写入后回读after。
- 发现当前状态与计划before不一致时停止，不强行覆盖。
- 重复执行时能识别“已经是目标状态”，避免重复新建或重复修改。
- 输出明确状态：planned / prepared / saved / verified / skipped / conflict。

## 优先抽成通用工具的旧脚本

只要脚本的主要价值是“读取、筛选、计划、更新、核验、图片处理、范围检查”，就优先改成参数化通用工具。

只有以下内容应继续留在公司专用区：具体业务正文、型号结论、活动规则、真实ID清单、一次性迁移数据。
