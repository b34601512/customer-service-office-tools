# 企业微信：能力与红线（木婉清专属）

> 来源：官方文档（open.work.weixin.qq.com/help2/pc/21676）+ 本仓库实践（1/4/14/19/22/24/25号）+ 2026-09-28~30 实测。
> **这是唯一出处**：22/24号 的 `经验/企业微信-能力边界.md`、27号 的 `经验/踩坑与红线.md` 都只留指路。
> 最后更新：2026-09-30

## 一、两种"机器人"，各管一段（用户 2026-09-30 拍板）
| | 木婉清（智能机器人 / aibot） | 群机器人（webhook） |
|---|---|---|
| 怎么接 | `wecom-cli`+Skill（27号） | 群里加机器人拿 webhook 地址 |
| 能发 | markdown / 图片 / 文件 / 语音 / 视频 | text / markdown / markdown_v2 / image / news / file / voice / template_card |
| **能 @ 人** | ❌ 没有 @ 参数（只能正文写名字） | ✅ `mentioned_mobile_list`（手机号）、行内 `<@userid>` |
| 能读消息 | ✅ 单聊/被 @ 的群消息（最近会话） | ❌ 单向，只能发 |
| 用在哪 | **群消息默认都走它**（默认群「金牌组」） | **只在需要真 @ 人时**用 |

- 群消息：**统一由木婉清发**；不能真 @ → 正文写「@张三 …」。要真 @ 才回退 webhook（2026-09-30 用户拍板）。
- 发消息一律**拆条、每条 ≤100 字**（像人聊天）；每次用 `wecom-cli message aibot sessions list` **现取** chat_id。

## 二、必须停下来问人的事
1. **扫码/验证码/短信验证 → 本人做**（`wecom-cli auth init` 会阻塞等扫码，窗口留可见叫人）。
2. **任何真实发送（群消息、单聊、邮件、文件回传）先给用户确认**（内容 + 目标）；27号脚本默认 dry-run，只有 `--send` 才真发。
3. 仓库通用红线照样适用：天猫发票「待同意」不点；金山表只读；平台后台只读。

## 三、路线 A（webhook）的坑
- **webhook 地址 = 密钥**：拿到就能发消息 → 不入库、不外传（只放本机 `project-config/`，已 gitignore）。
- **限频 20 条/分钟** → 超了 `errcode=45009`；**不自动重发**（重复消息比漏一条更糟）。
- 只能发到它所在的群，**不能私聊个人**；markdown 类型**不支持 @**。
- **key 真假探不出来**：非法请求一律回 `40058`（连假 key 也一样）→ 验 key 只能"真发一条最小消息"（先问用户）。（2026-09-30 实测）
- 机器人被删/重建会**换 key**：同一串 key 出现在 `14/22/24/25号` 的本地配置里，要一起换。

## 四、路线 B（木婉清 / CLI）的坑
- **只能发给「授权人本人」或「机器人最近有消息往来的会话」**：不能拿通讯录 userid / 历史 chat_id / 手打 ID 直接发；
  正确姿势 = `message aibot sessions list` 取**本次返回**的 chat_id；匹配不唯一就反问。
- **输出禁止出现内部 ID**（userid / chat_id / mail_id / media_id / docid…），一律用姓名、群名、主题、时间代替。官方硬约束，不因索要而放宽。
- 版本：`wecom-cli >= 1.2.1`；用前先 `wecom-cli --version` + `wecom-cli auth show --status`，不猜授权状态。
- 数据类权限（搜邮件/文档/会议/微盘/通讯录）可能要管理员审批；免审配置在：管理后台 → 安全与管理 → 管理工具 → 智能机器人 → 管理。
  （2026-09-30 实测：通讯录搜索报 `850002 no authorization` → 没授权就先不用它查 userid。）
- **官方风险提示（原文）**：AI 调 CLI 有模型幻觉导致数据泄露、越权的风险 → 不要批量操作生产数据，发送类动作人工过目。
- 两种接入方式（`auth init`）：①扫码（推荐）②手填 API 模式机器人 Bot ID + Secret；`--manual` **必须真实终端**（管道报 `893001`）；
  Secret 只在该窗口输入，**不要贴到聊天记录/文档/工单里**。

## 五、做不到的事（别重复踩）
- **读群消息**：webhook 是单向的（官方文档只有"消息推送"，没有接收接口）→ 读不到。
- **会话内容存档**（技术上能读群消息）：要管理后台开启 + 员工知情 + 外部联系人同意 + C++ SDK 拉取；
  **用户没有管理后台权限 → 2026-09-21 拍板堵死，不再尝试、不再提**。
  替代思路：让客服把信息写进可读渠道（金山表/智能表格）。

## 六、给其他客服主管的建议（2026-09-28 用户拍板）
- **默认走扫码**：不懂技术的主管只需做一件事——双击 `scripts/扫码授权.bat`，用手机企业微信扫二维码；创建机器人 + 授权一次完成，不用进后台、不用填 ID。
- API 模式（Bot ID + Secret）只留给「不想扫码 / 要把机器人凭据复用给 MCP/API」的人，并要求会开终端窗口。

## 七、消息收发范围（2026-09-28 实测）
- **单聊**：别人跟机器人单聊过之后，他后续每条消息机器人都收得到（不用 @），也能随时主动发他。
- **群聊**：机器人**只收到 @它的那条消息**；群里不 @ 的闲聊收不到（系统原文：「机器人在群聊内仅可获取和回复@他的消息」）。引用回复、不 @ 的发言一律收不到。
- **【可见范围】是硬闸门**：范围外的成员 @ 机器人，平台根本不推送；加进可见范围后立刻恢复。
- **会话列表**（`message aibot sessions list`，最多 20 个）：**只有「别人发进来」才刷新；机器人自己发的不刷新** → 别指望“常发消息保活会话”。
- 能发给谁：授权人 + **本次** sessions list 里的会话（chat_id 必须现取，不能复用旧的/userid）。
- **想读消息正文 → 只能上长连接**（`aibot_subscribe` 订阅、`aibot_msg_callback` 收、`aibot_respond_msg` 回）；CLI 只给会话列表，不给正文。

## 八、2026-09-29 实测补充（木婉清入职当天）
- **断线即丢**：连接断开期间到达的消息，**平台不补推** → 守护必须常驻（`tee -a .state/daemon.log` 留痕；日志里 `WebSocket connection closed` / `Received disconnected_event`＝被新连接顶掉）。
- **媒体默认看不到**：守护从 2026-09-29 起用 `downloadFile(url, aeskey)` 自动解密另存 `.state/media/`，记录里带 `mediaPath`。
- **秒级响应靠事件唤醒**：守护每收一条打印一行，调度器监听「监控输出」事件唤醒 AI，再按字节 `offset` 只读增量——比定时轮询快、也更省 token。
- **参数不要凭记忆猜**：Skill 目录里每个业务域都有一份 `references/wecomcli-*.md`，先读再拼命令。

## 九、入库 / 开源边界（企微部分）
- **绝不入库**：webhook 地址、Bot ID/Secret、`wecom-cli` 凭据、登录态、工单/聊天内容、客户与员工姓名手机号、真实表名与群名、内部文档链接。
- **可以入库**：官方文档链接、安装/排错步骤、错误码含义、参数化脚本模板（默认 dry-run）、脱敏示例（张三 / 13800000001）。
- **提交前检查**（机械做）：`git diff --cached` 搜 `key=`、`secret`、`webhook`、长数字手机号、订单号、真实人名/群名 → 命中就必须是占位符。
- 完整的仓库级判定清单见根 `开源边界.md`（落点、已处理项、待处理项都在那）。
