## 一、读
- 套列表：`phrase-set list --workspace <ws> --scope team`（拿 phrase_set_id / revision / 名字）
- 类目：`category list --workspace <ws> --scope team --phrase-set <0-9> --level 1|2 --limit 100`
- 话术：`phrase list … --phrase-set <0-9> [--category-id <uuid>] --limit 100 [--after <next_cursor>]`
  （**limit 上限 100**；分页看返回 `has_more` + `next_cursor`，字段名 `cursor_parameter=after`）
- 单条：`phrase get --workspace <ws> --scope team <phrase_id>`（**位置参数**，不是 --phrase-id）→ 给 `answer_raw`/`assets`/`revision`/`document_version`
- 附件：`attachment get --workspace <ws> --scope team --phrase-id <id> --file-id <id>`
- 导出全库：`export run --workspace <ws> --idempotency-key <k> --scopes '["team"]' --format xlsx --out-path <绝对路径>`
  （⚠ `--scopes` 要 JSON 数组；`--dry-run` 是开关、不带值）

## 二、写（都带 `--expected-revision` + `--idempotency-key`）
| 想干的事 | 命令 | 备注 |
|---|---|---|
| 类目换套/换父 | `category move` | **`--target-phrase-set` 与 `--parent-id` 只能二选一**（同时给 = INVALID_REQUEST）；给 parent_id 时配 `--expected-parent-revision`。**一级整棵子树跟着走**（子类+话术） |
| 套改名 | `phrase-set rename --phrase-set-id <id> --name <新名>` | 免审批 |
| 建类目 | `category create --level 1|2 --name <名> [--phrase-set <n> | --parent-id <id> --expected-parent-revision <r>]` | level1 给 phrase-set、level2 给 parent_id |
| 挪话术（同套内） | `phrase move-many --category-id <目标类> --expected-category-revision <r> --items '[{phrase_id,expected_revision}]'` | **目标必须是二级类目**；挂在一级下会 NOT_FOUND；**跨套挪单条话术不支持**（要跨套只能整类目搬） |
| 删话术 | `phrase delete-many --items '[…]'` | 要人工在客户端批准；删的在回收站可恢复 |
| 删空类 | `category delete --category-id <id> --expected-revision <r>` | 要人工批准 |
| 清空套 | `phrase-set clear --phrase-set-id <id> --expected-revision <r>` | 要人工批准；**先清后搬**，别反了 |

## 三、给话术挂图/附件（2026-10-05 打通，已换成官方 `content` 写法）
**首选（2026-10-05 16:1x 起，#3255）**：`phrase.create/update` 传 **`content`** 数组，程序自己转格式：
```jsonc
[{"type":"text","text":"…"},
 {"type":"image","path":"D:/绝对路径/a.png"},
 {"type":"file","path":"D:/绝对路径/b.xlsx"},
 {"type":"break"}]
```
读回来 `phrase.get` 也给同样的 `content`（`file_id` 形式）；**v3 条目不再回 `answer_raw`**。

### 老写法（仍可用，手写 v3 文档 + files）
`phrase.update` 传 **`document_raw` + `files`**（两个必须一起，单传 files = INVALID_REQUEST）：
```jsonc
// document_raw（v3 文档，注意前缀）：
"__softtalk_rich_v3__:" + JSON.stringify({
  "v": 3,
  "items": [{"t":"message","blocks":[
    {"t":"text","s": <原 answer_raw>},
    {"t":"img","file_id": <临时uuid>,"name": <文件名>,"mime":"image/png","size": <字节数>}
  ]}]
})
// files：
[{"file_id": <同一个临时uuid>, "path": "D:/绝对路径/xxx.png"}]
```
- 服务端会把临时 file_id **映射成真身份**（回执 `file_id_map`），文件进缓存（回读 `assets[].availability=cached`）
- `answer` 与 `document_raw` **不能同时传**；改文字用 `--answer`，挂图用 `document_raw`
- 上限：每条最多 9 图 + 9 文件；`document_raw` ≤ 200000 字符
- 用 `--input-file <json文件>` 传复杂参数最稳（避免命令行转义）
- 工具脚本参考：`任务证据/2026-10-05-客服宝图片/`（挂图日志 + 核对）

## 四、红线
- **改写已有话术/删除/清空 = 要人工批准**（CLI 不能批，只能在客户端点）；纯追加免审批
- 失败**不自动重试**；批量化前先 `--dry-run` 看 PREVIEW
- 不确定格式先 `schema <命令>` 看 input_schema；命令清单 `capabilities`
- **规定动作（黎路遥 2026-10-06 13:12：「后面你就用新方法看看是否有现成的话术」）**：业务问题先**按类目把相关类目列全、逐条读标题**，看有没有现成话术可用；确认没有再另想（补话术/写卡）。
- **找话术的正确顺序（2026-10-06 黎路遥追问后定）**：**先按类目列全，再挑**——`phrase list --workspace <ws> --scope team --set <0-9> --category-id <类目id> --limit 100`；类目 id 可从任一条话术 `phrase get` 的 `category_id` 反查（例：到货时效类目 `2562e16f-877e-4812-ae8d-56a12db839e3`，8 条全在）。`phrase search` **只按标题匹配**（不搜正文），标题里没那个词就搜不到 → 别只靠关键词猜。
- **搜话术**（2026-10-06 实测）：`phrase search --workspace <ws> --scope team --set <0-9> "<关键词>" --limit 20`——注意是 **`--workspace`/`--set`**（不是 `--workspace-id`/`--phrase-set`），关键词是**位置参数**（不是 `--query`）；返回里只有 `question`+`phrase_id`，**正文要再 `phrase get <id>` 取**（`content[]` 里 `type=text` 的 `text`）。
