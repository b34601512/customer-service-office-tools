# 探域「未成交（未下单）」会话取数方法（只读，2026-10-10 实测）

> 结论：探域后台**没有**「未成交订单 / 询单未转化」的客户级清单。
> 数据罗盘只有聚合：`/api/data-service/business/compass/summary`、`section/table`、`section/trend`、
> `customer-service/table`、`customer-service/detail/table`（按客服×日，不是按客户）；
> 「智能跟单」是营销侧跟进，不是 AI 会话质量数据。
> **可用信号** = 调优记录（agent-trace）按 `orderStatusList=[0]`（未下单）筛 + trace 明细 + 整段聊天。
> 本文件是唯一取数口径；实测响应在证据 `10-窗口探测-结果.json`、`15-未下单全量-结果.json`、`20/22`。

## 1. 会话清单（未下单筛选）

- `POST /api/im/agent-trace/paginateV2`
  - body：`{ "thirdShopId": "<店铺id>", "pageIndex": 1, "pageSize": 5000, "beginTime": "YYYY-MM-DD HH:mm:ss", "endTime": "YYYY-MM-DD HH:mm:ss", "orderStatusList": [0] }`
  - `orderStatusList` 是**未公开在文档里的筛选参数**（2026-10-10 实测）；值为订单状态枚举：
    `0=未下单 / 100=待付款 / 101=待发货 / 102=待成团 / 103=已发货 / 104=交易成功 / 105=交易关闭 / 106=订单取消 / 107=部分发货`
    （枚举来自前端 JS 常量；`orderStatus`/`orderStateList` 等其它写法**无效**，会静默返回全量）。
  - 返回行含：`id(=追踪ID/cardId), time(epoch ms), question, topicName, searchContent, content[], ifSend, sendType(1自动/2点击/3编辑), type(CONSULT_REPLY/CONSULT_PRODUCT), sellerAccount, buyerAccount, productInfo`。
  - 时间**必须带秒**（只到分会被拒/返回 code=0，2026-10-03 已记）。
- 行内没有订单状态，**必须**再拉明细才有 `orderState`。

## 2. 明细（订单状态 + 召回卡 + 风险）

- `POST /api/im/agent-trace/trace`，body `{ "cardId": "<行id>", "thirdShopId": "<店铺id>" }`
- 关键字段：
  - `orderState`：`售前(未下单)`、`发货后` 等；`orderStatusDesc`：`未下单`/`已发货`…
  - `noSendReason/Name`（未发送原因）、`riskRating`、`logIsCredible`
  - `snapShots[]`：召回的知识卡片段（`docId`、`chunkId`、`type=SHOP/DETAIL/CHAT`、`content`）
    - 注意：`chunkId` ≠ 卡片 id；查卡要用 `/api/kbe/v1/knowledge-card/detail?id=<卡id>`，卡 id 从全库列表拿（见 §4）。
  - `content[]`：该条生成的回复；`ifSend/sendType`。

## 3. 整段会话

- `GET /api/im/agent-trace/get-chat-list?thirdShopId=<店id>&cardId=<任一行的id>`
- 返回整段会话（无分页），`personType`：`0`=智能体、`1`=客服侧、`3`=买家；含人工消息——**只有它能看"AI有没有答到点上/人工接没接"**。
- 注意：一次拉一段；批量分析时先按 `buyerAccount` 去重，每个买家最多拉 1 次。

## 4. 卡片详情（为每条问题定位来源卡）

- `GET /api/kbe/v1/knowledge-card/detail?id=<卡id>`
- 卡 id 从全库快照/列表拿：`POST /api/kbe/v1/knowledge-card/page`（body `{pageNo:1, pageSize:8000}`，忽略分页一次给全）；
  本地已有快照可用 `17号/02.业务专用/德达医疗/任务/2026-10-10-每日例检/D2b-卡库快照.json`（7830 张，含 id/title/ifBelievable/ifOpen）。
- 定位口诀：trace `snapShots` 的 `content` 与 AI 回复逐句比对 → 找到对应 `content` 所在卡；再用标题在全库快照里查 id。

## 5. 复现命令（本机）

```bash
# 清单（注意 --browser-channel msedge，否则会找 headless_shell 报缺可执行文件）
PLAYWRIGHT_CORE_PATH="D:/桌面/木婉清/23.进店咨询导航问答优化/node_modules/playwright-core" \
node "17.探域科技AI自动配置/01.通用/工具/探域只读批量调用.cjs" \
  --base-url "http://agent.tanyuai.com" --profile "C:/Users/b3460/.pi-edge-auto" \
  --browser-channel msedge --allow-post true \
  --calls "调用清单.json" --out "结果.json"
```
- 调用清单 JSON：`[{ "name": "…", "endpoint": "/api/…", "method": "POST", "body": {...} }]`（GET 不用 --allow-post）。
- 坑：① Git Bash 裸 `/api/...` 无 query 会被 MSYS 转成路径 → 加 `MSYS_NO_PATHCONV=1`；② 大响应别用单条模板，容易撞 SPA 导航；③ 探域后台默认只读，本方法全程无写接口。

## 6. 已知限制（写进结论时要带上）

1. `orderState` 是**查询时刻**的状态：买家可能之后才下单，不等于平台口径的「询单未转化」（平台是 T+2、按买家去重）。
2. trace 只记录**智能体生成**的话术；人工客服自己发的消息不在里面（截图案例即如此）。
3. 窗口建议 1~2 天（本次 2026-10-09 00:00 ~ 10-10 17:30），30 天全量请求量大。
4. 京东自营店该窗口 0 条、京东DEDAKJ 仅 14 条 → 单店样本天然很小，结论要按店分开看。
