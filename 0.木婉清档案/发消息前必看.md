# 发消息前必看（唯一一份 · 木婉清）

> 为什么有这份：黎路遥 2026-11-02 连着说了三遍——
> 「你怎么发信息到客服群了」「这个事情已经发生很多次了，莫名其妙往某个群里发一条信息」「谁问你，你就回问谁」。
> 光写规矩没用，所以配了程序硬闸：**所有企微发送只走 `工具/企微/发企微.cjs`**；回复、主动私聊、主动群发各走固定信息流。

## 一、默认：私发到人

发任何消息前先问一句：**这条是发给一个人的，还是全组都要知道的？**

- 只有一个人要办 → **私发到他本人**（企微单聊，或内部私信）。
- 拿不准该谁 → 私发**他那组组长**让他分（售后＝李某某，售前无组长→私发到人问）。
- **私发优先于群发**：群里刷一遍容易漏，人收到才算派到。

## 二、谁问我，我就回问谁

别人把「要真人答的问题」交给我时：

1. **先回问提要求的那个人**：这是哪个任务、谁派的、最后要转给谁。
2. 他给不出「该问谁」→ 这件事就不该由我扩散，退回给他自己对接。
3. **不许我自己判断「可能谁懂」就去发群/发一堆人**。

> 2026-11-02 事故：王语嫣把两个订单型号确认交给我转客服，我判断「售前售后都可能知道」，直接发到客服群，被黎路遥撤回。正解＝回问她该问谁；她答「该问李沅芷」，那就私发李沅芷。

## 三、所有企微消息只走 `发企微.cjs`

```bash
cd "D:/桌面/木婉清/工具/企微"
node 读收件箱.mjs
node 发企微.cjs --回 R-XXXXXXXXXXXX --file 回复.txt --send
node 发企微.cjs --人 "邓某某（售后）" --file 正文.txt --send
node 发企微.cjs --群 "售后群" --理由 "售后全组都要知道：…" --file 正文.txt --send
```

三种模式互斥：

- **回复来信用 `--回`**：复制该条消息旁边的匿名回复码。目标由原消息定死；后来新到的群消息、其他客服私信或黎路遥私信都不能顶掉。
- **主动私聊用 `--人`**：只认本机人名表里的精确姓名；没起名、重名、把群当人，全部拒绝；底层同时签发一次性单聊路由票。
- **主动群发用 `--群`**：只认精确群名，不认数字编号；必须给理由，底层签发一次性群聊路由票。两类路由票都只有 60 秒、固定目标和渠道、只能使用一次。

> 2026-11-02 事故二：邓某某私发一单发票，回复时把「售后」误当售后群。根因不是“没记住规矩”，是发送工具允许按最近联系人和动态编号重新猜目标。现已从底层停用这两种入口。

## 四、程序硬锁（不是提示词）

1. `直连.mjs --回复` 永久拒绝：不再回“发送瞬间最后一条来信”。
2. `直连.mjs --to 数字` 永久拒绝：列表序号不是身份。
3. 主动私聊或群发没有工具包签名路由票永久拒绝；票固定目标和渠道、短时有效、用一次即销毁。
4. 出站台账同时记目标类型和来源回复码；不能再只记“发送成功”却查不出回错了谁。

每次真发仍落 `工具/企微/.state/发消息台账.jsonl`；不加 `--send` 只预览。

**正文里有反引号/`$()` 一律用 `--file`**。一条消息只装一件要对方动手的事。
