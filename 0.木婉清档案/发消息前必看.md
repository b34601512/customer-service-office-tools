# 发消息前必看（唯一一份 · 木婉清）

> 为什么有这份：黎路遥 2026-11-02 连着说了三遍——
> 「你怎么发信息到客服群了」「这个事情已经发生很多次了，莫名其妙往某个群里发一条信息」「谁问你，你就回问谁」。
> 光写规矩没用，所以配了一道闸：**发群只能走 `工具/企微/发群.cjs`**，不给理由发不出去。

## 一、默认：私发到人

发任何消息前先问一句：**这条是发给一个人的，还是全组都要知道的？**

- 只有一个人要办 → **私发到他本人**（企微单聊，或内部私信）。
- 拿不准该谁 → 私发**他那组组长**让他分（售后＝李某某，售前无组长→私发到人问）。
- **私发优先于群发**：群里刷一遍容易漏，人收到才算派到。

## 二、谁问我，我就回问谁

别人把「要真人答的问题」交给我时：

1. **先回问提要求的那个人**：这是哪个任务、谁派的、最后要转给谁。
2. 他给不出「该问谁」→ 这件事就不该由我扩散，退回给他自己对接。
3. **不许我自己判断「可能谁懂」就去发群/发一堆人**。

> 2026-11-02 事故：王语嫣把两个订单型号确认交给我转客服，我判断「售前售后都可能知道」，直接发到客服群，被黎路遥撤回。正解＝回问她该问谁；她答「该问李沅芷」，那就私发李沅芷。

## 三、发群三条硬条件（缺一不发）

1. **任务驱动**：因为某件事必须让全组看到，不是「通知一声」。
2. **全组都要知道**：能私发的绝不发群；发不出去的理由写进 `--理由`。
3. **群选对**：群归属看 [`谁能发哪个群.md`](./谁能发哪个群.md)（售前的事不发售后群，反之亦然）。

命令（不给理由直接拒绝）：

```bash
cd "D:/桌面/木婉清/工具/企微"
node 发群.cjs --群 4 --理由 "售后全组都要知道：本周起退款单改走 X 流程" --text "正文" --send
```

- 每次发群落台账 `工具/企微/.state/发群台账.jsonl`（时间/群/理由/开头），事后可查。
- 不加 `--send` 只预览，什么都不发。

## 四、发企微私聊（黎路遥/同事）

- 直接 `node 直连.mjs --to <编号> --text "…" --send`；`--to 2` ＝黎路遥。
- **正文里有反引号/`$()` 一律用 `--file`**（2026-11-02 就因反引号被 shell 吃掉，把文件路径发成了空白）。
- 一条消息只装一件要他动手的事；整条发、不拆条、不挂编号。
