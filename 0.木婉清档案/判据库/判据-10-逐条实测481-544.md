**四百八十一、「证据」列是给质疑用的，「影响」列是给判断用的。**
（同上：**「这个数只用来判断该不该动，不用来考核」——这句话写进「证据」会被当成证据的一部分，写进「影响」才对**，因为影响列本来就是讲后果的。）

**四百八十二、附注只留给需要人记住的那一条，其余照实写「无」。**
（同上：**如果每条「无」都带附注，这一列就没法扫了。**）

**四百八十三、「一条没人敢问的问题，会在最坏的时候被人问出来；一条摆在那里的行，会在最好的时候被人看到。」**
（同上，配殷素素抄走的那句「一条永远没人动的行，比一个没人敢问的问题好」。）

**四百八十四、会上最怕的不是数不精确，是「我们再查查」。**
（同上：**明天会前她必须备一个「初步数」，哪怕粗糙。**）

**四百八十五、老板说「9号项目，他手上的」——我第一版回的是 22号（半小时白干）。**
（2026-10-19 17:10：**老板问「今天有做巡检吗，为什么没看到客服数据更新」→ 我查了 22号 平台退款检查（跑了、13 店全跑到）→ 老板：「我说的是 9号项目，他手上的」。**）
**「客服数据」= 9号；「平台退款/巡检」= 22号。两个词在我这里是同义词，在他那里是两个项目。**
→ **判断动作：他说的那个词，先在我自己的项目表里搜一遍，看有几种东西对得上；有两种以上就先问一句，别挑一个先干。**

**四百八十六、9号 断了三天没人喊——因为「没跑」和「跑了但没问题」在报表上长得一样。**
（同上：**最后一次采集 10-16；10-17/18/19 三天零记录。金山仪表盘上看到的还是 16 号的数据，而没有人收到任何报警。**）
**同族**：`catch { return null }`、`已达标`、`扫描 0 行报 ✅`——**都是「什么都没发生」和「一切都好」共用一个输出。**

**四百八十七、先跑一家，跑通了再跑全量。**
（同上，给霍青桐的话：**「随便挑一家跑通了我再让你跑全量。跑不通就说卡在哪——不要反复重试，一次不通就停。」**）

**四百八十八、说错一个数，别人会说「你说错了」；说错一个性质，别人会说「好，那我去改」。**
（殷素素 2026-10-19：她差点报「13 张卡互相矛盾，差 36 个百分点」→ **查 SPU 才发现是 12 个不同机器，2L 时 60%/80%/95%/96% 是四台机器的真实参数**。）
**为什么更危险**：**她的判据（正则抽「NL/min≈X%」）完全正确、抽出来的数每一个都对，只有「放在一起比」这一步错**——**证据看起来太硬（13 个卡 id、四组数、有占比），运营当场就会分派任务，而那四张卡全是对的。**
→ **拿到「看起来很硬」的结论时，先问一句：这些东西是同一个东西的几种说法，还是几个不同东西各自的说法？**

**四百八十九、「我需要明天查清楚」在会上的效果是他们在等你。**
（同上：原句「另外 35 条数字有出处，但有一个隐患我需要明天查清楚」→ **改成「那 35 条数字本身有出处，但它们对应 12 个不同的机器型号。接下来要确认的是：AI 给数字的时候，说的是不是客户正在问的那台。」**）
**差别**：**「原句是一件事没做完，改后是一个已知的风险点。会上听到前者的反应是『那下次再说』，听到后者的反应是『这个要紧』。」**

**四百九十、判据正确，不等于判据说的是你想问的那件事。**
（同上：**「这个数字在库里搜不到」——按这个判据那 1 条真错抓不出来，因为 28% 和 30% 库里都有**，只是一个在「机器规格表 7L/min」语境、一个在「人体实际吸入浓度」语境。）
→ **「同一件事」机器判不了，只能人判。**

**四百九十一、跑之前先把写死的常量抄进回执（原值 + 改成什么 + 什么时候改的返回）。**
（同上，霍青桐发现 `tmall1.exportDateRange` 写着 `2026-10-01~10-14`——**大概率是 10-16 为了对齐手改的，之后没改回**：**「如果这次改完忘了改回，下一次又会拿着一道旧的题跑。」**）
→ **这就是「写死的常量答的是另一道题，而它每天看起来都在正常工作」。**

**四百九十二、不要为了「让它跑通」去绕登录。**
（同上，对霍青桐：**「这三天数据没有就是没有，绕出来的数据比没数据更坏。」**）

**四百九十三、「证据太硬」的时候，最该问的不是「对不对」，是「这些东西是不是同一个东西」。**
（殷素素 2026-10-19：**「证据硬不等于结论对，但硬证据会让人停止提问——包括我自己。」**）
→ **「对不对」你会去核对每个数，每个数都对；「是不是同一个东西」你要去看它们的出处。前者看得见，后者看不见。**

**四百九十四、「我需要查清楚」vs「这是已知风险」——分岔写清才叫判据。**
（同上，殷素素补的分岔：**已知风险 → 写成「X 是已知风险，接下来确认的是 Y」；未知问题 → 才写「还在查」。**）
**根因**：**「我写东西的时候，是在向对面报告『我做到哪一步』；而会上的人读的是『现在这件事处于什么状态』。」**
→ **「写『我需要查』，等于把一件已知风险降级成一件未完成事项。」**

**四百九十五、经验要按「我缺什么能力」并，不按「我错了两次」并。**
（同上：**「分成两条，将来读的人会以为是两个不同的坑，各学一遍。并成一条，才会看到『我缺的是同一件事这个判断能力』。」**）
→ **并的方式：不是并成「我犯过两次错」，是并成「同一件事的两种错法」。**

**四百九十六、「看不见的故障」会被当成「没有故障」；「看得见的空转」会被当成「一切正常」——后者更难纠正，因为纠正它要先推翻一个已经被接受的事实。**
（同上，殷素素拒绝挂一条永远不会触发的监听链：**「挂上去 Monitor 会跑起来，但永远不会触发 monitor:output，因为那个文件 40 小时零新增。而它会产生一个假的『我这边链条正常』的假象——将来有人查，会看到链在跑，从而以为通道是通的。这比不挂更危险。」**）

**四百九十七、自动体检按「应该有什么」来查，但它不知道「这台机器的那个部件已经被拆了」。**
（同上：**「它查完会说『你缺 X』，这句话本身是对的——它缺的正是『这台机器还是不是原来那台』。」**）
→ **动作：以后收到「你缺 X」的自动提醒，先查 X 还能不能用，再决定装不装。否则就是往一个已经封的接口上接一根管子。**

**四百九十八、「对不对」是核对，能做完；「是不是同一个东西」是定义，做完之前你不知道该核什么。**
（殷素素 2026-10-19 收工前最后一次自省：**「两次我都在核对『对不对』（13 张卡的数字一个一个核过全对／28% 在库里搜过有），两次我都没问『是不是同一个东西』（13 张卡是不是在说同一台机器→12 个 SPU／库里的 28% 和 AI 说的 28% 是不是同一件事→流量对照 vs 吸入浓度）。」**）

**四百九十九、「不挂」有人会问「为什么没有」；「挂上但空转」没人会问，因为看起来有。**
（同上：**「而『看起来有』这件事，会在某一天变成『我们一直以为它是通的』。」**）

**五百、不是「自动体检不可信」，是「自动体检的判据里少了一个维度：这台机器还是不是原来那台」。**
（同上：**这比「体检错了」准——体检没错，它只是不知道这台机器已经换了。**）

**五百零一、「今天的数据还没生成」和「系统坏了」是两件完全不同的事——前者要改口径，后者要修东西。**
（2026-10-19 霍青桐实跑：**登录 19 秒全过（17:27:38「确认已登录页面」），卡在「应用日期」——`rangeRight` 选择器带 `:not(.disabled-element)`，10-19 那格存在但被标成 disabled。**）
**报老板时分成三层**：①三天没跑（最直接）②智能模式永远延迟 2 天（设计如此）③**改到今天也拿不到，因为平台自己还没生成**。
→ **「没更新」不是「有人偷懒」，是「这套东西的口径和您的期待不一样」。**

**五百零二、「菜单上写着延迟 2 天」是观测，「实际能跑到 18 号」才是验证。**
（同上：**霍青桐那句「智能模式永远延迟 2 天」是从菜单文字和源码推的，还没被「连续跑两天」验过** → **必须带这个边界，否则明天 18 号还是灰的，那句话就变成一个错误的事实。**）

**五百零三、推断和观测在报给老板时必须分开说。**
（同上：**「登录是通的」= 你自己跑出来的（17:27:38 日志原文）＝观测；「延迟 2 天」= 从菜单文字和源码推的＝推断。**）
→ **「观测错了要马上去查，推断错了只是明天换个做法。」**

**五百零四、第三方软件：我的推断在它的行为面前作废。**
（同上，霍青桐自己主动声明：**「这个软件是第三方写的，不是我的代码。我今晚做的所有判断都是读它的日志和源码得出的，但我不能保证我读懂了它的全部逻辑。如果它以后行为跟我的判断不一致，以它为准，我的推断作废。」**）
→ **这条比任何免责声明都有用——它给了下一个人的第一条动作：先看它怎么动，别信我的解释。**

**五百零五、`exportDateMode: "automatic"` 会让单店写死的 `exportDateRange` 变成死数据。**
（同上：**9 家店日期全写着 `2026-10-01→10-14`，但那个值根本没生效**——**智能模式自己算日期，不读单店的值**。）
→ **「日期停在 10-14」不是有人改坏了，是智能模式在 10-16 那天就该算出 10-14（16-2）。真问题是 10-17 之后就没人跑过。**

**五百零六、「改了一个地方，以为改了，其实那一处根本不生效」——这是「写死常量」的隐形版。**
（霍青桐 2026-10-19：**「我改了 `globalDefaults.exportDateRange → 10-18`，但我在 17:25 把 `tmall1.usesGlobalExportDateRange` 设成了 false ⇒ 它不读全局，读自己的 ⇒ 而它自己的还是 10-19。」**）
**为什么更隐蔽**：**「常量的值是错的，你能看出来；而『不读这个变量』是看不见的」**——**改完还会得到一个看起来合理的失败，去查那个值对不对，永远查不出问题。**
→ **动作：改配置，改完先问一句「这个值是被读的那一份吗？」**

**五百零七、「以自己跑出来的」和「读代码推出来的」之间要留第三格：说不清。**
（同上：**三分法是「观测（我自己跑出来的）／推断（读代码和菜单得出）／说不清（今天没能定）」**——**「二分法会逼着人把『说不清』塞进『推断』，而『推断』听上去是有结论的。」**）

**五百零八、三条都成立的观测放在一起可能是矛盾的——那说明中间有一句是我理解错了。**
（同上：**「19 号那格是灰的」= 观测；「18 号那格能选」= 观测；「自动模式配置写着 delay=2」= 观测**。）
→ **「如果延迟真是 2 天，19 号这天应该只能选到 17 号。」** 所以更准的说法是：**「自动模式给自己算的是 T-2，但平台其实能给到 T-1——这意味着自动模式每天白丢一天数据。」**
→ **「不是坏了，是天天少一天」——这是老板最关心的那种事。**

**五百零九、「没做」不是「失败」。**
（同上：霍青桐跑完 17-18 后说：**「金山同步我没跑（只按了 [1] 没按 [A]），④⑤ 不是失败，是『没做』。这两个字要分清。」**）
→ **「失败」要查原因，「没做」只要补做；混在一起会让一段正常的流程看起来像事故。**

**五百一十、「跑得通」和「能验证别的」是两件事。**
（同上：**只测了天猫1，不能推出京东/拼多多/抖音的登录态**——**「京东那 3 家大概率要重新扫码，所以跑全量很可能会卡在人扫码那一步。」**）

**五百一十一、「只跑一部分」在采集环节是安全的，在同步环节是破坏性的。**
（霍青桐 2026-10-19：**同步 AirScript 是 `A1:X(newLastRow)` 全量覆盖 + `ClearContents` 清尾巴——本地 10 行 → 在线 2527 行被削到 10 行，2517 行内容清空。**）
**危险组合**：**采集可以只跑一家（`includedInSummary:false`）＋ 同步是全量覆盖 ＝ 每跑一家，就把其余全部删掉。**
→ **「这个组合平时看不出来，因为正常流程是『全跑完再同步』。」** **而「先跑一家试试」这个动作，本来是安全的。**

**五百一十二、报警的判据要盯「事件行」，不要盯「全文关键词」。**
（同上：她的检测器 `if (/登录已过期|扫码|安全验证|滑块/.test(全文))` 命中的是**菜单里的说明文字**——**「程序将按天猫、京东……出现滑块或安全验证时，浏览器会停在原地等待人工处理。」**）
→ **「说明文字、帮助文字、示例文字，跟我担心的那件事长得一模一样。」**
→ **修法：只认带时间戳的运行行（`[HH:MM:SS] [运行/失败]`）＋ 行内有动作词。** 双向验过：真日志 0 条／编一条真弹登录 → 1 条。

**五百一十三、报错警报比报错数字更贵，因为它会叫人来。**
（同上：**「前三次错：报一个错数字 → 撤回来就行；这次错：我会拿着『需要老板扫码』去报你 → 你把老板叫来 → 老板看了半天发现没弹窗。」**）

**五百一十四、「文件不存在」这个报错，可能是「用这个 cwd 找不到这个文件」，不是真没有。**
（同上：`spawn(process.execPath, [...], { cwd: "D:\...\9.客服数据自动更新" })` → `ENOENT`，而那个 node.exe 明明存在（92MB，ls 过）。）
→ **不传 cwd、让它继承 `process.cwd()` 就一定能跑；要换目录，先 `process.chdir()` 再 spawn。**
→ **同类**：**报错信息说的不是我以为的那件事。**

**五百一十五、报坏消息要在他自己发现之前，而且要说「现在是什么、正在怎么办、什么时候再报」。**
（同上：在线表被削到只剩 1 家店 → **「因为表里现在只有一家店，他随时可能打开。瞒着比报错更糟。」**）
→ **报法三句：①今天补了天猫 17-18②同步是全量覆盖所以现在只有这一家③剩下 8 家正在跑。**

**五百一十六、先跑一步验通路，和正式口径是两回事——正式口径变了，验通路那步的数据不用留。**
（2026-10-19 老板拍板「统一按 16 号」：**天猫 17-18 那 10 行是验通路用的，口径一变，反正会被 10-01~10-16 的全量覆盖，不用回滚**——**「最终状态以跑完全量后的那次同步为准。」**）

**五百一十七、他要哪天的数据，不是技术问题，是他的报表用什么口径。**
（同上：**「我要的就是16号的数据，因为转化率有的店铺只更新到16号，所以我统一按16号」**——**17/18 虽然能采，但会让金山表和周报两边数字对不上**。）
→ **数据范围跟着他的口径走，不跟着「能采到哪天」走。**

**五百一十八、周报不是「做了什么」，是「目标差多少、为什么、下周怎么办」。**
（2026-10-19 领导评价：**「感觉你的汇报里内容很多……但跟我们想要的结果还是有区别。每周汇报更应该体现周/月即时目标达成率……差异原因从你的数据分析中得出该改善的地方，形成有效的改善措施和目标，以便下周检验结果。」**）
→ **结构 = 目标达成率 + 差异原因（从数据来）+ 改善措施 + 下周检验。**

**五百一十九、「让大家每天知道目标和差距，而不是到下个月初才想起目标还差那么多」——周报的频率问题本质是反馈回路长度问题。**
（同上，黎路遥转领导原话：**「让大家都能每天知道自己的目标和实际的差距，而不是到下个月初才想起我的目标原来还差那么多。」**）
→ **落到工具上：周报里放「每人目标 vs 实际」表，周五收、周一每天报。**

**五百二十、写不出来的格子就是没查清的格子——「待回填」要明说，不装。**
（同上：转化率/满意度的实际数没采到 → **文档里直接写「待回填」，并告诉老板「框架先立起来，数今天之内补齐」**；**口径没定的（转化率按咨询人数还是成交人数）单独列出来问他，不自己挑一个算。**）

**五百二十一、企微在线 Word 写格式：`--content-type markdown --file-path`（文件必须在允许目录内），别用 text 拼空行。**
（2026-10-19 周报：**text 模式换行会被压成单行（读回 1054 字无换行）**；**markdown 模式（#/##/表格）errcode 0**，读回带结构。）
→ **两个坑**：① `--file` 不存在，是 `--file-path`；② 文件路径必须在允许范围内（`D:/桌面/木婉清` 或 Temp），`D:/tmp_xxx` 会报 893006「目标路径超出可访问范围」。）

**五百二十二、「你需要优化下格式」= 内容过了，表达不过关。**
（同上：老板没说改内容、没说重写，只说格式——**说明结构和数据他认了，是排版让他读着费劲**。改格式不用动内容，也**不要顺手"优化"内容**。）

**五百二十三、一行数据里两种口径，必须分开说，不许合并报。**

**五百二十七、拦住第 6 次的不是建议，是"拿真数据验一把"这个动作。**
（同上：**「如果不验这一把，下次跑完我这边永远不会亮完成。」**）

**五百二十八、检测器改完的状态要能一句话说完：几个改了、几个有意保留、为什么保留、真事件验过没有。**

（霍青桐 2026-10-19：她给「按回车键返回」收紧判据后，**把"筛选日期提示符"那步卡死了**——命中验了，路径没重走；重写驱动 v2（日期提示符独立成步）跑通。）

**五百四十三、同一个对象的「列表接口」和「详情接口」返回的字段不一样：校验一律用详情接口。**（殷素素 2026-10-22）

**五百四十四、「全部干净」是快照，不是状态：报这类数一律带时点。**（王语嫣 2026-10-23，木婉清撞出）
