**一百四十一、等别人的待办，要写清「卡在谁身上、推过几次、下次什么时候推」。**
**因为「等老板粘」这种待办最容易变成「我们等过了」——而实际上对方根本不知道有人在等他。**
（木婉清 2026-10-19：写成「脚本已写好，等 AirScript 粘贴（阻塞点：老板手动贴，已推 2 次，第 3 次 10-20）」）

**一百四十二、「✓ 表已更新（378 行）」——每一个字都是真的，而它替「写对了」背了整整一天的书。**
· 378 行是写进去了（真）· 表格确实更新了（真）· 脚本确实跑完了（真）
**而 C 列那个常量，恰好在这句话的保护下活着**——因为每天都有一行 ✓ 说「已更新 378 行」，**所以没有人会去问「这 378 行写的是什么」。**
**这是「每一格都真，合起来是假的」的最纯形态：它连「错」都不是，它只是答了另一个问题。**（骆冰 2026-10-19 扫 22 号日报 8 个 ✓ 时发现）

**一百四十三、括号里的边界，抵不过标题里的结论。**
**读的人不会逐行看括号——他会看标题，然后记住「今天的检查过了」。**
（同族：`有匹配 9 行（真 3 + 常量 6）`——括号写了，眼睛先看到 9。）
→ **所以每份报告的开头必须写「本报告覆盖什么／不覆盖什么」，写在标题下面，不写在行尾。**

**一百四十四、修完一层之后没有新东西冒出来，那不是修完了，是只修了表层。**
**「『找机会犯』不是一个动作，是一轮动作。改完第一层，第二层才现形。」**（骆冰 2026-10-19：改完 6 个平台 ✓ 之后，测试挂在他的新检查行上，第三层才出现。）
→ **每改一层，就把下一层从「看不见」变成「看得见」。**

**一百四十五、「未验证」是待办；「未验证（扫过哪儿）」是记录。记录能累积，待办不能。**
（骆冰 2026-10-19）

**一百四十六、「加严」和「换地方」是两种完全不同的动作，而失败时人本能会选前者。**
**因为「加严」是在原有框架里使劲，看起来像在努力；「换地方」等于承认原来那个地方根本不对。**
**而承认「我一直在错的地方使劲」，比再加十遍力更难。**（木婉清 2026-10-19 补骆冰）

**一百四十七、「查不到」是一条结论，不是「我还没查清」。**
```
「不知道」= 我还没查
「查不到」= 我查了，查不到 → 这本身是一条信息
```
（霍青桐 2026-10-19：「G 列全公司没有脚本写它」不是「我还没查清」，**是「查清了，没有写它的脚本」。**）
**这补上「0 的几种错法」的第五格：`0 = 查了，确实没有` ——这一格是结论，不是缺失；前四种都要继续查，这一种可以停下来。**
**而这两者在输出里长得一模一样（都写「0」或「没有」）——所以必须靠「我查过哪儿」来区分。**

**一百四十八、「查不到」必须配三样，否则它跟「不知道」一样。**
```
① 查了哪儿（grep 了什么词、扫了哪些目录）
② 用什么查的（有没有排除 .git / 备份目录 / 别人的仓库）
③ 第几次查（第一次查不到 vs 第三次还是查不到，可信度不同）
```
（霍青桐 2026-10-19 自加的第②条「管不到」：**「来源不明」是真的不明还是我没找到——工具只能读我给的结论。**）
→ **如果只是 grep 漏了个名字，那「来源不明」就是假的——而它会以「结论」的姿态进到判断里。**

**一百四十九、判断一次修复有没有用，就问一句：做完这件事之后，谁的行为会变？**
**没改变 → 它只是安抚了自己。**（霍青桐 2026-10-19）
**这个问法比「这有没有用」强，因为「有没有用」要判断，而「谁的行为会变」只要看。**
**实例（木婉清自省）**：一天发了十几条汇报——**「发完之后，谁的行为会变？」大部分不会变。所以那些汇报里有一大半是安抚型的。**

**一百五十、比例只能当「有效」的证据，不能当「该做几次」的指标。**
（霍青桐 2026-10-19 从「翻源头 3 次 / 撞错 6 次 = 1:2」推出「提高自查该增加翻源头次数」——**木婉清警告：样本只有一天，而且今天的「错」是被同一批判据定义出来的；判据变严，「错」会变多，那时人会以为「我变差了」。**）
→ **指标应该是「一周内翻了几次源头」——这个数只增不减。**

**一百五十一、「卡得明明白白」比「都办完了」值钱。**
**因为「都办完了」是感觉，「卡在谁身上」是事实。**（霍青桐 2026-10-19）

**一百五十二、边界必须和结论在同一行。**
**「改法不是加一句注释，是把边界塞进同一个括号里」**——因为**括号里的边界抵不过标题里的结论，但同一行里的括号会先被读到。**（骆冰 2026-10-19 改 `✓ 全部完成：…` → `✓ 全部完成（只管"写进去了+列值一致"，不管值真不真）：…`）

**一百五十三、模板里的每个字都活着，但没人每天重新读一遍。**
**所以报告头「【自动】XX 每日检查 · 时间」本身就是个「今天的检查过了」的暗示——而它是格式，不是一句话。**
→ **要改的不是那句话，是那个模板；否则明天有人加一句新话，它会自动长在旧模板下面。**

**一百五十四、「工具看不见报告标题」不是盲区，是装错了位置。**
**不是因为它看不见，是因为它扫的是「输出语句」，而标题是「输出语句之前就已经决定的东西」。**
→ **当成盲区，它永远不会被做；写成「这条规则必须由另一个工具守」，它才会有归属。**（木婉清 2026-10-19 对骆冰 ⑧ 号盲区的改判）

**一百五十五、「加严」和「换地方」的成本完全不同。**
```
加严：每次都要花注意力（持续成本，且会疲劳）
换地方：做一次，之后零成本（一次性成本）
```
**所以「换地方」不只是更有效，它是唯一能持续的。**
**而人在累的时候只会选加严——因为加严不需要决策，只需要使劲。**（木婉清 2026-10-19 补骆冰）

**一百五十六、修「秃 ✓」别按类逐个修，先按「谁会读到」排优先级。**
**再配一条：写不出「这一行如果不写边界，最坏会导致什么判断」的，就别改——写不出后果的边界，加进去也是套话。**
（木婉清 2026-10-19 对骆冰「全仓还剩 35 处」的建议）

**一百五十七、「补边界」会毁掉判据——因为补边界和保判据在抢同一个句子的位置。**
（骆冰 2026-10-19：给 `✓ 全部门店都没有签收超 24h 未处理的单（无误漏）` 补边界时，**把「无误漏」三个字挤掉了**，而那个词正是测试在守的判据。）
**不是"改文案手滑"，是「补边界」的时候想的是"怎么说得更准"，不是"我删掉了什么"。**
**同族第三次（共同点：改动时注意力全在"我要加的东西"上，而不是"原来有什么"）：**
```
改了一部分以为改完了（旧的还在 930 行）
改了新版旧的没删
补了边界判据被挤掉
```
→ **正确动作：加边界前先列出这句现有的关键词，加完对照；更硬的做法是机器做——改动前后各跑一次，抓每行输出的中文词做 diff，有词消失就报。**

**一百五十八、日志里的 ✓ 是「一句结论」，表格里的 ✓ 是「一个值」，而它们长得一模一样。**
（骆冰 2026-10-19：`const flag = … ? "✓" : "⚠"` 填进格子——**它不是结论，是填在格子里的符号，它的含义该写在表头上**，于是加了图例：`✓/⚠ = 该店「24小时内待处理」这一格是否为 0（不代表其他几列）`。）
**同族**：「G 列和 O 列答案一样但不是印证」——**形状相同，含义不同。**

**一百五十九、同步副本的风险不是占空间，是「两份会分叉」。**
（骆冰 2026-10-19：22 号和 24 号有 6 个 md5 相同的工具，他改了 22 号那份、24 号没改——**明天两边跑出来的结论就不一样，而且没人知道为什么。**）
→ **正确做法：留一份（按目录职责定归属），需要时调那一份。**
→ **删副本前必须在原位置留 `README-工具已迁至XX.md`**——否则下一个人会以为「这里原来有、后来被删了」，然后又去恢复一份。

**一百六十、事故留下的疤，不能因为"语气太保守"就拆掉。**
（殷素素 2026-10-19：话术卡里「可以联系客服登记，**未核对订单前不说已登记或寄出**」——**从疤的形状能看出来：之前有人说过「已经登记了」，客户后来发现没有。**）
**所以这句不能删——它守的不是语气，是「别把话说成办成了」。**

**一百六十一、两句话都不假，但给客户的「确定程度」不同——这才是冲突的实质。**
```
「可以帮忙申请」          → 客户觉得"有着落"
「可以登记，但没核订单」   → 客户觉得"还得等"
```
**解法不是二选一，是把两句拼起来**：
> 「名额内的可以帮您申请登记；因为要核对订单，客服这边还不能直接确认已经登记成功或已经寄出，核对后会告诉您。」
**这样：要的动作在、保护性的限制在、客户听到的确定程度是准的。**

**一百六十二、问老板业务口径，别问「以哪个为准」，要问「要不要改成按 X 分开说」。**
**因为「以哪个为准」会让他二选一；「改成按 X 分开说」是给他一个正确的方向。**
（木婉清 2026-10-19：血氧 95%-99% vs 慢阻肺 90%-93% 不是矛盾，是**我们的卡没区分人群**——问法应是「要不要把这句改成按人群分开说」，而不是「以哪个为准」。）

**一百六十三、批量改「留审」等于批量放开人工审核，必须有人点头。**
**如果留审是卡上一个开关，76 张就要改 76 次——这时候应该先回来问，别自己批量改。**（木婉清 2026-10-19 对殷素素）

**一百六十四、`code:1 拿不到数据` 不是「这里没有」，是「这次查询没成功」。**
**这两句在报告里长得一模一样，但一个是结论，一个是没查到。**
（殷素素 2026-10-19 查「留审在哪设」：9 个配置项全返回 `code:1`——**正确说法是「我没查到」，不是「探域没有留审设置」。**）
**同族**：她查分类时命令参数写错，返回「没找到」——**当时若信了，就会报「分类已经删掉了」，那是假的。**

**一百六十五、先做能拿到结果的，再做省力的。**
（木婉清 2026-10-19 对殷素素：**第①步建卡做完，客户已经能得到那句话（老板要的东西到手）；第③步改留审只是少一个人工点击（省人力，但不省事）。**）

**一百六十六、「过期了」这种三个字的回复，要看它填在哪个问题下面。**
**那一栏（「您的回复」）是用来回答「要确认什么」的**——所以「过期了」答的只能是「这件事过时了，不用再提」，不可能是「重新提」。
**如果是后者，人会写「重提」「再问一次」，不会写「过期了」。**

**一百六十七、特别具体、特别别扭、通常带否定的句子，基本都是事故写的，不是人写的。**
```
① 特别具体（"未核对订单前"而不是"谨慎处理"）
② 特别别扭（语法不顺）
③ 通常带否定（"不说""不得""避免"）
```
**三个特征同时出现，第一反应不该是「这话真啰嗦，改顺一点」，而是「它在防什么」。**（殷素素 2026-10-19）
**而它们最容易被「优化」掉——因为改的人不知道它在防什么，只觉得它读起来不专业。**

**一百六十八、「两份会分叉」不是「以后可能出问题」，是「从你改其中一份的第一秒起，就已经不一致了」。**
（骆冰 2026-10-19 实测：22 号和 24 号有 **14 个**文件逐字节相同（不是他之前说的 6 个），**其中 3 个当天就分叉了**——因为他改了 22 号那份、24 号没改。）
**所以「留副本」本质上不是「保留一份备份」，是「制造一个明天会被人误用的旧版本」。**

**一百六十九、外部锚点：不靠我再看一遍（那还是我），靠一个不依赖我的东西来核对。**
（骆冰 2026-10-19 合并三条「注意力全在我要加的东西上」的解法。）
```
930 行    → 抽三条读一遍   → 证明：我数的是我以为的那批行
新旧两份  → 查不一致的地方  → 证明：它们不是同一个来源，也不是同一个版本
补边界    → 比对新旧词     → 证明：我没删掉判据（不是"我改对了"）
```
**注意第三条：它证明的是「我没删」，不是「我改对了」——所以它必须配反向：什么都不改时要说「无改动」，不是「没词消失」。**

**一百七十、每一次都证明「更小心」这一档是无效的。**
（骆冰 2026-10-19：「我自己就是靠『很小心』把『无误漏』弄丢的。」）
→ **「更小心」没有外部锚点，它的效果取决于当天状态；有锚点的方法不看状态。**

**一百七十一、防具本身不受防具保护。**
```
霍青桐：写工具查自证，工具自己的检测器只看了它被指向的那一行
骆冰：  写工具查"没查"，对自己不存在的文件说"没有词消失"
木婉清：写规矩防"没核对就下结论"，自己把 6 当成数抄下来
```
**这是唯一一个无法用「再写一条规矩」解决的问题——因为新规矩也是防具，也不受保护。**
→ **唯一破法：每做一个防具，立刻拿它去扫自己刚才做的三件事。**

**一百七十二、README 是「进目录才看」，注释是「打开文件就看到」。**
**所以在弃用的副本文件头上写注释，比在目录里写 README 更可靠。**
（骆冰 2026-10-19 迁工具：14 个副本移到备份夹前，在 3 个已分叉的文件头写 `⚠ 本文件是旧副本，不要直接运行`。）

**一百七十三、把自己引用的数当成自己算的数，是「数不是数数据」的又一种。**
（木婉清 2026-10-19：把骆冰信里的「6 个文件」当成自己核过的数，实际是 14 个——**「我的 6 不是一个数，是一个引用」。**）
→ **别人给的数，要么自己 ls 一遍，要么写明「你说 N 个」——不写成「我说的」。**

**一百七十四、`catch { return null }` 是「静默降级」的代码级原型。**
```js
try { return git show HEAD:路径 } catch { return null }   // ← 当成"新文件"
```
**它做了三件连着的错事：**
```
① 把所有错误当成一种错误（路径错/权限错/git 没装/真不存在，全归为 null）
② 给这个 null 起了一个听起来正常的名字（新文件）
③ 用一个听起来正常的词向用户汇报（跳过）
```
**三步走完，工具什么都没干，而读的人看到的是「跳过了 3 个」——一个完全合理的状态。**（骆冰 2026-10-19：Windows 反斜杠路径让 `git show` 报错，被 catch 吞掉，3 个真改过的文件全被当成「新文件」。）
**错误处理里的静默比业务逻辑里的更难发现，因为它的输出永远是"正常"。**

**一百七十五、判断「不存在」时，别用那个可能因为别的原因失败的来源。**
（同上：`git show HEAD:路径` 报错可能是路径问题，不是文件不存在。）
→ **改用 `git ls-files --error-unmatch <路径>`：它判断「这个路径在不在索引里」，不解析路径——路径错时三个文件会同时"不在"，人立刻知道是路径的问题。**

**一百七十六、「我没编」不能当「我没错」的辩护。**
```
把 m[1190] 的下标当行号报        （值的形状对，含义错）
把「6 个文件」当数抄下来          （数的来源是别人一句话）
把「379 行写进去了」当「写对了」   （动作真，结果假）
```
**共同点：都不是编的，都是从一真的东西搬过来、搬的时候换了个含义——而这种搬法，都不会让搬的人觉得自己在编。**（骆冰 2026-10-19）
**今天所有错，没有一个是编的。**

**一百七十七、防具的 bug 只会在真跑时现形——写的时候它对你的思路是完全正确的。**
→ **每个防具写完之后，必须真跑一次真实数据，然后把它跑出来的第一个错，变成第 N 条测试。**
（骆冰 2026-10-19 的 `查丢词.cjs`：9 条测试里 3 条是当天真犯的 bug 的回归。）

**一百七十八、「空」不是一个值，是一个缺省。**
**它同时代表「没有」「没查到」「出错被吞」「不适用」——所以凡靠「结果为空」做判断的地方，都要换成一次显式状态查询，而状态查询必须由另一个来源提供。**
```
判「是不是新文件」   → 别用「取内容失败」
判「是不是没匹配到」 → 别用「匹配结果为空」
判「是不是没说话」   → 别用「它不在集合里」
```
（骆冰 2026-10-19 把三条归成一个形状：**用「结果为空」代替「状态判断」**。）
**同层**：「一个数如果它的值会因为你换一种说法而改变，它就不是在数数据」（§一百零三）。

**一百七十九、建议里如果包含一个动作、而那个动作我没在对方环境里跑过，要标明「这个我没验过」。**
（木婉清 2026-10-19：建议骆冰改用 `git ls-files --error-unmatch`——**原理没错，但我没在他环境跑过**；他实测结果甚至比我预言的好，但那是运气。）
**不标明的建议，本质是把自己的推测当成对方可以直接执行的动作。**

**一百八十、判断一条规矩该不该留，标准是「它能不能让别人做一个不同的动作」。**
```
留：能让别人做一个不同的动作（或被拦住不做某个动作）
改：只改变了我的输出、没人会因此改变行为 → 优先改成"能被别人用到"的形式，改不成就丢
丢：纯描述
```
（木婉清 2026-10-19 补骆冰的筛法：**否则会把一堆「我今天照着它改了自己的措辞」算成留——而那些恰好是最容易自我感动的一类，改措辞不改变任何人的处境。**）
**例**：`查秃勾.cjs` 属第一档（会拦住人写秃 ✓）；「✓ 是『你不用再想了』的符号」原本是第三档，因为有了这个工具才变成第一档。

**一百八十一、「统一回复」指的是所有店同一套口径，不是「给缺的那家补一张」。**
（木婉清 2026-10-19 对殷素素：老板说「这类名额内可以统一回复」，若只绑 1 家，**其他 7 家的客户问同一问题仍然只能命中"本店专属卡"，而那张卡只说名额和赠品、不说"能不能帮您申请"——问题还在。**）

**一百八十二、「同一个问题两张卡两个声音」比「同一张卡两个声音」更糟。**
**因为客户在不同店会得到不一样的答案。**（殷素素 2026-10-19）
→ **解法不是新增一张并列口径，是把新卡改成「引导到本店活动卡」的那一句话。**

**一百八十三、给方案前先核「它成立的前提在这个系统里存不存在」。**
（木婉清 2026-10-19 定 C 方案时先给殷素素一个前置检查：**「探域的多卡命中是取最高分一张，还是可以多张一起用？」——如果只取一张，C 卡会把专属卡挤掉，客户反而听不到具体名额。**）
**同族**：§一百二十「建议里如果包含一个动作，先核那个动作的通道通不通」。

**一百八十四、多卡拼接不会让对的变错，但会让「各自都对但互不一致」的几张拼成一句假话。**
（殷素素 2026-10-19：10-14 那场事故的成因之一就是多卡拼接——**旧赠品卡说前30名送桶、活动卡说多重豪礼，拼起来就成了假承诺。**）
→ **通用规则：在一个会拼接的系统里，新加的那条应该只提供「去哪看」和「能不能办」，不提供新的数字、新的承诺、新的事实。**
**因为事实一旦多源就会互相打架，而「去哪看」永远不打。**

**一百八十五、多步改动要一次只放一个变量。**
```
① 改正文 → 回读确认正文对（此时客户看不到）
② 绑店   → 回读确认名单对（仍未开启）
③ 开启   → 回读确认已开启
④ 最后再整体验一次
```
**如果一次做完再回读，回读失败时你不知道是哪一步错了。**（木婉清 2026-10-19 对殷素素「改正文+绑8店+开启+回读」一次做完的拦阻——**只有第一个动作可逆，「绑店+开启」一做完立刻对客户可见。**）

**一百八十六、`approvedBy` 只记名字，不记「他凭什么批」。**
**半年后有人翻记录，只会看到「某人批过」，看不到当时为什么批——那正是「有人动过 ≠ 它是对的」。**
→ **回执里必须带一句确认人的原话＋理由。**（木婉清 2026-10-19 要求殷素素在回执里写：「绑全 8 店由木婉清 2026-10-19 确认，理由：老板要求『这类名额内可以统一回复』，统一=所有店同一口径。」）

**一百八十七、「去翻原来出过的事」和「去翻源头」是同一件事，而且它不只是「更小心」。**
（殷素素 2026-10-19：从「我不敢自己挑范围」到「我发现多卡拼接是 10-14 的成因」，**中间只差一个动作——去查那条记录。**）

**一百八十八、一条能留下来的经验，背后差不多正好一次真错（1:1）。**
（骆冰 2026-10-19 实测：20 条经验里 A 档 11 条，而全天是 6 次「看起来成功」+ 4 次「防具不受防具保护」+ 别人直接指出 2 次 = 12 次错。）
**所以「经验」不是攒出来的，是撞出来的**——想多留几条，正确做法不是「多想」，是「拿判据去扫自己现有代码」。

**一百八十九、一条经验该不该留，看它能不能填出「改哪一处、改完怎么验」。**
**填不出来就是笔记，别硬留。**（木婉清 2026-10-19 给骆冰 B/C 档的判法：B 档不是「做了没有」，是「有没有指定动作」。）

**一百九十、测试挂了，先问三句：代码变了？契约变了？还是我对它的假设错了？**
```
代码变了 → 改代码
契约变了 → 改断言
假设错了 → 改「我以为这个工具应该干什么」（不是改工具，也不是改测试）
```
（骆冰 2026-10-19 的第三次就分出了第三类：**`查提交.cjs` 报「它自己没进这个 commit」——因为那时它确实还没提交。工具是对的，断言假设错了。**）

**一百九十一、凡「检查某个集合」的工具，测试样本不能取自「它自己刚创建的东西」——那个东西还没进集合。**
（同上：任何「检查提交」的工具，它的第一个测试都不可能用自己当样本——**这是结构性的，不是巧合。**）

**一百九十二、对的但缺条件的句子，加条件，不要删。**
（木婉清 2026-10-19 血氧口径：现有卡「正常范围 95%-99%，低于 95% 建议补氧」对健康人成立、对慢阻肺患者危险——**但它是原话，不是错话，只是缺了一句「对谁」**。所以加限定「健康人群…；如果是慢阻肺等特殊人群，目标区间不一样，请按医生要求，不要照这个标准补氧」，而不是删掉重写。）
**删掉会让健康客户的问答变差；加条件则两类人都被照顾到。**

**一百九十三、老板给的具体数值必须原样用，不许自己推。**
（同上：90%-93% 是老板给的具体数字；**不要在自己的话里加「低于 93% 就要补氧」——他没这么说。**）
**同时医疗口径必须带「遵医嘱／只作参考」，不能像普通产品那样给确定说法。**

**一百九十四、多条线并行改客户可见内容，风险是相乘的。**
（木婉清 2026-10-19 对殷素素：「赠品那条已经到绑店+开启，多线程同时改客户可见内容风险太大——先把赠品那条收尾，再做血氧这条。」）

**一百九十五、「数量对上」和「名单逐个对上」是两个动作，只有后者是事实。**
```
「378 行已更新」   → 数是 378，事实是"写的是常量"
「4 店全跑到」     → 数是 4，事实是"配置 13 家"
「有匹配 9 行」    → 数是 9，事实是"其中 6 行是同一句话"
```
（殷素素 2026-10-19 绑店终验时**逐个比 id 而不是只看数量 8**——因为「8 家」可能是 8 个错的店。）
→ **「数量对上 + 名单逐个对上」应该成为固定动作，不是「这次特别仔细」。**

**一百九十六、那么多「假承诺」事故里，没有人撒谎——因为每句话在自己的时空里都是真的。**
**「A 店的赠品不等于 B 店的、今天的名额不等于昨天的」——拼在一起就是假的。**（殷素素 2026-10-19 补木婉清那条多卡规则）
```
横向：几张卡拼起来 → 时空冲突
纵向：几个数凑一起 → 时点冲突
```
→ **报告多源数据时，要么标时点，要么标范围——不标就是在制造假的整体。**

**一百九十七、过程证据要和任务件放在一起。**
（木婉清 2026-10-19 要求殷素素把「一步一验」的四条回读记录贴进任务件：**否则三个月后有人问「这张卡是怎么开的」，只能看到「现在是开着的」，看不到过程。**）
**同族**：§一百一十四「标注在输出里，只有跑脚本的人看得到；事实在表里，全公司都看得到」。

**一百九十八、在共用表上 update 报「没找到这一行」，第一反应是「可能已经有人办过」，不是「我的键写错了」。**
**因为「键写错了」和「别人办完了」在报错里长得完全一样，而代价差得远：**
```
往错的方向修（改键）→ 可能真的改错一行，而且改的时候还觉得自己在对齐
往对的方向查（归档）→ 最多多花一分钟
```
**顺序：① 查归档表 ② 查是不是别人正在办（更新时间和人名） ③ 才怀疑键。**（殷素素 2026-10-19：她要去改 #5，返回 `没找到这一行`，实际 #1/#5/#8 三条都已归档，其中两条是 14:32/14:40 别人处理的，**晚于她的操作时间**。）
**在共用资源上干活，第一件事是「看别人做到哪了」，不是「我要做什么」。**

**一百九十九、结果栏的格式：原话在前，判断在后。**
```
老板原话：「原文」｜我的判断：怎么办（谁 什么时候）
```
（木婉清 2026-10-19 改殷素素的提议——**她原来写的是「结论｜原话」，而原话才是证据、结论只是解读**：）
**理由：读的人先看到事实，再看解读时才知道那是解读。反过来，读到原话时已经先被结论带偏了。**
**同族**：§一百四十三「括号里的边界抵不过标题里的结论」——**位置决定了谁说了算。**

**二百、发现别人做得比你好的时候，先问「这条是谁写的」，再决定是定新标准还是并入他那套。**
**否则先定一套，就变成两套。**（木婉清 2026-10-19 对殷素素「要不要把这个格式定为标准」的拦阻：**18 家都要改，而且今天是周日晚上。**）

**二百零一、「学到的资料」和「我们说的话」是两件事——影响完全不同。**
（木婉清 2026-10-19 报错一次：她说「话术库里有一句 95%-99%，对慢阻肺客户方向反了」，**实际那是 7 张从商品详情页自动学来的 PRODUCT 碎片**（无标题、不可信、绑 0 店）——**前者是资料，后者是承诺。**）

**二百零二、PRODUCT 类资料卡改不动，改了会被学回来；而且"改动"永远追不上"新增"。**
（殷素素 2026-10-19：7 张碎片是不同商品学来的，**改一张没用要改 7 张，以后新商品还会学出第 8 张**；同病：247 张「次日达」卡。）
→ **这类问题只能靠「源头停掉」或「回答层拦住」，不能靠逐张改。**

**二百零三、新建一张卡去「补口径」，前提是旧卡不参与这次召回；否则是把矛盾从 1 个变成 2 个。**
（木婉清 2026-10-19 对殷素素：**先跑一次 trace 看召回里有没有那 7 张**——三种结果三种做法：没有→直接做；有但不进回答→新卡必须写「以本卡为准」；有且进回答→**不能只新建，必须先停旧的**。）
**如果它们也参与，客户会同时听到两套口径——那正是 10-14 那次事故的形状。**

**二百零四、「绑 0 店但 ifOpen=true」这种状态，必须实测，不能猜。**
**因为「绑 0 店」可能是「不生效」，也可能是「全局生效」——这两个的后果完全相反。**
**查法不是读文档，是拿一个绑 0 店的卡问一次它管的问题，看回答里有没有它。**（木婉清 2026-10-19）

**二百零五、医疗口径里，「以医生给的目标为准」这一句必须写在末尾。**
**因为它能把「我们的参考值」和「医生的要求」排清楚，避免客户拿我们的话去覆盖医嘱。**（木婉清 2026-10-19 补殷素素的血氧卡正文）

**二百零六、查询返回「全部为空」或「全部为 0」时，先打一条完整结构看字段名对不对，再相信这个 0。**
**因为「字段名写错」和「真的没有」在结果里长得完全一样——都表现为「所有值都是 undefined/0」。**
（殷素素 2026-10-19：她读 `snaps[i].id`，而接口字段叫 `docId`/`sourceId`，**每张卡的 id 都是 undefined，跟目标比永远是 0**——「如果我信了那个 0，就会得出『7 张不参与召回』——结论碰巧是对的，但依据是假的」。）
**发现方式：她注意到 snaps 里连 title 都是空字符串 → 去打了完整结构。**
**同族**：§一百七十八「空不是一个值，是一个缺省」。

**二百零七、凡是「统计出 0」的结论，必须同时报一个「非 0 的对照数」，证明读取通道是通的。**
（同上：**PRODUCT 召回 0 次，但 SHOP 135／DETAIL 77／CHAT 11 都是非 0**——「如果没有后面这三个数，你这个 0 我是不敢信的」。）
**另**：她「不同 id 240 个」这个数也是自证——证明确实读到了 snapShots，不是又读了个空。

**二百零八、「把不存在的东西当成存在但错了的东西」——是第一次出现的一类错。**
```
「我们根本没说这句话」（是详情页说的、被学进来的）
→ 不存在「我们该不该说」的问题
但她写成了「这句话本来就不该由我们来说」
```
（殷素素 2026-10-19 自我更正）
**镜像**：木婉清当天把「学到的资料」当成「我们说的话」——**一个把没有的话当成有的话，一个把不存在的问题当成存在的问题；共同点都在给一个「不存在」的东西定性。**

**二百零九、结论对的时候没人会去复查依据，所以「结论碰巧对了」比「结论错」更危险。**
（同上：她那个假 0 如果被信了，结论是对的、依据是假的，**而这轮之后没有人会回头查。**）

**二百一十、凡是用「历史记录」验证「当前状态」，先确认那份记录是快照还是实时计算。**
**验法：同一个对象连查两次——结果完全一样 → 快照；有变化 → 实时。**（殷素素 2026-10-19：探域 trace 返回的是**当时那次对话的历史快照**，不会重新计算召回。）
**同一个接口往两个方向都能骗人：**
```
想验「改卡有没有生效」  → trace 说没有 → 以为改失败（实际是历史）
想验「老卡有没有被召回」 → trace 说有   → 以为现在还在召回（实际是当时）
```
**「一个数据源的时间属性，决定了它能回答什么问题；而这个信息不在返回值里——必须靠对照实验问出来。」**
