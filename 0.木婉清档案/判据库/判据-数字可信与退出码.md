# 判据 · 数字可信与退出码（0／有问题／判不了）

> 来源：2026-10-18 王语嫣实测 + 木婉清踩坑，2026-11-05 从《企微发消息与汇报》拆出来——**它讲的是「怎么相信一个数」，不是发消息**，所以单独一份。

## 一、看到 0，先问一句

凡是让你相信「某件事没发生」的数字（0 条／没人被拉起／无异常），先问：**这个 0 是真的 0，还是工具没在看？**

- 要能说出**源头确实有内容的凭据**才算真的 0（例：「收件箱共 466 条、已读 466 条」）。
- 说不出凭据的 0 一律当「不知道」，不当「没有」。
- 2026-10-18 实例：`读收件箱.mjs` 共 0 条时不说「正常」，改报警告＋列可能原因＋给下一步命令。

## 二、「判不了」必须自己占一档

- 三档退出码：**`0` 没问题 / `1` 有问题 / `2` 判不了**。不许让「判不了」借住「正常」那格。
- 正面教材 `机器人状态.mjs`：没有守护日志时不说「正常」，单独给结论「判不出来」、退出码 2。
- 报「没问题」也要说清**查了几家、宽限多少**；不给出凭据的 0 不算数。

## 三、三种「装成没问题」的写法（同一工具上实测三处）

1. `if (!exists) continue;`——看不到就当没问题（跳过后既不算有问题，也不算无数据）。
2. 没问题时什么都不打印——沉默的 0，分不清「扫了 19 家全正常」和「一家都没扫到」。
3. 退出码只有 0/1——没有「判不了」的位置。

## 四、数字变了，先说清是哪一种

- **翻倍＝系统性漏了一整类**；小幅浮动才是噪声。实例：6→12 是正则残了，不是抖动。
- **`| head` 和 `| tail` 一样吞退出码**：`node x.js | head -10; echo $?` 拿到的是 `head` 的 0。取码一律 `> 文件 2>&1; echo $?` 或 `>/dev/null 2>&1; echo $?`。
- 统计类工具**改完必须拿已知样例验数**——它坏的时候不报错，只报小数字。

## 定时/环的触发时间：必须有探针证据

- 2026-11-05 骆冰把"环按 UTC 算、排到 23:40"当结论报上来，实际只是她的推断（真实原因未查实）。她事后自己撤回。
- 判据：**任何"几点几分会自动跑"的说法，必须有探针或回读证据**（挂一个 5 分钟后的探针环验触发、或读调度记录的下次触发时间）。
- 没验过的触发时间只能写成"预计/待验"，**不许写进"每天自动跑"这类会被人当事实用的句子里**。
- 同源毛病：文档写"自动跑"、实际任务 10-19 就 Disabled —— 一个没人跑的定时比跑错更贵。

## 「扫了 N 行」先问两件事：是不是同一批行、有没有被截断

- 2026-11-11 实案：巡检员报「湖南退货退款表服务端扫 250000 行、0 命中」，实际是 AirScript 默认 `maxRows=50000`，13 个关键词分 5 批、**5 批都扫的 1~50000 同一段**。表真实数据到 50088 行，退回记录正好在 50031/50032 → 报「未退回」被老板一眼看出错。
- 判据一：**批量数不等于不同行数**。「5 批×5 万」要说清每批的起止行；说不出起止，就按「同一段扫了 5 遍」处理。
- 判据二：**扫到的行数要跟表的实际行数比**。扫 5 万行、表有 5 万零 88 行，就是漏了尾巴——工具该报错，不该静默返回「0 命中」。
- 判据三：**「0 命中」必须能被反例推翻**才有可信度。给一个真实存在的样本（这里是 2237）去搜，搜不到才叫 0 命中；搜得到就说明查询键或范围错了。
- 落地写法：查询工具默认行数留足（≥10 万）＋「读到行数 < 表实际行数」直接报错；报「0 条」时附上扫描区间与样本反测结果。

## 三、人做的动作，要看落在哪个环境里

「我登录了」「我点过了」这类人给的结论，**不等于工具能用的状态**——同一个软件可能有多个会话池（浏览器配置、账号池、免登态），人在 A 里做了，工具读的是 B。

- 2026-11-11 实案：老板说「我登录了」，人真登了，但登的是他平时那个 Edge；贴脚本用的是**专用浏览器配置**，那边 cookie 还是空的，页面还是「立即登录」。判断依据错一步，后面全错。
- 判据：**验收标准写成工具能读到的证据**，不写「他说做了」。例：「右上角变成头像/名字」不算，要「工具读到 `wps_sid` 才会动手」。
- 问人的时候把**窗口标题/时间/成功标志**一起给（例如《2026年10月退货原因分析》、14:11 开、右上角变头像），人才知道该在哪个窗口做、做没做成。
- 反面也一样：工具报「已登录」也要看它读的是哪份会话，别拿缓存的旧会话当今天可用。
