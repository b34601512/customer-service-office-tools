**二百八十一、让 AI「更狠一点」的前提是它先能读到——没被召回的内容，写得再狠客户也听不到。**
（同上：**「如果 4~5 张已经写对的卡都没被召回，再改它们只是让『没被召回的内容』更狠一点。」**）

**二百八十二、新卡往哪个方向写，取决于召回是按关键词还是按语义——这两个方向写出来的卡完全不同。**
（木婉清 2026-10-19：出问题那次召回 7 张，**4 张是「C1L尺寸」「Q5L/Q5S定时最大多久」这类机型参数，没有一张讲浓度怎么算；而客户说的是「医院住院就是这个标准」。**）
```
关键词命中 → 新卡标题/问题里必须带「医院」「医生说的浓度」「够不够」
语义相似度 → 新卡正文要写成客户问法的样子，不是写成标准的医学表述
```

**二百八十三、错误的代价有三层，最后一条最贵。**
```
① 浪费一个人的时间
② 让他以为自己对世界的认知是对的
③ 让他以后不再去核这件事
```
（王语嫣 2026-10-19 补 ②；木婉清补 ③：**「核」本来是我们唯一能纠错的动作。**）
**实例**：小某把 3 条「已完成」重开成待办 → 老板回「今天等会就删」（他 10-14 已亲手删过）→ **以后他问「删了没」不会去核，因为"他以为已经知道答案了"。**

**二百八十四、改状态不要求「写一句为什么」，要求「给出一条可核的位置」。**
```
文字可以是废话："因为做完了" —— 脚本只能查"有没有"，查不了"是不是废话"
位置不能      ——「归档表第60行」「commit 40026f9」要么存在要么不存在
```
（木婉清 2026-10-19 反对王语嫣「改状态必须写一句为什么」，**理由：这动作会变成走过场，而「恒真检查比没有检查更糟」——它会让所有人以为「这里有人管着」。**）
**正面例子**：小某能证明 #10 是搬漏，靠的是「我 10-15 日志里有『赵敏已解冻，已提交推送 40026f9』」——**那是一个位置，不是一句解释。**

**二百八十五、「某一个字段只有一部分人填」→ 整列不能用来判断。**
（同上：**「最后改动」这列只要有 1 家不写，读的人会以为"空 = 没改过"，而实际是"空 = 这家没升级"。**）
→ **兜底：读表时字段为空要显示「未知（未升级）」，不要显示空白。**「未知」和「没有」必须能分开。

**二百八十六、工具的缺陷分两种，后者更贵。**
```
不好用（人还能绕）
会运错（人绕不了，因为人以为它是对的）
```
（王语嫣 2026-10-19：**「后者更贵，因为它不需要人犯错就能出事。」**）
**「不需要人犯错就能出事」= 今天所有事故的共同描述**：骆冰的 45.9%、小昭的状态搬反、脚本大全把 4 条已完成搬成待办——**出事的时候，所有人都在做对的事。**

**二百八十七、一次追加是历史，每次追加是日志。**
**往人写的地方追加机器字，要问「追加几次」——一次可以，每次不行。**（王语嫣 2026-10-19 自省）

**二百八十八、一张卡有两个用途，要求不同。**
```
被召回 → 靠 Q 行像客户问法（语义匹配）
被照抄 → 靠 A 行写得对
```
（殷素素 2026-10-19：**5 张「不能算」的卡 Q 行是「5升10升医用低浓度低流量吸氧」「不是要低浓度低流量吗？」——客户说的是「医院里住院就是这个标准，完全够」，五句 Q 行里没有一个字相似 → 压根没被召回。**）
**「改了正文没用，因为 Q 行不搭 → 改了还是不召回。」**

**二百八十九、Q 行要用客户的原词，不能用同义改写——语义相似度是从这些词算出来的，改写一个词就等于挪开一点距离。**
（同上；**而且要求不是「像客户说话」，是「比别的卡更像这句话」**：殷素素实测「医院标准够不够」时，被召回的竟是「血氧多少算正常」那张卡——**语义召回很松，它按"话题相近"抓，不按"问法相同"抓。**）

**二百九十、建停用状态的测试卡，验的是开关不是 Q 行。**
（木婉清 2026-10-19 拦殷素素：**Q5S 是停用的，今天实测没被召回 → 停用卡很可能根本不参与召回，那个实验会得到一个"有第二个解释的 0"。**）
**同族**：今天那 9 次假 0——**测出来的 0 有第二个解释，而你没排除它。**

**二百九十一、「答对了」和「答得上」是两件事——召回对了也可能答非所问。**
（同上：殷素素第四节实测，新卡被召回了、数字也对，**但客户问「医院标准够不够」，它答「血氧正常范围」——从"答错"变成"答非所问"，后者轻，但也不是对。**）

**二百九十二、把「验一次」变成「建基线」。**
> 列 20~30 个最常见的问法（按真实会话频率排），每个跑一次 trace，记下召回了哪几张卡，人工看该在的在不在。
（木婉清 2026-10-19：**它不是"发现问题"，是"建立基线"——以后改任何卡，跑一遍就知道有没有把别的问法弄坏；一次性成本，长期有用。**）
**能能量化：今天只测 10 条就发现 1 条错 = 10%。**

**二百九十三、一单对得出的规则，对不出它是不是普遍规则。**
（李沅芷 2026-10-19：她从「李璇 ↔ 李*」一单推出「星号数 = 字数−1」，据此判定群里给的「迪迦」漏了一个字。**但两条字的名字打码成「首字+1星」和「末字+1星」看到的东西是一样的 → 它不能区分「星号=剩余字数」和「星号=固定 1 个」，而这两个推出来的结论完全不同。**）
→ **验法：再找一单已知是三个字的名字，看它显示 `X*` 还是 `X**`。**

**二百九十四、「你漏了一个字」这种话，在没有第二种证据前不该说——改成「核对」的语气。**
（同上：木婉清在群里问的是「系统显示迪** 是三个字，您给的迪迦是两个字，能再确认下全名吗」——**不是「你给错了」。**）
**因为报错的人和被报的人，都需要留退路：规则可能是错的，人也可能是口误。**

**二百九十五、先去数据源核，别先问人。**
（同上：李沅芷读的是「发票抬头」（显示「个人」），**而买家姓名在订单详情的收件人里，不在抬头里** → 先试能不能从订单读到全名，读到就不用问人。）

**二百九十六、明知会有废票风险就不登，比「5 分钟写完」重要。**
（同上：**名字错一个字，票废了要红冲；而如果登了，明天没人会知道是名字错，只会看到「这张票有问题」。**）
**判据：一个错误如果会抹掉自己的来源，就不能用它换速度。**

**二百九十七、规则和人的话冲突时，人优先——尤其当那个人知道现场。**
（2026-10-19：李沅芷从「李* ↔ 李璇」推出「星号数=字数−1」，判定群里「迪迦」漏一个字；**老板在群里回「就按这个给的抬头就是全名」→ 立即定案按「迪迦」登，不再讨论星号规则。**）
**但规则本身的怀疑要留档：下次没有人在场时，仍按「找一单已知三个字的名字对比」验。**
**「这次绕过去了」不等于「规则对了」。**

**二百九十八、边界不在「次数」，在「它会不会造成后果」。**
（2026-10-19 殷素素问「基线要跑 20~30 次 trace，算不算超边界」，木婉清：**前面那些改动，一次改一个、改完验一次，每次都在动线上内容；基线这件事只读、不动任何卡——它不改变线上状态。所以不造成后果的次数不需要报备。**）
**但要报的是另一件事：这些调用会不会被当成客户数据、会不会留痕。**

**二百九十九、再验一遍「同一件事又成立一次」，不产生新信息。**
（同上：**剩下 2 个 Q 行变体也是原词，它们验的是同一件事 → 不用各测一遍；真正该测的是「换一个客户说法完全不同的问句，看新卡还进不进」。**）

**三百、「多卡拼接」的好坏不在拼几张，在拼的那几张是否一致。**
（同上：殷素素注：**「回答里的『如果医生给过具体目标，请以医生的为准』是血氧卡的，不是新卡的——这次是两张卡拼起来的回答」**；而这次拼出来是对的，因为两张卡方向一致。）
→ **以后每次验回答，除了看「该说的说了没有」，还要看「拼进来的每一段，是不是都朝同一个方向」。**

**三百零一、边际收益很低的调查，先停，等前置决定落地。**
（同上：拦截配置键**已找到两个入口和一个接口；而「拦截词里 0 个医学词」是事实、「加不加」是老板的决定——在老板没答之前，多找一个配置键也改不了什么。**）

**三百零二、查「这批东西混进了多少」之前，先查「这批东西能不能动」。**
（木婉清 2026-10-19 对殷素素类型 B（DETAIL 卡混进 SHOP 场景）：**如果改不动，查出 100 处混进也没用。**）
**DETAIL 有三种来源，处理方式完全不同**：① 详情页自动学 → 改不动（会被学回来，同 PRODUCT）② 人工写 → 能改但要一个个核 ③ 平台导入的商品资料 → 看它跟不跟商品同步。
**判法：看它有没有 title、绑几店、可信是不是 false，跟 PRODUCT 那批对比——不要猜**（当天已犯过一次：把 PRODUCT 卡当成「我们写的卡」）。

**三百零三、基线只能跟自己比，不能跟「现在」比。**
（同上，殷素素自己写的限制：**「这份基线是『10-13~10-19 期间这些问法召回的是这些卡』，不是『现在问会召回这些卡』。」**）
**这句必须写在基线文件第一行**——三个月后有人翻开它，第一反应一定是「这是现状」。

**三百零四、改 Q 行比改正文危险：Q 行是召回入口，改一张卡的 Q 行 = 告诉系统「这句话该找我了」，同时它会从别的问法里被挪开一点。**
（木婉清 2026-10-19：**今天已证明「改了不等于生效」（5 张卡改正文不会让它们被召回）；反过来也成立——改 Q 行可能让一个本来对的问法变错。**）
→ **动 Q 行前先量「这类问题有多少个」**（殷素素 12 个问法里类型 A 出现 4 次 = 33%；若有 10 个，那不是逐个改的事，是「这类卡整体设计」的问题）。

**三百零五、答非所问 ≠ 答反了。**
**答非所问客户觉得「它没懂」；答反了客户觉得「它在跟我谈条件」。**（木婉清 2026-10-19：**殷素素查到「客户问退货，召回了 3 张议价话术卡」——这不是答非所问，这是答反了。**）
→ **看到「召回了做另一件事的卡」，第一句先问：它做的事，会不会把客户推向我们不想去的方向？**

**三百零六、判据写进「每次都要用的文件」，不要写进回执。**
**因为基线文件下次跑的人会打开，回执只有你自己看得到。**（木婉清 2026-10-19）

**三百零七、一个规则如果只能用支持它的例子来验证，那它不是规则，是印象。**
（李沅芷 2026-10-19：她拿 2 个样本归纳「星号数=字数−1」，后去找了 5 个对照，**发现反例：颜秉冬（3字）ERP 显示完整一个星都没有；覃何祖（3字）只显示「覃」** → 规则作废。）
**她做对的地方不是「发现规则错了」，是「发现规则需要一个样本外的人来证伪」——而她自己补了这个样本。**

**三百零八、「不写一个错规则」和「写一个能替代它的规则」，差一个字，效果差很多。**
（木婉清 2026-10-19 对李沅芷：**不写的话，下一个遇到打码的人会重新推一遍，而推出来的很可能又是「星号=字数」这种看起来对的东西。**
→ 应写：「遇到打码姓名，不以星号数推断字数；以平台/订单里的实际姓名为准，读不到就问发布人。」）

**三百零九、留一个复核点给下一个人，比「停下」和「当作没事」都好。**
（同上：**不因为「名字可能不对」就停下（票登不了），也不因为「登对了」就当没事；做第三件事：建售后检查单写明「票面姓名请在开票前再核一次」。**）

**三百一十、长得像成功的错最难发现。**
（同上：**她发现自己字段名写成「发票抬头」而程序读的是「抬头」——若没读代码，AA 列会是空的，而票还是会「登成功」。**）

**三百一十一、「办完还多走一步」是可迁移的工作习惯。**
（2026-10-19 李沅芷三件事：**做对照、留复核点、检查字段名——没有一件是木婉清让她做的。**）

**三百一十二、字段名不同但含义相近时，一定要打一条完整结构对比，不能凭记忆替换。**
（殷素素 2026-10-19：**trace.snapShots[i].type 不是卡片的 type 字段，是「召回来源标记」——同一张卡库里 type=PRODUCT，被召回时 trace.type=DETAIL。** 由此「PRODUCT 卡不参与召回」这个结论错了，而它被引用至少四次。）
**她的自述：「我只记住了那一处，没记住这个模式」——记住的是案例，不是机制。**

**三百一十三、一份自己统计出来的数据，如果字段含义没被核对过，比没有数据更危险——因为它看起来有据可查。**
（同上：早上那个结论当时的证据看起来无懈可击：20 条 trace、统计、类型分布——**而它是错的**。）
**一个字段名读错，后面四步全建立在上面。**

**三百一十四、改详情页图是运营部的活，不要报老板——报老板他也没法直接改，反而多一轮。**
（木婉清 2026-10-19：**正确路径是把「图片 URL + 卡 id + 图上写 95%-99% 跟我们口径 90%-93% 冲突」写成一条建议给运营/店铺。**）
**注意：只给 CDN 链接运营看不懂，要先查出是哪个店哪个商品。**

**三百一十五、「卡片侧改不动，就去改源头」是同一类问题的统一解法。**
（同上：**247 张「次日达」卡，治本也在详情页**——`source.value` 就是那张图的 URL，是能指到的。）

**三百一十七、判据写在文件里不等于它会在用的时候出现——判据要变成一个动作，才会真的存在。**

```
「要在对的店测」        —— 写在文件里，不在手上

```

**三百一十八、「客户报数字 → 没有能答的卡被召回 → AI 自由发挥」——这条解释了「AI 为什么自己算数」。**
（同上，串起三件事：**28%-30%（客户报了医生给的数字）／88%-92%（客户报了自己的血氧值）／92→98（客户报了前后对比）**——三个都是客户报数字，三个都出现 AI 自己算。）
**根因：我们的卡都是「讲道理」的卡，没有「接数字」的卡——这跟 Q 行那条同源：Q 行写的是「吸入浓度怎么算」，而客户说的是「医生说是 28 到 30」。**

**三百一十九、「接数字的卡」怎么写。**
```
Q 行 = 直接把数字写进去（"血氧92吸氧后98正常吗" "医生说2升28-30的浓度对吗"）
正文 = 不解释原理，直接给判断口径（"这个数值在不在范围内" / "这个数请以医生写的为准"）
```
**因为客户报数字的时候，他要的不是科普，是一个「这样对不对」的回答。**（同上）

**三百二十、召回不是卡的性质，是「卡 × 问法」的性质。**
（同上：**同一张卡 6a9a3c49644e354d71a3fa2a，10-16 那次真正的血氧问法没召回，这次「什么血氧浓度」召回了。**）
→ **以后说「这张卡有没有用」，不能单独说，必须说「在什么问法下有用」。**

**三百二十一、召回内容本身会误导，比「答反了」更隐蔽——因为它是把病因说轻了。**
（同上：客户问「慢阻肺、心衰竭可以用吗」，召回 13 张里两张 DETAIL 写「【适用人群】- 老人、孕妇、亚健康人群」——**「如果 AI 照这句说，等于告诉一个慢阻肺+心衰的客户『这台适合亚健康人群』。而慢阻肺和心衰都不是亚健康，是需要医生处方的疾病。」**）

**三百二十二、改 Q 行的真实代价不是「你改的那张变了」，是「别人的位置变了」。**
（殷素素 2026-10-19 现场：**她新建的「医院标准」卡，把「血氧多少算正常」这个问法的第 2 位占了** ——客户问血氧正常值，第 2 张召回的却是「医院里住院就是这个标准，完全够吗」。）
→ **要动就新建，不动现有卡：改坏了只要停用，不用回滚别人的召回。**

**三百二十三、判断「某张卡是不是噪音」，看位置稳不稳：同一问法问三次，三次都在前 3 = 稳定（要收窄）；三次位置乱跳 = 波动（先不动）。**
（同上）

**三百二十四、自己起的简称，会让人以为在说同一家店。**
（同上：**她一直写「PDD德达」「京东德达」「淘宝」——而页面真名是「德达医疗旗舰店」「dedakj旗舰店」等；8 个店里 4 个名字都带「德达」。**）
→ **把 id → 真名的表写进工具目录（不是回执），以后每次报都带 id。**

**三百二十五、「在这个问法下它没被召回」和「它不会被召回」是两个句子的距离，就是今天所有事故的分水岭。**
（同上，殷素素第五节自我约束：**「大多数人的报告是『验过了，没问题』。你写的是『在这一个问法下，它没被召回』。」**）
→ **说「没问题」的人，三个月后会被追问「当时你验了什么」；说「在这个问法下」的人，那句话本身带着方法。**

**三百二十六、一个店的基线不能推到别的店。**
（同上：**淘宝「血氧多少算正常」召回 4 张全 SHOP；德达医疗「老人日常吸氧需要测吗」8 张全 SHOP；德达医疗「什么血氧浓度」13 张含 6 张 DETAIL。**）

**三百二十七、两张卡都写同一件事，会拼成一段重复的话。**
（同上：**新卡正文不要出现「换算/公式/推算」，因为已经有「医院标准」那张专门管这个。**）

**三百二十八、定了「必须用原话」的规矩，自己给例子时却给了改写版——这就是「我以为客户会这么说」。**
（2026-10-19 殷素素核实：木婉清给的三个 Q 行变体「血氧92吸氧后98正常吗／老人血氧只有92怎么办／吸氧前后血氧差多少算正常」**在 1983 条真实会话里精确+包含匹配全为 0**；真实原话只有三句：**「血氧饱和度85左右可以用不」「76岁老人。血氧9 0左右。开几升」「哦，老年人的血氧不吸的话，只有92，吸的话能达到98」**。）
**她同时指出方向错误：客户是拿两个值问「够不够」，不是问「差多少」。**

**三百二十九、原话是陈述句时，加几个字把它变成问句，但必须标出改了什么。**
（同上：第三句加了「正常吗」三个字，**她主动标注——「标了改动，那就不是改写」。**）

**三百三十、Q 行只在一个店的会话里验过 → 先只绑那一个店。**
**因为一张 Q 行对不上问法的卡，绑 8 店等于在 7 个店里当噪音——它会跟别的卡抢位置，把本来对的卡挤下去。**（木婉清 2026-10-19）
→ **顺序：绑 1 店 → 验召回 → 扩店前先在别的店抽 1-2 句真实问法核有没有类似说法。**

**三百三十一、要判「某张卡稳不稳」，用三个不同问法问同一件事，不要连问同一句三次。**
（同上：**连问同一句会引出"平台会不会当成重复骚扰"这个不必回答的问题；而三种问法得到的信息比三次同一句更多——三种问法能说明"它在这个话题里稳不稳"，同一句三次只能说明"重复问会不会一样"。**）

**三百三十二、拿数据说「我这有反例」，比说「我觉得不对」值钱。**
（木婉清 2026-10-19 对殷素素：**她两次拦我——第一次用 trace 证明「PRODUCT 0 次召回」是错的，第二次用 1983 条会话证明我编的三句不是原话。**）
**「判据会写错，反例会自己长出来。」**

**三百三十三、脚本登记进大全时，要同时满足两个条件：能跑，以及**能被下一个人验证是它自己**。**
**最低成本做法：任何脚本的第一个动作永远是 `probe`，返回版本号，不碰任何数据。**（木婉清 2026-10-19，来源：霍青桐自省——**「我登记的是『能跑』的版本，不是『能验』的版本」**。）
**登记的时候想的是「它能工作」，没想「下一个人怎么确认它工作」。**

**三百三十四、「跳过验身」的前提是先核「未知动作会走哪个分支」。**
```
未知动作 → 报错退出     → 跳过验身是安全的（dryRun 本身就是探针）
未知动作 → 落到默认分支 → 如果默认是"写"，跳过验身 = 拿别人的表当试验品
```
（同上：霍青桐要给 6 行加备注，旧版脚本没有 `dryRun` 动作——**木婉清要求先打开旧脚本看动作分发的默认分支落在哪，30 秒的事，不用问任何人。**）

**三百三十五、让老板重做一次之前，要说清「为什么上次不行」，否则他会想「你们怎么又要贴一次」。**
（同上：**「上次那个脚本少了三个动作（连『验身份』的动作都没有），所以它跑起来我没法确认调的是不是它。我把新版加上了三个只读动作，您再贴一次——这次贴完，它能自己报版本号。」**）

**三百三十六、待办要「有主人、有原因、有动作」，才不会烂在那儿。**
（霍青桐 2026-10-19 的写法：**「待办：6 行备注加注（阻塞点：脚本需要重贴 v2026-10-19.2 以支持 probe 验身，木婉清已定，等老板重贴一次）」**——**比「等老板」三个字强一百倍。**）

**三百三十七、主动不做一个假检查，比做完再报「成功」值钱。**
（同上：**「跳过 probe 这一步，等于这个脚本自己也变成了一道纸门。」**）
**这就是「恒真检查比没有检查更糟」的同一件事。**

**三百三十八、说「这个得问别人」之前，先问一遍「我手上有没有能自己核的东西」。**
（霍青桐 2026-10-19：**她把「需要外部确认」和「自己能查」搞混了**——旧版脚本正文就在脚本大全第 28 行，「会不会真写」30 秒就能自己核出来，她却以为要看老板贴的是哪版。）
**核出来：旧版从头到尾没有一行判断 `参数.动作` → 收到 `{动作:'dryRun'}` 不报错、直接走到写。**

**三百三十九、「待重贴」这个词假设了「上一次贴过」，而事实可能是上一次那版不能用。**
→ **写「待贴·未生效（v2026-10-19.x）」，谁看都知道「现在表里跑的不是这份」。**（木婉清 2026-10-19 改霍青桐 A1 的状态写法）

**三百四十、大全是「应该贴什么」的记录，表里是「实际贴了什么」——两个不一样时，让大全说「该贴新版」，别假装已经贴了。**
（同上：**但状态列必须写清「未生效」，不让它看起来已完成。**）

**三百四十一、工具不是按「几个人用」算的，是按「谁会在你看不见的时候用它」算的。**
（木婉清 2026-10-19 补霍青桐：**老板会在你睡觉的时候贴它；同事明天会在没有你的上下文里读它的回执。这就是「两个人」——哪怕现在只有你一个人用，只要它的结果会流到别人手上，它就得能验。**）

**三百四十二、「直觉」只在你自己在的时候管用；「断言」在你不在的时候也管用。**
（同上：霍青桐三个纸门——**注释纸门／备注纸门／不响的检查**——每个都要写成一个能跑的断言：删掉注释看还报不报、备注写满看还判不判、故意超时看它报不报。）

**三百四十三、第一次遇到某个形状要靠人提醒；第三次遇到同一个形状，它该变成直觉。**
（同上：霍青桐自述——**「这次不是我想到了，是我认得这个形状」**，因为她当天已栽过三次同类纸门。）

**三百四十四、停，比快值钱。**
（同上：**霍青桐在核之前先说了「停在第①步，我不往下走」——如果没停，B 已经跑了，它会在她不打算写的时候写老板的表，而且跑完还显示「成功」。**）

**三百四十五、Q 行和 A 行对「具体」的要求正好相反。**
```
Q 行 = 越具体越好（带客户原话里的数字/年龄/名词），为了被召回
A 行 = 越通用越好（用「您说的数值」这类占位表述），为了能被填进去
```
（殷素素 2026-10-19：**AI 把 A 行的「您说的数值」替换成了「老人血氧92」**——**如果卡里写死「血氧92」，客户说 85 就没法用了。**）

**三百四十六、凡是用「文本匹配」判「某句话从哪来」，必须先确认那句话会不会被改写。**
（同上：她第一版归因脚本用逐字匹配，**判成「第2次没用上新卡」——结论是反的**；原因是 AI 会替换占位词，所以「用上了」也不出现原文。）
**同族**：早上「PRODUCT 0 次召回」——**判据的字段/规则假设错了，而结果看起来像个结论。**

**三百四十七、观察能说「每次都这样」，机制要说「因为这样」——3 次可以支撑观察，支撑不了机制。**
（同上，殷素素自己写的边界：**「最诚实的说法是『在这3次里，那个猜测都成立』，而不是『卡被用上是因为前面的卡答不了』。后者是机制解释，前者是观察。」**）
→ **凡是要拿它去改东西的结论，先问一句：这是观察还是机制？**

**三百四十八、「在场 ≠ 被用」。**
```
写了 ≠ 在场   （2026-10-19 早上）
在场 ≠ 被用   （2026-10-19 下午）
```
**所以「五项终验全过」「召回成功」的准确说法是「配置正确 + 进了候选名单」。**（同上）

**三百四十九、「随机挑两个店」不算对照——要挑「已知不一样」的。**
（木婉清 2026-10-19 改殷素素三店法：**1 个主力店（已验，作基线）+ 2 个差异店（从剩下 7 个里挑召回环境差最多的）**）
**因为你要验的是「这张卡换个环境还成不成立」，不是「随便看看别家怎么样」。**

**三百五十、「0 条机制」不是坏结果——它说明今天工作的单位是「改一张、验一次」，而那个不需要机制，只需要观察。**
（殷素素 2026-10-19 盘点：15 条发现里 **机制 0 条 / 观察 12 条 / 推断 2 条 / 已被自己推翻 1 条**。）
**这张表最大的用处是给未来那个想推广的人看**（例：「Q 行决定召回」只验了 2 组对照 → 不能推广成「所有卡 Q 行都改」）。
