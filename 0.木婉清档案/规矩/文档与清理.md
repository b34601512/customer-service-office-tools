## 十、文档与清理（现行规矩，黎路遥 2026-10-24 首定、2026-10-25 18:0x 升为六条，**每天都做**）

**六条**（一条一句，细则不写历史）：每条都要写明**为什么**（不这么做会真出什么事）；写「谁说的」不算理由（黎路遥 2026-10-24：引老板没意义，老板说的不一定对，**关键是为什么要做**）。
1. **一个文件只说一件事**：别把内容揉到一个文件；每次要用只读那一个文件（上下文隔离）。真人公司专人专岗也是同一个道理——每次只加载需要的那块。
2. **过时的真删，不划删除线、不写「旧写法作废」**，只保留最新思想；要查历史走 git。留着旧内容＝每次读都白烧 token，还会误导自己或同事。
3. **要复用的留本地，不用的归档，没做完的进 GitHub issue**（新待办也走 issue，办完主动关）。堆积＝下次又要重读一遍，还会反复重问。
4. **内容/功能一致的只留一份**，其他人索引；通用工具一套，改一次全公司生效。同一口径写两处＝改一处必漏另一处。
5. **规则文件必须写「为什么」**：知道为什么，才不会曲解成另一个意思；引「老板说的」不算理由。
6. **垃圾文件＝不需要二次复用的文件，但必须人工一个个删，禁止程序化自动清理**（会误删）。

**落法**：
- **总索引** `0.木婉清档案/索引.md`（一屏以内，**只放指针不放正文**）；**项目索引**每个项目一份（`<项目>/项目索引.md`）＝开工先看：规矩/口径、经验/踩坑、常用命令、红线。
- **流水账**（任务书/回执这类「新窗口不会去读的」）→ 按分类/按月归档进 `任务/归档/YYYY-MM/`，留 `索引.md` 指路；**必读件里只留「在办 #号 + 一句话」**。
- **历史决策流水**（「10-09 改 X、10-11 改 Y」）只留现口径那句，过程删；**过时口径/作废方案/过期数字直接删正文**，只留「为什么有这条」一句（做不到会出什么事）；要查哪天谁定的走 git。
- **清理时把要复用的抽成《XX规范》/《XX经验》**（每个项目一套，如 `7号/发票登记规范.md`，新口径只进这一份），只有一次性的才留在流水账里。
- **节奏**：每天清理一次（早上 08:20，跟王语嫣 08:00 的清单接上）；开工先看总索引 → 再进项目索引；聊到某话题主动翻对应笔记。判断标准：**每次必读的要一眼扫完，偶尔才查的（台账/验收/归档）才允许长**。
- **拆文件前先问两件**（2026-10-23 小昭/焦宛儿同一结论）：① 是不是母版铺下来的成品（是 → 别拆，改真源，`工具/企微/boot-prompt.md`、各家 `README.md` 这类）；② 里面混了几件事（只有一件事 → 文首加「一页速查」，不硬拆）。都不成立才拆，拆完原处留指针。
- **删除线一条不留**（2026-10-24 定）：过时的、被否的答案一律**真删**（旧方案划线圈着照样占 token、照样误导）；「当初为什么被否」用一句话写进现行那条，不另留残骸。
- **「用不上」≠「可以删」**（钟灵/王语嫣 2026-10-23）：被启动单、体检工具按**文件名**认的东西（`守护.mjs`/`直连.mjs`/`环.cjs` 这类）留着，删了会报缺件、又被当成故障。
