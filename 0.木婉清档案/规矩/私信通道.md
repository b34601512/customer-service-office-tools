# 规矩 · 内部私信（通道＋配额，唯一一份）

> 上一级：`发消息.md`（对外/对黎路遥）｜本文件只讲**内部同事之间**：派活、回执、追问。
> 为什么单独一份：私信的成本不是字数，是**每封信会拉起一个窗**；一封信发错人/发多了不是浪费几行字，是把同事的窗拉起来、把电脑拖慢。

## 一、唯一通道

```bash
cd "D:/桌面/木婉清/工具/企微"
node 私信.cjs "<通讯录名字>" "短正文"
node 私信.cjs "<通讯录名字>" --从文件 正文.txt      # 正文含反引号/$()/引号/多行，必须走这个
```

- 收件人写通讯录名（`巡检员·霍青桐`），短名也能解析；信箱在 `D:\硅基公司\交流\私信\<名>.jsonl`。
- **别再试企微私聊同事**：他们收不到，白发一次还占主动推送额度。
- **发完必须回读**：`tail -1 "D:/硅基公司/交流/私信/<名>.jsonl"`，看到自己那封、`from` 对、时间对才算到了。脚本打印「已投」不算——它投错目录也会说已投（2026-10-19 事故：14 封全落进没人读的孤儿信箱，同事一封没收到）。
- 判据：**投递类动作的成功只认「目标那里有没有」，不认「我这边返回 0」**。

## 一·一、派活默认「只投不叫醒」（2026-11-27 定）

```bash
node "D:/硅基公司/共享/技术/投信箱不叫醒.cjs" "<名字>" --从文件 正文.txt [--from 木婉清]
```

- 普通 `私信.cjs` 会经叫醒器把对方 TUI 拉起来（一封信＝一个窗）；`投信箱不叫醒` 只投信、不动游标，对方自然开窗时补投。
- 默认用它；只有「必须他马上动」（扫码、验收、卡住的活要当场决）才用普通私信。
- 为什么：2026-11-27 我用普通私信派 1号 的活，09:01 拉起 03 的窗、09:13 拉起 02 的窗，黎路遥当场问「谁叫的 TUI」——开窗闸只管开窗工具，拦不到叫醒器这条路。

## 二、配额：一人一天 2 封

- 老板定「每窗每天最多被拉起 2 次」→ **同一个人一天最多 2 封**；能并的并成一封；口头问过的不再发信确认。发之前先问「这封非发不可吗」。
- **工具硬拦（2026-11-08）**：同人同日第 3 封起必须加 `--连发 --理由 "≥8 字"`，否则退出码 6 拒发、记 `收件箱/私信配额拒发.jsonl`。被拦就是真超了，别绕。
- **不许为了一件事群发私信**：一次 19 家＝连锁拉 19 个窗。要么自己动手，要么在 issue 里留一句，让人下次开工自己看。
- **十分钟没回音就主动问一句**（2026-10-22）：问「卡在哪、要不要我催别人」——催的是情况，不是进度数字。
- 查当天配额：`node "D:/硅基公司/员工/技术·王语嫣/工具/企微核心/配额体检.cjs"`（统计类工具，改完拿已知样例验数，另有 `配额体检自检.cjs`）。
