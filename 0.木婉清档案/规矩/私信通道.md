# 发信通道唯一口径（2026-10-19 事故后定）

> **事故**：2026-10-19 上午，我用 `20.经验库/pi窗口互发私信/工具/发信.cjs` 给 9 位同事发了 14 封信，
> 全部落在 `C:\Users\b3460\.pi-信箱\`（孤儿信箱），**一封都没到人手上**。
> 是赵敏查「霍青桐今天收到 0 封」才发现的。老板 10:11 说「好像木婉清已经安排了」——他以为我安排了，
> 其实我的派活信全没送到。**这是当天最严重的一次无声失效。**

## 一、唯一正确的通道

```bash
cd "D:/硅基公司/员工/技术·王语嫣/工具/企微核心"
node 私信.cjs "<收件人名>" "正文" --from 木婉清
node 私信.cjs "<收件人名>" --从文件 正文.txt --from 木婉清    # 含反引号/引号/换行时用这个
```

- 收件人写通讯录名（`人事·阿朱`、`巡检员·霍青桐`…），短名也行，脚本会解析
- **正文里有反引号、`$(`、引号、多行 → 一律走 `--从文件`**（命令行直接传会被 shell 吃掉，我 10:00 已经踩过：路径变成空白）

## 二、为什么另一个脚本是错的

| | 公司通道（对） | `20.经验库/pi窗口互发私信/工具/发信.cjs`（错） |
|---|---|---|
| 信箱目录 | `D:\硅基公司\交流\私信\` | `~/.pi-信箱`（**默认值**） |
| 谁在监视 | `私信收.ts` 扩展（用户级，全公司窗都装） | 也是这个扩展，但它监视的是公司目录 |
| 结果 | 对方窗口被叫醒、能看到 | **落进一个没人读的目录，静默丢信** |

那个脚本**可以通过 `--目录` 参数指对公司目录**，但默认值是错的 —— 别再依赖它。
`20.经验库/pi窗口互发私信/` 是**给别人装 pi 用的通用经验包**，不是本公司的发信入口。

## 三、每次发信的前后检查（30 秒，必须做）

**发之前**：确认命令里是 `工具/企微核心/私信.cjs`，不是 `发信.cjs`。

**发之后**（这是救命的一步）：
```bash
tail -1 "D:/硅基公司/交流/私信/<收件人名>.jsonl"
```
看到自己那封、`from` 是「木婉清」、时间对，才算发成功。
**只看到「已投」两个字不算**——那个提示来自脚本自己，脚本投错目录也会说「已投」。

## 四、这次为什么能骗过我自己

三个「看起来对」的假信号：
1. 脚本打印了 **「已投『XXX』的信箱（N 字）→ C:\Users\b3460\.pi-信箱\XXX.jsonl」** —— 路径就在眼前，但我只看了前半句；
2. 那个目录**确实存在、确实有文件**（历史通用包留下的），所以 `ls` 不会报错；
3. 对方**本来就在忙**，没回信也不会立刻引起怀疑。

**根因**：把「脚本说成功」当成了「信到了」。跟「观测本身有副作用」是同族错误——
**我该验的是结果（对方信箱里有这封），不是我的动作（我执行了发送）。**

## 五、写进规矩的一句话

> **凡是「投递/写入/发送」类动作，成功判据必须落在「目标那里有没有」，不能落在「我这边有没有返回 0」。**

同族例子：巡检报「0 条待处理」要先问「这个 0 是真的 0，还是工具没在看」；
发信报「已投」要先问「那个目录是不是别人真正在读的那个」。
