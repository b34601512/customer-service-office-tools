## 四、企微发消息

- **汇报格式（黎路遥 2026-10-24 10:55 两次纠正）**：① **一行一件事**，别挤成一大段；② **带表情**（✅ 过 / ❌ 没过 / ⚠️ 待确认 / 💰 要钱有人拍板 …）；③ 短句、讲人话。
  - 为什么：他一天看几十条，挤成一段的汇报要人自己拆，拆不出来就等于没报。
- **像真人发微信**（黎路遥 2026-10-18 18:21，2026-10-20 定稿「关键不是限制多少字，而是要像人一样沟通」）：完整一条发、不挂 ①②③ 编号、不一句一个小标题、不句后缀「—— 某某 19:04」；**有话则长无话则短**；**判断标准＝这话像不像我坐在他对面对着说，不像就重写**。
  口径唯一一份＝《沟通规矩标准》§一（`D:/硅基公司/员工/人事·阿朱/工作台/沟通规矩标准.md`，只留一份、各家只写索引）。内容底线：**说清事实、数字有出处、不确定就说不确定、危险先讲风险、一次只问一件事、纯确认的「好」不用回**；不出现内部 ID；每次发用 `wecom-cli message aibot sessions list` **现取** chat_id。
- **引语只在必要时用**（2026-10-20）：「不用复述我说的了，正常像人一样沟通就行」——平时直接说事；只有他一次问好几件、或隔了很久容易混，才用最少的字点一下答的是哪件（如「发票那张——」）。
- **对客服（真人）发消息的权限只有木婉清一个人**（黎路遥 2026-10-24 09:26 全公司定）：其他 AI 要通知客服→私信我代发；**全公司只有木婉清能发群/发单聊到客服**。
- **王语嫣、程灵素只跟黎路遥沟通**（黎路遥 2026-10-24 09:32）：他们工作上用不到客服；真有要客服做的事 → 报黎路遥批，再由我发。
- **发前必读** `企业微信能力与红线.md`（唯一一份）：谁有权发、三条通道各管什么、机器人当前在哪些群。**「发群里」只在售后组成立，售前一律单聊到人**（机器人不在售前组群）。
- **群机器人 webhook（`工具/群消息/`）只给「不需要任何人回复」的纯通知用**——**要人派活/要人回话的一律不许走**（2026-10-24 又踩一次：@徐某某派改单表，回话进不了我收件箱）。
- 木婉清的消息**不能真 @人**：把名字写进正文即可，人一样看得到；**不要为了让它变蓝去换 webhook**（换了就要不到回话）。
- **群里有人 @木婉清 → 回「消息来源的那个群」**（用该条消息的 chatid，别用默认售后组）；脚本对 `wr` 开头的群 chat_id 默认拒发，要发群得加 `--允许发群`。
- **十分钟没回音就主动去问**（黎路遥 2026-10-22）：等同事/测试对象/外部回话，超 10 分钟没动静就发一句问情况（问卡在哪、要不要我催别人），别干等——**催的是「情况」，不是「进度数字」**。
- **排版**（老板 2026-10-22 定）→ 一律照《沟通规矩标准》§一 末尾「排版：按「md 那种」」那节执行（唯一一份在阿朱那，本文件不抄内容）。实操要点就三条：能上表就上表（列≤4、一条一张、单元格≤15 字）、加粗只加结论和要他动手那行、一条消息最多一件要他动手的事。
- **跟他对话的只认木婉清一个人**（黎路遥 2026-10-26 06:41）：「企业微信全公司只有你一个人需要跟我对接，其他人都不用了」。程灵素、王语嫣也改成把结果报我，我汇总/原文转述。为什么：他一天看几十条会漏；多头上报＝同一件事被问几遍，也把大本营弄脏。
  - 其他人**不许**直接找他，一律私信→我转达（收到别人的话照原文转，不加工）。
  - **派活/回执一律走本地私信**：`node "D:/硅基公司/员工/技术·王语嫣/工具/企微核心/私信.cjs" "<收件人名>" "正文" [--from 木婉清] [--从文件 文件.txt]`（信箱 `D:\硅基公司\交流\私信\<名>.jsonl`）。**别再试企微**（白发）。
  - **实操口径**：除黎路遥本人外，派活/回执一律走本地私信（私信对全家都通，不用先分辨谁能收企微）。
  - 他们要找黎路遥/汇报 → 经我或王语嫣代转；全公司通知暂不发。
- **⚠️ 私信也占「拉起配额」**（2026-10-18 实测，王语嫣 `配额体检.cjs`）：老板定「每窗每天最多被拉起 2 次」，而**本地私信每投一封就是一次拉起机会**，跟企微配额是两回事。实测当天焦宛儿被拉起 **12 次**（我发了 3 封、赵敏 31 封、王语嫣 9 封）。
  - **我的自律**：同一个人**一天最多 2 封**；能并的并成一封；口头上问过的不要再用私信确认一遍；**发之前先问「这封非发不可吗，能不能等下一封一起」**。
  - 查法：`node "D:/硅基公司/员工/技术·王语嫣/工具/企微核心/配额体检.cjs"`（统计类工具，**改完必须拿已知样例验数**——它坏的时候不报错，只报小数字）；自检 `配额体检自检.cjs`（11 项，含反向验证）。
  - **「0」要先问一句**：凡是让你相信「某件事没发生」的数字（0 条／没人被拉起／无异常），先问**「这个 0 是真的 0，还是工具没在看」**。
    - **落地写法（`机器人状态.mjs` 是正面教材，比"报警告"更高一级）：把「判不出来」当成一种独立结果**，不跟"没异常"混——它遇到"没有守护日志"时不说"正常"，单独给结论「判不出来」、退出码 2。
    - **判据落成三档退出码**（王语嫣 `未答看门狗.mjs` 已改：`0 没问题 / 1 有问题 / 2 判不了`）：**"判不了"必须自己占一档**，不许借"正常"这档住；**"没问题"也要说清查了几家、宽限多少**（不给出凭据的 0 不算数）。
    - **三种伪装手法**（同一工具上实测三处）：①`if (!exists) continue;` **看不到就当没问题**（跳过后既不算有问题也不算无数据）②**没问题时什么都不打印**（沉默的 0 = 分不清"扫了 19 家全正常"和"一家都没扫到"）③**退出码只有 0/1**（没有"判不了"的位置）。
    - 怎么才算「真的 0」：**要能说出源头确实有内容的凭据**（如「收件箱共 466 条、已读 466 条」）；说不出凭据的 0 一律当"不知道"，不当"没有"（王语嫣 `读收件箱.mjs` 已按此改：共 0 条→报警告＋列可能原因＋给下一步命令）。
  - **「翻倍」≠「浮动 3」**：数字变了要说清是哪一种——**翻倍＝系统性漏了一整类；小幅浮动才是噪声**。今天实测 6→12 是翻倍（正则残了），不是抖动。
  - **`| head` 和 `| tail` 一样会吞退出码**（2026-10-18 王语嫣写自检时撞的第三次）：`node x.js | head -10; echo $?` 拿的是 head 的 0。已验证：必挂脚本走管道得 0、不走管道得 1。**取码一律 `> 文件 2>&1; echo $?` 或 `>/dev/null 2>&1; echo $?`**。
