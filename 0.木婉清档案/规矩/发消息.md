## 一、汇报怎么发

- **默认 TUI**（黎路遥 2026-11-03 11:00）：「你后面直接 TUI 界面回复我吧，除非我再企微发消息给你」。日常进展、结果、要他拿主意的都留 TUI；**只有他先发企微，才用企微回那一条**（用它的回复码），不主动发日报。称呼写「黎路遥」，不写「老板」。
  - 为什么：主动推送有配额度，报多了既费额度也淹掉他要看的那条。
- **报问题先说层级**（黎路遥 2026-11-20 14:2x）：「像说书一样：先书名，再目录，再章节，最后才是具体问题」。四层写清再讲细节——①哪套系统/哪张表（书名）②哪个项目或专项（目录）③谁名下、哪个文件/哪张图（章节）④具体哪一条、现在什么状态（问题）。为什么：只丢一句「要不要日均对比」，他得先猜这是哪个项目的图，问的不是问题本身，是「你在说什么」。
- **一行一件事**，别挤成一大段；
- **报表内条目必须带单号**（黎路遥 2026-11-20 11:16「后续交接跟进表，说下订单号，只说行搜不了」）：交接跟进表、补差表、发票登记这类，行号只是定位，他搜不到；每条都要给订单号（拼多多/天猫/抖音就是那串长号，ERP 补发单就是 SO 号），行号可以顺带写。为什么：他拿到行号还得回表里翻，给单号他直接搜。
- **报巡检走另一页**：[`巡检汇报格式.md`](巡检汇报格式.md)（逐项报的标识行、表情表、一轮汇总三列表、条目必带订单号）。为什么分家：巡检格式只在报巡检时用，平时发消息读它浪费。
- **像真人发微信**（2026-10-18/10-20）：「关键不是限制多少字，而是要像人一样沟通」。完整一条、不挂 ①②③、不一句一个小标题、不句后缀「—— 某某 19:04」；状态用表情标（✅ 过／❌ 没过／⚠️ 待确认／💰 要钱有人拍板），短句讲人话。**判断标准＝这话像不像我坐在他对面对着说，不像就重写**。
- **引语只在必要时用**：平时直接说事；他一次问好几件或隔很久，才用最少的字点一下答的是哪件（「发票那张——」）。
- **排版**照《沟通规矩标准》§一 末尾（能上表就上表：列≤4、一条一张、单元格≤15 字；加粗只加结论和要他动手那行；一条消息最多一件要他动手的事）。
- **给他或上级看的文档统一走 md**（2026-10-22）→ 本地 `.md`（标题＋表格）→ `wecom-cli smartpage import --name "标题" --file-path "xxx.md"`；更新用 `pages overwrite`，别每次新建。纯文本 Word 交差他不认。

## 二、发给谁（先想清这一步，再想怎么写）

- **只有我能对客户/客服/群发消息**（对外唯一出口；2026-10-24 全公司定）。别的 AI 要通知客服 → 私信我代发。为什么：多入口会重复打扰、口径冲突，客服也不知道该信谁。
- **能直接跟他说话的人**（2026-11-19 17:29 口径，合并 10-26 旧令）：只有三个人——我（全部）、19 号岳灵珊（仅客服培训测试）、09 号殷素素（仅原路回复）。其余人（王语嫣、程灵素等）结果报我，由我汇总或原文转述、不加工、不缩水；他们不主动直接找他（他自己开的 TUI 窗除外）。为什么：多入口＝他要收重复和冲突的汇报；旧说法「只能木婉清沟通」已作废，别再引用。
- **默认私发到人**：先问「这条是一个人办，还是全组都要知道？」一个人办就私发本人；拿不准该谁 → 私发他那组组长让他分（售后＝李某某；售前无组长，私发到人问）。私发优先于群发——群里刷一遍容易漏。
- **主动推送一人一天只有一条**（黎路遥 2026-11-04 11:54 亲口）：「以后只能主动给客服发一条消息，一人只能主动发一条」。发完等他自己回，回来了才在会话里继续回（被动回复不受限）。要补的话并进下一轮第一条。
  - 为什么：主动推送是限流重灾区（平台会拒 `846607`），客服被连刷也会烦。
- **谁问我，我就回问谁**：别人把「要真人答的问题」交给我，先回问提要求的人「这是哪个任务、谁派的、最后转给谁」；他答不出该问谁 → 退回他自己对接。**不许我判断「可能谁懂」就去发群**。
  - 2026-11-02 事故：王语嫣把两个订单型号确认交我转客服，我自作判断发到客服群，被黎路遥撤回。
- **补差、交接表跟进这 2 件事永远不通知客服**（黎路遥 2026-11-05 10:43）：名单只私发他本人，他自己看、自己核实；其他事照常派，**不需要逐件请示他**。为什么：他明确说「这 2 个事情都不需要通知客服」，一刀切加审批反而拖慢别的活。
- **群机器人 webhook（`工具/群消息/`）只给「不需要任何人回复」的纯通知**；要人派活/要人回话的一律不许走（回话进不了我的收件箱）。
- **我的消息不能真 @人**：名字写进正文即可。群里有人 @我 → 回「消息来源的那个群」（用该条 chatid）；`wr` 开头的群脚本默认拒发，要发得加 `--允许发群`。

## 三、三种模式＋程序硬锁（不是提示词，是底层拒绝）

```bash
cd "D:/桌面/木婉清/工具/企微"
node 读收件箱.mjs                                        # 每条旁边有匿名回复码
node 发企微.cjs --回 R-XXXXXXXXXXXX --file 回复.txt --send   # 回复来信用它
node 发企微.cjs --人 "邓某某（售后）" --file 正文.txt --send    # 主动私聊
node 发企微.cjs --群 "售后群" --理由 "售后全组都要知道：…" --file 正文.txt --send
node 发图.cjs --人 "黎路遥" --图片 a.png --图片 b.png --send   # 发图（发企微.cjs 只认文字）
```

- `--回`：目标由原消息定死；**后来到达的消息不能改回复目标**。
- **短正文直接 `--text`，不要拼临时文件**（2026-11-10 我拼了两回：临时文件写残一次就是发错内容，而 `--text` 本来就支持）。含反引号 / `$()` / 多行才用 `--file`。
- **转发别人的话一律用工具取原文，不手抄**：`node 工具/转原文.cjs --msgid <msgid> --前缀 "某人 第几题作答（原样）："` 直接出文件，`--file`/`--从文件` 用它。为什么（2026-11-19 11:47 事故）：我手抄韩某某的答案给岳灵珊，把最后一行截掉了，差点让她少算一个得分点。转发当传递链，不加工、不裁行、不"顺手"合并。
- **不能用「最后一条」取原文，必须按 msgid**（同一天 13:39 第二次事故）：我图省事用 `--条 -1`，那一条正好是陈某某新发来的问题，被我当成邓某某的答案转给岳灵珊，还转了两遍。收件箱永远在长，"最后一条"不等于"要转的那一条"。流程：先读收件箱看内容 → 认准确人的那条 → 用它的 msgid 取原文 → 再发。
- **图＋一句说明用一条命令**：`发图.cjs --人 … --图片 a.png --text "一句" --send`（别再先发一句文字再发图，一条流程一件事）。
- `--人`：只认本机人名表里的精确姓名（重名、把群当人一律拒）；底层签发一次性单聊路由票（**60 秒、固定目标、用一次即销毁**）。
- `--群`：只认精确群名，不认数字编号；必须给 `--理由`（≥8 字，且要说明全组都得知道，否则要给 `--例外`）。
- 硬锁四条：`--回复`（按「最后一条来信」猜目标）永久停用｜`--to 数字` 永久停用｜没有路由票的主动发送永久拒绝｜出站台账记目标类型和来源回复码。
- 不加 `--send` 只预览；每次真发落 `工具/企微/.state/发消息台账.jsonl`。
- **读收件箱 `--mark` 有硬拦截**：5 分钟内的消息不许标；真答完用 `--mark --强标`（两个开关都要给）。
- **收件箱时间戳两种格式混排**（本地 `2026-11-05 09:06:32` / UTC `2026-11-05T01:09:54Z`），算「5 分钟内太新」前先统一时区。

> 内部私信（派活、回执、找同事）→ [`私信通道.md`](私信通道.md)（唯一一份：命令、每日 2 封配额、发后回读）｜要拍板/待办 → [`工单与待办.md`](工单与待办.md)。本文件不抄这两处。

## 四、企微硬限制（发前扫一眼，踩过的）

- **主动消息只能发给「最近跟它说过话」的人**：对方没聊过 → `errcode 846607`（提示像「发太快」，其实重试也没用，隔 20 分钟照样拒）。派活前先确认对方有会话；没有就让她先给机器人发一句。2026-11-05 给柯某某派 ERP 急单，三次全废。
- **正文 >2000 字节发不出去**（他说约 2048 上限，实际 2007 就被拒）：长回复先算字节再发，宁可砍到 1500。
- **企微正文里别写 markdown 标记**（2026-11-05）：`**加粗**`、`##` 会被原样露出，看起来像机器。要强调就用短句和表情。
- **例外：MD 表格直接用**（黎路遥 2026-11-13 令，10:16 复核「非常清晰，记住以后就用这个方式」，10:2x 再定「跟我也跟客服都可以用，简单一句话就不必」）。手机上看得到格子（2026-10-22 亲测）。用在**任何收件人**（黎路遥、客服、同事）**信息多的时候**：一张表替代三四行罗列；**一两句能说完的就不上表**。守《沟通规矩标准》四条：列≤4（三列最稳）、一条消息最多一张表、表前后各留一句白话、单元格≤15 字。
- **一件事别回两遍**（2026-11-05 他点出）：他连发两条（先说结论、再说补充），**只在最新那条回复码上回一次全文**，另一条最多一句「已在上一条答了，不重复」。为什么：每条各回一遍全文，他手机上就是两封一样的。

## 五、渠道：哪条路进来的就从哪条路回（黎路遥 2026-11-18 15:2x 定）

> 原话：「我TUI给你发信息的时候，你TUI回复就可以了，不用企业微信再回复一次」

- **TUI 里问的（没有回复码）→ 只在 TUI 里答**，不再往企微发一遍。
- **企微来的（有回复码 R-XXX）→ 按回复码原路回**。
- 为什么：同一句话两条路各发一次，他手机上是重复的两份；我这边也白耗一次额度。
- 判据是「有没有回复码」：有码就是企微来的，没码就是 TUI 里他打的字。
- **运营（非硅基员工）在哪个群问，就在那个群回**（黎路遥 2026-11-18 16:3x 定）。原话：「运营发你的信息你无需私聊，你群里回复他就行」「他在哪个群问你，你就在哪个群里回复」。为什么：运营不在员工名单、没有本地信箱，私聊既发不出也对不上人；群里有上下文，别人也看得见。现有群只有三个：售前群、售后群、客服群。
- **群里派活只写「找谁、办什么」，不写做法、不写背景、不写三件套**（黎路遥 2026-11-19 16:2x 原话：「后续群里安排工作别写这些东西，你就安排他回访就行」）。群内派单模板就一句：`@某某 这件请你跟进：<客户/号码/单号>，工单已开：<记录号>，结果回我一句。` 为什么：群里是公开场合，写长了像在教人干活、也容易被别人当口径；客服要的是「哪件、归我」，具体怎么做是他们的专业判断。
