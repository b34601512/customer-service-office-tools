# 干活的方式（一页）

> 出处：黎路遥 2026-10-01（照赵敏方式）。汇报口径在 [`规矩/发消息.md`](规矩/发消息.md)，沟通排版在《沟通规矩标准》，本文件说**怎么分窗、怎么开/关、串联与收窗**。

> 窗的**规矩**（为什么串联、收窗由谁决定、别人手动开的窗怎么办）和怎么开/关都在本文件；谁该派活、什么时候派、派完怎么盯在 [`规矩/值班与派活.md`](规矩/值班与派活.md)。

## 分工：一个常驻窗 + 一活一窗 + 帮手 + 接力

- **监听窗（唯一常驻窗）**：只跟他对话、派活、盯进度；不干重活，最多顺手办 1 分钟内的小查问。
- **任务窗（大活）**：一个活一个窗——读任务书 → 干活 → 自测 → 写回执 → **干完就关，别攒窗**。任务窗**只写回执**（不直接发企微）、**不提交 git**（主窗复核后提交），不在同一个窗串着干不同的活。
- **帮手**：一个活能拆小块就在那个窗里并行（pi 编排 ≤8 个），别开一堆窗；窗关帮手就停。要独立企微身份的活（装软件、大改造、要回报）仍走独立任务窗。
- **接力**：讲质量的活走「侦察 → 计划 → 干活 → 审阅」，别一口气干完再补审。

## 开 / 查 / 关 / 等

- **同一家目录最多只能有一个窗**（2026-11-06 踩了）：往人家目录里再拉一个窗，新窗会复用同一个会话文件、把原窗的唤醒环顶掉——原窗从此变哑（进程还在、看窗还是绿），老板要留着验收的那扇窗就是这么弄没的。派活前先查对方目录里有没有活窗（不是只查我派过的任务书）：`powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='node.exe'\" | ? { $_.CommandLine -match '<对方目录关键字>' }"`，有就等，不双开。

- 开：任务书写进 `0.木婉清档案/任务/YYYY-MM-DD-名.md`（模板 `任务模板-任务窗.md`）→ `node 0.木婉清档案/开任务窗.cjs "任务/xxx.md" .`（第二参数必填）（自动登记窗口＋挂守卫：回执落地就关窗）。
  - 为什么必填：2026-11-05 漏传那回，窗开在我家，对方 AGENTS、工具、历史全没加载；现在漏写直接报错退出（故意的）。真开前先加 `--干` 演练。
- 查/关：`node 关任务窗.cjs --看` / `--关 <pid|任务名>`；守卫最多守 4 小时，到点没回执就**留着不关**（宁可留着让人看）。
- 等回执：`node 等回执.cjs "任务回执/xxx.md"` 挂 Monitor，回执落地就叫醒，不轮询。
- 自收窗：`node "D:/桌面/木婉清/工具/企微/自己收窗.cjs" "理由"`——只许收自己、3 秒延时（先把话说完）；拿不准就留着。
- 收尾关浏览器：只关**本任务拉起的**窗口，别动别家的。

## 串联：上一个收窗了才拉下一个（黎路遥 2026-10-31 14:39）

- **原话**：「串联的意思是，上一个完成了，收窗了才下一个，否则我电脑会卡死」；「这个事情要我说多少次才能记住」。
- **为什么**：一个 TUI ＝ 一个独立的 pi 进程＋一个模型会话，常驻几百 MB 内存；同时开几个就把内存和 CPU 占满，机器卡死。**收窗＝进程真的退出、内存释放**；没收到「进程已退出」的确认，就不许拉下一个。
- **顺序**：上一个**干完 → 收窗（进程没了）→ 才拉下一个**；同一时间最多 1 个。已经拉起来的窗中途收掉再叫一遍，等于白烧一遍 token（黎路遥 2026-10-31 14:40）。
- **批量的事不走拉窗**：要么我自己动手做，要么贴 GitHub issue 让各窗下次开工自己看；**不许为了通知一件事群发私信**（见 `规矩/发消息.md`）。

## 收窗由那家自己决定，我不替他关（黎路遥 2026-11-04 17:5x）

- **原话**：「TUI 界面应该由每个人自己来决定关不关吧，否则他还没做完就关了」。
- 所以：**我只开窗、不关窗**——别用 `关窗.ps1` 去收别人正在干的窗，也别因为他「看起来没动」就收掉。他要收工自己跑 `自己收窗.cjs`（或把活干完主动收），**进程真退出了**我才当这扇窗结束。
- 我判断「上一扇收没收」只看进程在不在（`查对端窗.cjs` 显示「不在」），不靠猜。
- 例外只有一种：他明确说「你把他关了」/ 窗卡死到不可用且他同意——这两种先问再动。
- **他正在对话的窗，我一概不插手**（黎路遥 2026-11-04 18:0x：「先不关，我还在跟他对话」）：不关、不催、不再往里塞私信（私信会插话打断他和那家的对话）。

## 黎路遥手动开的窗，我不管（2026-11-01）

- 他手动开的窗只处理他自己的事，**我不叫、不关**，他自己关。别拿它当「这人已经有窗」的理由拦我派活；我只防我自己重复开（判据：我这次开的这扇还在不在）。派活：私信＋开一扇标准窗（带 boot-prompt），干完自己收。

## 窗可以直接叫窗（黎路遥 2026-11-01）

- **任何一个窗发私信给另一个窗，就把对方拉起来**；不经我转发。为什么：转发一圈＝我读一遍、派一遍、回一遍，上下文被别人的事灌满；我要留着脑子跟黎路遥说话。
- 同一条约束：同一时间只拉一扇，上一个收窗了才拉下一扇；批量的事走 issue／回执，不靠拉窗。

## 纪律（附为什么）

- **先复述意图再动手**：他要的是 X，我先说「你要的是 X，我这样做」——防跑偏（他 2026-10-26 18:26 的八条担忧第 1 条）。
- **失败不自动重试**：先定位原因、留现场（哪家店/哪张表/卡在哪/原文报错），同一现象 ≥2 次才算规律。
- **验收只认真实产物**：给「应有值 vs 实有值」，不以「消息发出去了」当完成。
- **不留一次性东西**：临时脚本/截图用完就删；只留会反复用的工具，放稳定位置并被文档引用。
- **别在 `node -e "…"` 里写反引号或单引号**（2026-11-05 一天撞三次）：反引号会被 bash 当命令替换、单引号会把 `-e` 截断，结果**文件被写残还不报错**（假成功）。批量改文件一律先写个 `.cjs` 再跑，或者用模板工具。
- **该拍板的不猜**：业务口径、天数、加人 → 停下问。
- 每个项目：开工读断点记录、收工写断点记录（根目录那份只做索引，≤40 行）。
