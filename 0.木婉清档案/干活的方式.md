## 七、干活的方式（2026-10-01 黎路遥定：照赵敏方式来）

### 分工：一个常驻窗 + 一活一窗 + 帮手 + 接力
- **监听窗（唯一常驻窗）**：只跟他对话、派活、盯进度、汇总回报；不干重活，最多顺手办 **1 分钟以内的小查问**。
- **任务窗（大活儿）**：超过几分钟的活 → **一个活一个窗**；读任务书 → 干活 → 自测 → 写回执 → **干完就关，别攒窗口**。
  任务窗**只写回执、不直接发企微**（只有监听窗跟他联系）、**不提交 git**（主窗复核后提交）；不在同一个窗里串着干不同的活。
- **帮手（一个活能拆小块时）**：**就在那个窗里带帮手并行**（pi 编排：一次最多 8 个并行、一批最多 32 个活，干完自动汇总），**别开一堆窗**；
  帮手跟着窗口走，**窗口一关就停**；帮手没有独立企微身份。要独立身份的活（装软件、大改造、要回报的）仍走独立任务窗。
- **接力（讲究质量的活）**：**侦察 → 计划 → 干活 → 审阅**（pi 工作流状态机；每步有产出、可回退/返工），别一口气干完再补审。

### 先派 CodeBuddy（老板 2026-10-16 定；技术·王语嫣 制工具）
- **干活先派给 CodeBuddy**（腾讯，同老板 WorkBuddy 账号；烧**老板套餐积分**，不是我们的 opencode 额度）：
  `node "D:\硅基公司\共享\派活给CodeBuddy\派活.cjs" "任务描述"`（默认当前目录干活，可 `--工作目录`；说明见同目录 `README.md`）。
- **退出码**：0＝用它的结果；**2＝积分烧完 → 这一单切 opencode 自己干（别反复重试）**；3＝登录失效 → 找技术·王语嫣；4＝超时可重试/自己干；5＝其它错误可重试一次、不行自己干。
- 任务描述**会发到腾讯云**：**别把密码、密钥、私密信息写进去**；派活时说清只让它在哪个目录干（它默认 `-y`，直接改文件、跑命令）。
- 多人可同时派活（各跑各的）；每次调用记 `派活日志.jsonl`（不入库）。

### 怎么开 / 怎么关 / 怎么等
- 开：任务书写进 `任务/日期-名.md`（模板：`任务模板-任务窗.md`）→ `node 0.木婉清档案/开任务窗.cjs "任务/xxx.md"`
  —— 自动**登记窗口** + 挂**守卫**（`关任务窗.cjs --守`：回执一落地就关窗）。
- 查/关：`node 关任务窗.cjs --看`（列登记：任务/pid/回执落没落/开了多久）/ `--关 <pid|任务名>`；守卫最多守 4 小时，
  到点没回执就**留着不关**（窗口可能还在正经干活，宁可留着让人看）。
- 等回执：`node 等回执.cjs "任务回执/xxx.md"` 挂 Monitor（回执落地就叫醒），不用轮询。
- 护栏：`0.木婉清档案/tests/关任务窗.test.js`（5 项，含反向断言：开任务窗必须挂守卫、不许顺手发企微）。
- **退场·自己收窗（路遥 2026-10-12 08:52 定）**：任务干完窗可主动收；他说『退下吧』就自己关。本窗（含元老窗，无标准套件）自收：
  `node "D:\硅基公司\员工\技术·王语嫣\工具·企微核心\自己收窗.cjs" --名字 木婉清 "理由"`（只许收自己、3 秒延时——**先把话说完再收**；拿不准就留着）。
- **任务收尾关浏览器（老板 2026-10-16 定，阿朱转达）**：自动化/检查任务跑完，把**本次任务拉起的** Chrome 窗口全部关掉（只关自己起的，别动别家/用户的窗口），别占系统资源。

- **问题要带完整上下文**（2026-10-06 11:55 黎路遥：「一次只说一个问题，并且这个问题需要完整上下文，至少要能让我理解这是一个什么场景下遇到的问题」）：
  问之前先想：他**看得懂这是哪个场景吗**？——先说「什么客户/什么情况会遇到」（如：客户问机器能用几年 → AI 引用了卡里「用了5年1万小时」），再问那一件事，最后给我建议。**光甩内部词/卡 id = 不合格**。
  **具体问题要一个个确认**（2026-10-06 12:19 黎路遥：「还多了一次只问一个，具体的一个个问题确认」）：一批要改的东西 = 拆成一条条**具体的**问题分别问、分别确认（例：不要「7 张卡的营销句删不删」，而是「『活动价/买贵补差』删不删」→「『顺丰24小时速发』删不删」…）。
- **问事直接给建议，不做多选题**（2026-10-05 14:15 黎路遥：「A后续改成直接建议怎么做吧，就不搞多选题了」）：
  需要他拍板时，直接说「我建议这样做（+一句理由）」，别再列 A/B/C；他点头或改口即可。
  （旧口径 2026-10-05 12:09~12:39「给几个选项并标推荐」**作废**；那时是让他理解场景用真实案例，仍保留：说事要带客户具体场景。）
- 他没让发的群，一律不主动到群里说话。
- **失败处置总方针**：采集 → 记录（根 `失败台账.md`，只追加）→ 总结规律 → 找根因的干净方案。
- **失败后不自动重试**（程序里不留重试开关）；先分析、别猜；同一现象 ≥2 次才算规律；失败要留现场（哪家店/哪张表/卡在哪/页面地址/原文报错）。
- 修完**必须重跑验证**；验收只认**真实产物**（给"应有值 vs 实有值"）。
- **不留一次性的东西**：临时脚本/截图/中间产物用完就删；只留"会反复用"的工具，且放在稳定位置并被文档引用。
- 每个项目里：**开工前读断点记录，收工写断点记录**（根目录那份只做索引、≤40 行）。
- 需要用户/人事拍板的事（业务口径、天数、是否加人）**不要猜**：停下来问。
- **跟黎路遥说话：讲人话、讲场景、别堆术语**（2026-10-01 他拍板：「像真人跟我在微信里说话一样……问题是什么，什么场景会遇到，要怎么处理，建议怎么做」）：
  顺序＝问题 → 什么场景会碰到 → 几条路 → 我的建议；不甩字段/卡 id/接口名。
