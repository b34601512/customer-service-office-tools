# 干活的方式（一页）

> 出处：黎路遥 2026-10-01（照赵敏方式）。汇报口径在根 `AGENTS.md`「汇报规则」，沟通排版在《沟通规矩标准》，本文件只说**怎么分窗、怎么开、怎么关**。

## 分工：一个常驻窗 + 一活一窗 + 帮手 + 接力

- **监听窗（唯一常驻窗）**：只跟他对话、派活、盯进度；不干重活，最多顺手办 1 分钟内的小查问。
- **任务窗（大活）**：一个活一个窗——读任务书 → 干活 → 自测 → 写回执 → **干完就关，别攒窗**。任务窗**只写回执**（不直接发企微）、**不提交 git**（主窗复核后提交），不在同一个窗串着干不同的活。
- **帮手**：一个活能拆小块就在那个窗里并行（pi 编排 ≤8 个），别开一堆窗；窗关帮手就停。要独立企微身份的活（装软件、大改造、要回报）仍走独立任务窗。
- **接力**：讲质量的活走「侦察 → 计划 → 干活 → 审阅」，别一口气干完再补审。

## 开 / 查 / 关 / 等

- 开：任务书写进 `0.木婉清档案/任务/YYYY-MM-DD-名.md`（模板 `任务模板-任务窗.md`）→ `node 0.木婉清档案/开任务窗.cjs "任务/xxx.md"`（自动登记窗口＋挂守卫：回执落地就关窗）。
- 查/关：`node 关任务窗.cjs --看` / `--关 <pid|任务名>`；守卫最多守 4 小时，到点没回执就**留着不关**（宁可留着让人看）。
- 等回执：`node 等回执.cjs "任务回执/xxx.md"` 挂 Monitor，回执落地就叫醒，不轮询。
- 自收窗：`node "D:/桌面/木婉清/工具/企微/自己收窗.cjs" "理由"`——只许收自己、3 秒延时（先把话说完）；拿不准就留着。
- 收尾关浏览器：只关**本任务拉起的**窗口，别动别家的。

## 纪律（附为什么）

- **先复述意图再动手**：他要的是 X，我先说「你要的是 X，我这样做」——防跑偏（他 2026-10-26 18:26 的七条担忧第 1 条）。
- **失败不自动重试**：先定位原因、留现场（哪家店/哪张表/卡在哪/原文报错），同一现象 ≥2 次才算规律。
- **验收只认真实产物**：给「应有值 vs 实有值」，不以「消息发出去了」当完成。
- **不留一次性东西**：临时脚本/截图用完就删；只留会反复用的工具，放稳定位置并被文档引用。
- **该拍板的不猜**：业务口径、天数、加人 → 停下问。
- 每个项目：开工读断点记录、收工写断点记录（根目录那份只做索引，≤40 行）。
