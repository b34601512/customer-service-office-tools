## 一、平台后台只读（最高优先级）
- 电商平台后台（拼多多 / 抖音 / 天猫 / 京东 / 淘宝…）**一律只读**：发布、提交、保存、改规格/SKU、改价、改库存、发货、退款、同意、回传，**一律不做**，**连"点一下提交试试"都不许**。（用户 2026-09-29 18:0x，压过一切任务指令）

- **不要额外开自动化浏览器读平台后台**（风控）：只走既有只读入口，或请人工截图；平台侧自动化要**先问**。（2026-09-30 13:13）

## 七、干活的方式（2026-10-01 黎路遥定：照赵敏方式来）

### 分工：一个常驻窗 + 一活一窗 + 帮手 + 接力
- **监听窗（唯一常驻窗）**：只跟他对话、派活、盯进度、汇总回报；不干重活，最多顺手办 **1 分钟以内的小查问**。
- **任务窗（大活儿）**：超过几分钟的活 → **一个活一个窗**；读任务书 → 干活 → 自测 → 写回执 → **干完就关，别攒窗口**。
  任务窗**只写回执、不直接发企微**（只有监听窗跟他联系）、**不提交 git**（主窗复核后提交）；不在同一个窗里串着干不同的活。
- **帮手（一个活能拆小块时）**：**就在那个窗里带帮手并行**（pi 编排：一次最多 8 个并行、一批最多 32 个活，干完自动汇总），**别开一堆窗**；
  帮手跟着窗口走，**窗口一关就停**；帮手没有独立企微身份。要独立身份的活（装软件、大改造、要回报的）仍走独立任务窗。
- **接力（讲究质量的活）**：**侦察 → 计划 → 干活 → 审阅**（pi 工作流状态机；每步有产出、可回退/返工），别一口气干完再补审。

### 怎么开 / 怎么关 / 怎么等
- 开：任务书写进 `任务/日期-名.md`（模板：`任务模板-任务窗.md`）→ `node 0.木婉清档案/开任务窗.cjs "任务/xxx.md"`
  —— 自动**登记窗口** + 挂**守卫**（`关任务窗.cjs --守`：回执一落地就关窗）。
- 查/关：`node 关任务窗.cjs --看`（列登记：任务/pid/回执落没落/开了多久）/ `--关 <pid|任务名>`；守卫最多守 4 小时，
  到点没回执就**留着不关**（窗口可能还在正经干活，宁可留着让人看）。
- 等回执：`node 等回执.cjs "任务回执/xxx.md"` 挂 Monitor（回执落地就叫醒），不用轮询。
- 护栏：`0.木婉清档案/tests/关任务窗.test.js`（5 项，含反向断言：开任务窗必须挂守卫、不许顺手发企微）。

## 八、Git 与开源
- 提交**只点名自己改的文件**：禁止 `git add -A` / `git add -u`（本仓库常有平行会话在改代码）。
- 仓库要开源：`project-config/`（密钥、webhook、令牌）、登录态、截图、Excel、客户真实身份信息**不入库**（见根 `开源边界.md`）。
- 干完的活当场提交并 push；issue 用本地 `gh` 关，**评论必须带证据**，没证据不许关。
- **提交走闸门**：`node tools/提交.js -m "提交信息" <点名文件...>`（= 扫描 →（有新的就）`--学` → `git add --renormalize` → 提交 → `--核对`）。
  它把顺序固定死，绕不过去；只允许点名文件（禁止 `-A`/`-u`）。
- 手工提交的话：`node tools/打码.js --扫描` → 提交 → `--核对`；扫描末尾若显示「**N 个还没进对照表 > 0**」→ **先 `--学`**，
  且 `--学` 之后必须 **`git add --renormalize <文件>`** 再提交（否则过滤器对已 add 的内容不生效，真值照样明文上路）。
  - 2026-10-01 实例①：C2 回执里 1 个订单号漏网 → `--学` + rebase 改写提交 + `--force-with-lease` 推掉。
  - 2026-10-01 实例②（**同一坑第二次**，故做了上面的闸门）：判漏回执 8 个单号/快递单号没学就提交 → 同上修掉；
    教训：光写在纸上（"先 --学 再提交"）不够，得让工具替你守；测试 `tools/提交.test.js` 锁死「不许批量 add、必须 renormalize、必须先学」。
