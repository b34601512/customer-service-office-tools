## 一、平台后台只读（最高优先级）
- 电商平台后台（拼多多 / 抖音 / 天猫 / 京东 / 淘宝…）**一律只读**：发布、提交、保存、改规格/SKU、改价、改库存、发货、退款、同意、回传，**一律不做**，**连"点一下提交试试"都不许**。（用户 2026-09-29 18:0x，压过一切任务指令）

## 八、Git 与开源
- 提交**只点名自己改的文件**：禁止 `git add -A` / `git add -u`（本仓库常有平行会话在改代码）。

- 干完的活当场提交并 push；issue 用本地 `gh` 关，**评论必须带证据**，没证据不许关。

- 手工提交的话：`node tools/打码.js --扫描` → 提交 → `--核对`；扫描末尾若显示「**N 个还没进对照表 > 0**」→ **先 `--学`**，
  且 `--学` 之后必须 **`git add --renormalize <文件>`** 再提交（否则过滤器对已 add 的内容不生效，真值照样明文上路）。
  - 2026-10-01 实例①：C2 回执里 1 个订单号漏网 → `--学` + rebase 改写提交 + `--force-with-lease` 推掉。
  - 2026-10-01 实例②（**同一坑第二次**，故做了上面的闸门）：判漏回执 8 个单号/快递单号没学就提交 → 同上修掉；
    教训：光写在纸上（"先 --学 再提交"）不够，得让工具替你守；测试 `tools/提交.test.js` 锁死「不许批量 add、必须 renormalize、必须先学」。

## 十、笔记与索引（2026-10-09 黎路遥定）

> 原话要点：「你所有的笔记要不要整理一下，该建立文件夹的建立文件夹，该建立索引就索引……最好是一个项目用一个文件夹归类好，当做某个项目的时候就先看下索引，这个索引下都有哪些规矩、经验都记录好……**流水账的笔记都要拆分出来归档好分类存放好**。」
> 「**只要流水账你新窗口不会去看的你就要拆成索引归档，以后每次新窗口都看下索引，聊到某个问题的时候就主动看下对应的**……以后你**定期自动拆分整理，没活的时候就自动搞**。」

- **总索引**：`0.木婉清档案/索引.md`（一屏内）——总规矩、各项目索引、经验库、台账/验收/待办待确认、日常流程、值班口径。
- **项目索引**：每个项目一份（`<项目>/项目索引.md`，或并入现有 README 的一节）＝**开工先看**：规矩/口径（带原文链接）、经验/踩坑、常用命令、红线。
- **流水账**：任务书/回执这类「新窗口不会去读的」→ **按分类/按月归档**（`0.木婉清档案/任务/归档/YYYY-MM/`），并留 `索引.md` 指路；**只挪不删**。
- **节奏**：① 开工先看总索引 → 再进对应项目索引；② 聊到某个话题**主动翻对应笔记**；③ **每天 19:30 自动整理**（没活就归档当天流水账+更新索引，忙就跳过）；④ 判断标准照旧：**每次必读的要一眼扫完，偶尔才查的（台账/验收/归档）才允许长**。
- **教训（起因）**：「个人票=收货人姓名」这条口径**记过**（7号 断点/经验里）但用时没找到 → 写成「个人」。→ 规矩必须挂在**项目索引**上，不能只躺在流水账里。
- **升级（2026-10-09 16:00 黎路遥）**：「正常**所有项目都应该有这样的东西，一套规范，汇总到一起**……整理的时候就要把以后要复用的经验抽成可复用的规范或经验，**只有一次性的不需要复用的才让他留在流水账里**。」
