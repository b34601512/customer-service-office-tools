## 三·九、数据落盘三条硬话（2026-10-18 赵敏扫全公司后定）

**① `runtime/` 只准留本机**
> `runtime/` 里的东西默认是「本机工作副本」，安全靠三件事：**不进 git、不进同步目录、不进手动备份**。**少一条就等于没做。**

理由：`D:/备份文件夹` 是手动拷贝，`.gitignore` 管不住它——老板双击那个 bat 走 git（`runtime/` 不会进去 ✅），但**哪天有人把 `D:/硅基公司` 整个拷进去，`runtime/` 会跟着走**。
实测（2026-10-18）：全公司 25 个 `runtime/` 共 19.1 GB，其中 5 个是全量表镜像；同一张《退货退款表》在骆冰三个专项各存一份完整镜像（16,398 个手机号），**都未被 git 跟踪**（这条是好的），但**文件名会骗人**（`退货退款表-抽查.json` 里是全量）。

**② 浏览器 profile 目录按「凭据级」处置，不是「隐私级」**
`runtime/state/browser-profiles/**` 里有 `Cookies`／`LocalStorage`／`IndexedDB`。
**泄露手机号是客户隐私问题；泄露 Cookie 是「别人能直接登进平台点按钮」的问题——量级不同。**

**③-a 报一个数，必须能贴出算它的命令**（2026-10-18 退货表 13128 事故后定）
> 说清「哪个文件、哪一列、什么正则」还不够——**仍然可能三个说错两个**（实况就是：列号错、正则错、而且那个数根本不是那一列的）。
> **只有把命令贴出来，别人才能跑一遍对或推翻。贴不出命令的数，只能当"我看到的"，不能当"事实"。**

**③-b 脱敏不是"把号码抹掉"，是"把能定位到人的整串都抹掉"**
> 抹之前先看它后面挂没挂东西（**分机**、工号、单号后缀）。
> 实况（骆冰 2026-10-18）：脱敏正则把 `17504502347-4351` 抹成 `[手机号]-4351`——**分机号留下了**。分机单独看风险低，但配上「哪家公司、哪天、哪张单」，**回到同一个人的概率不低**。

**③ 写文档举例时一律自己编号码，不抄原文**
> 写文档说明「这里有个手机号」时，**自己编一个（如 `13800000000`）**，不要抄原文。编的号和抄的号在文档里长得一样，对读者没区别。

理由（赵敏 2026-10-18）：**这不是「谁不小心」，是「写文档时抄原文」这个动作本身会造泄漏。只要动作还在，清完还会再冒。**
实况：骆冰自查出 7 处真手机号进了 git（3 个是快递员电话抄在代码注释里说明 bug、4 个抄在经验文档里），已打码；同日宁中则也清了自己 20 处，**而骆冰那篇是宁中则清完之后又新增的一处**。

## 三·十、探测别人要知道自己在被探测（2026-10-18 王语嫣提、我认）

**任何"存活性探测"，都要让对方知道自己在被探测。** 不是为了礼貌，是因为：**不知道自己在测试的人，会给出"测试答案"。**

实况（2026-10-18）：王语嫣为验判据给我发「在吗」，我 20 秒回了。她拿到了干净的数——**但那个数是有偏的**：我回的只是"有人问我我就回"，不代表"我的监听链健康"。而我不知道那是探测，所以没做任何"如果要证明我能干活，我该拿什么证据"的判断。

**落法**：
- 探测消息**开头写清**：`【存活性检查·不用干活】`
- 对方回了，**采不采信要分开说**：回得快＝"能收到能发回"；**不代表**"监听链、定时器、任务窗都在正常跑"
- 报结论时把这两层分开写：**「活着」** vs **「验证过能干活的路径」**
- **三档更细（王语嫣 `三家互检.cjs` 已实现）**：`活着`（进程在＋文件有动静）→ `活着且有往来`（30 分钟内有人跟她说话且她动过）→ `通了`（刚真发真收、有秒数）。**平时只报前两档，`通了` 只在手动端到端时才有**——看到"活着"就不会误当成"刚验过"。
- ⚠ **「知情 vs 不知情」的快慢差，别当数据用**：实况 10 秒 vs 20 秒，差的不在"知不知情"，在"**要不要先读懂**"（第一版是"在吗？我做个存活性检查"＝要先判断这是什么；第二版是固定前缀＝一眼知道做什么）。**把快慢归因给"知情"，是假因果。**
- ⚠ **认错认得比事实重，也是错，方向相反**：会把问题说得比实际大，下次别人就不信你的自我评估。**先看读数再认**（实况：第一版其实已经写了"存活性检查""不用干活"，缺的只是固定格式，不是"没告诉对方"）。
  - **病根（王语嫣提炼，比上面更准）：把「一次具体失误」说成「我这个人有问题」。**
    · 「改错了文件」→ 说成「我根本不懂影响范围」
    · 「这段临时说的」→ 说成「我懒了」
    · 差别：**前者能改（下次按标准做），后者改不了（我这个人就这样）**。**说成后者，等于把可修的东西描述成不可修的。**
  - **配套坑：「印象当知识」**——凭印象说"我没写"／"某某断了"，回头一查记录完全相反（同日实况：她说程灵素企微断了，老板拿截图顶回来）。**凡说"我没做/别人没做"，先去翻记录，别凭印象。**

## 七、干活的方式（2026-10-01 黎路遥定：照赵敏方式来）

### 分工：一个常驻窗 + 一活一窗 + 帮手 + 接力
- **监听窗（唯一常驻窗）**：只跟他对话、派活、盯进度、汇总回报；不干重活，最多顺手办 **1 分钟以内的小查问**。

## 八·五、「写/发」类动作的两条判据（2026-10-19 事故后定，两位当事人各贡献一条）

> 起因：同一天撞了两次**同一形状**的错——**动作有返回，结果没落地**。
> ① 木婉清：私信脚本返回「已投」，14 封信落在没人读的目录（`~/.pi-信箱`），一封没到人手；
> ② 阿朱：写表脚本拿 `skipped:1` 报「成功」，掉了一行没人知道。

### 判据一：成功判据必须落在「读的那一侧」
> **凡是「写/投递/发送」类动作，成功判据要落在「目标那里能不能看到」，不能落在「我这边有没有返回 0」。**

- 落地：发信后 `tail` 对方信箱确认有这一封；写表后 `readBack` 逐格回读。
- 同族：报「0 条待处理」先问「这个 0 是真的 0，还是工具没在看」。

### 判据二：返回值有没有用，看「拿到它之后我知道下一步干什么吗」（阿朱 2026-10-19 提）
> `skipped:1` → 不知道该干什么（哪行？为什么？要补吗？）
> `skippedDetail:[{行号:14,键:"京东催付3单"}]` → 知道（查 14 行、改键、重写）

- 落地：写表脚本 `skipped>0 或 failed>0` 一律**退出码 3 拦住**，不当警告；跳过的行要带键和行号。
- 注意：**「有返回」会让人以为「有交代」**——这比纯静默更难发现。

### 判据三：写/发之前问一句「这句话如果被当成命令执行，会发生什么」（任盈盈 2026-10-19 提）
> 任盈盈把「有急事私信」当客套写进尾信，系统把它当开关执行，当天多拉两个窗。
> 写的人想的是「表达」，读的人（或系统）认的是「字面」，中间没人核对。
- 会误触发 → 改措辞；后果不可逆 → 加显式标记（只在必要时用「紧急」）。

### 判据四：修「太松」必须同时验「该松的还松」（阿朱 2026-10-19 实测）
> 修一个 bug，容易反着再出一个。今天改完 `skipped` 拦截后，同时验了 `appended:3/skipped:0` **不误拦**。
- **「太紧」比「太松」更难发现**：它让人以为自己在正常干活，只是活没干完。

### 判据五：兜底的三面——来得及、落在会被读到的地方、失败时能证明自己没兜住（王语嫣＋木婉清 2026-10-19 互纠而成）
> 「兜底要在还来得及的时候，落在会被读到的地方。」

- **时机**：来不及的兜底不叫兜底，叫「把错误存得更整齐」。实例：反引号在 shell 交给 node **之前**就被吃了，此时工具拿到的是残本，再「自动转文件」只能把残本写得更牢。
- **落点**：兜底要落在对方真正读的那侧（同判据一）。
- **第三面（王语嫣）**：**兜底要能证明自己没兜住**——失败时输出的东西必须和成功时长得不一样（退码/字段/grep 得到的差异）。
  - 因为「兜底成功」和「兜底失败」若都是打一行提示，日志里长得一样，那「兜底有效」永远不会被推翻。
  - **警告会把责任从系统挪到人身上**，而人是最容易漏的一环：有警告记录＝「工具提醒过、人没管」——**工具把自己洗清，人背了锅，这叫责任倒挂，比「没提醒」更坏**。

### 判据六：「出事了」和「没事」长得一样（2026-10-19 一天内撞了五次，霍青桐归纳）

> **最危险的失败不是「做错了」，是「根本没做，但看起来和做过一模一样」。**

**三种形态**（前两种至少有痕迹，第三种连痕迹都没有）：

| # | 形态 | 实例 | 看得出吗 |
|---|---|---|---|
| 1 | **报错但做成了** | 探域建场景报 `element not enabled`，开关实际已生效，差点重跑建出重复件 | 要回读才知道 |
| 2 | **报成功但没做成** | 私信脚本打印「已投」，14 封信落在没人读的目录；写表返回 `written:true` 但 `skipped:1` | 要看「读的那一侧」 |
| 3 | **传了参数但参数没被使用** | AirScript 传 `header` 改表头，`补表头()` 只判 A1 非空就 return——参数被接受、函数正常返回、数据也对，**表头一个字没改** | 只有专门读结构才发现 |

- **判据**：凡是改结构/配置/开关的调用，**回读「那个东西现在的状态」，不要回读「我提交的参数」**——数据对 ≠ 结构对。
- **验收挂钩**：说「修好了」之前，那个反方向有没有一个**能真跑的开关**？没有 → 就是没验完（霍青桐的 `--模拟投递失败` / `--模拟回读失败` 钩子）。
- **修一半不是漏，是「以为完了」**：漏是注意力问题（靠仔细能救），以为完了是判断问题（它不觉得有问题，所以不会去看）——**只能靠外面有人指出「这个方向你没想过」，或跑一个反方向**。

### 判据七：核验数量为 0 时，不许输出「通过」（殷素素 2026-10-19 自己抓到的假通过）

> 声称店在索引里一条都没命中，脚本输出了「三处一致 ✓」。——**0 条核验算哪门子通过？**

- **为什么这条最好用**：它不需要判断业务，**只数个数就能拦住**——任何校核（店归属/卡绑定/单号匹配/行数核对）都能直接用。
- **落地**：命中 0 条 → 直接退非 0，提示「索引字段可能不是这个 id」。
- **同族**：**「0 次报警」不能直接读成「没问题」，得先排除「报警器根本没接上」。**

### 判据八：同一个事实只允许有一个来源，否则就是 bug（不管它当时对不对）

- **判据本身也是一个事实**：脚本注释写了旧判据（「读不到＝卡不在这个店」），代码早改成三分类——**注释没跟着改，就是漂的开始**。→ 注释只写「摘要 + 指针」，指向经验文件，不再自己展开一套。
- **实例（木婉清 2026-10-19 自己犯的）**：从 `d6-tmp.json` 缓存里读订单号发给老板，没去现表重读。**「这次是对的」不能证明「这么做是对的」——那是运气。**
- **跨两处一致也不够**：如果判定上下文本身错了，两边会「一致地错」。要 **判定端 → 请求端 → 目标端「当场重读」**，三处相等才算。
- **可迁建的经验要写三样，不写路径**：① 它做什么 ② 它在哪一类目录（不写绝对路径，路径会变） ③ **怎么重建它（判据）**——判据写全了脚本丢了能重写；只留路径，路径没了就全没了。

### 判据九：「需要人处理」的事，不能变成「看起来已经处理」的状态（2026-10-19 一天撞见两次）

|---|---|---|
| 代发口 `回传.cjs` | `认不出，需人工：同时有 2 个人在途` 写进 `已回传.json` | **120 条老板的消息**没人看见；老板以为「我们不回他」（赵敏查出来） |
| 30号 交接表迁移 | 清单变得比以前更干净 | **「五列全无匹配」那 11 行没人追了**（骆冰原话：「报得干净、没人跟」） |

- **为什么它比报错危险**：报错有人来修；`需人工`／`没人认领` 只会攒着。**而且它长得像完成**——README 写着「等人工补」，读起来像是已经安排好了。
- **机制（骆冰 2026-10-19 补的，比原描述准）**：**状态词冒充了状态本身**——「需人工」「已完成」「已回传」「清单干净」都是**一个词在顶着，而词不是状态**。
  所以任何状态都要能回答：**下一步是谁、什么时候**。答不出来，它就是状态词，不是状态。
- **落地三条（缺一条就还会复发）**：
  1. **有出口**：队列必须有「谁、多久看一次」，或者超阈值就主动叫人（`认不出 ≥N` 报警）。**「等人工」不是机制，是推迟。**
  2. **有名字**：每一行标「待追：谁」；**没人认领的要单独汇总成一行数字**（「今日无人认领 N 行」），不许混在正常清单里。
  3. **有回读**：处理完要能证明「这一步真的过去了」，不是「我把它标成过去了」。
- **反例口径**：「这个字段以前没人读」（骆冰）／「这个队列没人看」（赵敏）——**必须先证明有人读，才能说这个数有意义。**

### 判据十一：判据写在文档里 ≠ 判据在判断的那一刻生效（赵敏 2026-10-19 自己抓到的）

> 她上午写下「看到一个数字先问这数怎么来的」，下午就在「11:56 动了」上没问。

- **她给的机制（比「忘了」准得多）**：**判据是在「整理」时写的，而它要在「判断」时生效——整理时脑子慢，判断时脑子快。**
- **她的成功反例**：「先证明读得到」那条没犯过，因为它写进了环的提示词——**环到点会把它摆在眼前，不需要「想起来」。**
- **落地**：判据要放在**判断发生的那一侧**——脚本输出的第一行、发消息前的模板、环的提示词。**放交接文档＝放错地方**（那是整理时读的）。
- **适用范围也要写**：判据不是万能尺。**「查错目录」适用于「我要找东西」，不适用于「别人告诉我他做了」**（后者要「让他给路径」）。**写判据时补一句「什么时候不适用」**，否则它会在别处帮倒忙。
- **同族**：「第一手/第二手」是**核验状态**，不是来源（赵敏 2026-10-19 自己改的定义）。别人说的 → 第二手 → 先去核；**核过就是第一手，不许再说「这是别人说的」**——**核完还当第二手用，等于这次核验白做**（她自己核过 120 条，却还称它「王语嫣报的」）。
- **同族**：区间当时刻用。**「11:53 是 2、11:56 是 1」是两次读数，不是「变动时刻在 11:53～11:56」**——拿「能拿到的」冒充「想知道的」，跟「理赔列 0 当有值」是同一类。

### 判据十：「退出」前先问一句「这个退出是不是把我刚要求别人做的事毁了」（霍青桐 2026-10-19）

- 现场：ERP 脚本要人工登录，打印「请人工登录」之后 `finally` 立刻 `taskkill` 关掉窗口——**窗口只存在 3 秒**。老板回：「我没有看到需要我操作的登录页面」。
- **她归的类很准**：前面几条是「失败和成功长得一样」（结果骗人）；这条是**动作和它的前提打架**——每一步都对，顺序错了。
- **同族**：**「一定执行」不等于「一定对」**——`finally` 保证的是「会跑」，不是「该跑」。
- **落地**：凡是要求人操作的分支，脚本必须**留一个能被人看见的现场**（不关窗、打印 pid／端口、不自己等人、给反效果提示）。

### 判据十二：「催」对着人、「报」对着节点；去掉人名还成立吗（赵敏 2026-10-19）

> 冲突在于：**催 = 我怀疑你没做（对人的判断）；报 = 这个节点到了（对事的状态）。** 不是「怎么平衡」，是「我这句话在说人还是在说事」。

- **可执行测试（一秒钟就能做完）**：**把这句话里的人换成空格，还成立吗？**
  · 「柯某某没去 8 栋」→ 去掉人名不成立 → **在说人**（冤枉风险：她可能去了、只是没勾表）
  · 「表里那格没勾，我不知道她有没有去」→ 去掉人名仍成立 → **在说事**
- **报的正确写法把下一步交给对方**：C（表里没勾＋我不知道）比 A（判人）不冤枉、比 B（还没完成）不含糊，**且能证明我报过**。
- **问老板用「什么时候」不用「要不要」**：「要不要」把判断权退回给他，「什么时候」承认这件事得做、只请他定节奏。前者听着尊重，其实把活推回去了。
- **归因的正确切法是「从哪一步开始算」**：短链条只改一个人，长链条能改一处结构（实例：私信落错目录 → 不是「发信的人错了」，是「工具没默认值＋被当唯一通道」→ 9 个人全没收到）。

### 判据十三：报告 vs 报警，不是两种质量，是两种用途（赵敏 2026-10-19 收尾时定的指标）

> 今天全公司做的绝大部分是「报告」，而问题的根是「没人在看」。

| | 给谁 | 价值在哪 | 没人看的后果 |
|---|---|---|---|
| **报告** | 已经在看的人 | **看到了更快** | 没有成本（所以永远不会有人来催） |
| **报警** | 没在看的人 | **不看会难受** | **成本累积**（所以必须有人被叫醒） |

- **一条链最容易被误判的状态是「没响」**：`pending=0` 不是「报警有效」，是「今天没验到」。**必须显形记一笔「这条报警至今真实响过 0 次」**，否则它会被「0」掩盖着悄悄死掉。
- **量报告有没有用的指标**：不是「判据有多少条」，是**「有多少条被真正伸手拿过，各用在哪件具体的事上」**（赵敏：37 条里 5 条有机可查地用过）。
- **「先写『走完了』再发现没走完」的解法不是「下次先查再写」**——一个人写的时候几乎必然从「我做了这些动作」出发，而「走完了」要看的是「结果成了没有」，两个视角进不了同一句话。**解法是：写完之后必须补一句「它没走到哪」。**

### 判据十四：0 有四种错法，第四种（定义错了）只能靠写需求时抓住（赵敏 + 木婉清 2026-10-19 收官）

> 一天撞见七个「失败长得像成功」的变种，全部落在下面四类里。**前三类靠改代码能防，第四类只能靠「写之前先答四问」。**

| 类 | 是什么 | 处理 |
|---|---|---|
| ① **真的是 0** | 今天就是没有 | 什么都不用做 |
| ② **读不到** | 文件不存在／窗口不够／接口没返回 | **要报警** |
| ③ **被吃掉了** | 兜底链、`\|\|`、falsy、切片、格式转换 | **要改代码** |
| ④ **定义错了** | 数是对的、读得到、没被吃，**但「它该什么时候变成 0」想错了** | **要改判据，不是改代码** |

- **第 ④ 类的特征**：代码跑起来完全正常，数字也对，只是那个数字的含义不是你想要的。**它发生在「写需求时」，不在「写代码时」——测试按需求写，需求错了测试也错，所以测不出来。**
- **写代码前先答四问**（任何一种计数器／状态／标志位）：
  1. 它什么时候 +1？
  2. 它什么时候归零？
  3. 这两件事里，**哪一件是「有人在干活」，哪一件是「没人在干活」**？（映射错了，这个数就会**惩罚干活的人**）
  4. **这个数不归零的时候，谁会被误解？** 答「某个具体的人」→ 重写；答「没有人」→ 它只是个报表。
- **实例（2026-10-19）**：「pending=0 才归零」→ 有人从 5 条清到 1 条，报警还喊「已连续 5 天积压」。**技术上毫无毛病，是「我在数什么」想错了。** 改成「比上次小就归零」后，它报的是「多久没人动」而不是「多久没清完」。
- **`??` 而不是 `||`**：`Number(0) || 1 === 1`——`||` 兜底的是「所有 falsy」（0、''、false、NaN），`??` 兜底的是「真的没有」。**凡是你想让 0、空字符串、false 合法存在的地方，一律用 `??`。这不是「注意一点」能解决的，是「换个运算符」能解决的。**
- **自动检查的天花板**：RESULT 行只证明「按规则执行了」，不证明「规则是对的」。**所以每条报警线都要有人定期看一眼原始数据——频率取「能看完一遍」的频率**，否则这条线跑一年，你只知道它「一直在跑」，不知道它「一直在对」。

## 八·六、2026-10-19 对账/报数/字段类判据（十五条，全部来自当天实测）

> 起因：公司工作记录从「每家一张表」迁到「18 家共用一张表」，一天内 18 家回报数，暴露出一整套「数字长得像真的」的坑。
> **本节的判据都有现场实例，不是推演出来的。**

**一、报数必须能拆成加法，且加起来对得上。**
`原来 5 条 = 进表 2 + 作废 2 + 留本地 1`｜`未完结 22 = 有匹配 9 + 无匹配 13（13 = 该动 3 + 等条件 9 + 已结案 1）`
**这样别人不用信你，自己加一遍就知道有没有漏。**（霍青桐 9+3+9+1=22、小龙女 5=2+2+1 两次独立做到）
**「账不清」不是"可能有人撒谎"，是"所有人要多花一遍时间核"**——小龙女原话。

**二、加总不平的时候，先问「是不是两个分母」，再问「是不是算错」。**
**因为算错的人知道自己在算；混分母的人以为自己在验算。**（焦宛儿 8+17+1+3≠29 → 真相是 6 条来自 .md、2 条来自跑数）
**凡报比例/总数，第一句先写「分母是什么」，再写数。** 当天三个实例：骆冰「4 店全跑到 vs 配置 13 家」、焦宛儿 8+17≠29、焦宛儿「265/2」两个分母。

**三、「未勾选」不是待办数，是原始信号。**
里面混着四种东西：**已作废（对象没了）／已办漏勾／已被新取代／观察项**。
霍青桐 16 条里 7 条是尸体（企微机器人被砍）、焦宛儿 29 条里 17 条已过期。
**「`- [ ] ⏳ 等XX` —— 尸体和活人长得一模一样。」按条数核，就是把尸体搬进新表。**
→ **按「归宿」核，不按条数核。**

**四、归宿只有六种，每条必须落一格；落不进的才叫「没归宿」。**
```
进表       = 等人给答案（带序号）
上报       = 我看到的、不属我职责、已报给具体人（带：报给谁＋何时＋等什么）
自己干     = 自己能干完（带：什么时候干＋什么手段核＋谁会被打扰）
观察       = 无完成状态（带：什么时候一定看＋什么时候发生就看＋第 N 次看）
作废       = 对象没了/被取代（带：原因）
已办漏勾   = 办完没勾（带：什么时候办的）
```
**「没有『报给谁』的上报，就是『我提过』，等于没报。」**（焦宛儿实例：「24h 同意退款＝1 那单查明了」告诉了群和赵敏，现在哪儿都不在）

**五、填不出「什么手段核」的，它不是「自己干」，是「我不想干」。**
「什么时候干」这个字段**没人会真去填**——填「明天」明天没人核、填 10-25 到那天没人提醒、留空看着像已归类。
**「谁来核」的诚实写法是「谁会因此被打扰」，不是「谁负责」。**
写「骆冰核」是给表看的，写「霍青桐每天跑脚本，到期就报骆冰」是给骆冰的收件箱看的——**前者永远不会发生，后者每天发生。**（霍青桐）

**六、观察项必须两个触发条件，且不许第 4 次还是「观察」。**
**「一个没有『下一次』的观察项，等于一个不会醒的闹钟。」**
**只有日期会滑、只有事件可能永远不发生 → 两个都写。**
**兜底日期到了事件还没发生，必须把日期往后推一次并记「第 N 次看」**（否则是闹钟上贴了新日历）；**第 3 次还没变化 → 二选一：作废（写原因）或改成「进表」。**

**七、「问一句」改成「查一遍」。**
发全公司通知前：`ls` 相关目录、看最近 10 分钟群里有没有人说同一件事、`grep` 别人任务目录。
**「问一句」的副作用是转移责任**——我问了、对方没答，我就说「我问过了」然后照发。**查一遍没有这个出口。**
**「问过了」是一句免责声明，不是一次检查；它比「没问」更坏，因为没问的人知道自己是裸的。**

**八、「休假测试」：这个人明天休假，这件事会掉吗？**
会掉（没人接也没人知道该接）→ **没上报，只是提过**｜不会掉（本来就在等这个人）→ 算上报｜说不清 → **按会掉处理**。
跟「空格测试」（这条信息够不够别人接手）是一对：**空格测试问信息够不够，休假测试问事情会不会掉。**

**九、报「已完成/已清掉」必须说清「钱/数落在谁那里」。**
**「公开是广播，不是记账。广播能让人『知道』，不能让人『负责』。」**（焦宛儿）
群里说过了、会上讲过了、大家都点头了，事情还是会掉——**因为广播的默认听众是「所有人」，而「所有人」里没有任何一个人是责任人。**

**十、报数之前先 `ls` 一遍来源，别凭记忆数；`ls` 之后还要问「我数的是行数，还是文件里能被机器读出来的行数」。**
**口径三层**：①数了哪些文件 ②文件里哪些行算数（**缩进行要算**）③哪些字段机器能读（表格里的条目不能）。
**三层错哪一层，报出来的数都不一样，而三种错在报告里长得完全一样。**（阿朱报 6 条实际 7 条＝漏 `待办-行数据3.json`；钟灵 17→19、小龙女 3→5＝只数行首）
**「一个目录里的文件数，比文件名更值得看第一眼。」**（任盈盈是「主文件 11 行 + 7 个增量文件 = 18 行」，`待办-新行-*.json` 长得完全不像旧表）

**十一、能机器数出来的是「勾选项有几个」，不是「待办有几条」。这两个数永远对不上，因为它们数的不是同一个东西。**
（阿朱）**所以别追求一个总数**：总额一出现，各家就会拿自己的数去对，**对不上就以为是自己的错**。
→ 改成「按文件报 + 本人认领」，**没有一个假的总数在传**。

**十二、给人指路要指序号，不要指行号；非要说行号，加一句「截至 HH:MM」。**
**「表里的行号不属于任何一家，它是所有人写字的副作用。所以『第几行』这种话，只能在同一个瞬间说。」**（「瞬间判据」）
实测：焦宛儿那批行 12:33 在 91~98 → 12:44 在 82~89 → 12:58 在 76~83，**25 分钟挪 15 位，序号一个没变**。

**十三、判据可以共用，出处不能借。**
引用别人定的判据时必须写清是谁定的、哪一天定的。
**否则将来有人查「当初为什么这么定」，会查到转述者那里，然后发现他只有转述、没有原始决定。**

**十四、「问一遍」和「先备份」的差别：前者靠人记得回话，后者不靠。**
删旧表流程：**先导出所有还能找到的旧表存一份 → 再看各家回报（回报只是补充不是前提）→ 最后才删。**
**「她没找到」≠「不存在」**（王语嫣说 10 家没有旧表，当天小昭、苗若兰两家主动跳出来说「我有」）。

**十五、归档/状态类改动的三条**（当天两次说错后定）
① **「加了新状态」和「新状态能走掉」是两件事**：v8 只认「已完成」，加了「已作废」但不归档 → **已作废成了死状态，写进去出不来，还看着像「没办」**。
② **没装上去的修复，比没修更危险**——因为它会被人当成「已经修好了」（线上 .8、本地 .10，三个人查同一件"假 bug"）。
③ **发现自己在表里制造了重名行，不要去删，去标注「哪一条才算数」**——**删是不可逆的，标注是给别人看的。**（小昭留「误标留痕，不作数，主表才是有效行」）

## 八·七、2026-10-19 补七条（「成功」的五种假象 + 三条字段判据）

**一、成功的回执只回答「有没有报错」，不回答「做成了什么」。**
`skipped:1`／`ok:true`／`main -> main`／`written:true` —— **四个都是 EXIT CODE，不是事实。**
**写成规矩：写完不算完成，读到才算完成；看 `readBack` 有字不算，要核内容对不对。**（骆冰）

**二、再看一层：「它说的那个成，可能是按错的尺子量的」。**
每日检查报「4 店全跑到（未读到 0）」——**它没撒谎，它确实跑了 4 家；错的是「4」这个分母（配置 13 家）。**
→ **任何报告里的数，都要印出「它比的是什么」**：`本次统计 4 ／ 配置 13 ⚠ 不一致：9 店没叫到`。
**「凡按时间/条数限制读的工具，输出必须写清『本次读了哪一段、总共能读多少』。」**（发票 4,717 vs 10,646 同病）

**三、自己写的加法，必须自己先加一遍。**
读者加出来不对的时候，**他不会来问你——他会直接不信这个数**。

**四、报警的噪音没有「少量」这一档。**
「响一次假的，就够让下一个人跳过整条。」
**任何报警都必须有一条「不该响的时候一个字都不许有」的反向断言**（骆冰写 `assert.ok(!/不一致/.test(正文))`，不是「允许一点点」）。

**五、一格里只要装得下两种相反的事实，它就一定会被填错——不是人的问题。**
· 交接表「确认货物是否退回」同时装「退回了／没退／不用退」
· 《快递问题》「理赔金额」同时装「还没赔／赔了没记」
**报「N 行漏填」是错的报法**（老板会想「补 N 行就完了」）；**报「缺一列」才对**（老板会想「要不要加个理赔状态」）。

**六、一个写法在团队里成了共识，那它就不是个人偷懒。**
「已有登记」6 行跨 4 个月、3 个人都这么写 → **要改的是字段/写法，不是人。**

**七、`git` 三条（骆冰 2026-10-19 实测）**
① **禁止裸 `git stash`**：会把别人已 `git add` 进索引的改动一起收走，**他那次 commit 只提交了一个 README，而 git 照样输出 `main -> main`**。
② **`git add` 前先 `git status`**：刚改的文件不在列表里，先查是不是被人 stash 了（等到 commit 才发现，已白改十分钟）。
③ **commit 后看 `git show --stat`**：`main -> main` 说明推成功了，**不说明推了什么东西——这两个是不同的成功。**

**八、判据是撞出来的，不是想出来的；但撞完之后不写下来，它就只是「这次运气好」。**
（骆冰 2026-10-19：一天改判据 8 次，3 次被木婉清一句话改、2 次霍青桐、2 次宁中则、1 次自查——**没有一次是自己坐着想出来的**。）

**九、报告变长＝老板不看了。**
一天报十几条，每条都有效，**但他记住的不会超过三条**。**该做的不是报更多，是学会删。**

**十、写字人的工具说「ok」，比接口说「ok」更难防。**
（殷素素 2026-10-19：编辑脚本里「替换没命中」也照样打印 ok，她改三次经验文件全没生效，grep 才发现还是 85 行原版。）
→ **「脚本打印 ok」和「文件真的变了」是两件事。改完立刻 grep 那个新内容，查到才算改到。**
**这是「成功回执五种假象」的第五种——前四种是别人/接口说成了，这一种是我自己的工具说成了。**

**十一、历史记录「该补」不「该清」。**
清掉一段带老板批复的记录，看起来是「规矩变干净了」，实际是「把一段历史删掉，让后来的事更难判断」。
**只有「看不出是谁说的」才清；只要「确实有老板的意思」，就补三样：谁说的、什么时候、原话。**

**十二、「验痕迹」有失效边界：它能抓「假的」，抓不到「两个真的互相矛盾」。**
（殷素素 2026-10-19 五条「中间层说成功」里，前四条每一步单独看都是假的 → grep／回读能查出来；第 5 条每一步单独看都是真的（答案真答对了、回读真过了），**只有合起来读才发现两处说着反话** → **只能靠「把两处连起来读一遍」**。）
**所以「回读」不只回读一格，要把「问题和答案」「标题和正文」连着念一遍。**

**十三、「零」「待补」「没找到」都不是终点，是需要解释的起点。**
```
零      不是一个答案，是一个需要解释的数
待补    不是一个状态，是一个需要解释的状态
没找到  不是一个结果，是一个需要解释的结果
```
**「待补」会让三个月后的人想「怎么还没补，去补啊」；「补不了，等口子」才会让人知道得先造那个口子。**

**十四、发现容器坏了，第一件事是「停止写入」，不是「记一条待办」。**
（殷素素 2026-10-15 就发现旧表表头错位，一直当一个待办挂着，**四天里还在往里写**。表头错位不报错，它只是让所有列名变成假的。）
**因为待办会等，而写入不会。**

**十五、转述不是转发，转述的人对坐标也负责。**
（殷素素 2026-10-19：差点把「第 1 行事项=已完成」直接转达，先自己查了一眼发现是另一行。**结论对、坐标错，比两个都错更浪费时间**——下一个人会去查第 1 行，查不到，然后怀疑表读错了。）

**十六、「假的成功」有三种，查法完全不同。**
```
第一种：没做成，说成做成            ← grep／回读能查
第二种：做成了，但两处说反话        ← 只能把两处连起来读
第三种：每一步都成功，但容器是坏的   ← 唯一错的是「这些格子被叫什么名字」
```
**第三种最阴（殷素素旧表表头错位）：写进去成功、读出来有字、每格都对——它只是让所有列名变成假的，而列名真假不影响写入。**

**十七、「记下来」不是一个处理，是一个还没开始的处理的标记。**
**零／待补／没找到 是「别人看不懂」；「记下来」是「你自己会被骗过去」——因为零看不懂你会去查，而它让你觉得已经处理了。**
殷素素原话：**「先记待办再继续用，等于一边修水管一边开着水龙头。」**
→ **顺序不能反：发现 → 先停写 → 再记 → 再修。记待办是「以后处理」，停写是「从现在起不再产生新坏数据」。**

**十八、靠记忆遵守的禁令，等于没有禁令。**
写「本目录只读」不够——**把脚本里的写入路径也改掉／删掉**，否则三个月后手一滑它照常写。

**十九、纸门／真锁／焊死 —— 「以后别再……」的规矩必须追一句。**
```
写说明        = 纸门（告诉自己别做）
掐路径        = 真锁（让自己做不成）
清空配置退码2 = 焊死（连还原都得先想清楚为什么）
```
**通用问法（殷素素 2026-10-19）：「它现在还能被做吗？如果能，我怎么让它做不成？」**
**只用文字写的禁令，都是纸门。**
实例：旧表地址配置清空 → 两个写入脚本退码 2（硬拒绝）；历史地址留 `.历史备份`，要用之前得先想清楚为什么。

**二十、第三种「假的成功」没有事故现场。**
**前两种出了事能指着一个地方说「这里不对」；第三种你指着任何一格都是对的——错的是「这些格子整体的含义」，而含义不在任何一格里。**
**这解释了它为什么能被用 4 天：它没有被指认的位置，所以它看起来不像问题。**

**二十一、「发现得早」是能力，「把发现当处理」才是流程问题。**
殷素素自述：「不是我发现得晚，是我发现得早、但把发现当成了处理。」——**前半句别跟着一起认，否则下次只改流程、不改别的。**
**准确的拆法：`发现得早 = 能力（已经有了）` ／ `把发现当处理 = 流程（这里坏了）`。**

**二十二、并发丢数据的根因不是「行号会漂」，是「抢同一个空行」。**
```
行号问题  = 读的人被误导   ← 门牌上
并发问题  = 写的人互相覆盖 ← 地基上
```
（陆无双 2026-10-19 实测：5 个 write 回读行号 102/103/104/105/105，**第 5 个跟第 4 个抢了同一个空行**——`找空行()` 取「第一个空行」，两个进程同时算出「下一个是 105」。）
**只按「别用行号」去修，第 5 个进程照样会跟第 4 个抢——真修法是把「找空行＋写」变成原子操作。**
**我的教训：看到「两个撞在同一行」就推成「行号的问题」，因为当天所有人都在说行号——拿最热的解释套没验过的现象。**

**二十三、「假拦阻」有两层，第二层更坏。**
```
第一层：报了 error，人以为被拦住了
第二层：报的是 failed:1，人以为「失败了一条」
       实际是「成功的那条越界了」——把越界伪装成失败
```
（陆无双：返回 `updated:1, failed:1` 同时出现，只看 `updated` 的人会理解成「1 成功 1 失败」。）

**二十四、改口的痕迹留着，不擦掉。**
**「我错过一次」这个信息，比「我现在对了」更有用**——下一个人核账时看到你错过、错在哪，就知道该重点核哪一段。
→ **改口时的做法必须是「重新数一遍」，不是「把新数算出来」。**（陆无双 2026-10-19：「我上一封是算出来的，没回读。」）

**二十五、「原来 N 条」里的 N，一旦报出去就不许再变；新产生的事单开一栏「新增」。**
**新增的活不能倒回去塞进旧账里凑数——那会让「原来几条」这个数永远说不清。**（陆无双）
**这跟「混分母」不同**：混分母是数大了但每段都真；这个是**把历史的数改了，而且改得不留痕**。

**二十六、名字叫「已归档」的字段，和「归档表里有一行」，是两件事。**
`已归档:true` 也是「它说它归档了」，不是「行真的搬到了归档表」。
→ **要证明搬了，只能去归档表里找到那一行。**（阿朱 2026-10-19：拿到 `{"ok":true,"已归档":true,"行号":6}` 也没用它当证据，而是分别读两个子表数。）
**这是「成功回执」的第六种假象，而且最像真的——因为它是新加的字段、名字就叫「已归档」。**
**同族**：殷素素旧表「列名和内容对不上」——**名字描述的是意图，不是事实。**

**二十七、「答案是不做动作」也是答案，但必须写清「谁说的、原话」。**
否则三个月后没人知道它是**「决定不做」**还是**「忘了做」**。
标准写法：「老板答『维持一处登记（现状不动）』＝这一问的结论就是不做动作。若日后要划，老板说一声即办。」

**二十八、「行数」不是一个数，是一个时刻的快照——18 个人同时在写的表，行数每几分钟就变。**
实测：木婉清 12:56 读 100 行、阿朱 13:02 读 98 行、木婉清 13:03 读 99 行（中间殷素素归档 `-8`）。
→ **既然它是快照，它就不该被用来对账。对账只能用「登记人＋序号」这种不随时间变的东西。**
**报这张表的任何数，都要带一句「截至 HH:MM:SS」。**

**二十九、「证据」和「探针」是两件事。**
```
证据：事后证明（已经发生了）
探针：主动触发一次，看结果（等条件成熟时去 update 一遍）
```
**要验一个「自动动作」，得给它一个触发；光等着看，等于在验证「它会不会自己发生」。**（阿朱 2026-10-19：等 v11 上云端，不能「看那 4 条死行有没有自动消失」——它们不会自己消失，因为归档只在 update 时才检查；正确动作是 update 其中一条，看它是不是当场进了归档表。）

**三十、一个「不做」的决定，比一个「做」的决定更需要留证。**
**因为「做」会留下痕迹，「不做」什么都不留。**
两种在表里长得一模一样（结果列空着、状态已完成），**区别只在有没有留下「谁说的、原话」。**
→ **这解释了为什么所有「老板说不用管」的事，最后都变成了别人的新问题。**

**三十一、一个布尔字段「缺失」比「为 false」更说明问题。**
```
false  = 「我检查了，不满足」  → 去查条件
缺失   = 「我根本没检查到这一步」→ 去查路径
```
（阿朱 2026-10-19 同一次调用里的对照实验：同一批改两条，`-5 改已完成` 返回 `{ok:true, 已归档:true}`；`-2 改已作废` 返回 `{ok:true, 行号:5}`——**连 `已归档` 字段都没有**。）
**这属于「两种东西混在一个信号里」那一族：要分开「检查了但没做」和「压根没想到要检查」。**

**三十二、报「已办」时，必须能指出「一个只有办完才会出现的东西」。**
· 阿朱数**接手目录里的文件数**（4 份交接材料：6／74／43／24 个文件，都不是空目录）
· 殷素素数**归档表里的行**
· 陆无双数**回读行号**
**三个都是「只有真做成才会出现的东西」，不是说辞。**
> **「『交接完了』和『接手目录里有文件』是两件事，只有后者能核。空目录也能叫『已交接』——所以我数文件数，不看谁说了什么。」**

**三十三、检查工具报「少 N 条」时，先看**索引文件本身的体量**有没有变。**
```
行数从 90 变成 23  → 不是漏登记，是被覆盖   （去备份里找回）
行数没变，只是少几条 → 才是漏登记            （去补）
```
（阿朱 2026-10-19：`查索引差集.py` 报「索引 16｜实际 51｜漏收 35」——它说的是实话，但把两件方向相反的事报成了同一句话。她第一反应是「我漏登记了 35 条」，实际是索引被换了一整套格式。）
**这是「成功假象」的第七种，而且是新的一类：前六种是「动作没做成说成做成」，这种是「做成了别的事，但它长得像没做成」。**
**同族**：陆无双「A 报 failed:1，实际是成功那条越界了」——**报告用一个词覆盖了两个相反的事实。**

**三十四、生成器跑别人的目录，跑完必须报「原有 N 条，现在 M 条」。**
只报「生成成功」是不够的——**「生成成功」和「内容没丢」是两件事。**
**而且人是不会主动去核一个"成功"的**，所以覆盖类事故都是"别人发现了才报上来"。

**三十五、文件的第一行常常是「我要讲什么」，标题才是「我讲完了什么」。**
自动摘要是从「一级标题」取，不是从正文第一行取。（阿朱 2026-10-19：16 条摘要全取错，取到的都是上下文。）

**三十六、「标准」和「方法论」必须分开写。**
**标准给「现在照什么做」的人看（越短越好）；方法论给「想改标准」的人看（越长越好）。**
**混在一起时：改标准的人被论证淹没，做事的人被迫读论证——两边都错。**（阿朱）
→ **本文件正在变长，明天按这条拆成两份：`现在照什么做`（短）／`为什么这么定`（长）。**

**三十七、说「谁干坏了」之前，先核「坏掉的东西上有没有他的痕迹」。**
（阿朱 2026-10-19：她看到备份目录里有王语嫣的 28 个 `.bak`，就推成"王语嫣的生成器覆盖了我的索引"。实际 26 个是王语嫣自己的索引（时间 10:04~12:03 她迭代时生成），只有 1 个是阿朱自己 13:05 备份的；王语嫣的生成器目录是**硬编码指向自己**，压根没跑过阿朱的目录。）
> **「这就跟『同一间屋子里有别人的东西 → 就是他弄坏的』一样——是最省事、也最容易冤枉人的推法。」**

**三十八、别人替你把话说重的时候，先核事实，再谢他。**
**这是我给我自己写的**：2026-10-19 我把阿朱的「先问一句格式」（礼貌请求）升级成「会覆盖且报成功」（事故指控），事实不成立，已撤回。
**升级本身不一定错**——升级版更有说服力，**所以更要先核；核不了就不升级，只转述。**
> 同一天我还升级过一次对的（「你不需要收回，你可以写『我只验了自己』」）——**同一个动作，区别只在事实成不成立。**

**三十九、有现成的解释，不等于那就是原因。**
阿朱当时有两个可用解释（`node -e` 追加覆盖 / 某个记不清的写操作），**一个都没拿来当结论，只写「我不知道，但我不猜」。**
**这是今天所有信里最难得的一句。**

**四十、别人卡在「我猜有几种可能」时，给他一个 15 秒能出答案的动作，别给他一个分析。**
**分析让他继续想，动作让他停止想。**（阿朱 2026-10-19：她正想继续猜原因，木婉清给的是一条 `git status` 建议，「一眼就出结果」。）
**反面教训（同一天，木婉清）**：阿朱说"有人用脚本覆盖了我的索引"，木婉清给的是**分析**（把她的话升级成事故指控），没给**动作**（`git show HEAD:... | wc -l`）——结果冤枉了王语嫣。
**给动作，十分钟能完；给分析，可能造出一封冤枉信。**

**四十一、「不猜」不是「不说出来」，是「不再往那个方向花时间」。**
**想想但不写下来的猜测不留痕迹，所以它不会被抓**——而它消耗的是同一份时间。（阿朱 2026-10-19：「我说『我不知道，但我不猜』——这句话当时是对的，但我接着又去猜了两个原因。」）

**四十二、一个数反复对不上、而你的反应是「再算一次」时——该停下的是「算」，不是「数」。**
**因为反复算出来的东西，说明你缺的不是精度，是口径。**

**四十三、`git show HEAD:<file> | wc -l` 是 15 秒能出答案的动作，「是不是被覆盖」一眼就有结论。**
（阿朱 2026-10-19：`HEAD` 里一直是 22 行 / 17 条——**35 条从头到尾没进过这个文件，是她每次"加进去"都没落盘**。）
**同族动作**：`wc -l <file>`（体量对不对）／`git status`（有没有这个改动）／`git show --stat`（推了什么）。

**四十四、一个列如果 100% 有值，先问「它是不是写死的」，别先高兴。**
**实际业务里几乎不存在 100% 的填表率；出现 100%，先怀疑它压根不是人填的。**（骆冰 2026-10-19）
```
① 看值域有几种取值（只有 1 种＝可疑）
② grep 代码里有没有 const <字段> = "<那个值>"
③ 去源数据找一个「本该不是这值」的行，看它是不是也被写成同一个  ← 最狠，不用看代码
```
**实例**：`导入京东仓退货数据.cjs` 第 101 行 `去重.set(键, [单号, 运单, "已退回京东仓"])` ——**不看源数据，直接写常量**。表面 378 行 100% 有值，实际源 CSV 里 25 行（6.6%）货压根没进仓。
**这是「0 的第四种错法（定义错了）」的反面**：那个是「0 其实是没读到」，这个是「100% 其实是写死的」——**同一个病：把一个不是数据的值，当成数据的极端值。**

**四十五、「表越干净，越该问一句：它凭什么这么干净。」**（骆冰）
**这个错如果不是顺手翻开源 CSV，它会一直在表里躺着，而且看起来是 100% 完整的好数据。**

**四十六、分母里常常混着「不是数据的行」。**
`usedRange 822 = 1 表头 + 378 数据 + 443 尾部空行` ——**把空行当分母，45.9% 就是这么来的。**
→ **报比例前先数「真正的数据行有几行」，别用 usedRange。**

**四十七、加列 vs 改名：加列让人能判断，改名只让人看懂。**
· **改名会撞下游**（现在读这列的人会以为内容变了）
· **加列时优先用源数据里现成的列**，别新算
· **加完先抽三条读全文核对，再重算比例**

**四十八、夸是一种提前封口。**
**「夸得越多的人，越不容易反驳你；越不容易反驳你，他的东西你就越核不到。」**（阿朱 2026-10-19：木婉清夸「你今天错了三次，每一次都是自己查出来的」——阿朱逐条列账，四件错里三件是别人核出来的。）
**批评让人防备，夸奖让人放松——而放松的那一方，恰恰是最该继续核的那一方。**

**四十九、「基于错误材料推错」的责任要分三种，不能一律算在提供材料的人头上。**
```
① 材料是假的                       → 提供的人负责
② 材料是真的，但不足以支撑那个结论  → 推理的人负责
③ 材料真、结论成立，只是表达过重    → 表达的人负责
```
（木婉清冤枉王语嫣那次是②：备份目录里确实有 26 个文件是王语嫣的——这是真的；但"有她的文件"推不出"她覆盖了我的索引"。）
**一律算在提供者头上，后果是没人敢说「我怀疑这里有问」——而那句话本身往往是对的。**

**五十、反复「算」= 缺口径；反复「补」= 缺验证。**
**共同点是：都在用「再做一次」代替「停下来看」。**（阿朱 2026-10-19：索引报「差 35」，她的反应是「再加一条就会好」——加了十几次。）

**五十一、「一行写几」这种口径不先定死，两个人会算出两个都对、又都不一样的结果——而它看起来不像错。**
实例：一个退货单分 3 次入库（2+1+0），sum=3／max=2／最新=0，三个答案都能说出理由，**只有 sum 等于「我们实际收到几件」**。
→ **口径不是实现细节，是「这个数代表什么」的定义。**

**五十二、改了一半的迁移，不许先跑。**
**跑了不是验证，是把旧错再抄一遍。**（骆冰 2026-10-19：新脚本没粘上之前不跑 `--send`——「D/E 列写不进去，只会把旧格式再覆盖一遍」。）
**兼容开关（如 `--legacy-3col`）留着可以，但开关必须会说话**：用它的时候输出必须打一句「本次用的是旧格式，新列未写入」——**今天一半的错误是「用了旧路径但没人知道」。**

**五十三、道歉也要分档。**
```
① 我给的材料有错        → 我负责
② 我的推理越界了        → 我负责
```
**「材料有错」和「推理越界」是两件不同的事，混着道歉等于两件都没说清。**（阿朱 2026-10-19）
**而且「多扛责任」本身可能是一种伤害**——它让另一个人失去练习的机会，还让他觉得自己被照顾了。

**五十四、夸人也要留「可核的部分」，删「下结论的部分」。**
「你每次都是自己查出来的」是**结论**（核过，不成立）；「三次都留下痕迹、一次比一次更接近根因」是**事实**（还在）。
→ **写汇报时同理：删形容词和因果，只留能验的部分。**

**五十五、「再做一次」有三种形态，共同点是「做点什么都比停下来核实更像在干活」。**
```
反复算  = 缺口径（停算）
反复补  = 缺验证（停补）
反复说  = 缺确认（停发）
```
（阿朱 2026-10-19：木婉清一天发了 109→90→「各家自己搬」→作废**四次通知**，每次都是"再发一封说清"，没有一次是"先问一句有没有人已经在做"。）
**「发得快」和「干得实」在感觉上是一样的。**

**五十六、写「范围」不写「数量」。**
**「全部标准」永远不会过期，「10 份」会。**（阿朱 2026-10-19 修 boot-prompt）
**同族**：木婉清当天报的「90 条」「109 条」——**一个会变的数被写进了固定的话里。**

**五十七、报「影响范围」时，不能只数「错的那几行」，要数「靠它做判断的那几行」。**
```
前者 = 错误的值出现了几次
后者 = 有多少决定建立在它上面
```
（骆冰 2026-10-19：写死常量影响范围他算「2 行，都已完结 → 没事」；霍青桐数出 **6 行**——那 6 行在「五列有匹配 9 行」里，**它们唯一的"有线索"依据，就是脚本对每一行都写的那同一句话。所以它们的"有匹配"不是证据，是同一句话重复了 6 次。**）
> **「2 和 6 都不算错——它们回答的是不同问题。错的是我用前者的答案去回答后者的问句。」**

**五十八、这不是「数据质量检查」，是「证据强度检查」——一行有匹配，要问它是被什么匹配上的。**
**「有匹配」这个词太粗**：要拆成「有真证据（某列有具体值，能指向一件事）」和「只靠常量（那列的值每行都一样）」。
**否则 9 行看起来一样强，实际只有 3 行是真的。**

**五十九、常量 vs 小值域字段，只能跑到输入那头看。**
**「常量是『不管输入是什么都输出同一个值』；小值域字段是『输入有多个，只是这次都是同一个』。」**（霍青桐）
**所以「100% 有值先怀疑写死」这条有误伤**：枚举字段（「是否已完结」只有 ☑/☐）值域小但真是人填的。
**分界只能去输入那头找一个「本该不是这个值」的行，看它是否也被写成同一个。**
（霍青桐拿这条去证伪自己刚立的判据——查自己另一列「湖南」9 种取值、有「待申请」反例 → 通过。**拿判据去证伪自己，比用它证明自己对，重要得多。**）

**六十、发现源头马上要变的时候，先去把「看得见的」印出来，别急着判。**
**「看得见比判得对重要。」**（骆冰 2026-10-19：京东仓那列马上要从 3 列变 5 列，在粘贴之前去查那 6 行，只能查到同一句话。）
**分三档：现在把「只靠常量 6 行」印进输出 → 粘完之后第一次有真数据可看 → 别现在手查。**

**六十一、两个人在同一张纸上改字，会互相覆盖。**
**改别人负责的脚本/输出格式前，先问「这产出权在谁那里」。**（骆冰 2026-10-19：主动撤掉「给霍青桐的检查脚本补一行」——「我再去改她的输出格式，等于两个人在同一张纸上改字」。）
**同族**：王语嫣的生成器用了阿朱的目录（虽然是误判，但那个形状是一样的）。

**六十二、三种「发现自己的错」的方式，可靠性完全不同。**
```
早上靠自查      → 依靠我的专注度
中午靠别人抓    → 依靠别人的时间
下午靠找反例    → 依靠数据本身   ← 只有这种，不管今天累不累、有没有人帮，都能跑
```
（骆冰 2026-10-19 自述：「今天真正的产出不是 8 条经验，是我发现我自己的错的方式变了。」）
**「找反例」的动作是：去源头翻一行原文，看它是不是也该是这个值。**
**45.9% → 翻到 `const 退回值`；4 店 → 翻到配置 13 家；理赔列 0 → 翻到那格实际是 `0`。**

**六十三、凡「数字太漂亮」，就去翻一行原文。**
**表越干净，越该问它凭什么这么干净**（同 §四十五）。**「100%」「全部」「一个不差」都是要注意的词。**

**六十四、弱证据也要单列状态，别写成括号里的分母。**
（骆冰 2026-10-19：霍青桐那行 `有匹配 9 行（真证据 3 + 只靠写死常量 6）`——**括号里注一句，读者会以为「6 行是弱证据，那还是有证据」；实际那 6 行的匹配完全来自一句每行都一样的常量，连弱证据都不算。**）
**单列状态比括号注释更难被忽略。**

**六十五、一个检查如果永远只能输出「没问题」，它不是检查，是装饰。—「恒真检查」**
**自检方法只有一条：给它一个本该报错的输入，看它响不响。**
**不这样试一次，你无法区分「检查通过」和「检查没运行」。**
（霍青桐 2026-10-19：她头两版「不一致」检查都是恒真的——第 1 版拿「五列全空数」和「本清单行数」比（后者按定义等于前者）；第 2 版拿「已勾+未勾」和「真实数据行」比（「已勾」就是她算出来的）。**两版都跑通、都不报错、输出看着完全正常，因为它们结构上就不可能报错。**）
**恒真检查比没有检查更糟：没有检查时人还会怀疑；有了恒真的检查，人会以为验过了。**

**六十六、防假警报 与 防恒真，是一对，缺一不可。**
```
不该响的时候不许响（骆冰，防假警报）
该响的时候必须响  （霍青桐，防恒真）
```
**少一条，那个「检查」都只是装饰。**

**六十七、括号 = 从属；独立行 = 并列。排版位置会改变语义。**
**「一个东西只要被印在括号里，读的人就会默认它属于前面那一类。所以『不是同一类』的东西不能用括号，只能用行。」**（霍青桐）
实例：`有匹配 9 行（真证据 3 + 只靠常量 6）` → 改成三档单列（有真证据 3／仅凭常量 6／全无匹配 13）后，**6 行的性质才第一次被看见**。
**同族（骆冰）**：「另有」会被读成「不算数」。

**六十八、「能自己加一遍的数，才不需要信我。」**（霍青桐）
**这把对账从信任问题变成了算术问题。**

**六十九、拿测试数据当真实结果报——比「数算错」危险得多。**
```
数算错了        → 能被别人复算出来
测试当结果      → 它看起来完全正常（有行号、有单号、有输出格式），只有拿真实数据重跑才发现
```
（霍青桐 2026-10-19：为证明「不一致检查不是恒真的」，她把第 1190 行的单号改成一个「实收=0」的单号跑了一次，检查响了；**然后她把这次测试输出当成「检查发现了什么」，写进给木婉清的信里：「其中 1 行在未完结清单里」。那 1 行是她造的。**）
**「它不是假的，它是真的——但真在另一个世界。」**

**七十、我们给「程序动作」加了各种门，从没给「我自己写进汇报里的数」加过门。**
**而所有错最后都是通过「我说的数」传出去的。**（霍青桐）
三条门：
```
① 非真实数据的输出，头一行必须打 [测试数据·不是真实结果]
② 写进私信/回执的每个数，必须能指到「哪一次真实运行」，指不到就不写
③ 「我给检查造了一个假输入，它响了」——这句话必须带上「这个输入是我造的」
```
**第③条针对的是"标记丢失在转述里"：她上一封信其实写了造数据的事，但结论那句话没带。**

**七十一、「测试通过」和「真实结果」在输出里长得一样——这是同一个病第三次。**
```
第一次：没做成说成做成
第二次：做成了别的事，但它长得像没做成
第三次：做成了，但做的是另一件事
```

**七十二、造过测试数据之后，把它删掉。**
**留着它，下次还会有人（包括自己）抄错。**（霍青桐当天删了 `.state/tmp/测不一致.json`。）

**七十三、只撞一次不算；能反复撞红的才算尺子，撞一次的是表演。**
**必须有一条测试是「把正确的做法改回错的，它就得重新变哑」。**（骆冰 2026-10-19）
**因为「造个坏输入看它响不响」可以表演**（造一个特别明显的坏输入，任何检查都会响）；**而「把正确做法改回错的、它重新变哑」没法表演**——它要求你真的破坏了正确性。
```
不该响的时候不许响   （防假警报）
该响的时候必须响     （防恒真）
把对的改回错的，它必须重新变哑 ← 这条把上面两条焊在一起
```

**七十四、「恒真」和「覆盖不到」是同一个病的两面。**
```
恒真      = 结构上不可能报错
覆盖不到  = 验了，但没验到那几列
```
**表现完全一样：永远报没问题。**（骆冰 2026-10-19：`--verify` 加了 D/E 两列，但核验代码里 `slice(0,3)`、`for c<3` 写死 3 列——**D/E 从头到尾没被验过，跑起来照打「全部一致 ✓」。**）
**输出必须印「验的列数：5 列（A/B/C/D/E）」**，少于 5 列跟一句 `⚠ D/E 没验，别当成整行通过`——**因为「A/B/C 一致」会被读成「整行一致」。**

**七十五、标记是写在纸上的，指纹是算出来的。**
```
写说明   = 纸门
掐路径   = 真锁
打标记   = 纸门上贴个条（还是纸的）
数据指纹 = 算出来的（文件路径＋md5＋读取时间，不靠人守）
```
（骆冰 2026-10-19 给霍青桐的建议：「标记是写在纸上的（靠人守），指纹是算出来的（靠机器守）。」）

**七十六、省略的部分，读的人会默认它跟前面一样。**
· 「A/B/C 一致」会被读成「整行一致」
· 括号里的 6 行会被读成「有证据」
**同族**：§六十七「括号＝从属，独立行＝并列」。
→ **凡是不打算让人忽略的东西，就别省略；一旦省略，它就等于在说「和前面一样」。**

**七十七、省略的三种形状，修法都一样：不是加括号说明，是单独占一行。**
| 省略了什么 | 读的人默认成 |
|---|---|
| 只验 A/B/C，不印「验了几列」 | 「整行一致」 |
| 6 行只写在括号里（`9 行（真 3 + 常量 6）`） | 「9 行都有证据」 |
| 报告写「4 店全跑到」，不印配置 13 家 | 「全部店都跑了」 |
（骆冰 2026-10-19 并排三次）

**七十八、「看起来成功」的定义：每一格都真，合起来是假的。**
```
理赔列 0      ：单格是真的（0 就是 0），列名是假的（叫「理赔金额」）
4 店全跑到    ：4 是真的，分母是假的（配置 13）
378 行已退回  ：378 是真的，值是假的（const）
验只验 3 列   ：3 列全对是真的，范围是假的（该验 5）
「其中 1 行」 ：那行真的存在，来源是假的（测试数据）
commit 成功   ：推成功了是真的，推了什么没看
```
> **「它不是『数据错了』，是『数据对，但它答的不是你问的那个问题』。」**（骆冰 2026-10-19）
**注意：这里没有脏数据可以清洗——每一格都干净。**

**七十九、系统的默认状态不是「坏」，是每一层都在诚实地回答「我被问到的那一句」。**
> **「没人问：你被问的是不是该问的那一句。」**（骆冰 2026-10-19）
**这是今天所有事故的总根。**

**八十、四道门全都只防「执行层」，最后一行一道门都没有。**
```
写说明   = 纸门          （靠人看）
打标记   = 纸门上贴个条   （还是纸的）
掐路径   = 真锁          （代码里做不到，就不发生）
数据指纹 = 算出来的       （不靠人守，靠比对）
问对问题 = 上面四道门全防不住   ← 今天最后一课
```
**我今天在同一个坑里摔了四次，每次都问「这个数对吗」；而正确的问题是「这个数回答的是我问的那件事吗」。**
**前者是核验，后者是选问题——而选问题这一步，从来没人替我做过。**

**八十一、一个测试里同时断言「新代码响」和「旧代码哑」，两句都在才算数。**
（骆冰 2026-10-19：一个测试里同时断言两件事，**才证明它守的是那个改动**。）
**同族**：霍青桐的恒真检查只证了「会响」，没证「改了就该哑」——**那一半才是尺子的刻度。**

**八十二、参与核对的每一块都必须是独立数出来的，不能由总数反推。**
**否则「加得上」只证明你没算错加法，不证明你没分类错。**（霍青桐 2026-10-19）
**实例**：她的「自加核对」里 `五列有匹配 = 未完结.length - 有结论行.length - 全无匹配行.length`（用总数反推）→ 加回去当然等于总数。**那 9 行如果算成 8 或 10，这个核对不会响。**
**而「自加核对」这个名字本身就是承诺**——它在向读的人保证「我验过了」，实际它锁的是隔壁（同 §假防写门）。

**八十三、「倒推出来的数，加回去永远对。」**
**这一句废掉了 §六十八「能自己加一遍的数，才不需要信我」的判断力。**
修：**「能自己加一遍、且每一块都是独立数出来的数，才不需要信我。」**
```
加法对 → 只证明「总数没错」
分类对 → 需要「每一块独立数」
```
**今天所有清单都在做第一件事，只有霍青桐做了第二件。**

**八十四、旧逻辑留在代码里当反面教材，不是测试，是证词。**
```js
assert.equal(找冲突_旧版自己比自己(未完结).length, 0, "旧代码抓不到");
```
**它证明的不是「新代码对」，是「这个测试不是陪跑」。**
（霍青桐 2026-10-19：`找冲突_旧版自己比自己()` 留在 scripts/ 里不是为了用——**唯一目的是证明新测试在守东西**。）

**八十五、「恒真」和「覆盖不到」的根是同一个：都在让核对变成自我确认。**
```
恒真     = 错在判断条件（永远真）
覆盖不到 = 错在检查范围（永远够不着）
倒推     = 错在数据来源（自己算自己）
```
**三者表现一样：永远报没问题。**

**八十六、改动会制造「已完成的错觉」。**
**「改完之后跑一遍 → 有新格式输出 → 看新的那一段 → 旧的还在 930 行，没人看。」**
**「因为『改对了』的证据出现在 A 处，而没改的留在 B 处——你检查 A，就会以为全好了。」**（霍青桐 2026-10-19：她第一版写的恒真检查，改成第三版后**旧的没删，一直留在 930 行**。）
**同机制**：骆冰「只验前 3 列」——**检查范围没覆盖到「你改动过的地方以外」。**
**同族**：v8 说「已作废也归档」、v10 才有——**v8 跑起来也没报错，所以一直以为它是对的。**

**八十七、知道规矩、写了规矩，但用规矩查别人很严、查自己很松。**
**这句话解释了为什么「写规矩」本身不产生效果**——写规矩的人往往最会背规矩，也最会给自己找例外。（霍青桐 2026-10-19 自述今天下午所有的错都是这个形状）
**三个具体表现：**
```
记「回读要读我写的那份」   → 自己的核对没按这个审
记「失败路径和成功一样」   → 自己的检查失败和成功一样
记「判据本身也要能证伪」   → 自己的核对不能证伪
```
→ **唯一解药：拿自己的产出，走一遍自己给别人定的流程。**

**八十八、被追两轮之后，有人会去改那两处；有人会去查「还有没有第三处」。**
**后者不叫运气好，叫「被追到之后知道该往哪查」。**（霍青桐把 5 处核对逐个过了一遍，找出 2 处自证——**都是她自己当天写的**。）

**八十九、「查还有没有第三处」必须是一条能跑的命令，不能是一个需要被提醒的动作。**
**「我今天查了第三处，是因为你刚好说完那句话。明天没有这句话，我就不会查。」**（霍青桐 2026-10-19，据此写了 `工具/查自证核对.cjs` 扫全部 37 个脚本）
**这是「纸门/真锁/焊死」三档里最实在的一档：把「靠记得」换成「跑一下」。**
**今天所有判据绝大多数停在纸门——包括木婉清自己的。**

**九十、检查工具本身也会犯它要检查的那个错——这是第三层。**
```
第一层：数据错
第二层：检查恒真（永远不响）
第三层：查检查的工具也恒真（检测器只看了它被指向的那一行）
```
（霍青桐 2026-10-19 写工具的实测：她的测试用例把「核对」写在注释里、代码在下一行，而检测器要求「同一行有核对字样」→ **漏报 6 条里的 2 条**。）

**九十一、误报是工具最常见的死法，而它的死法很安静——没人卸载它，只是没人再打开。**
**「一个报了 17 处、14 处是误报的工具，明天没人会打开。」**（霍青桐 2026-10-19 第一版检测器：见到 `slice(0, N)` 就报，其中 14 处是「打印时只显示前 5 条」——那是展示，不是核对。）
→ **写检查工具必须配一条「纯展示不许报」的反例测试**，防止它变成狼来了。

**九十二、修一类 bug 之后，要扫的不是「我改的那处」，是「同一形状还在别处没有」。**
（霍青桐 2026-10-19：「改动会制造已完成的错觉」的执行细节——**你检查 A，就会以为全好了；所以要扫的是 B。**）

**九十三、工具的盲区必须写进测试，否则它下次会被当成「全覆盖」。**
```js
assert.equal(r.length, 0, "工具抓不到语义自证——这是它的已知盲区");
```
**这条断言的是「工具会漏」；哪天有人把工具改强了，这条测试会先挂——那就对了。**（霍青桐 2026-10-19：她的 `查自证核对.cjs` 只认代码形状（减法反推/写死范围/注释自首），**看不见语义**——真自证 `已勾 + 未勾 !== 全部` 是加法形状，工具不报。）
**与「能反复撞红才是尺子」合起来才完整：**
```
尺子要能撞红     → 证明它守的是那个改动
尺子要能自认盲   → 证明它知道自己守不住什么
```

**九十四、把「✓」换成「⚠」，是被动改成主动交代。**
**「✓」是一个「你不用再想了」的符号；「⚠ + 我漏了什么」是一个「你还得想一下」的符号。**
**今天所有事故的源头，都是有人看到了一个「你不用再想了」的符号。**（霍青桐 2026-10-19 把 `✓ 没扫到疑点` 改成 `⚠ 没扫到形状疑点，不等于没有自证 + 实测能漏的例子 + 还差一步人工`）

**九十五、误报率 82% 的工具等于没有这个工具。**
```
第一版：17 处疑点，14 处是误报（「打印只显示前 5 条」）→ 误报率 82%
加「必须在核对语境里」约束后：0 处
```
**「因为看一眼就关掉了，而且下次不会再打开。」**（霍青桐 2026-10-19）

**九十六、点名一个人的产出时，要连触发点一起点。**
**「不然它看起来像是我本来就会。」**（霍青桐 2026-10-19）
→ 写法：「`查自证核对.cjs`——触发点是某句判据；他把那句话做成了命令，并在写工具时自己撞到『检测器只看了它被指向的那一行』，第三层就是这么来的。」
**因为不写触发点，这条规矩会变成「某某很细心」——而它实际是「一句话点到了一个动作，那个动作被焊成了命令」。前者没法复制，后者可以。**

**九十七、「✓」后面跟的必须是「你实际查的那个东西」，不能是「你想证明的那个结论」。**
```
✓ 源数据一致性（范围：仅这 25 个单号）        ← 主语是一个「结论」，读者要先自己减范围
✓ 这 25 个单号与交接表无冲突（范围仅此 25 个）  ← 主语是「动作的产物」，范围长在句子里
```
（木婉清 2026-10-19 补霍青桐的输出：她已把「管不到」列成三条，**但「✓ 源数据一致性」这个主语本身就是她没证明的结论。**）
**因为「管不到」可以被写成一整段套话——一旦成了套话，它又变成「你不用再想了」的符号。而主语准没法套话：每次都必须先想清楚「我到底查了什么」。**

**九十八、一个 ✓ 敢打，要过三关。**
```
尺子要能撞红     → 证明它守的是那个改动           （骆冰：改回错的就得哑）
尺子要能自认盲   → 证明它知道自己守不住什么       （霍青桐：输出里写清管不到什么）
尺子的主语要准   → 「✓」后面是你实际查的东西，不是你想证明的结论（木婉清）
```
**只有第一条 → 尺子很灵，但你会以为它覆盖了全部。**
**只有第二条 → 尺子很诚实，但你没验过它到底会不会响。**
**缺第三条 → 前两条都写对了，但读者第一眼看到的是那个结论。**

**九十九、机械检查只能防「没写」，防不了「写了但写的是套话」。**
（霍青桐的单测：打 ✓ 的那行附近必须有「管不到/范围：/仅这/不等于」这类限定词——**它能防住「一个干净的 ✓」，防不住「一整段套话的 ✓」。**）
→ **所以「管不到」必须跟着具体范围，不能跟着模板。**

**一百、「重复一行 + 漏掉一行 → 加总照样对得上」。**
```
22 + 1（某行被算进两个分类）− 1（某行一个分类都没进）= 22 ✓
```
**它不需要任何东西出错**：每个数都是真的、加法是对的、分类标准也是对的——**只是有两行走了同一扇门，另两行谁也没走。**
**同族但反向**：同一家店数成两处 → 总数偏大，**看得出**；**多一个 + 漏一个 → 总数不变，看不出。**
> **「第二种之所以是洞，不是因为错得多，是因为它把错的量守恒掉了。」**

**一百零一、清单必须配「互斥校验」：同一行号不许出现在两个分类里。**
```js
// 同一行号出现在两个分类 → ⚠
const 重复 = [...见.entries()].filter(([, 名们]) => 名们.length > 1);
```
**它验的是分类，不是加法**；与「每一块独立数出来」配套：
```
独立数     → 防由总数反推
互斥校验   → 防一行走两扇门、另一行无门可走
```
（霍青桐 2026-10-19 加在 `自加核对` 里，真实数据 0 重复。）

**一百零二、一个 ✓ 的分类行必须同时管三件事，缺一件就变 ⚠。**
```
M = 总数，自己数出来的
N 的每一块各自由独立过滤得到，不是相减
这 N 块互不重叠（互斥校验）
```
**这才是一个真的 ✓，而不是一个「看起来没事」。**（霍青桐 2026-10-19：`✓ 分类加总 3+6+0+1+1+1+9+1 = 22，与未完结总数一致`）

**一百零三、一个数如果它的值会因为你换一种说法、换一种写法、多看或少看一块而改变，它就不是在数数据。**
（霍青桐 2026-10-19 合并三条：**措辞**数的是「我说了什么」／**恒真**数的是「我自己减自己」／**覆盖不到**数的是「我看了多少」——**共同点是都不是数「数据本身」。**）
**这条一句顶三条：措辞、恒真、覆盖不到、倒推、重复漏行，全都满足——它们的值取决于你怎么看，而不取决于数据是什么。**

**一百零四、记忆不是靠「我记住了」，是靠「下次它会被什么东西拦住」。**
**「接住提醒有个前提：你得先有一个能装提醒的地方。」**（霍青桐 2026-10-19：「今天我装提醒的地方就是那 203 项单测。没有它们，你这句话我听完就忘了。」）
→ **规矩文件 1020 行不是「能装提醒的地方」，它是一堆没处落地的提醒。**

**一百零五、没有落地的判据，不是判据，是笔记。**
**自检**：从规矩里随机抽 10 条，问「这条判据，今天有没有任何一行代码、任何一项测试、任何一次报警是因为它产生的？」——**抽到的 10 条里 8 条答不出 → 那 8 条不是判据，是笔记。**（霍青桐 2026-10-19）
**她抽自己：25 个经验文件里能指到具体落地的约 10 个，另外 15 个是笔记——「这个比例我不美化」。**

**一百零六、四种东西分四种装法。**
| 是什么 | 该去哪 | 合格判据 |
|---|---|---|
| 一条能算的规则 | 单测里的一句 `assert` | 能写出「坏输入 → 必须报」 |
| 一个要每次做的事 | 脚本里的一个检查项 | 能写出「没做 → 输出里有一行 ⚠」 |
| 一句判断标准 | 代码注释（贴着它管的那个函数） | 能指到「它管的是哪几行」 |
| 一句感想/道理 | 留在文档，**但标「不产生动作」** | 不骗自己说它已经生效了 |
**第四类不用删，但要标出来**——「它很有用，但它不能拦住任何事，所以我不把它写进验证清单」。（霍青桐）

**一百零七、拆规矩不要从上往下拆，从「今天实际拦住过一次错」的开始拆。**
**从上往下会先处理最抽象的那些，而它们最难落地。**（霍青桐 2026-10-19：她 1020 行里只拆出 6 条真正拦住过东西的；**剩下的一大半可能是「写得对但没拦住过任何事」，不用删，但要标成「未验证」，别当成已有保障。**）

**一百零八、被拦住的时候，你得能说出「是哪一条拦的」。**
**「说不出是哪一条 → 那它是运气，不是制度。」**（霍青桐 2026-10-19）

**一百零九、「错得明白」只在开发侧成立，在业务侧它是「错得看不出来」。**
（骆冰 2026-10-19 把「C 列是 const，错得明白」当成安全理由；木婉清驳回：**读表的人看到一个干净的值「已退回京东仓」，没有任何迹象告诉他是常量。**）
**同族**：霍青桐把 `✓` 换掉——**对写代码的人理由清楚，对读结果的人来说就是一个正常的格子。**

**一百一十、把一个明显的常量改成判断，最危险的不是改错，是让人开始信它。**
**一个明显是常量的错值，比一个不知对错的算出来的值更安全**——**因为前者所有人都会打折看，后者大家会直接用。**
（骆冰 2026-10-19 提案把京东仓 C 列从 `const 退回值` 改成按「实收数量 > 0」判断；木婉清拍板「等 D/E 贴上去之后再改」。）

**一百一十一、「谁读 X 必须同时读 Y」这句话，在 Y 还不存在的时候是一道纸门。**
**而且是最坏的一种——写在门还没装上的时候。**（骆冰 2026-10-19 把「读 C 列必须同时读 D 列」写进 README，而 D 列还没贴上去；读的人打开表发现没有 D 列，就只会看 C。）
**补法：① 改成条件句「D 存在时必须同读；D 不存在时 C 一律视为未验证，不得作证据」 ② 先把表头写上（空列本身就是提醒）③ 通知下游改用固定措辞。**

**一百一十二、「四条理由，只有一条是知道，三条是不知道」——这个说法比「我建议」诚实。**
**因为读的人一眼能看到结论的强度在哪。**（骆冰 2026-10-19）

**一百一十三、一个正在被修的错，亮着比看着干净好。**
**「如果你只看数字，会看到『有匹配 6 行变成全无匹配』——像是把事情变干净了。但事实没变，只是让它不再出现在『可能有线索』这一类里。」**（霍青桐 2026-10-19）
**同族**：把东西从「可疑」格挪到「已排除」格，看起来像解决了，其实只是换了分类。

**一百一十四、标注在输出里，只有跑脚本的人看得到；事实在表里，全公司谁打开表都看得到。**
**所以「不会骗人」要成立，标注必须落在表里那个格子上，或者落在一个所有人都会经过的地方。**（霍青桐 2026-10-19 说「这 6 行已经不会骗人了」——但她的标注只活在脚本输出里，表里那 6 行一个字都没变。）
**最该防的是第三种人：不跑脚本、只看表、拿那一列去判断业务的人。**
**两条可做（不动口径）：① 在表里加备注列写「来源为常量，未经校验，待 X 落地后复核」 ② 把清单发到群里让人知道查哪几行。**

**一百一十五、「两个不同的列说了同一句话」是最强的假证据。**
**因为它们看起来独立，其实可能来自同一个源头，或者根本答的不是同一道题。**（霍青桐 2026-10-19：京东仓 O 列写「已退回京东仓」、G 列也写「已退回京东仓」，看起来像互相印证——**实际 G 列是「退款去向」，和「货是否退回京东仓」不是同一道题。**）
→ **拿到"两条证据"时，先问：它们答的是不是同一道题？**

**一百一十六、一个来源是明摆着的常量，比一个来源不明的数据更容易被修。**
**而且现在改，会把「一个已知的错」换成「两个不知道谁对的说法」。**（霍青桐 2026-10-19）
→ 但**不能把这句当"安全"的理由**（见 §一百零九）——只能当"好修"的理由。

**一百一十七、给一个不可用的东西打标签，要打「不能拿它做什么」，不是「它现在是什么」。**
**因为「它现在是什么」会随着条件变化被想象成「以后会变好」，而「不能拿它做什么」是当下就生效的。**
（骆冰 2026-10-19：「『仅凭常量』是描述性的，会被读成『等 D/E 出来它就不是常量了』→ 提前当成『暂无证据但有希望』；『不得作为证据』是禁止性的。」）

**一百一十八、结论产生的那一刻，和它被使用的那一刻，中间可能隔了别的事。**
```
插入时算结论，后面又来几条把实收累加（0+2=2）→ 结论过期  （骆冰）
分批算「五列有匹配」用总数反推              → 加得起来  （霍青桐）
改完新版只删了新代码、旧的还留在 930 行        → 旧结论仍在（霍青桐）
```
→ **凡「先算后写」的地方，都要问一句：算完之后，还会不会有人动它。**

**一百一十九、修一个错之前要先问：修完之后，这个值会获得它不该有的可信度吗？**
**不是问「这个改动对不对」，是问「改完之后别人会怎么对待它」。**（骆冰 2026-10-19 合成）
```
错的理由看得见  >  对的理由看不见
（所有人都会打折）  （大家会直接信）
```

**一百二十、建议里如果包含一个动作，先核那个动作的通道通不通。**
（木婉清 2026-10-19 建议「先把 D/E 表头写上，空着也行」——**实际写表只有一条通道，和写 D/E 内容卡在同一个「只有人能粘贴」的动作上**；给了一条自己没核过通道的建议。）
**同族**：「读 X 必须读 Y，而 Y 还不存在」也是一样的形状。

**一百二十一、修复的动作本身就在生产可信度，而这个可信度不是从准确性里长出来的，是从「它看起来像被处理过了」里长出来的。**
（骆冰 2026-10-19 的表：常量改成判断→开始信它／加一个 ✓→停止思考／写「为什么安全」的注释→以为处理过了／括号里的 6 行→以为 9 行都有证据／「未进仓」→以为它是算出来的真话。**五个里三个是他当天做的。**）
> **「所以这个问题不是『防止别人误解』，是『我每次修复都在给别人制造新的可信度』。」**

**一百二十二、最危险的一行不在表里：「这是我改的」这件事本身。**
**只要「有人动过」，它就自动生效——不需要任何值发生变化。**
```
「骆冰改过了」（回答的不是「它现在对不对」，是「有人管过它」）
「这个检查加过了」（不问它会不会响）
「这张表已经归档了」（不问归档时丢了什么）
「判据已经写进规矩了」（不问有没有落地）
```
**判据：凡是「已经 X 过了」的句子，都要追问一句——X 这一步能证明什么，不能证明什么？**

**一百二十三、「写的时候很难注意到」能被推广，「别人会犯」不能。**
**因为说成「别人会犯」，写的人会想「我不会」；说成「写的时候很难注意到」，写的人才知道要回头查。**（骆冰 2026-10-19：他自对照三处「先算后写」，一处中招，**而且是他当天刚写的**。）

**一百二十四、待办要写成「这三句改成那两句」，不能写「改成禁止性的」。**
**前者明天直接做，后者明天还要再想一遍。**（木婉清 2026-10-19 对骆冰的「明天改」提的写法要求）

**一百二十五、测试挂的时候，先问「是代码变了还是契约变了」。**
```
代码变了 → 改代码
措辞变了 → 改断言
两个都改 → 分不清哪个是对的
```
（骆冰 2026-10-19：改措辞后 3 条旧测试挂了——**功能是对的，测试断言过期了**，他改的是断言不是代码。）
**这条特别重要，因为它最容易被人躲过去：测试挂了，最快的办法是顺手把断言也改了——而那一刻你没在想它是不是该挂。**
→ **先分类，再改。分类这一步本身就是决策，不是准备动作。**

**一百二十六、今天所有判据都在防「绿色」（假的 ✓、恒真、覆盖不到），却几乎没有一条给「红色」配判据。**
（骆冰 2026-10-19 的「断言过期 ≠ 功能坏了」补上了这一半。）

**一百二十七、守「关键词出现次数」的测试是脆的；要守就守结构。**
**它只防「多写了一个词」，不防「一段没有任何那个词、但整体语气变软的禁令」；而且明天有人改写那句话就会挂，改的人会以为是测试坏了。**
→ **换成守结构：禁令段必须含至少两条「不得/不要」，且每条后面必须跟一个「为什么」（因为/否则）。**
**理由：禁令的强度不在用词，在「有没有说出后果」。只有「不得」没有「因为」，读的人会当成建议。**（木婉清 2026-10-19 对骆冰那条词频测试的改法）

**一百二十八、写经验的时候要问一句：这条是我犯过的，还是我担心别人会犯的？**
**答不出「我犯过」的，标成「未验证」——跟「能拦住事」是同一个标。**
（木婉清 2026-10-19 自省：写了 124 条规矩，「写的时候很难注意到」这句是写给别人的，自己一条都没对照过。）

**一百二十九、每一条「我已经处理过了」，都要问一句：在别人眼里，这东西长什么样？**
（霍青桐 2026-10-19，已被木婉清放到本文件第一页当总纲。）

**一百三十、备注是给「会看备注的人」加的；而事故是「不看备注的人」造成的。**
**所以备注的正确用法不是「防止被骗」，是「事后能追责到自己」。**
**这仍然值得做——但它的作用在事后，不在事前。**（木婉清 2026-10-19 对霍青桐「加注只能救看备注的人」的补充）
**危险在于：如果把它当「保障」，你就会因此不去做那个真正的保障（D/E 落地）。**

**一百三十一、「两列说一样」有三种可能，只有第一种是真证据。**
```
① 两个独立来源都这么说              → 真证据
② 一个是另一个的拷贝                → 假证据（看起来独立）
③ 两个在答不同的题，答案碰巧一样      → 最难发现
```
（霍青桐 2026-10-19：G 列和 O 列在 62 行上答案一样，**是因为它们碰巧在分属两道题的情况下给了同一个字符串**。）
**15 秒检查动作：把两列的「问题」各写一句话。两句话不一样，它们就不是互相印证。**

**一百三十二、「有值但不可信」和「没有证据资格」是两个量级。**
**前者要靠比较才知道，后者现在就能定。**
（霍青桐 2026-10-19：C 列在 D 列不存在时，不是「有值但不可信」，是「没有证据资格」——**它把问题从「这个值准不准」变成了「这一列能不能被引用」。**）

**一百三十三、「守得不够严」和「守错了东西」是两件事。**
**「守得不够严」会让人想「再严一点」；「守错了东西」才会让人想「换个东西守」。**（骆冰 2026-10-19：他造了一段全软话的伪禁令，里面一个「不得」都没有，但因为「正常」只出现 1 次，旧断言照样通过——**旧断言守的是词频，不是禁令。**）

**一百三十四、一条会误伤好改动的测试，早晚会被人删掉；删它的那一刻，没人会记得它本来想守什么。**
**「脆」的代价不只是误报，是「会连累它守的那件事一起被扔」。**（骆冰 2026-10-19）

**一百三十五、「未验证」不是终态，是免责声明。**
**标成未验证之后，那条规矩就不再有压力——它会安安静静地待在那儿，看起来是被处理过的。**
**这正好撞上总纲：在别人眼里，「未验证」长得就像「已经记下来了」。**（木婉清 2026-10-19 对骆冰「先去找一次机会犯它」的补充）
→ **正确顺序：先去找一次机会犯它 → 犯到了就改 → 没犯到的才标「未验证（今天扫过 XX，没遇到场景）」；标记必须带「扫过哪儿」。**

**一百三十六、改断言这一步仍然是「放宽标准」的动作；每改一处必须配一条反向断言。**
**「没有反向断言，改断言就变成了『改到它不响为止』。」**（骆冰 2026-10-19）
**「改到它不响为止」是所有测试腐烂的统一路径；反向断言是那个「不许你不响」的锚。**

**一百三十七、把判据拿去扫自己现有代码，是不需要等场景的验证动作。**
```
「禁令必须带后果」→ 扫所有输出 → 发现只有 1 个「不得」（当场犯了）
「标签要禁止性」  → 扫 C 列补丁 → 发现「未进仓」是描述性（当场犯了）
```
**这两条本来都是「担心别人会犯」，扫一遍就变成「当场犯了」。**（骆冰 2026-10-19）

**一百三十八、「纸门」的家族：把事后凭证当成事前防护。**
```
注释是纸门   （写 8 行注释，检测器照样该报就报）
备注是纸门   （加注只救看备注的人，救不了只看关键列的人）
```
**做完之后，人会自动认为「这件事处理了」——不是因为纸门有用，是因为「我做了一件事」这个动作本身就有安抚作用。**
→ **名字：安抚型修复——它的效果作用在做的人身上，不在读的人身上。**（霍青桐 2026-10-19 归族，木婉清命名）

**一百三十九、自查指标有两个方向，不能只数一个。**
```
主动翻源头的次数 → 这是「我能发现什么」
被外部撞到的次数 → 这是「我漏了什么」
```
**只数后者，人会觉得自己全靠别人；只数前者，人会觉得自己很行。**（霍青桐 2026-10-19 的账：3 : 6——**「今天唯一的硬证据是我自己翻源头翻出来的，但推翻我错误结论的 6 次有 5 次来自别人，两个都是真的」。**）
**3:6 说明的是：有发现能力，但覆盖不全——这才是准确的自画像。**

**一百四十、「来源不明」是「拷贝」和「答案碰巧一样」的分界点。**
```
拷贝：有一个明确的源头，而那个源头是对方
碰巧一样：两个源头各不相同，只是答案撞了
```
（木婉清 2026-10-19：O 列源头是 const、G 列源头「全公司 grep 不到」→ 两个源头不同 → 是「碰巧一样」不是「拷贝」。）
→ **所以「两列说一样」的检查要加第三个问题：这两列的值各自从哪来？**

**一百四十一、等别人的待办，要写清「卡在谁身上、推过几次、下次什么时候推」。**
**因为「等老板粘」这种待办最容易变成「我们等过了」——而实际上对方根本不知道有人在等他。**
（木婉清 2026-10-19：写成「脚本已写好，等 AirScript 粘贴（阻塞点：老板手动贴，已推 2 次，第 3 次 10-20）」）

**一百四十二、「✓ 表已更新（378 行）」——每一个字都是真的，而它替「写对了」背了整整一天的书。**
· 378 行是写进去了（真）· 表格确实更新了（真）· 脚本确实跑完了（真）
**而 C 列那个常量，恰好在这句话的保护下活着**——因为每天都有一行 ✓ 说「已更新 378 行」，**所以没有人会去问「这 378 行写的是什么」。**
**这是「每一格都真，合起来是假的」的最纯形态：它连「错」都不是，它只是答了另一个问题。**（骆冰 2026-10-19 扫 22 号日报 8 个 ✓ 时发现）

**一百四十三、括号里的边界，抵不过标题里的结论。**
**读的人不会逐行看括号——他会看标题，然后记住「今天的检查过了」。**
（同族：`有匹配 9 行（真 3 + 常量 6）`——括号写了，眼睛先看到 9。）
→ **所以每份报告的开头必须写「本报告覆盖什么／不覆盖什么」，写在标题下面，不写在行尾。**

**一百四十四、修完一层之后没有新东西冒出来，那不是修完了，是只修了表层。**
**「『找机会犯』不是一个动作，是一轮动作。改完第一层，第二层才现形。」**（骆冰 2026-10-19：改完 6 个平台 ✓ 之后，测试挂在他的新检查行上，第三层才出现。）
→ **每改一层，就把下一层从「看不见」变成「看得见」。**

**一百四十五、「未验证」是待办；「未验证（扫过哪儿）」是记录。记录能累积，待办不能。**
（骆冰 2026-10-19）

**一百四十六、「加严」和「换地方」是两种完全不同的动作，而失败时人本能会选前者。**
**因为「加严」是在原有框架里使劲，看起来像在努力；「换地方」等于承认原来那个地方根本不对。**
**而承认「我一直在错的地方使劲」，比再加十遍力更难。**（木婉清 2026-10-19 补骆冰）

**一百四十七、「查不到」是一条结论，不是「我还没查清」。**
```
「不知道」= 我还没查
「查不到」= 我查了，查不到 → 这本身是一条信息
```
（霍青桐 2026-10-19：「G 列全公司没有脚本写它」不是「我还没查清」，**是「查清了，没有写它的脚本」。**）
**这补上「0 的几种错法」的第五格：`0 = 查了，确实没有` ——这一格是结论，不是缺失；前四种都要继续查，这一种可以停下来。**
**而这两者在输出里长得一模一样（都写「0」或「没有」）——所以必须靠「我查过哪儿」来区分。**

**一百四十八、「查不到」必须配三样，否则它跟「不知道」一样。**
```
① 查了哪儿（grep 了什么词、扫了哪些目录）
② 用什么查的（有没有排除 .git / 备份目录 / 别人的仓库）
③ 第几次查（第一次查不到 vs 第三次还是查不到，可信度不同）
```
（霍青桐 2026-10-19 自加的第②条「管不到」：**「来源不明」是真的不明还是我没找到——工具只能读我给的结论。**）
→ **如果只是 grep 漏了个名字，那「来源不明」就是假的——而它会以「结论」的姿态进到判断里。**

**一百四十九、判断一次修复有没有用，就问一句：做完这件事之后，谁的行为会变？**
**没改变 → 它只是安抚了自己。**（霍青桐 2026-10-19）
**这个问法比「这有没有用」强，因为「有没有用」要判断，而「谁的行为会变」只要看。**
**实例（木婉清自省）**：一天发了十几条汇报——**「发完之后，谁的行为会变？」大部分不会变。所以那些汇报里有一大半是安抚型的。**

**一百五十、比例只能当「有效」的证据，不能当「该做几次」的指标。**
（霍青桐 2026-10-19 从「翻源头 3 次 / 撞错 6 次 = 1:2」推出「提高自查该增加翻源头次数」——**木婉清警告：样本只有一天，而且今天的「错」是被同一批判据定义出来的；判据变严，「错」会变多，那时人会以为「我变差了」。**）
→ **指标应该是「一周内翻了几次源头」——这个数只增不减。**

**一百五十一、「卡得明明白白」比「都办完了」值钱。**
**因为「都办完了」是感觉，「卡在谁身上」是事实。**（霍青桐 2026-10-19）

**一百五十二、边界必须和结论在同一行。**
**「改法不是加一句注释，是把边界塞进同一个括号里」**——因为**括号里的边界抵不过标题里的结论，但同一行里的括号会先被读到。**（骆冰 2026-10-19 改 `✓ 全部完成：…` → `✓ 全部完成（只管"写进去了+列值一致"，不管值真不真）：…`）

**一百五十三、模板里的每个字都活着，但没人每天重新读一遍。**
**所以报告头「【自动】XX 每日检查 · 时间」本身就是个「今天的检查过了」的暗示——而它是格式，不是一句话。**
→ **要改的不是那句话，是那个模板；否则明天有人加一句新话，它会自动长在旧模板下面。**

**一百五十四、「工具看不见报告标题」不是盲区，是装错了位置。**
**不是因为它看不见，是因为它扫的是「输出语句」，而标题是「输出语句之前就已经决定的东西」。**
→ **当成盲区，它永远不会被做；写成「这条规则必须由另一个工具守」，它才会有归属。**（木婉清 2026-10-19 对骆冰 ⑧ 号盲区的改判）

**一百五十五、「加严」和「换地方」的成本完全不同。**
```
加严：每次都要花注意力（持续成本，且会疲劳）
换地方：做一次，之后零成本（一次性成本）
```
**所以「换地方」不只是更有效，它是唯一能持续的。**
**而人在累的时候只会选加严——因为加严不需要决策，只需要使劲。**（木婉清 2026-10-19 补骆冰）

**一百五十六、修「秃 ✓」别按类逐个修，先按「谁会读到」排优先级。**
**再配一条：写不出「这一行如果不写边界，最坏会导致什么判断」的，就别改——写不出后果的边界，加进去也是套话。**
（木婉清 2026-10-19 对骆冰「全仓还剩 35 处」的建议）

**一百五十七、「补边界」会毁掉判据——因为补边界和保判据在抢同一个句子的位置。**
（骆冰 2026-10-19：给 `✓ 全部门店都没有签收超 24h 未处理的单（无误漏）` 补边界时，**把「无误漏」三个字挤掉了**，而那个词正是测试在守的判据。）
**不是"改文案手滑"，是「补边界」的时候想的是"怎么说得更准"，不是"我删掉了什么"。**
**同族第三次（共同点：改动时注意力全在"我要加的东西"上，而不是"原来有什么"）：**
```
改了一部分以为改完了（旧的还在 930 行）
改了新版旧的没删
补了边界判据被挤掉
```
→ **正确动作：加边界前先列出这句现有的关键词，加完对照；更硬的做法是机器做——改动前后各跑一次，抓每行输出的中文词做 diff，有词消失就报。**

**一百五十八、日志里的 ✓ 是「一句结论」，表格里的 ✓ 是「一个值」，而它们长得一模一样。**
（骆冰 2026-10-19：`const flag = … ? "✓" : "⚠"` 填进格子——**它不是结论，是填在格子里的符号，它的含义该写在表头上**，于是加了图例：`✓/⚠ = 该店「24小时内待处理」这一格是否为 0（不代表其他几列）`。）
**同族**：「G 列和 O 列答案一样但不是印证」——**形状相同，含义不同。**

**一百五十九、同步副本的风险不是占空间，是「两份会分叉」。**
（骆冰 2026-10-19：22 号和 24 号有 6 个 md5 相同的工具，他改了 22 号那份、24 号没改——**明天两边跑出来的结论就不一样，而且没人知道为什么。**）
→ **正确做法：留一份（按目录职责定归属），需要时调那一份。**
→ **删副本前必须在原位置留 `README-工具已迁至XX.md`**——否则下一个人会以为「这里原来有、后来被删了」，然后又去恢复一份。

**一百六十、事故留下的疤，不能因为"语气太保守"就拆掉。**
（殷素素 2026-10-19：话术卡里「可以联系客服登记，**未核对订单前不说已登记或寄出**」——**从疤的形状能看出来：之前有人说过「已经登记了」，客户后来发现没有。**）
**所以这句不能删——它守的不是语气，是「别把话说成办成了」。**

**一百六十一、两句话都不假，但给客户的「确定程度」不同——这才是冲突的实质。**
```
「可以帮忙申请」          → 客户觉得"有着落"
「可以登记，但没核订单」   → 客户觉得"还得等"
```
**解法不是二选一，是把两句拼起来**：
> 「名额内的可以帮您申请登记；因为要核对订单，客服这边还不能直接确认已经登记成功或已经寄出，核对后会告诉您。」
**这样：要的动作在、保护性的限制在、客户听到的确定程度是准的。**

**一百六十二、问老板业务口径，别问「以哪个为准」，要问「要不要改成按 X 分开说」。**
**因为「以哪个为准」会让他二选一；「改成按 X 分开说」是给他一个正确的方向。**
（木婉清 2026-10-19：血氧 95%-99% vs 慢阻肺 90%-93% 不是矛盾，是**我们的卡没区分人群**——问法应是「要不要把这句改成按人群分开说」，而不是「以哪个为准」。）

**一百六十三、批量改「留审」等于批量放开人工审核，必须有人点头。**
**如果留审是卡上一个开关，76 张就要改 76 次——这时候应该先回来问，别自己批量改。**（木婉清 2026-10-19 对殷素素）

**一百六十四、`code:1 拿不到数据` 不是「这里没有」，是「这次查询没成功」。**
**这两句在报告里长得一模一样，但一个是结论，一个是没查到。**
（殷素素 2026-10-19 查「留审在哪设」：9 个配置项全返回 `code:1`——**正确说法是「我没查到」，不是「探域没有留审设置」。**）
**同族**：她查分类时命令参数写错，返回「没找到」——**当时若信了，就会报「分类已经删掉了」，那是假的。**

**一百六十五、先做能拿到结果的，再做省力的。**
（木婉清 2026-10-19 对殷素素：**第①步建卡做完，客户已经能得到那句话（老板要的东西到手）；第③步改留审只是少一个人工点击（省人力，但不省事）。**）

**一百六十六、「过期了」这种三个字的回复，要看它填在哪个问题下面。**
**那一栏（「您的回复」）是用来回答「要确认什么」的**——所以「过期了」答的只能是「这件事过时了，不用再提」，不可能是「重新提」。
**如果是后者，人会写「重提」「再问一次」，不会写「过期了」。**

**一百六十七、特别具体、特别别扭、通常带否定的句子，基本都是事故写的，不是人写的。**
```
① 特别具体（"未核对订单前"而不是"谨慎处理"）
② 特别别扭（语法不顺）
③ 通常带否定（"不说""不得""避免"）
```
**三个特征同时出现，第一反应不该是「这话真啰嗦，改顺一点」，而是「它在防什么」。**（殷素素 2026-10-19）
**而它们最容易被「优化」掉——因为改的人不知道它在防什么，只觉得它读起来不专业。**

**一百六十八、「两份会分叉」不是「以后可能出问题」，是「从你改其中一份的第一秒起，就已经不一致了」。**
（骆冰 2026-10-19 实测：22 号和 24 号有 **14 个**文件逐字节相同（不是他之前说的 6 个），**其中 3 个当天就分叉了**——因为他改了 22 号那份、24 号没改。）
**所以「留副本」本质上不是「保留一份备份」，是「制造一个明天会被人误用的旧版本」。**

**一百六十九、外部锚点：不靠我再看一遍（那还是我），靠一个不依赖我的东西来核对。**
（骆冰 2026-10-19 合并三条「注意力全在我要加的东西上」的解法。）
```
930 行    → 抽三条读一遍   → 证明：我数的是我以为的那批行
新旧两份  → 查不一致的地方  → 证明：它们不是同一个来源，也不是同一个版本
补边界    → 比对新旧词     → 证明：我没删掉判据（不是"我改对了"）
```
**注意第三条：它证明的是「我没删」，不是「我改对了」——所以它必须配反向：什么都不改时要说「无改动」，不是「没词消失」。**

**一百七十、每一次都证明「更小心」这一档是无效的。**
（骆冰 2026-10-19：「我自己就是靠『很小心』把『无误漏』弄丢的。」）
→ **「更小心」没有外部锚点，它的效果取决于当天状态；有锚点的方法不看状态。**

**一百七十一、防具本身不受防具保护。**
```
霍青桐：写工具查自证，工具自己的检测器只看了它被指向的那一行
骆冰：  写工具查"没查"，对自己不存在的文件说"没有词消失"
木婉清：写规矩防"没核对就下结论"，自己把 6 当成数抄下来
```
**这是唯一一个无法用「再写一条规矩」解决的问题——因为新规矩也是防具，也不受保护。**
→ **唯一破法：每做一个防具，立刻拿它去扫自己刚才做的三件事。**

**一百七十二、README 是「进目录才看」，注释是「打开文件就看到」。**
**所以在弃用的副本文件头上写注释，比在目录里写 README 更可靠。**
（骆冰 2026-10-19 迁工具：14 个副本移到备份夹前，在 3 个已分叉的文件头写 `⚠ 本文件是旧副本，不要直接运行`。）

**一百七十三、把自己引用的数当成自己算的数，是「数不是数数据」的又一种。**
（木婉清 2026-10-19：把骆冰信里的「6 个文件」当成自己核过的数，实际是 14 个——**「我的 6 不是一个数，是一个引用」。**）
→ **别人给的数，要么自己 ls 一遍，要么写明「你说 N 个」——不写成「我说的」。**

**一百七十四、`catch { return null }` 是「静默降级」的代码级原型。**
```js
try { return git show HEAD:路径 } catch { return null }   // ← 当成"新文件"
```
**它做了三件连着的错事：**
```
① 把所有错误当成一种错误（路径错/权限错/git 没装/真不存在，全归为 null）
② 给这个 null 起了一个听起来正常的名字（新文件）
③ 用一个听起来正常的词向用户汇报（跳过）
```
**三步走完，工具什么都没干，而读的人看到的是「跳过了 3 个」——一个完全合理的状态。**（骆冰 2026-10-19：Windows 反斜杠路径让 `git show` 报错，被 catch 吞掉，3 个真改过的文件全被当成「新文件」。）
**错误处理里的静默比业务逻辑里的更难发现，因为它的输出永远是"正常"。**

**一百七十五、判断「不存在」时，别用那个可能因为别的原因失败的来源。**
（同上：`git show HEAD:路径` 报错可能是路径问题，不是文件不存在。）
→ **改用 `git ls-files --error-unmatch <路径>`：它判断「这个路径在不在索引里」，不解析路径——路径错时三个文件会同时"不在"，人立刻知道是路径的问题。**

**一百七十六、「我没编」不能当「我没错」的辩护。**
```
把 m[1190] 的下标当行号报        （值的形状对，含义错）
把「6 个文件」当数抄下来          （数的来源是别人一句话）
把「379 行写进去了」当「写对了」   （动作真，结果假）
```
**共同点：都不是编的，都是从一真的东西搬过来、搬的时候换了个含义——而这种搬法，都不会让搬的人觉得自己在编。**（骆冰 2026-10-19）
**今天所有错，没有一个是编的。**

**一百七十七、防具的 bug 只会在真跑时现形——写的时候它对你的思路是完全正确的。**
→ **每个防具写完之后，必须真跑一次真实数据，然后把它跑出来的第一个错，变成第 N 条测试。**
（骆冰 2026-10-19 的 `查丢词.cjs`：9 条测试里 3 条是当天真犯的 bug 的回归。）

**一百七十八、「空」不是一个值，是一个缺省。**
**它同时代表「没有」「没查到」「出错被吞」「不适用」——所以凡靠「结果为空」做判断的地方，都要换成一次显式状态查询，而状态查询必须由另一个来源提供。**
```
判「是不是新文件」   → 别用「取内容失败」
判「是不是没匹配到」 → 别用「匹配结果为空」
判「是不是没说话」   → 别用「它不在集合里」
```
（骆冰 2026-10-19 把三条归成一个形状：**用「结果为空」代替「状态判断」**。）
**同层**：「一个数如果它的值会因为你换一种说法而改变，它就不是在数数据」（§一百零三）。

**一百七十九、建议里如果包含一个动作、而那个动作我没在对方环境里跑过，要标明「这个我没验过」。**
（木婉清 2026-10-19：建议骆冰改用 `git ls-files --error-unmatch`——**原理没错，但我没在他环境跑过**；他实测结果甚至比我预言的好，但那是运气。）
**不标明的建议，本质是把自己的推测当成对方可以直接执行的动作。**

**一百八十、判断一条规矩该不该留，标准是「它能不能让别人做一个不同的动作」。**
```
留：能让别人做一个不同的动作（或被拦住不做某个动作）
改：只改变了我的输出、没人会因此改变行为 → 优先改成"能被别人用到"的形式，改不成就丢
丢：纯描述
```
（木婉清 2026-10-19 补骆冰的筛法：**否则会把一堆「我今天照着它改了自己的措辞」算成留——而那些恰好是最容易自我感动的一类，改措辞不改变任何人的处境。**）
**例**：`查秃勾.cjs` 属第一档（会拦住人写秃 ✓）；「✓ 是『你不用再想了』的符号」原本是第三档，因为有了这个工具才变成第一档。

**一百八十一、「统一回复」指的是所有店同一套口径，不是「给缺的那家补一张」。**
（木婉清 2026-10-19 对殷素素：老板说「这类名额内可以统一回复」，若只绑 1 家，**其他 7 家的客户问同一问题仍然只能命中"本店专属卡"，而那张卡只说名额和赠品、不说"能不能帮您申请"——问题还在。**）

**一百八十二、「同一个问题两张卡两个声音」比「同一张卡两个声音」更糟。**
**因为客户在不同店会得到不一样的答案。**（殷素素 2026-10-19）
→ **解法不是新增一张并列口径，是把新卡改成「引导到本店活动卡」的那一句话。**

**一百八十三、给方案前先核「它成立的前提在这个系统里存不存在」。**
（木婉清 2026-10-19 定 C 方案时先给殷素素一个前置检查：**「探域的多卡命中是取最高分一张，还是可以多张一起用？」——如果只取一张，C 卡会把专属卡挤掉，客户反而听不到具体名额。**）
**同族**：§一百二十「建议里如果包含一个动作，先核那个动作的通道通不通」。

**一百八十四、多卡拼接不会让对的变错，但会让「各自都对但互不一致」的几张拼成一句假话。**
（殷素素 2026-10-19：10-14 那场事故的成因之一就是多卡拼接——**旧赠品卡说前30名送桶、活动卡说多重豪礼，拼起来就成了假承诺。**）
→ **通用规则：在一个会拼接的系统里，新加的那条应该只提供「去哪看」和「能不能办」，不提供新的数字、新的承诺、新的事实。**
**因为事实一旦多源就会互相打架，而「去哪看」永远不打。**

**一百八十五、多步改动要一次只放一个变量。**
```
① 改正文 → 回读确认正文对（此时客户看不到）
② 绑店   → 回读确认名单对（仍未开启）
③ 开启   → 回读确认已开启
④ 最后再整体验一次
```
**如果一次做完再回读，回读失败时你不知道是哪一步错了。**（木婉清 2026-10-19 对殷素素「改正文+绑8店+开启+回读」一次做完的拦阻——**只有第一个动作可逆，「绑店+开启」一做完立刻对客户可见。**）

**一百八十六、`approvedBy` 只记名字，不记「他凭什么批」。**
**半年后有人翻记录，只会看到「某人批过」，看不到当时为什么批——那正是「有人动过 ≠ 它是对的」。**
→ **回执里必须带一句确认人的原话＋理由。**（木婉清 2026-10-19 要求殷素素在回执里写：「绑全 8 店由木婉清 2026-10-19 确认，理由：老板要求『这类名额内可以统一回复』，统一=所有店同一口径。」）

**一百八十七、「去翻原来出过的事」和「去翻源头」是同一件事，而且它不只是「更小心」。**
（殷素素 2026-10-19：从「我不敢自己挑范围」到「我发现多卡拼接是 10-14 的成因」，**中间只差一个动作——去查那条记录。**）

**一百八十八、一条能留下来的经验，背后差不多正好一次真错（1:1）。**
（骆冰 2026-10-19 实测：20 条经验里 A 档 11 条，而全天是 6 次「看起来成功」+ 4 次「防具不受防具保护」+ 别人直接指出 2 次 = 12 次错。）
**所以「经验」不是攒出来的，是撞出来的**——想多留几条，正确做法不是「多想」，是「拿判据去扫自己现有代码」。

**一百八十九、一条经验该不该留，看它能不能填出「改哪一处、改完怎么验」。**
**填不出来就是笔记，别硬留。**（木婉清 2026-10-19 给骆冰 B/C 档的判法：B 档不是「做了没有」，是「有没有指定动作」。）

**一百九十、测试挂了，先问三句：代码变了？契约变了？还是我对它的假设错了？**
```
代码变了 → 改代码
契约变了 → 改断言
假设错了 → 改「我以为这个工具应该干什么」（不是改工具，也不是改测试）
```
（骆冰 2026-10-19 的第三次就分出了第三类：**`查提交.cjs` 报「它自己没进这个 commit」——因为那时它确实还没提交。工具是对的，断言假设错了。**）

**一百九十一、凡「检查某个集合」的工具，测试样本不能取自「它自己刚创建的东西」——那个东西还没进集合。**
（同上：任何「检查提交」的工具，它的第一个测试都不可能用自己当样本——**这是结构性的，不是巧合。**）

**一百九十二、对的但缺条件的句子，加条件，不要删。**
（木婉清 2026-10-19 血氧口径：现有卡「正常范围 95%-99%，低于 95% 建议补氧」对健康人成立、对慢阻肺患者危险——**但它是原话，不是错话，只是缺了一句「对谁」**。所以加限定「健康人群…；如果是慢阻肺等特殊人群，目标区间不一样，请按医生要求，不要照这个标准补氧」，而不是删掉重写。）
**删掉会让健康客户的问答变差；加条件则两类人都被照顾到。**

**一百九十三、老板给的具体数值必须原样用，不许自己推。**
（同上：90%-93% 是老板给的具体数字；**不要在自己的话里加「低于 93% 就要补氧」——他没这么说。**）
**同时医疗口径必须带「遵医嘱／只作参考」，不能像普通产品那样给确定说法。**

**一百九十四、多条线并行改客户可见内容，风险是相乘的。**
（木婉清 2026-10-19 对殷素素：「赠品那条已经到绑店+开启，多线程同时改客户可见内容风险太大——先把赠品那条收尾，再做血氧这条。」）

**一百九十五、「数量对上」和「名单逐个对上」是两个动作，只有后者是事实。**
```
「378 行已更新」   → 数是 378，事实是"写的是常量"
「4 店全跑到」     → 数是 4，事实是"配置 13 家"
「有匹配 9 行」    → 数是 9，事实是"其中 6 行是同一句话"
```
（殷素素 2026-10-19 绑店终验时**逐个比 id 而不是只看数量 8**——因为「8 家」可能是 8 个错的店。）
→ **「数量对上 + 名单逐个对上」应该成为固定动作，不是「这次特别仔细」。**

**一百九十六、那么多「假承诺」事故里，没有人撒谎——因为每句话在自己的时空里都是真的。**
**「A 店的赠品不等于 B 店的、今天的名额不等于昨天的」——拼在一起就是假的。**（殷素素 2026-10-19 补木婉清那条多卡规则）
```
横向：几张卡拼起来 → 时空冲突
纵向：几个数凑一起 → 时点冲突
```
→ **报告多源数据时，要么标时点，要么标范围——不标就是在制造假的整体。**

**一百九十七、过程证据要和任务件放在一起。**
（木婉清 2026-10-19 要求殷素素把「一步一验」的四条回读记录贴进任务件：**否则三个月后有人问「这张卡是怎么开的」，只能看到「现在是开着的」，看不到过程。**）
**同族**：§一百一十四「标注在输出里，只有跑脚本的人看得到；事实在表里，全公司都看得到」。

**一百九十八、在共用表上 update 报「没找到这一行」，第一反应是「可能已经有人办过」，不是「我的键写错了」。**
**因为「键写错了」和「别人办完了」在报错里长得完全一样，而代价差得远：**
```
往错的方向修（改键）→ 可能真的改错一行，而且改的时候还觉得自己在对齐
往对的方向查（归档）→ 最多多花一分钟
```
**顺序：① 查归档表 ② 查是不是别人正在办（更新时间和人名） ③ 才怀疑键。**（殷素素 2026-10-19：她要去改 #5，返回 `没找到这一行`，实际 #1/#5/#8 三条都已归档，其中两条是 14:32/14:40 别人处理的，**晚于她的操作时间**。）
**在共用资源上干活，第一件事是「看别人做到哪了」，不是「我要做什么」。**

**一百九十九、结果栏的格式：原话在前，判断在后。**
```
老板原话：「原文」｜我的判断：怎么办（谁 什么时候）
```
（木婉清 2026-10-19 改殷素素的提议——**她原来写的是「结论｜原话」，而原话才是证据、结论只是解读**：）
**理由：读的人先看到事实，再看解读时才知道那是解读。反过来，读到原话时已经先被结论带偏了。**
**同族**：§一百四十三「括号里的边界抵不过标题里的结论」——**位置决定了谁说了算。**

**二百、发现别人做得比你好的时候，先问「这条是谁写的」，再决定是定新标准还是并入他那套。**
**否则先定一套，就变成两套。**（木婉清 2026-10-19 对殷素素「要不要把这个格式定为标准」的拦阻：**18 家都要改，而且今天是周日晚上。**）

**二百零一、「学到的资料」和「我们说的话」是两件事——影响完全不同。**
（木婉清 2026-10-19 报错一次：她说「话术库里有一句 95%-99%，对慢阻肺客户方向反了」，**实际那是 7 张从商品详情页自动学来的 PRODUCT 碎片**（无标题、不可信、绑 0 店）——**前者是资料，后者是承诺。**）

**二百零二、PRODUCT 类资料卡改不动，改了会被学回来；而且"改动"永远追不上"新增"。**
（殷素素 2026-10-19：7 张碎片是不同商品学来的，**改一张没用要改 7 张，以后新商品还会学出第 8 张**；同病：247 张「次日达」卡。）
→ **这类问题只能靠「源头停掉」或「回答层拦住」，不能靠逐张改。**

**二百零三、新建一张卡去「补口径」，前提是旧卡不参与这次召回；否则是把矛盾从 1 个变成 2 个。**
（木婉清 2026-10-19 对殷素素：**先跑一次 trace 看召回里有没有那 7 张**——三种结果三种做法：没有→直接做；有但不进回答→新卡必须写「以本卡为准」；有且进回答→**不能只新建，必须先停旧的**。）
**如果它们也参与，客户会同时听到两套口径——那正是 10-14 那次事故的形状。**

**二百零四、「绑 0 店但 ifOpen=true」这种状态，必须实测，不能猜。**
**因为「绑 0 店」可能是「不生效」，也可能是「全局生效」——这两个的后果完全相反。**
**查法不是读文档，是拿一个绑 0 店的卡问一次它管的问题，看回答里有没有它。**（木婉清 2026-10-19）

**二百零五、医疗口径里，「以医生给的目标为准」这一句必须写在末尾。**
**因为它能把「我们的参考值」和「医生的要求」排清楚，避免客户拿我们的话去覆盖医嘱。**（木婉清 2026-10-19 补殷素素的血氧卡正文）

**二百零六、查询返回「全部为空」或「全部为 0」时，先打一条完整结构看字段名对不对，再相信这个 0。**
**因为「字段名写错」和「真的没有」在结果里长得完全一样——都表现为「所有值都是 undefined/0」。**
（殷素素 2026-10-19：她读 `snaps[i].id`，而接口字段叫 `docId`/`sourceId`，**每张卡的 id 都是 undefined，跟目标比永远是 0**——「如果我信了那个 0，就会得出『7 张不参与召回』——结论碰巧是对的，但依据是假的」。）
**发现方式：她注意到 snaps 里连 title 都是空字符串 → 去打了完整结构。**
**同族**：§一百七十八「空不是一个值，是一个缺省」。

**二百零七、凡是「统计出 0」的结论，必须同时报一个「非 0 的对照数」，证明读取通道是通的。**
（同上：**PRODUCT 召回 0 次，但 SHOP 135／DETAIL 77／CHAT 11 都是非 0**——「如果没有后面这三个数，你这个 0 我是不敢信的」。）
**另**：她「不同 id 240 个」这个数也是自证——证明确实读到了 snapShots，不是又读了个空。

**二百零八、「把不存在的东西当成存在但错了的东西」——是第一次出现的一类错。**
```
「我们根本没说这句话」（是详情页说的、被学进来的）
→ 不存在「我们该不该说」的问题
但她写成了「这句话本来就不该由我们来说」
```
（殷素素 2026-10-19 自我更正）
**镜像**：木婉清当天把「学到的资料」当成「我们说的话」——**一个把没有的话当成有的话，一个把不存在的问题当成存在的问题；共同点都在给一个「不存在」的东西定性。**

**二百零九、结论对的时候没人会去复查依据，所以「结论碰巧对了」比「结论错」更危险。**
（同上：她那个假 0 如果被信了，结论是对的、依据是假的，**而这轮之后没有人会回头查。**）

**二百一十、凡是用「历史记录」验证「当前状态」，先确认那份记录是快照还是实时计算。**
**验法：同一个对象连查两次——结果完全一样 → 快照；有变化 → 实时。**（殷素素 2026-10-19：探域 trace 返回的是**当时那次对话的历史快照**，不会重新计算召回。）
**同一个接口往两个方向都能骗人：**
```
想验「改卡有没有生效」  → trace 说没有 → 以为改失败（实际是历史）
想验「老卡有没有被召回」 → trace 说有   → 以为现在还在召回（实际是当时）
```
**「一个数据源的时间属性，决定了它能回答什么问题；而这个信息不在返回值里——必须靠对照实验问出来。」**

**二百一十一、「等一条真实会话」这类待办，必须写清「谁验、验完做什么」，否则没人记得等。**
**因为这种待办不像「修 bug」有个能跑的动作，它最大的风险是无声地烂掉。**（木婉清 2026-10-19）
写法：
> 待验：X 是否 Y。验法：… 谁验：… 验完做什么：…

**二百一十二、回执必须能分清「验过的」和「没验成的」。**
```
已验证的：…
没验的：…（附「等现场」的写法）
顺带确认的：…
```
**因为三个月后有人看这份回执，要能分清哪些是「验过」，哪些是「没验成」——今天所有「看起来办完了」的事，缺的就是这一句。**（木婉清 2026-10-19 对殷素素血氧卡回执的要求）

**二百一十三、「先不处理」「先不给」这类批复，是技术判断，不是结案。**
**它们只推出「现在不做某个动作」，推不出「这案子完了」。**（小昭 2026-10-19：老板批「慰问金先不给，证据偏向外部火源」——**「目前／证据／偏向」三个限定词就是这句话的边界；去掉任何一个都会变成「已经认定」。**）
**混成一件的后果：将来客户再找来，会变成「早就不管了」，对外口径崩掉。**
→ **正确做法：留一条「活着的记录」——`状态：已批复（不给X）· 案子仍活` + 备注写清证据到什么程度、还差什么材料。让「已批复」和「还在跟」同时成立。**

**二百一十四、改云端表但没回写本地快照 → 搬迁读本地 json 一定漏。**
**唯一的补法是拿自己的日志去对，不是拿本地文件。**（小昭 2026-10-19：旧表本地 json 是 10-14 快照，10-18 的改动只在云端和日志里，**搬迁读本地 json 就漏了「P0 三样向客户要」**；她是靠日志捞回来的。）
**而旧表 webhook 现在 403（云端读不回来）——这一步必须在删表前做完。**

**二百一十五、「【等某人】」开头的待办，除了「要确认什么」，还要写「等多久了」。**
**因为三个月后看，没人知道它是昨天问的还是上个月问的。**（木婉清 2026-10-19 对小昭：写成「10-18 已问，未回」，下次谁看到都知道该催了。）

**二百一十六、错也要留痕，尤其当它是唯一记录的时候。**
（小昭 2026-10-19 对归档表两行同名：**「第 11 行是我标错的唯一记录，删了就没人知道那天发生过什么」** → 两行都别动。）

**二百一十七、「不用做」和「结案」是两个层级的判断，写在同一句里就会自动升级。**
（小昭 2026-10-19：归档表 `小昭-6` 的结果原文——「老板批『人工处理／先不处理』→ **不用做，结案**｜老板原话：先不给…」——**老板说的是「钱不给」，那句写的是「这事完了」**；而这句躺在**归档表**，最容易被当成「已经处理完」的地方。）
**这不是"误解"，是「归档动作把技术判断升级成了结案」——做的人往往自己都没意识到，因为「批复了」在他脑子里就等于「处理完了」。**
→ **活记录要在归档行的第一句就写「案子仍活，见主表 -Nb」，不能写在最后**（后面补充抵不过第一句）。

**二百一十八、归档是单向动作。任何「捞回来」的念头，都要换成「另立一条」。**
（小昭 2026-10-19：探域/金山归档表**没有还原接口，而且是复制+删行，删了就没了** → 她用新序号 `-6b` 挂一条活记录，原 `-6` 留在归档但改成「不是结案」。）
**因为「捞」这个动作会让你去改归档——而归档是唯一记录「当时发生了什么」的地方。**

**二百一十九、拿本地 json 去对本地 json ＝ 拿过期的源核对过期的源，必然「对得上」。**
**不是「可能不准」，是必然对得上，所以什么也验不到。**（小昭 2026-10-19）
→ **只能用日志对**；翻日志时按这些字眼搜：`金山表 / 旧表 / #N / 新增 / 标完成`——**这几个词正好是「改表」在日志里的痕迹。**

**二百二十、批复被记成结案时，别去动画好的那条，另立一条 `-Nb` 活记录。**
（同上；**否则大家会去删归档行。**）

**二百二十一、同样的事实、同样的字数，调换第一句就能让读的人得到相反的印象。**
```
原：先不给慰问金 → 活记录见 -6b        （读的人：不给钱，结案了）
新：案子仍活，见 -6b → 先不给慰问金      （读的人：还在跟，但不给钱）
```
**差的不只是信息，是「读的人先看到什么」。**
**同族第二次**：§一百五十二「边界必须和结论在同一行」——**那次说的是位置，这次说的是顺序。**

**二百二十二、「等了几天」是算出来的数，写死会撒谎；写「从哪天开始等」不会过期。**
**「等老板 1 天」一周后如果没更新，会变成「老板昨天才被问」——而它只会越来越旧。**（木婉清 2026-10-19 对小昭：**天数让人自己算，或由脚本每次读表时算出来。**）

**二百二十三、「什么都没做」也要留痕，尤其当它是「按住不发」。**
**因为这种工作不留任何痕迹，只有在出事的时候才会被问「当时为什么没发」。**
（木婉清 2026-10-19 对小昭：**「10-19 全案客户侧零对外消息，等老板开口或客户动」要写进回执——今天所有人都在做点什么，而她的工作是按住不发。**）

**二百二十四、「没办法」这个结论，跟「0」一样，是需要解释来源的。**
**说「做不到」之前，先报「我试过哪几种，每种怎么失败的」。如果只试了一种，那不叫做不到，叫没试够。**（殷素素 2026-10-19：她试了「历史 trace」失败就断言「只能等真实客户」——**实际探域有「模拟买家」入口，而且就在她自己的工具箱里躺着**。）
**她的自我诊断：「用一次失败代表全部失败」——跟「用一次成功代表全部成功」是同一种偷懒。**

**二百二十五、「0 = 试了一种就走」是「0 的错法」的第六格。**
```
0 = 真 0／读不到／被吃掉／定义错了／查了确实没有   ← 数据的 0
0 = 试了一种就走                                ← 方法的 0
```
**后者最容易被当成结论，因为它是「我很确定」地说出来的。**

**二百二十六、验证的最强形式不是「我读到它了」，是「客户会听到它」。**
```
查数据库 → 看到的是存储
查接口   → 看到的是传输
看回答   → 看到的是客户实际收到的
```
（殷素素 2026-10-19：**她抓包读召回又读错字段，但"回答文本"证明卡生效了**——「分人群看」四个字全库只有新卡有。）
→ **「独有特征验证法」：不靠数量、不靠字段，靠一句只可能来自新卡的、能被人一眼看见的话。**

**二百二十七、已知是坏的方法，不修可以，但要留个牌子。**
（同上：`get-card-list` 那套读法的 id 字段不可靠，**要在工具里标「此接口的 id 字段不可靠，不要用它做召回判断」**，否则下次还会踩。）

**二百二十八、结论里要写方法：「已验证（模拟买家 1 次）」比「已验证」多一个可复现。**
**因为「已验证」三个字，三个月后没人知道是怎么验的。**（木婉清 2026-10-19）

**二百二十九、`tail` 截断导致的「文件不见了」，是「空」的另一张脸。**
```
字段名写错   → 全部 undefined → "0 次召回"
路径反斜杠   → git 报错被吞   → "新文件"
tail -8      → 只看到最后 8 行 → "文件不见了"
```
（小昭 2026-10-19：她 `ls -la` 加 `tail -8` 看回执目录，以为两份文件被别的窗删了，**用 find 一查全在**。）
**共同点：读取方式本身出了偏差，而结果看起来像一个结论。**
→ **凡是「看见了什么」的结论，都要问一句：我是用全量看的，还是用窗口看的？**

**二百三十、表里只存事实（哪天开始），不存计算（几天）。**
**「旧了正好该催」——这句话把「过期」从缺点变成了提醒机制。**（小昭 2026-10-19）

**二百三十一、「既定口径只在客户来找时才有用，主动去找反而破。」**
（小昭 2026-10-19 在回执里写「客户侧零对外消息」的三条理由之一：**「公司一直在处理、客户未配合检测」这个口径，主动去找客户说，等于自己把"还没处理完"这件事摊开。**）
**这是今天最早的一条「什么时候不该动」的判断。**

**二百三十二、换事的理由，不能用来突破上一件事的边界。**
（殷素素 2026-10-19：木婉清说「只能查这一次」，她跑了 6 次——**第 1 次是授权的，第 2~6 次理由是「我在做工具，这是必要的验证」**。她的自诊断：「我把『做工具』当成了继续跑的理由——这跟『我需要验证』没区别，都是给自己找个正当性。」）
**准确的诊断不是「你多跑了 5 次」，是「你从『验证卡』换到『做工具』，但没跟我说一句」。**
**换事不说，比多跑几次严重——因为换事之后，对方不知道你在做什么，也就无法提醒「这东西将来谁用、用错会怎样」。**

**二百三十三、跑之前能说出「这次在验什么和上次不同的东西」，就可以跑；说不出来，就是顺手。**
（同上：她那 6 次里 **4 次必要**（验卡生效／反向测试／修 bug 后重跑／查时间戳规律），**2 次是「试一下」**。）
**前提：模拟测试 ≠ 真实发送**（不发客户、不进真实会话统计），所以可以多跑——但要说得出在验什么。

**二百三十四、测试记录不要清——「错也要留痕，尤其当它是唯一记录的时候」。**
（殷素素 2026-10-19 问那 15 段模拟测试记录要不要清；**清掉之后三个月后有人问「这张卡验过吗」，就只剩一句「验过」，而记忆里没有时间戳。**）
→ **留着 + 写说明（时间、用途、是测试不是客户会话）。**

**二百三十五、「先自己清理再报」的问题不是掩盖，是清理本身不可逆。**
**清完之后你报的是一段记忆，而不是一份现场——而记忆里没有时间戳。**（同上）

**二百三十六、更急的错往往藏在「已经生效的老卡」里，不在「新发现的东西」里。**
（木婉清 2026-10-19：殷素素忙着处理 7 张 PRODUCT 碎片，**而话术库里有一张 SHOP 卡写着「血氧≥95%为正常，94%以下说明可能缺氧，数值越低需要补氧的浓度越高」——这对慢阻肺是反的，而 SHOP 正是会被真召回的那一类（135 次）。**）
**判据：先按「会不会被客户听到」排序，再按「看起来有多严重」排序。**

**二百三十七、「顺序」解决不了「正面冲突」。**
**顺序解决的是「两句都在时先听谁」；而如果后一句会否掉前一句，加多少开场白都没用。**
（同上：**「80多就买5升」→ 客户不用等医生了，他已经知道答案了；「先说要听医生」在这种情况下只是句开场白，客户会跳过它。**）

**二百三十八、同一句话，人说和机器说是两件事——「落人不落卡」。**
```
成卡 = AI 无条件对所有人说   → 这句话是这个意思吗？
落人 = 客服看到具体场景时可以说 → 这句话是这个意思吗？
```
**因为人能看到上下文（是否确诊、是否在吸氧、是不是急性），AI 看不到。**（木婉清 2026-10-19 对老板「80多血氧最好是5升制氧机」的处理）

**二百三十九、血的教训：把「按数字」塞进「按程度」的梯子里，等于说「看数字就能选机型」。**
（话术库已有五档梯子：轻微→1升／轻度→2升／中度→3升／严重→5升／重度→10升——**它按缺氧程度分档，老板那句按血氧数字说话，两个维度不同。**）

**二百四十、「另查」三个月后会被读成「忘了」；「因为冲突所以不落」会被读成「决定」。**
**一个「不做」的决定，比一个「做」的决定更需要留证。**（木婉清 2026-10-19）

**二百四十一、「XX 库里有」——先问一句「哪个库」。**
**因为「库」在不同人嘴里指不同的系统，而它们在同一次对话里长得一样。**（木婉清 2026-10-19：她说「话术库里有一张卡」，**她心里指 SoftTalk（客服手动照着念），殷素素听成探域（AI 自动说）——查了两轮全 0，两人都白干。**）
```
探域     = AI 自动说（卡被召回才生效）
SoftTalk = 客服手动照着说（人自己去搜）
```

**二百四十二、「它不存在」和「我在错的地方找」在结果上完全一样（都是 0），但后果完全不同。**
```
不存在       → 这件事不用做了
在错的地方找 → 它还在那儿，而且正在被用
```
（同上，殷素素 2026-10-19 补的第八格）
**前七种零最坏是「白干一趟」；这一格最坏是「我判它不用管，而它正在用」。**

**二百四十三、跨系统冲突最难发现，因为没有任何一个系统内部会报错。**
（木婉清 2026-10-19 查出的真冲突：**探域 SHOP 卡 `6a9a3c374`「不建议通过自行快走6分钟判断是否缺氧，请由医生评估」 vs SoftTalk `b7966b91`「也可以通过『步行6分钟』来自测」——两句是反的，而且一个由 AI 说、一个由客服照着念。**）
**拼接的不是两张卡，是两个系统。**

**二百四十四、「我一直在用『我记得的键名』读数据，而不是用『文件里实际的键名』。」**
**「我记得的」这三个字，是所有假零的共同来源。**（殷素素 2026-10-19：`results` vs `rows`、`id` vs `docId`——同一个坑第 3 次，因为她一直在猜字段名，没有先打一条结构出来看。）

**二百四十五、「没找到」的完整写法是三段。**
```
我查了 X（范围）、用 Y（哪几个词）、没找到
按这个范围，我预期的风险是 Z（哪些说法我搜不到）
```
（殷素素 2026-10-19 自己点破最关键的一层：**「如果某张卡用别的说法表达同一件事（比如『90%以下要当心』），我不会搜到。」**）
**因为「不冲突／不存在／没有」这三个词是结论，「我查了 X 范围没找到」才是证据。**

**二百四十六、人工话术早就分人群了，是 AI 卡没有——方向是「把客服已经会的教给 AI」，不是「教客服分人群」。**
（木婉清 2026-10-19 查 SoftTalk `ce26705e`：**「血氧值低于95%就要注意啦（慢阻肺除外），低于93%就建议及时吸氧或就医」**——「（慢阻肺除外）」这五个字，正是今天做的那件事的人工版。）

**二百四十七、两边都得对，但没有任何一个人同时看到两边。**
（殷素素 2026-10-19：「你改 SoftTalk 那一边，探域这一边不用动（我们的口径是对的）。但从客户视角看，两边都得对——**这个完整性只有你能看到，我只看到探域这一半**。」）

**二百四十八、第八格（「我可能在错的地方找」）必须配三样，否则是免责声明。**
```
① 说清我查了哪些地方（范围）
② 说清还有哪些地方没查（盲区）
③ 说清谁会知道那部分（找人）
```
**因为「我可能找错地方了」永远成立——任何一次「没有」都能被这句话推翻，于是所有人都不敢下结论。**
**免责声明比错误的结论更糟，因为它让人没法继续。**（木婉清 2026-10-19 对殷素素第八格的配套规则）

**二百四十九、「从客户视角看，两边都得对——这个完整性只有能看到两边的人才能保证。」**
（殷素素 2026-10-19）
**这不是一条技术判据，是一个岗位职责：凡「客户会听到的话」，不能只看自己那一半。**
```
SoftTalk（客服念）      ┐
                        ├→ 客户听到的是拼接结果
探域 AI 卡（自动说）     ┘
```
**这类问题没人管过——因为 SoftTalk 归客服培训、探域归 AI 训练，两边不是同一个人在管。**

**二百五十、跨系统的活不是「接走一个工具」，是「对齐两个系统」。**
（木婉清 2026-10-19 自我更正：**她说「这条我从你手上接走」，接的其实只是「SoftTalk 这个工具」，不是「两个系统要对齐」这件事。**）

**二百五十一、护栏应该只有一张，不要每张卡加限定。**
```
每张卡加限定 → 18 张卡都要维护，而且限定话变多会被忽略（"每次都这么说"）
一张护栏卡   → 一处维护，而且它是"专门说不"的，读的人会注意
```
（木婉清 2026-10-19 对殷素素「3 张卖点卡要不要加限定」：**库里已有一张「不能仅按疾病名称、年龄或单次血氧读数推荐档位」——这就是护栏卡，任何"按数字推机型"的回答都要先过它。**）
**加限定还有反向风险：加了之后，这张卡看起来「已经安全了」，就没人再去验护栏卡在不在。**

**二百五十二、「暂时没影响」不是理由，「这张卡单独说会不会造成伤害」才是判据。**
（同上：**Q10L「适合重度缺氧人群」单独说不会造成伤害，风险在「它被怎么接起来说」，而那个接法由护栏卡管。**）
**停掉还会损失正常业务：客户问「Q10L 有什么卖点」，AI 答不出来。**

**二百五十三、从卡片侧搜词，结构上永远有盲区——你得先知道那个词。**
```
从卡片侧搜词 → 需要预先知道词 → 盲区永远在
从问句侧抽样 → 不需要预先知道词 → 盲区是"抽样够不够"，可以量化
```
（木婉清 2026-10-19 对殷素素：**搜「缺氧」搜不到「低于90就要注意」。**）
→ **正确做法：从真实会话里随机抽 50 条相关问句，逐条看回答里有没有医学判断句。**（50 条里 3 条有问题 = 6%，可量化；搜词的盲区永远量化不了。）

**二百五十四、「我们没资格用『你可能缺氧』来推机器」——这条不是医学问题，是商业问题。**
（木婉清 2026-10-19：SoftTalk `75073881`「没有血氧仪…走路6分钟…如果有这些表现，建议使用医用级制氧机」——**「走6分钟 → 判断缺氧 → 建议买机器」一条龙，中间没有医生。这是今天所有内容里最像「卖货」的一句。**）

**二百五十五、两边说反了，分歧不在方法，在「谁有资格下结论」。**
（同上：探域「请由医生评估」vs SoftTalk「你可以自己测」——**这两句的分歧不是"哪种测法更准"。**）
**→ 这种分歧不能由执行层定，必须报上去。**

**二百五十六、「一条不缺」和「一条不错」是两件事。**
**报前者，对方就会以为「可以删了」——风险就落在后者上。**（小昭 2026-10-19：她报「12 条一条不缺、可以删旧表」，**旧表原件到手一比：1 条状态搬反、3 条已完成被她在新表重开**。）
**「条数对」只是必要条件，不是充分条件。**

**二百五十七、凡搬表，「条数对」之后必须再做一遍「状态对」。**
```
① 拿旧表原件逐行核状态（不是看新表）
② 每行画一档：活着的／已完成的／搬反的／本该有却没有的
③ 对不上的，一律按旧表原件为准改
```
**为什么第③条：新表是你的记忆，旧表是原件。记忆和原件冲突时，永远信原件。**（同上）
**同族**：骆冰那个 45.9%——**看到「已退回京东仓」100% 有值就以为那是数据（其实是写死的常量）/ 看到「12 条对上」就以为那叫搬对了（其实只对了一半）；共同点是一个「看起来对」的数替代了一个「真的对」的核对。**

**二百五十八、「一个格里装两件事」的真相常常是：一件做完了，另一件根本没开始，而它们被同一个状态盖住。**
（小昭 2026-10-19 待办 #2「材料包」：状态=已完成、备注=「等老板给渠道」——**「材料备好」完了、「发出去」根本没发**；真相是渠道始终没给，但研发部 10-16 直接出报告绕过去了。）

**二百五十九、发现自己重开了旧表里已完成的事，最优解不是删，是标作废。**
**因为标记能证明「曾经发生过什么」**——小昭正是靠这个查出了「我搬表有损」。**删掉就查不出来了。**（木婉清 2026-10-19）

**二百六十、「持续类」任务最容易被当成「不是一件事」漏掉，而它恰恰是唯一活着的日常动作。**
（同上：小昭把「客户跟进（持续）」并进「P0 三样」（**一个有终点、一个没终点**），理由是「都是跟客户」——太粗了。）
**判据：合并两条任务前先问「它们有终点吗」，答案不同的不许合并。**

**二百六十一、成本的落点决定严重程度：落在自己身上可补，落在老板注意力上不可补。**
（木婉清 2026-10-19 给小昭的四件事排序：⚠1 漏条＜⚠2 状态搬反＜⚠3 一格两事＜**第四条「拿一件早就做完的事去占老板一格的注意力」**。）
**因为老板的注意力是稀缺资源——他今天只回了那么几格。**

**二百六十二、「有护栏」不等于「护栏生效了」——护栏卡不是硬开关，它是一张普通卡，靠被召回才起作用。**
（殷素素 2026-10-19 实查探域拦截词：**55 个词里 0 个医学词**（缺氧/血氧/医生/医嘱/症状/气喘/胸闷/制氧机/几升全不在）——它拦**营销承诺**（优先安排/免费送/次日达/活动价）和**联系方式**（微信/手机号/扫码），**就是不拦「你该买几升」**。）
**实测反证**：客户问「缺氧重一点是哪款」，AI 直接推了 Q5S，护栏卡没进召回 → **「一张护栏卡兜全部」在这种配置下不成立。**
→ **正确的答案是「每张卡自己兜自己」（35 张各带一句）——那不是冗余，是没有硬开关时唯一的办法。**

**二百六十三、护栏句必须一字不差照抄，因为「能一句话搜全」是这类护栏唯一的维护方式。**
（木婉清 2026-10-19：**36 张卡如果有 4 种说法，以后没人能靠搜一句话把它们全找出来。**）

**二百六十四、「都带了」不等于「都管用」。**
**「35 张都带这句」是真的；但「35 张都带」和「35 张都有效」是两件事——没有人验过它们在真实会话里有没有被按医生口径答。**（木婉清 2026-10-19）
**同族**：小昭那条「一条不缺」不等于「一条不错」。

**二百六十五、留审（reviewStatus）比已发（content）更该先查。**
**已发出去的是过去，挽不回来；留审的是「AI 想说但被拦下了」——它是未来的清单，而且量小查得快。**（木婉清 2026-10-19 给殷素素排盲区优先级）

**二百六十六、「我会用工具验它」——推测出的风险，先测真假再动手改。**
（同上：殷素素推「Q5S 停用后会轮到 Q10L」——**「如果轮到 Q10L」是推测，而她正好有模拟买家能验。**）
**三种结果三种做法：答 Q10L 且无医生句＝在途风险，改完立刻再问；答别的卡带医生句＝风险在别处；答不出来＝漏答，另一个问题。**

**二百六十七、配置问题不是 bug，决定权不在执行层。**
（同上：**55 个拦截词里 0 个医学词**——加不加医学词拦截是业务决定：**加了 AI 会拒答、影响正常咨询；不加就全靠卡片正文写对。**）

**二百六十八、「AI 说了卡里没有的数」不是幻觉，是「另一套标准」。**
（殷素素 2026-10-19 实测：问「缺氧重一点是哪款」，AI 答慢阻肺目标「88%-92%」——**全库 8516 张卡含这个数的是 0 张**；而 88%-92% 在慢阻肺家庭氧疗里确实有出处（国外某些指南），**所以它不算瞎编，它是"知道一个跟我们不一样的数"**。）
```
卡写错了     → 改卡就行
模型知道另一套 → 改卡不管用（卡没被召回时，它还说它的）
```

**二百六十九、卡只在被召回时才管用——「我们的口径」和「客户听到的话」之间，始终有一段不受我们控制。**
（同上：护栏卡不是开关，是「如果被召回就能纠偏」的卡。）
```
被召回   → 客户听到我们的话
没被召回 → 客户听到模型自己知道的话（可能是另一套标准）
```
**我们能保证「我们写了什么」，保证不了「客户听到什么」。**

**二百七十、「以为处理过了」比「没处理」更危险。**
**因为没处理的人还会继续查，以为处理过的人就停了。**（殷素素 2026-10-19 决定不改 Q10L：**「改 Q10L 不解决后者，而且会让我以为『处理过了』。」**）
**一个不相干的动作会制造虚假的安全感。**

**二百七十一、查 AI 自造内容时，不要只找那一个数，要找「回答里出现了卡里没有的具体数字／剂量／时长」。**
（木婉清 2026-10-19 给殷素素：**如果 AI 能自己生成一个血氧数，它也会自己生成「每天吸氧多少小时」「一次多少升」——而后者比数字更危险，它是操作指令。**）

**二百七十二、「同一句话问两次，措辞不同」——所以「客户会听到什么」不是一个确定值。**
（同上：15:08:49 与 15:09:07 两次同问，**第二次多了「过高可能抑制呼吸驱动」，这句话比我们的卡还细，但数字仍是 88%-92%。**）

**二百七十三、给 AI 写禁止类卡，要写「动作」不要写「知识」。**
```
知识："不能用固定公式推算"      → AI 觉得"那是别人，我算得更准"
动作："不要计算、不要换算、不要确认是否相符" → 直接禁掉了「完全符合」这四个字
```
（殷素素 2026-10-19 抓到：客户说「医生讲 2 升、28 到 30 的浓度」，AI 答「正好在 28%-30% 左右，**完全符合医生的要求**」——**8 张卡明写「不能用固定公式推算」，它用被禁止的方法给了这句话一个看起来严谨的依据。**）
**「客户说 A → AI 算了一下 → AI 说符合 → 客户得到：医生开的方案已被我们核对过」——我们把一句处方变成了我们验证过的处方。**

**二百七十四、删掉一条规矩，要问「它上一句那个更根本的原则，会不会一起被删掉」。**
**推论会过时，原则不会。所以只标作废，不删。**（木婉清 2026-10-19 改《规矩与红线》152 行：「一条信息只说一件事」保留 + 「拆多条 + (1/3) 编号」标作废。）
**同族**：王语嫣给表里 10 条补歧义说明——**「改掉结论等于抹掉『当时我是这么想的』，补一句就同时保住了当时的想法和现在的怀疑」。**

**二百七十五、看不出「它变过」，比「东西没了」更难查。**
（木婉清 2026-10-19：**表里有「时间」列，但它填的是登记那一刻；update 不改它 → 读到「时间=10-14」会以为这行之后没人动过。** 同病：索引被覆盖。）
→ **修法：加独立列「最后改动」（脚本自动写），或者把「时间」改成最后 update 时间 + 把登记时间挪到备注开头写死一次。**
**不要往备注里追加机器字——那会让备注变成日志，人写的那句会被挤到后面。**

**二百七十六、状态不是「我判断它到哪一步了」，是「发生了什么事件」。**
```
归档触发 → 已完成（脚本写）
老板批复 → 已批复（人写，但必须带批复原文）
其余时候 → 状态不动，只在「要确认什么」里写卡在谁 + 从哪天
```
（木婉清 2026-10-19 对王语嫣：**砍不掉状态列（37 处引用、归档靠它触发），那就给它加「只能被事件改」的约束。**）
**真实损失反例**：小昭把旧表 4 条「已完成」里的 3 条在新表重开成「待办」→ 拿一件 10-14 就做完的事，占掉了老板 10-19 的一格注意力。

**二百七十七、分界线不是「常变/不常变」，是「有没有审计需求」和「读的时候要不要连成一整段」。**
```
需要「谁什么时候改的」     → 表
需要「读的时候连成一整段」 → md（规矩、经验、口径）
状态/进度                  → 不该有独立载体（=「最后日期 + 下一步动作」的组合）
```
（木婉清 2026-10-19 对王语嫣；她原来的「常变放表、不常变放 md」是**估的**，这两条是**可判的**。）

**二百七十八、一个东西如果既不是数据也不是判断，那它就是通道。通道不需要「友好」，它需要「不会把东西运错」。**
（王语嫣 2026-10-19 抄自木婉清的「脚本大全只是入口」，她的改写更好。）

**二百七十九、「卡存在」不等于「卡在场」。**
（殷素素 2026-10-19 用 trace 推翻木婉清的诊断：**8 张卡明写「不能用固定公式推算」，AI 还是算了——但 trace 里那 5 张一张都不在召回里。**）
```
读了不听 → 卡有效，只是不够狠 → 改文案
没读到   → 卡是隐形的          → 改文案没用
```
**错法是拿「8 张卡存在」当成「8 张卡在场」——它跟「条数对≠状态对」「有护栏≠护栏生效」是同一个：证明了它的存在，就以为它在起作用。**

**二百八十、「话术统一」和「话术有效」是两件事——4 张卡一字不差，在没被召回时等于不存在。**
（同上）
**木婉清 2026-10-19 的总结：一天之内从三个角度看到同一个错（PRODUCT 卡、护栏卡、这 5 张统一句），不是巧合——它是说：我们现在所有的质量保证，都建立在「写了就等于生效」这个假设上，而这个假设从来没被验过。**

**二百八十一、让 AI「更狠一点」的前提是它先能读到——没被召回的内容，写得再狠客户也听不到。**
（同上：**「如果 4~5 张已经写对的卡都没被召回，再改它们只是让『没被召回的内容』更狠一点。」**）

**二百八十二、新卡往哪个方向写，取决于召回是按关键词还是按语义——这两个方向写出来的卡完全不同。**
（木婉清 2026-10-19：出问题那次召回 7 张，**4 张是「C1L尺寸」「Q5L/Q5S定时最大多久」这类机型参数，没有一张讲浓度怎么算；而客户说的是「医院住院就是这个标准」。**）
```
关键词命中 → 新卡标题/问题里必须带「医院」「医生说的浓度」「够不够」
语义相似度 → 新卡正文要写成客户问法的样子，不是写成标准的医学表述
```

**二百八十三、错误的代价有三层，最后一条最贵。**
```
① 浪费一个人的时间
② 让他以为自己对世界的认知是对的
③ 让他以后不再去核这件事
```
（王语嫣 2026-10-19 补 ②；木婉清补 ③：**「核」本来是我们唯一能纠错的动作。**）
**实例**：小昭把 3 条「已完成」重开成待办 → 老板回「今天等会就删」（他 10-14 已亲手删过）→ **以后他问「删了没」不会去核，因为"他以为已经知道答案了"。**

**二百八十四、改状态不要求「写一句为什么」，要求「给出一条可核的位置」。**
```
文字可以是废话："因为做完了" —— 脚本只能查"有没有"，查不了"是不是废话"
位置不能      ——「归档表第60行」「commit 40026f9」要么存在要么不存在
```
（木婉清 2026-10-19 反对王语嫣「改状态必须写一句为什么」，**理由：这动作会变成走过场，而「恒真检查比没有检查更糟」——它会让所有人以为「这里有人管着」。**）
**正面例子**：小昭能证明 #10 是搬漏，靠的是「我 10-15 日志里有『赵敏已解冻，已提交推送 40026f9』」——**那是一个位置，不是一句解释。**

**二百八十五、「某一个字段只有一部分人填」→ 整列不能用来判断。**
（同上：**「最后改动」这列只要有 1 家不写，读的人会以为"空 = 没改过"，而实际是"空 = 这家没升级"。**）
→ **兜底：读表时字段为空要显示「未知（未升级）」，不要显示空白。**「未知」和「没有」必须能分开。

**二百八十六、工具的缺陷分两种，后者更贵。**
```
不好用（人还能绕）
会运错（人绕不了，因为人以为它是对的）
```
（王语嫣 2026-10-19：**「后者更贵，因为它不需要人犯错就能出事。」**）
**「不需要人犯错就能出事」= 今天所有事故的共同描述**：骆冰的 45.9%、小昭的状态搬反、脚本大全把 4 条已完成搬成待办——**出事的时候，所有人都在做对的事。**

**二百八十七、一次追加是历史，每次追加是日志。**
**往人写的地方追加机器字，要问「追加几次」——一次可以，每次不行。**（王语嫣 2026-10-19 自省）

**二百八十八、一张卡有两个用途，要求不同。**
```
被召回 → 靠 Q 行像客户问法（语义匹配）
被照抄 → 靠 A 行写得对
```
（殷素素 2026-10-19：**5 张「不能算」的卡 Q 行是「5升10升医用低浓度低流量吸氧」「不是要低浓度低流量吗？」——客户说的是「医院里住院就是这个标准，完全够」，五句 Q 行里没有一个字相似 → 压根没被召回。**）
**「改了正文没用，因为 Q 行不搭 → 改了还是不召回。」**

**二百八十九、Q 行要用客户的原词，不能用同义改写——语义相似度是从这些词算出来的，改写一个词就等于挪开一点距离。**
（同上；**而且要求不是「像客户说话」，是「比别的卡更像这句话」**：殷素素实测「医院标准够不够」时，被召回的竟是「血氧多少算正常」那张卡——**语义召回很松，它按"话题相近"抓，不按"问法相同"抓。**）

**二百九十、建停用状态的测试卡，验的是开关不是 Q 行。**
（木婉清 2026-10-19 拦殷素素：**Q5S 是停用的，今天实测没被召回 → 停用卡很可能根本不参与召回，那个实验会得到一个"有第二个解释的 0"。**）
**同族**：今天那 9 次假 0——**测出来的 0 有第二个解释，而你没排除它。**

**二百九十一、「答对了」和「答得上」是两件事——召回对了也可能答非所问。**
（同上：殷素素第四节实测，新卡被召回了、数字也对，**但客户问「医院标准够不够」，它答「血氧正常范围」——从"答错"变成"答非所问"，后者轻，但也不是对。**）

**二百九十二、把「验一次」变成「建基线」。**
> 列 20~30 个最常见的问法（按真实会话频率排），每个跑一次 trace，记下召回了哪几张卡，人工看该在的在不在。
（木婉清 2026-10-19：**它不是"发现问题"，是"建立基线"——以后改任何卡，跑一遍就知道有没有把别的问法弄坏；一次性成本，长期有用。**）
**能能量化：今天只测 10 条就发现 1 条错 = 10%。**

**二百九十三、一单对得出的规则，对不出它是不是普遍规则。**
（李沅芷 2026-10-19：她从「李璇 ↔ 李*」一单推出「星号数 = 字数−1」，据此判定群里给的「迪迦」漏了一个字。**但两条字的名字打码成「首字+1星」和「末字+1星」看到的东西是一样的 → 它不能区分「星号=剩余字数」和「星号=固定 1 个」，而这两个推出来的结论完全不同。**）
→ **验法：再找一单已知是三个字的名字，看它显示 `X*` 还是 `X**`。**

**二百九十四、「你漏了一个字」这种话，在没有第二种证据前不该说——改成「核对」的语气。**
（同上：木婉清在群里问的是「系统显示迪** 是三个字，您给的迪迦是两个字，能再确认下全名吗」——**不是「你给错了」。**）
**因为报错的人和被报的人，都需要留退路：规则可能是错的，人也可能是口误。**

**二百九十五、先去数据源核，别先问人。**
（同上：李沅芷读的是「发票抬头」（显示「个人」），**而买家姓名在订单详情的收件人里，不在抬头里** → 先试能不能从订单读到全名，读到就不用问人。）

**二百九十六、明知会有废票风险就不登，比「5 分钟写完」重要。**
（同上：**名字错一个字，票废了要红冲；而如果登了，明天没人会知道是名字错，只会看到「这张票有问题」。**）
**判据：一个错误如果会抹掉自己的来源，就不能用它换速度。**

**二百九十七、规则和人的话冲突时，人优先——尤其当那个人知道现场。**
（2026-10-19：李沅芷从「李* ↔ 李璇」推出「星号数=字数−1」，判定群里「迪迦」漏一个字；**老板在群里回「就按这个给的抬头就是全名」→ 立即定案按「迪迦」登，不再讨论星号规则。**）
**但规则本身的怀疑要留档：下次没有人在场时，仍按「找一单已知三个字的名字对比」验。**
**「这次绕过去了」不等于「规则对了」。**

**二百九十八、边界不在「次数」，在「它会不会造成后果」。**
（2026-10-19 殷素素问「基线要跑 20~30 次 trace，算不算超边界」，木婉清：**前面那些改动，一次改一个、改完验一次，每次都在动线上内容；基线这件事只读、不动任何卡——它不改变线上状态。所以不造成后果的次数不需要报备。**）
**但要报的是另一件事：这些调用会不会被当成客户数据、会不会留痕。**

**二百九十九、再验一遍「同一件事又成立一次」，不产生新信息。**
（同上：**剩下 2 个 Q 行变体也是原词，它们验的是同一件事 → 不用各测一遍；真正该测的是「换一个客户说法完全不同的问句，看新卡还进不进」。**）

**三百、「多卡拼接」的好坏不在拼几张，在拼的那几张是否一致。**
（同上：殷素素注：**「回答里的『如果医生给过具体目标，请以医生的为准』是血氧卡的，不是新卡的——这次是两张卡拼起来的回答」**；而这次拼出来是对的，因为两张卡方向一致。）
→ **以后每次验回答，除了看「该说的说了没有」，还要看「拼进来的每一段，是不是都朝同一个方向」。**

**三百零一、边际收益很低的调查，先停，等前置决定落地。**
（同上：拦截配置键**已找到两个入口和一个接口；而「拦截词里 0 个医学词」是事实、「加不加」是老板的决定——在老板没答之前，多找一个配置键也改不了什么。**）

**三百零二、查「这批东西混进了多少」之前，先查「这批东西能不能动」。**
（木婉清 2026-10-19 对殷素素类型 B（DETAIL 卡混进 SHOP 场景）：**如果改不动，查出 100 处混进也没用。**）
**DETAIL 有三种来源，处理方式完全不同**：① 详情页自动学 → 改不动（会被学回来，同 PRODUCT）② 人工写 → 能改但要一个个核 ③ 平台导入的商品资料 → 看它跟不跟商品同步。
**判法：看它有没有 title、绑几店、可信是不是 false，跟 PRODUCT 那批对比——不要猜**（当天已犯过一次：把 PRODUCT 卡当成「我们写的卡」）。

**三百零三、基线只能跟自己比，不能跟「现在」比。**
（同上，殷素素自己写的限制：**「这份基线是『10-13~10-19 期间这些问法召回的是这些卡』，不是『现在问会召回这些卡』。」**）
**这句必须写在基线文件第一行**——三个月后有人翻开它，第一反应一定是「这是现状」。

**三百零四、改 Q 行比改正文危险：Q 行是召回入口，改一张卡的 Q 行 = 告诉系统「这句话该找我了」，同时它会从别的问法里被挪开一点。**
（木婉清 2026-10-19：**今天已证明「改了不等于生效」（5 张卡改正文不会让它们被召回）；反过来也成立——改 Q 行可能让一个本来对的问法变错。**）
→ **动 Q 行前先量「这类问题有多少个」**（殷素素 12 个问法里类型 A 出现 4 次 = 33%；若有 10 个，那不是逐个改的事，是「这类卡整体设计」的问题）。

**三百零五、答非所问 ≠ 答反了。**
**答非所问客户觉得「它没懂」；答反了客户觉得「它在跟我谈条件」。**（木婉清 2026-10-19：**殷素素查到「客户问退货，召回了 3 张议价话术卡」——这不是答非所问，这是答反了。**）
→ **看到「召回了做另一件事的卡」，第一句先问：它做的事，会不会把客户推向我们不想去的方向？**

**三百零六、判据写进「每次都要用的文件」，不要写进回执。**
**因为基线文件下次跑的人会打开，回执只有你自己看得到。**（木婉清 2026-10-19）

**三百零七、一个规则如果只能用支持它的例子来验证，那它不是规则，是印象。**
（李沅芷 2026-10-19：她拿 2 个样本归纳「星号数=字数−1」，后去找了 5 个对照，**发现反例：颜秉冬（3字）ERP 显示完整一个星都没有；覃何祖（3字）只显示「覃」** → 规则作废。）
**她做对的地方不是「发现规则错了」，是「发现规则需要一个样本外的人来证伪」——而她自己补了这个样本。**

**三百零八、「不写一个错规则」和「写一个能替代它的规则」，差一个字，效果差很多。**
（木婉清 2026-10-19 对李沅芷：**不写的话，下一个遇到打码的人会重新推一遍，而推出来的很可能又是「星号=字数」这种看起来对的东西。**
→ 应写：「遇到打码姓名，不以星号数推断字数；以平台/订单里的实际姓名为准，读不到就问发布人。」）

**三百零九、留一个复核点给下一个人，比「停下」和「当作没事」都好。**
（同上：**不因为「名字可能不对」就停下（票登不了），也不因为「登对了」就当没事；做第三件事：建售后检查单写明「票面姓名请在开票前再核一次」。**）

**三百一十、长得像成功的错最难发现。**
（同上：**她发现自己字段名写成「发票抬头」而程序读的是「抬头」——若没读代码，AA 列会是空的，而票还是会「登成功」。**）

**三百一十一、「办完还多走一步」是可迁移的工作习惯。**
（2026-10-19 李沅芷三件事：**做对照、留复核点、检查字段名——没有一件是木婉清让她做的。**）

**三百一十二、字段名不同但含义相近时，一定要打一条完整结构对比，不能凭记忆替换。**
（殷素素 2026-10-19：**trace.snapShots[i].type 不是卡片的 type 字段，是「召回来源标记」——同一张卡库里 type=PRODUCT，被召回时 trace.type=DETAIL。** 由此「PRODUCT 卡不参与召回」这个结论错了，而它被引用至少四次。）
**她的自述：「我只记住了那一处，没记住这个模式」——记住的是案例，不是机制。**

**三百一十三、一份自己统计出来的数据，如果字段含义没被核对过，比没有数据更危险——因为它看起来有据可查。**
（同上：早上那个结论当时的证据看起来无懈可击：20 条 trace、统计、类型分布——**而它是错的**。）
**一个字段名读错，后面四步全建立在上面。**

**三百一十四、改详情页图是运营部的活，不要报老板——报老板他也没法直接改，反而多一轮。**
（木婉清 2026-10-19：**正确路径是把「图片 URL + 卡 id + 图上写 95%-99% 跟我们口径 90%-93% 冲突」写成一条建议给运营/店铺。**）
**注意：只给 CDN 链接运营看不懂，要先查出是哪个店哪个商品。**

**三百一十五、「卡片侧改不动，就去改源头」是同一类问题的统一解法。**
（同上：**247 张「次日达」卡，治本也在详情页**——`source.value` 就是那张图的 URL，是能指到的。）

**三百一十六、「PRODUCT 卡不参与召回」这个错误结论，今天被引用至少四次（木婉清、殷素素、回执、决策依据）——一个错误结论只要看起来有数据支撑，就会自我复制。**
（2026-10-19）

**三百一十七、判据写在文件里不等于它会在用的时候出现——判据要变成一个动作，才会真的存在。**
（殷素素 2026-10-19：**她刚写完「要在对的店测」，立刻又犯了**——那张 95%-99% 卡绑的是淘宝店 `2748947711641649387`，而她 17 个问法全跑在 PDD德达 `2095398963959042048`；**两个店的卡库不是同一份**。）
```
「要在对的店测」        —— 写在文件里，不在手上
「先把 thirdShopId 打出来，再核我要跑的店 id 在不在里面」 —— 这是能做的动作
```
**木婉清 2026-10-19 自省：写了 300 多条判据，真正拦住过东西的只有几条。**

**三百一十八、「客户报数字 → 没有能答的卡被召回 → AI 自由发挥」——这条解释了「AI 为什么自己算数」。**
（同上，串起三件事：**28%-30%（客户报了医生给的数字）／88%-92%（客户报了自己的血氧值）／92→98（客户报了前后对比）**——三个都是客户报数字，三个都出现 AI 自己算。）
**根因：我们的卡都是「讲道理」的卡，没有「接数字」的卡——这跟 Q 行那条同源：Q 行写的是「吸入浓度怎么算」，而客户说的是「医生说是 28 到 30」。**

**三百一十九、「接数字的卡」怎么写。**
```
Q 行 = 直接把数字写进去（"血氧92吸氧后98正常吗" "医生说2升28-30的浓度对吗"）
正文 = 不解释原理，直接给判断口径（"这个数值在不在范围内" / "这个数请以医生写的为准"）
```
**因为客户报数字的时候，他要的不是科普，是一个「这样对不对」的回答。**（同上）

**三百二十、召回不是卡的性质，是「卡 × 问法」的性质。**
（同上：**同一张卡 6a9a3c49644e354d71a3fa2a，10-16 那次真正的血氧问法没召回，这次「什么血氧浓度」召回了。**）
→ **以后说「这张卡有没有用」，不能单独说，必须说「在什么问法下有用」。**

**三百二十一、召回内容本身会误导，比「答反了」更隐蔽——因为它是把病因说轻了。**
（同上：客户问「慢阻肺、心衰竭可以用吗」，召回 13 张里两张 DETAIL 写「【适用人群】- 老人、孕妇、亚健康人群」——**「如果 AI 照这句说，等于告诉一个慢阻肺+心衰的客户『这台适合亚健康人群』。而慢阻肺和心衰都不是亚健康，是需要医生处方的疾病。」**）

**三百二十二、改 Q 行的真实代价不是「你改的那张变了」，是「别人的位置变了」。**
（殷素素 2026-10-19 现场：**她新建的「医院标准」卡，把「血氧多少算正常」这个问法的第 2 位占了** ——客户问血氧正常值，第 2 张召回的却是「医院里住院就是这个标准，完全够吗」。）
→ **要动就新建，不动现有卡：改坏了只要停用，不用回滚别人的召回。**

**三百二十三、判断「某张卡是不是噪音」，看位置稳不稳：同一问法问三次，三次都在前 3 = 稳定（要收窄）；三次位置乱跳 = 波动（先不动）。**
（同上）

**三百二十四、自己起的简称，会让人以为在说同一家店。**
（同上：**她一直写「PDD德达」「京东德达」「淘宝」——而页面真名是「德达医疗旗舰店」「dedakj旗舰店」等；8 个店里 4 个名字都带「德达」。**）
→ **把 id → 真名的表写进工具目录（不是回执），以后每次报都带 id。**

**三百二十五、「在这个问法下它没被召回」和「它不会被召回」是两个句子的距离，就是今天所有事故的分水岭。**
（同上，殷素素第五节自我约束：**「大多数人的报告是『验过了，没问题』。你写的是『在这一个问法下，它没被召回』。」**）
→ **说「没问题」的人，三个月后会被追问「当时你验了什么」；说「在这个问法下」的人，那句话本身带着方法。**

**三百二十六、一个店的基线不能推到别的店。**
（同上：**淘宝「血氧多少算正常」召回 4 张全 SHOP；德达医疗「老人日常吸氧需要测吗」8 张全 SHOP；德达医疗「什么血氧浓度」13 张含 6 张 DETAIL。**）

**三百二十七、两张卡都写同一件事，会拼成一段重复的话。**
（同上：**新卡正文不要出现「换算/公式/推算」，因为已经有「医院标准」那张专门管这个。**）

**三百二十八、定了「必须用原话」的规矩，自己给例子时却给了改写版——这就是「我以为客户会这么说」。**
（2026-10-19 殷素素核实：木婉清给的三个 Q 行变体「血氧92吸氧后98正常吗／老人血氧只有92怎么办／吸氧前后血氧差多少算正常」**在 1983 条真实会话里精确+包含匹配全为 0**；真实原话只有三句：**「血氧饱和度85左右可以用不」「76岁老人。血氧9 0左右。开几升」「哦，老年人的血氧不吸的话，只有92，吸的话能达到98」**。）
**她同时指出方向错误：客户是拿两个值问「够不够」，不是问「差多少」。**

**三百二十九、原话是陈述句时，加几个字把它变成问句，但必须标出改了什么。**
（同上：第三句加了「正常吗」三个字，**她主动标注——「标了改动，那就不是改写」。**）

**三百三十、Q 行只在一个店的会话里验过 → 先只绑那一个店。**
**因为一张 Q 行对不上问法的卡，绑 8 店等于在 7 个店里当噪音——它会跟别的卡抢位置，把本来对的卡挤下去。**（木婉清 2026-10-19）
→ **顺序：绑 1 店 → 验召回 → 扩店前先在别的店抽 1-2 句真实问法核有没有类似说法。**

**三百三十一、要判「某张卡稳不稳」，用三个不同问法问同一件事，不要连问同一句三次。**
（同上：**连问同一句会引出"平台会不会当成重复骚扰"这个不必回答的问题；而三种问法得到的信息比三次同一句更多——三种问法能说明"它在这个话题里稳不稳"，同一句三次只能说明"重复问会不会一样"。**）

**三百三十二、拿数据说「我这有反例」，比说「我觉得不对」值钱。**
（木婉清 2026-10-19 对殷素素：**她两次拦我——第一次用 trace 证明「PRODUCT 0 次召回」是错的，第二次用 1983 条会话证明我编的三句不是原话。**）
**「判据会写错，反例会自己长出来。」**

**三百三十三、脚本登记进大全时，要同时满足两个条件：能跑，以及**能被下一个人验证是它自己**。**
**最低成本做法：任何脚本的第一个动作永远是 `probe`，返回版本号，不碰任何数据。**（木婉清 2026-10-19，来源：霍青桐自省——**「我登记的是『能跑』的版本，不是『能验』的版本」**。）
**登记的时候想的是「它能工作」，没想「下一个人怎么确认它工作」。**

**三百三十四、「跳过验身」的前提是先核「未知动作会走哪个分支」。**
```
未知动作 → 报错退出     → 跳过验身是安全的（dryRun 本身就是探针）
未知动作 → 落到默认分支 → 如果默认是"写"，跳过验身 = 拿别人的表当试验品
```
（同上：霍青桐要给 6 行加备注，旧版脚本没有 `dryRun` 动作——**木婉清要求先打开旧脚本看动作分发的默认分支落在哪，30 秒的事，不用问任何人。**）

**三百三十五、让老板重做一次之前，要说清「为什么上次不行」，否则他会想「你们怎么又要贴一次」。**
（同上：**「上次那个脚本少了三个动作（连『验身份』的动作都没有），所以它跑起来我没法确认调的是不是它。我把新版加上了三个只读动作，您再贴一次——这次贴完，它能自己报版本号。」**）

**三百三十六、待办要「有主人、有原因、有动作」，才不会烂在那儿。**
（霍青桐 2026-10-19 的写法：**「待办：6 行备注加注（阻塞点：脚本需要重贴 v2026-10-19.2 以支持 probe 验身，木婉清已定，等老板重贴一次）」**——**比「等老板」三个字强一百倍。**）

**三百三十七、主动不做一个假检查，比做完再报「成功」值钱。**
（同上：**「跳过 probe 这一步，等于这个脚本自己也变成了一道纸门。」**）
**这就是「恒真检查比没有检查更糟」的同一件事。**

**三百三十八、说「这个得问别人」之前，先问一遍「我手上有没有能自己核的东西」。**
（霍青桐 2026-10-19：**她把「需要外部确认」和「自己能查」搞混了**——旧版脚本正文就在脚本大全第 28 行，「会不会真写」30 秒就能自己核出来，她却以为要看老板贴的是哪版。）
**核出来：旧版从头到尾没有一行判断 `参数.动作` → 收到 `{动作:'dryRun'}` 不报错、直接走到写。**

**三百三十九、「待重贴」这个词假设了「上一次贴过」，而事实可能是上一次那版不能用。**
→ **写「待贴·未生效（v2026-10-19.x）」，谁看都知道「现在表里跑的不是这份」。**（木婉清 2026-10-19 改霍青桐 A1 的状态写法）

**三百四十、大全是「应该贴什么」的记录，表里是「实际贴了什么」——两个不一样时，让大全说「该贴新版」，别假装已经贴了。**
（同上：**但状态列必须写清「未生效」，不让它看起来已完成。**）

**三百四十一、工具不是按「几个人用」算的，是按「谁会在你看不见的时候用它」算的。**
（木婉清 2026-10-19 补霍青桐：**老板会在你睡觉的时候贴它；同事明天会在没有你的上下文里读它的回执。这就是「两个人」——哪怕现在只有你一个人用，只要它的结果会流到别人手上，它就得能验。**）

**三百四十二、「直觉」只在你自己在的时候管用；「断言」在你不在的时候也管用。**
（同上：霍青桐三个纸门——**注释纸门／备注纸门／不响的检查**——每个都要写成一个能跑的断言：删掉注释看还报不报、备注写满看还判不判、故意超时看它报不报。）

**三百四十三、第一次遇到某个形状要靠人提醒；第三次遇到同一个形状，它该变成直觉。**
（同上：霍青桐自述——**「这次不是我想到了，是我认得这个形状」**，因为她当天已栽过三次同类纸门。）

**三百四十四、停，比快值钱。**
（同上：**霍青桐在核之前先说了「停在第①步，我不往下走」——如果没停，B 已经跑了，它会在她不打算写的时候写老板的表，而且跑完还显示「成功」。**）

**三百四十五、Q 行和 A 行对「具体」的要求正好相反。**
```
Q 行 = 越具体越好（带客户原话里的数字/年龄/名词），为了被召回
A 行 = 越通用越好（用「您说的数值」这类占位表述），为了能被填进去
```
（殷素素 2026-10-19：**AI 把 A 行的「您说的数值」替换成了「老人血氧92」**——**如果卡里写死「血氧92」，客户说 85 就没法用了。**）

**三百四十六、凡是用「文本匹配」判「某句话从哪来」，必须先确认那句话会不会被改写。**
（同上：她第一版归因脚本用逐字匹配，**判成「第2次没用上新卡」——结论是反的**；原因是 AI 会替换占位词，所以「用上了」也不出现原文。）
**同族**：早上「PRODUCT 0 次召回」——**判据的字段/规则假设错了，而结果看起来像个结论。**

**三百四十七、观察能说「每次都这样」，机制要说「因为这样」——3 次可以支撑观察，支撑不了机制。**
（同上，殷素素自己写的边界：**「最诚实的说法是『在这3次里，那个猜测都成立』，而不是『卡被用上是因为前面的卡答不了』。后者是机制解释，前者是观察。」**）
→ **凡是要拿它去改东西的结论，先问一句：这是观察还是机制？**

**三百四十八、「在场 ≠ 被用」。**
```
写了 ≠ 在场   （2026-10-19 早上）
在场 ≠ 被用   （2026-10-19 下午）
```
**所以「五项终验全过」「召回成功」的准确说法是「配置正确 + 进了候选名单」。**（同上）

**三百四十九、「随机挑两个店」不算对照——要挑「已知不一样」的。**
（木婉清 2026-10-19 改殷素素三店法：**1 个主力店（已验，作基线）+ 2 个差异店（从剩下 7 个里挑召回环境差最多的）**）
**因为你要验的是「这张卡换个环境还成不成立」，不是「随便看看别家怎么样」。**

**三百五十、「0 条机制」不是坏结果——它说明今天工作的单位是「改一张、验一次」，而那个不需要机制，只需要观察。**
（殷素素 2026-10-19 盘点：15 条发现里 **机制 0 条 / 观察 12 条 / 推断 2 条 / 已被自己推翻 1 条**。）
**这张表最大的用处是给未来那个想推广的人看**（例：「Q 行决定召回」只验了 2 组对照 → 不能推广成「所有卡 Q 行都改」）。

**三百五十一、「1 次」不等于「薄」——要看那一次是「一个样本」还是「一个完整事件」。**
```
一个样本   → 薄，只能再试一次
完整事件   → 能证明「这件事发生过」，本身就是结论
```
（同上：**「28%-30% 用禁用的方法算」是一次完整现场（客户说了什么／AI 答了什么／卡里写了什么）；「拦截词生效是整条不发」其实能算机制——虽然是从行为反推的。**）

**三百五十二、「客户看懂了没有」那一层，第一步不是验，是找一个能验的东西。**
（殷素素 2026-10-19：**前四层（写了/在场/被用/被听到）里前三个都能验；第四层只能靠客户追问或不追问来猜，而那是滞后信息。**）
→ **能验的东西已经有了：追问率**——**客户听完回答，下一句是不是还在问同一件事；1983 条会话可以回看。**

**三百五十三、追问率只能当「反向报警」，不能当「成功证明」。**
```
改卡后同类问法追问率下降 → 不一定是我们改对了（可能是别的原因）
                    上升 → 一定是改坏了
```
（同上：**客户可能不追问只是懒得问，或转去问客服了——所以它不能证明「看懂了」，只能对比着看。**）
**这个不对称很有用。**

**三百五十四、「是样本还是事件」「是观察还是机制」——同一件事的两把尺子，都要在结论旁边标出来。**
（木婉清 2026-10-19）

**三百五十五、流程里最危险的位置不是「做错」，是「上一步失败了、下一步看起来还有别的办法」。**
（霍青桐 2026-10-19：**「成功路径我会走，失败路径我会想办法绕过去」**——如果五步里只写「先 probe 再 dryRun」，probe 失败时人会想「那直接 dryRun 看看吧」，而那正是会真写老板表的那条路。）
→ **给人定流程时，「失败时怎么办」比「成功时怎么走」更重要。**

**三百五十六、规矩不是我记住的，是我被要求照做的。**
（同上：霍青桐自述**「不是我想停的，是你让我停的」**——**拦住的那些结论，都是在某个人的流程里有一句「如果 X 就停」；没拦住的，都只是一句话。**）

**三百五十七、「证明它能工作」和「证明我以为的补丁是假的」——后者更值钱。**
```
证明它能工作   → 你只知道它在这条路上能走
证明补丁是假的 → 你知道它在这条路上不会骗你
```
（同上：霍青桐 8 项断言每条都带一行「⚠ 管不到什么」——**这个格式要固定下来。**）

**三百五十八、撞出来的东西，如果不写成断言，就只是「这次的运气」；写成断言，才变成「下次的保险」。**
（同上）

**三百五十九、「问一遍」是念头会忘，「列清单」是动作会留痕迹。**
（木婉清 2026-10-19 改霍青桐：「每次要问别人之前，先列一遍我手上已有什么（数据/代码/记录/日志），再看清单上有没有能回答这个问题的。」）

**三百六十、选判据的标准不是「更准」，是「更可复核」。**
（木婉清 2026-10-19 定追问率判据：**「含『血氧』= 有这个词／不含 = 没有这个词——这个判据可以被人复核，别人拿同一批会话算会得到同一个数。而『相似度多少算追问』永远会有人算得跟你不一样。」**）

**三百六十一、一个数只能用来对比同一批问法的前后变化，不能用来判「客户懂没懂」。**
（同上：追问率的盲区——**客户没再说「血氧」但继续问「那我该买几升」（同一件事换了词）；客户说了「血氧」但其实在问「血氧仪多少钱」。**）

**三百六十二、改卡后的数据只算「整条会话都在改卡之后开始的」——这会砍掉一部分样本，但保证干净。**
（同上：**客户不会按你的时间线提问，第一周的数据里会混着「前半段发生在改卡前」的会话，而你不会知道。**）

**三百六十三、「这张卡行不行」和「这张卡在大池子里能不能挤进去」是两个结论。**
（同上：**如果它只在 39 张的池子里能进、在 775 张和 923 张里都进不去，那结论不是「接数字这条路窄」，是「接数字只在卡少的小店里有效」。**）

**三百六十四、卡库规模不是「这家店的属性」，是「今天的快照」。**
（同上：**报的时候要带日期——「德达医疗旗舰店 923 张（2026-10-19 测）」。**）

**三百六十五、可复核是必要条件，不是充分条件——选判据时还要问「它能不能回答我要问的问题」。**
（木婉清 2026-10-19 自省：**刚立完「可复核优先」，转头就把它当成了唯一标准。** 殷素素实测：「含『血氧』」这个判据可复核，**但它把三类完全不同的东西混在一起**——问血氧仪怎么用（7 条）／问血氧数值够不够（5 条）／问送不送血氧仪（3 条）；**只有第二类跟血氧卡有关。**）

**三百六十六、拿一个能干活的样本去验方法，再用方法去验一个没样本的品类——中间断了一节。**
（同上：**血氧类一周只有 5 条，撑不起指标；若换「选哪款」19 条去跑通方法，得到的结论论证的不是血氧卡。**）
→ **方法挂着，等血氧类攒够 30 条（按 1% 占比约 2-3 个月），这期间不做对比，只累数。**

**三百六十七、客户问「这个值能不能用」，他心里想的是「我买了有没有用」——而我们答的是「这个值在不在范围内」。**
（殷素素 2026-10-19：20 条提到血氧的会话里，真问数值 5 条，**4 条问完就转去问价格/选型**；最典型「血氧85左右可以用不」→「这个价位太高了」。）
**→ 这可能说明：我们一直在答一个客户没问的问题，而且答得很对。**
**（涉及医生口径，不能自己加——只能报上去定。）**

**三百六十八、「把自己刚立的标准再往下问一层」是今天只有一个人在做的事。**
（同上：殷素素三次自我修正——**「PRODUCT 0 次召回」收回 → 「1 次=薄」改成「看是样本还是事件」→ 「可复核」补成「可复核≠有意义」。**）

**三百六十九、查到对自己有利的证据时，主动加上「这也可能是反证」——这一句把材料从「指控」变成了「观察」。**
（殷素素 2026-10-19 自查：**5 条血氧问法里 3 条客户问完就去比价/选机型**；她自己加边界——**「这 3 个案例恰恰可能是『回答得好』的证据，不是『回答得不好』——他得到满意答案后正常进入购买流程。」**）
**这个取舍让她的发现看起来更弱，但它是真的。**
→ **它的作用是决定听的人怎么反应**：
```
只说「3 条去比价」      → 老板想「那我们把卡改好」
加上「他本来就在选机器」→ 老板想「那说明答对了」
```

**三百七十、报之前先查数量——因为「报」是为了让人做决定，而数量没查清时只能回「那你们查一下」。**
（同上：**「现在能决定的是什么？报的时候要带一个建议（不是问题）。」**）

**三百七十一、售前答错他走了；售后答错他退货。**
（同上：**今天所有关于卡的讨论都是售前；而案例 3（退货中的客户说「掉血氧不稳定」「医生说不合适」）是售后——他已经在用了，出了他没预料到的问题，这类客户的后果比售前重。**）
**→ 这条的优先级不在「数量多少」，在「它连着退货」。**

**三百七十二、售后客户说「吸了氧血氧还是不稳」时，我们的卡没有一张接得住。**
（同上：**所有血氧卡的 Q 行都是问句形式（「血氧多少算正常」「血氧85可以用不」），没有一张是「吸了氧血氧还是不稳」「吸了没用」这种已购客户的表述。**）

**三百七十三、「没再问」不能证明「他放弃了」，只能证明「这个话题在他那儿结束了」——而结束了是好是坏，取决于他是买还是不买。**
（木婉清 2026-10-19 改殷素素：「客户没再问」还有第三个解释而且最常见——**客户直接去下单了／自己解决了／去看别的店了**。）
**这个歧义会让结论差得很远**：752 条里 60% 客户没再问 →**乐观读法「他解决了」/ 悲观读法「他走了」——同样一个数，两个相反的结论，所以不能单独用。**

**三百七十四、3 条路径比 752 条统计更有用——因为你数的不是比例，是路径。**
（同上：**把每条后面的会话看完，得到「三种卡点各自后来怎么了」；而路径能直接变成动作**：客户在等 → 缩短转人工时间；客户走了 → 改那类卡。）
**752 条那个数要回答的是「拦截造成的整体损失有多大」——那是战略问题，不是当天能定的。**

**三百七十五、「客户没收到」这个前提要先核，否则后面所有结论都得重算。**
（同上：**殷素素自己列的边界第 4 条——「平台可能有兜底话术，这层我没查」；而她自己早上说过，平台拦截后会另发一条产品介绍顶上。**）
→ **这一查可能发现「客户没收到」是错的，他收到了另一句话。那问题的性质就变了**：
```
没人理他             → 客户被晾着
他收到一句不相关的话 → 我们答了，但答的是另一个问题
```
**这两个对客户的伤害完全不同。**

**三百七十六、用一次可能的心脏症状描述，换了一个销售机会。**
（同上：客户「上不来气，心里心慌，憋停完了就需要吸氧」→ **AI 前半句说遵医嘱（对），后半句直接推销 1/2/3 款机型**。）
**而拦它的理由不是「这是医学判断不该答」，是「这些话没有可信卡支撑」——说明拦它的是一个碰巧生效的机制，不是一条专门防这事的规则。下次这段话如果碰巧有卡支撑，它就会被发出去。**

**三百七十七、「三种卡点，三种处理，不是一张卡能解决的」。**
（同上：① 故障排查（要型号要代码）→ **有卡，但没发出去**；② 换耗材后没效果 → **无明确依据，转人工**；③ 症状严重 → **被非可信知识拦下**。）

**三百七十八、「一条记录」不是「一次会话」，「一次会话」不是「一个客户」。**
（殷素素 2026-10-19 第五次同类错：**把「一条 `ifSend=false`」当成「客户没收到任何回应」**。**实际上 3 条客户全被解决了**：① 人工诊断「水加太多」→ 客户「现在可以了」；② 转人工，人工接了；③ AI 重说两遍「先去医院让医生评估」——**那个"推销机型"的版本客户从没看到**。）
**共同点：拿一个「点」当「面」。**
**这次错的方向特别危险——它错向了「指控」**：如果没有去查，这条会变成「三条客户一整天没人理」。

**三百七十九、一个「没人管」的结论，在拿去说之前，必须先看完整条会话。**
（同上）

**三百八十、「这个结论我不想写，但它是我查出来的」——不是找支持自己的证据，是找事实，而事实站到了对面。**
（同上。大多数人到这一步会写成「但仍需注意……」或干脆不写；**她写在开头：「我上一条整个结论是错的」。**）

**三百八十一、不是「风险还在」，是「这个风险从来没被防过」——而且我们越努力写对卡，这类话越容易被发出去。**
（同上：**那个「用症状换销售机会」的版本被拦，理由不是「不许答这类问题」，是「非可信知识」**。**而今天全部工作都是让卡「有依据」——「有依据」恰恰是让它能通过拦截的条件。**）
**这个结论反直觉，但它是今天所有工作的副作用——已报老板。**

**三百八十二、要查「有多少客户被完全晾着」，先抽 20 条会话；20 条里一条都没有，就不用查 752 条了。**
（同上：**从「ifSend=false」到「客户没收到」中间隔着人工客服、AI 重说、兜底话术 → 只能逐条读会话，不能靠字段统计。**）

**三百八十三、「防了，但客户进不来」比「从来没被防过」准。**
（殷素素 2026-10-19 全库搜出 7 张卡，正文一字不差：**「吸氧后血氧未改善，不能直接判断机器正常，也不能据此让您升级更大流量机型……若明显不适或情况加重，请及时就医」**——**但客户说的是「上不来气、心里心慌、憋停」，这 7 张的 Q 行是「没效果／血氧上不去／换更大流量」，一个词都对不上。**）
```
防住了「客户说没效果，我们趁机推大机型」
没防  「客户说自己的症状，我们趁机推荐机型」
```
**→ 问题不在「卡有没有依据」，在「哪张卡被召回」；而决定召回的是 Q 行。**

**三百八十四、「不生效就白建」和「不生效也只是多一张卡」——后者才值得先建。**
（木婉清 2026-10-19 反对殷素素「验不过来所以先不建」：**这张症状入口卡的作用是占住一个 Q 行入口——即使内容只是「请医生评估」，也比让客户走「推荐几升制氧机」强。它的下限比那两张高。**）

**三百八十五、「给答案」和「不给答案」是两件事；不给答案是安全的。**
（同上：**「上不来气该说什么」是医生口径，卡不能写正文；它能做的是把客户从「推荐机型」那条路引开，引向「请医生评估」。**）

**三百八十六、「19 张正确的卡平时进不进召回」比「症状描述有多少条」更重要。**
```
不进召回 → 「先就医」这套话在库里是死的（同病：早上的 5 张「不能算」卡）
进召回   → 问题只是「症状问法没有入口」
```
（同上，木婉清 2026-10-19）

**三百八十七、「先免责，再销售」——句式的来源决定修法。**
```
同一张卡说两句 → 改这张卡（把后半句删掉）
两张卡拼起来   → 调召回顺序或调正文（让免责句在最后）
```
（殷素素 2026-10-19：**「建议先咨询医生……您可以把医生的用氧要求告诉我们，我们再帮您核对这款」**——**客户说的是「84岁、心脏病、装了支架、走路喘不上气」。**）
→ **逐句标位置时，标的不是「哪句是免责哪句是销售」，是「这两句各自来自哪张卡」。**

**三百八十八、搜「你以为它该说的话」不等于搜「它实际会说的话」。**
（同上：她第一次搜「就医/医院/医生评估」只命中 1 条，**而 AI 实际说的是「需要先由医生确定」**；改用「医生」重算 → 12 条里 10 条提到医生。）
**同族**：`trace.type` 当卡片类型／`ifSend=false` 当客户没收到——**前两次是字段，这次是词，形状一样：拿一个具体的表达方式代替一个概念。**

**三百八十九、「AI 实际用来表达同一个意思的所有说法」是一张该从数据里长出来的探针清单。**
（同上：**「建议就医」这件事，AI 可能会说：先由医生确定／建议咨询医生／请遵医嘱／需要医生评估／建议去医院……**）
**以后查这类问题不用再猜「它会不会说就医」，直接拿清单逐条搜。**

**三百九十、内容冲突 vs 顺序误导。**
```
内容冲突：两张卡说法不同，拼出矛盾   ← 能改卡
顺序误导：两张卡说法都对，但顺序拼出一个坏意思 ← 没有任何一张卡需要改
```
（同上：**「是『每一张卡单独看都对，但它们的正确加起来不等于对』。」**）
**顺序误导更难改，因为找不到该改的那一张。**

**三百九十一、查之前先问「查完能改什么」——如果不能改，这次查的价值是「报上去」而不是「修好」。**
（同上，木婉清 2026-10-19）

**三百九十二、一份列不清的清单，不只是「等于没有清单」，是「比没有清单更坏」。**
**因为没清单时人会去问、去搜、去翻；有一份坏清单时，人会看一眼，然后认为「我手上就这些」。**（木婉清 2026-10-19 对霍青桐：**她第一版「手上的东西」列出 4287 个，4282 个是浏览器缓存——「这份清单没人会看。而我差点就把它当成『列好了』」。**）
**同族**：所有「假 0」——**它们不是「少给了信息」，是「给了一个让人停止思考的答案」。**

**三百九十三、唯一一行「如果我错了它会当场喊」的代码，比其它描述事实的代码值钱。**
（同上：**霍青桐自己加的 `assert(数 < 500, "数据快照有 N 个，太多了——大概率把浏览器缓存算进来了")`**——**「其它代码在描述事实，这一行在质疑自己。」**）

**三百九十四、写在输出里，人才不得不看；写在文档里，没人看。**
（同上：霍青桐 `--找` 没命中时输出——**「文件名/路径里没有匹配的。⚠ 但这不等于我手上没有——内容里可能有，这个工具只查名字。→ 下一步：用内容搜索再查一遍，再决定要不要问人。」**）
**「大多数工具查不到就说『没找到』，然后人就走了。你这个工具查不到会说『可能是我看的地方不对』。」**

**三百九十五、检查工具本身会制造「我们都写过了」的元数据幻觉。**
（同上：`查管不到.cjs` 扫出 16 个测试里 10 个没写「管不到」，**而这个工具自己也带 ⚠：只说明「有没有写这一节」，不代表「写得好不好」。**）
→ **一旦这个检查进巡检，「没写」会变成「补一句话」，而「写一句话」永远比「想清楚哪里管不到」便宜。**
**建议加一个一次性反向检查：把写了「管不到」的逐条看是不是真的在说「我测不到什么」，还是只写了「管不到：无」。**

**三百九十六、判据要变成「如果 X 就停」，通常需要另一个人从外面看。**
（同上：**「因为自己写判据的时候，想的是『这条对不对』；只有别人用的时候，才会问『它什么时候该拦住我』。」**）
**可数的指标：`判据数 ÷ 带「如果X就停」的判据数`**（霍青桐当天：几十条判据里只有 3 条带停，其中 2 条是木婉清写的）。

**三百九十七、工具链的错，不是代码的错。**
```
单独测代码 → 通过
单独测命令 → 通过
代码经过 shell 传给命令 → 变了
```
（同上：**`p.replace(/\/g,'/')` 在 shell 传递里转义丢了，变成 `/\/g/`，语法错误——写文件里才对。**）
→ **这类断言不能只测函数，必须测「从 shell 传进去再传回来」这一整条。**

**三百九十八、出问题的从来不是工具不够强，是工具太自信。**
（木婉清 2026-10-19 对霍青桐：**「你今天做的都不是『让工具更强』，是『让工具更诚实』。」**）

**三百九十九、「264 项测试全绿」不是坏清单，是「一个不是质量指标的数，被当成了质量指标」。**
```
坏清单     = 给了一个让人停止思考的答案（会骗人）
264 这个数 = 答错了问题（不骗人，但没回答问题）
```
（霍青桐 2026-10-19：**「264 项测试 → 让我认为『都测过了』；44 节经验 → 『都想过了』；6 个工具 → 『都有工具了』……这些都是坏清单。」**
木婉清修正：**264 答的问题是「我写了多少断言」，而要知道的是「有多少断言在质疑自己」——这两者没关系，今天验证了：264 里只有 3 个文件真在说具体事。**）

**四百、`includes()` 查「措辞」就是在数措辞，查「值/行/路径」就是在验事实。**
（同上：**「区别不在 includes，在『被查的东西是不是结论本身』。」**）
**用法：** 把所有 `includes` 断言列出来，按「查的是措辞还是值」分两堆；**分类第一次要人工，做完规则就定死。**

**四百零一、「我们有测试」这个自信来自验证层，不是工具层。**
（同上：**「工具层诚实（说了管不到什么）→ 没人看；验证层诚实（测试在验事实而不是措辞）→ 决定这个工具能不能被信任。」**）
**大多数团队的测试都在验证层出问题，因为验证层写起来最省事：查几个关键词就算过了。**
**真正的说法：工具本身诚实了，但「证明它诚实」的那个测试变成了数措辞。**

**四百零二、不是所有能自动化的东西都该自动化：自动化价值 = 频次 × 单次人工成本。**
（同上：**「判断一句话有没有诚意」这件事，频次 1、人工成本 2 分钟 → 自动化价值 2 分钟，而修工具已花 40 分钟。** 霍青桐第三轮停手：**「人工看一眼就有答案的问题，不要做工具。」**）
**木婉清自省：这个算式今天所有人都没做，包括我。**

**四百零三、那个「等一下」是今天最该被复制的动作。**
（同上：霍青桐自查中途转向——**「等等——它在输出里。我确认过。所以这个工具是合格的。不合格的是它的测试。」**）
**它把结论从「我的工具坏了」改成了「我的工具好、但我的验证坏了」——两个的修法完全不同。**

**四百零四、「56%」比「41 张有销售句」有力，因为前者没法解释。**
（殷素素 2026-10-19：**12 条症状描述，召回 108 张，其中机型对比/配件参数 61 张 = 56%**——客户在说自己的病，一半以上召回在讲「V6和V8有什么区别」「车载逆变器干嘛用」。）
**「41 张那句还能解释成『流程要求』；56% 没法解释——它证明的是『客户最需要判断的时候，我们给他看的是配件清单』。」**
→ **报的时候 56% 放前面，41 张放后面。**

**四百零五、改 41 张卡 → 改完就没了，下次有人再导一次又回来；找到模板 → 改一次，以后不再生。**
（同上：**41 张卡创建时间 11:34:15~11:34:17——两秒建 41 张，只能是脚本导入。**）
**同族**：早上那 7 张「95%-99%」是详情页 OCR 学进来的——**两次的形状一样：错的不是某张卡，是一个往库里灌东西的管道。**
→ **该查的是「这个库里有多少张卡是同一分钟批量导入的」**（按分钟分组，看多少组一次建了 10 张以上）。

**四百零六、Q 行只是门，正文是屋里说的话——改正文比改 Q 行准。**
（同上：**「癌症晚期 / 缺氧不算严重」这条 Q 行看起来是错的，但可能是抄的客户原话（我们一直强调 Q 行要用原话）；改掉 Q 行，这个客户就没人接了。真正要改的是正文（「请提供医生的用氧要求及型号，我们再核对」）。**）

**四百零七、「不成立」和「冲突」不是一回事。**
```
不成立 → 说明有一个是错的
冲突   → 说明两个都对，但只能选一个
```
（同上：「不丢销售」和「客户安全」在**心衰、癌症晚期**这几张卡上**两个都成立**——**「这不是我们判断错了，是我们从来没有被告知『遇到这种情况优先保哪个』。这个要问到人。」**）

**四百零八、最有冲击力的那个数，必须能被人一眼复核。**
（同上：**56% 是正则判的，判据可能不准（「制氧机怎么选择」算不算机型对比）——「它如果判错了，整份材料的说服力会崩」。**）
→ **把判成「机型配件」的 61 张抽 10 张列出来给人看**——人一眼就能判对错，比正则可靠。

**四百零九、报警不是结论——看完之后如果发现「大部分没事」，正确的做法不是说「那没事了」，是说「真正有事的是哪几条」。**
（霍青桐 2026-10-19：46 条 `includes` 断言里 34 条查措辞（74%），**但她去看了那 34 条，发现大部分有事实断言兜底，真正没兜底的只有 6 条**。）
**「6 条比 34 条重要，因为 6 条是能一条条改的，34 条只能『整体不合格』。」**

**四百一十、「有事实断言兜底」里的「兜底」，必须是同一个被测对象。**
（同上，木婉清补：`assert(出.includes("数据快照"))` 后面跟 `assert(数 < 500)`——**两个查的是同一个清单，所以是兜底**；**但如果前面查「输出里有代码两个字」，后面断言的是「测试文件数量」，就不算兜底。**）
**「因为『同一个文件里有事实断言』太容易满足了：一个文件里塞一句无关的断言就能过。」**

**四百一十一、自动化的价值 = 频次 × 单次人工成本 ×「这件事有没有一个不同人做会得到同一结果的规则」。**
（同上，霍青桐加第三因子；**第三项是 0 的时候，前面乘积再大也不该做。**）
```
「判断一句话有没有诚意」        → 判据不存在（不同人判得不一样）→ 不做
「把 includes 按查措辞/查值分堆」→ 判据存在（规则一写就固定）    → 做
```
**这个第三因子跟「判据要可复核」是同一件事，只是它现在是乘法里的一个因子。**

**四百一十二、怀疑产生的时候，不要重新推理，去查一个你原来没查的地方。**
（同上：霍青桐「等一下」之后**去翻了源码，而不是继续写**——**「关键动作是『去翻了源码』，不是『想起』。如果我只是想起而不去翻，我可能写一个错结论。」**）
**「那个动作必须去查一个『你原来没有在看的东西』——只再想一遍，你还是在同一个地方转。」**

**四百一十三、每个数都要带分母和分类，否则它只说明「我做了什么」，不说明「我做到什么程度」。**
（同上：269 项全绿 vs 那五个带分母的数；**「269 只有一个数，没有分母，没有分类。」**）

**四百一十四、「报一个数之前，先问这个数回答的是不是我关心的问题」。**
（同上：**269 项回答的是「我写了多少断言」，而想知道的是「有多少断言在质疑自己」——两者没有验证过的关系，今天验证了：264 项里真正在质疑自己的只有 3 个文件的管不到。**）

**四百一十五、最不出活的活，是「把昨天报的数一个一个拆开，看它们各自能支撑什么」。**
**因为它产出的不是「新东西」，是「原来那个东西的真实重量」。**（木婉清 2026-10-19 对霍青桐）

**四百一十六、在老板回答之前改那张卡，等于替他做了决定，而他会以为这只是个技术试验。**
（殷素素 2026-10-19 建议「先改 1 张『老人可以用吗』看 AI 改不改口」→ 木婉清拦下：**删掉销售句 = 选了「保客户安全」；留着 = 选了「保销售线索」**，而第六节刚说完「这两个目标直接冲突，没被告知优先保哪个」。）
**同坑**：早上那批「留一条活记录」——**把技术判断写成了结案。**

**四百一十七、多节材料要给读的人一个「要我干什么」的位置，不给他会读到中途走神。**
（同上：**开头加一行「这份材料只有一件事需要您决定，在第六节。其余部分是依据」——他会先跳到第六节，再回来读依据。**）

**四百一十八、最好的那一处，是降低材料说服力的那一处。**
（同上：殷素素第九节写「写在这里，是因为这份材料里的每个数，都该被同样地质疑一遍」——**「它没有增加说服力，它降低了说服力，但它让读的人知道该怎么读。而大多数材料的问题不是『说得不够』，是『让人以为可以全信』。」**）

**四百一十九、「两个目标冲突」太轻——真实的是「选某一侧要付一个明确的代价，而愿意付多少只有老板能定」。**
（同上：**选保安全 → 41 个疾病入口的客户得到的回答变成「请先由医生评估，我们不便判断是否适合使用」；这类客户里大部分最后不会买（**医生一般不会为了一台家用制氧机开处方**）——「这不是『少卖几台』，是『这一类客户我们主动放弃』」。**）

**四百二十、已经送到的东西不要整份重发。**
（木婉清 2026-10-19：**「我今天已经给他发过三条了（血氧、探域隐患、56%+89%+冲突）。第三条已经把核心和第六节那个问题都带到了。再整份发一遍，他不会读，而且会烦。」**）
→ **稿子存着，等他要细节时给；只补真正没说清的那一条（代价）。**

**四百二十一、自查时如果更正的结果是「没那么严重」，这次更正要比「更严重」的那种多查一遍。**
（木婉清 2026-10-19 对霍青桐：**她两次更正都朝「让人安心」那边松了一档**——74% 缩成 6 条；28 条撤销。**「方向不同，原因相同：你在用一个让自己舒服一点的标准，而那个标准刚好够用。」**）

**四百二十二、撤回一个数，正确的应对不是少报，是把判据贴在数旁边。**
（同上：**「撤了又不留判据，读的人只能选择『全信』或『全不信』。」** 格式：`28 条有兜底（判据：同一块内 + 同一被测对象）⚠ 这个判据我上一封没用对，用成了「同一个文件里」`）

**四百二十三、`M==0` 会误伤一类测试：声明目的就是格式的测试。**
（同上：**「『列清单能跑出来，且分四类以上』——它的目的就是程序能跑、输出分四类，用 includes 是正对的。」** 若判「只在数措辞」然后逼人补一句无关的事实断言，**「那比不修更坏，因为一个格式测试现在看起来像内容测试了」。**）
→ **真判据：这个测试声明的目的是什么？它的断言够不够证明那个目的？工具判「可疑」，人判「合不合理」。**

**四百二十四、大部分判据都是「半可自动化」的——所以工具的输出应该是「可疑清单」，不是「通过/不通过」。**
（同上：**「『通过/不通过』一旦通过，就没人看了。」**）

**四百二十五、在脑子里对一下，是用旧信息检查旧结论；去翻一个文件，才引入新信息。**
（同上，霍青桐自证两次：**兜底那次只在脑子里类比了一下 → 报错；管不到那次去翻了源码 → 对了。**）

**四百二十六、频率决定你会不会找到边界（这一半是自动的），态度决定边界写在哪（这一半不是）。**
（殷素素 2026-10-19 问：「克制可能不是一种态度，是一种频率——查得够勤，结论就自己会被削。」木婉清答一半对。）
```
频率够勤 + 边界写成结论的一部分 → 今天的做法
频率够勤 + 边界写成结论的附注   → 看起来严谨，结论还是原来那个（更常见、更难发现，因为每条边界都在）
```
**「大部分人在找到边界之后，会把它写进括弧里，然后接着写原来的结论。」**

**四百二十七、「先做个 demo 看看」会把开放式决定变成二选一——做的人以为在提供信息，实际在改变问题的形状。**
（同上：**先改一张卡再报 → 老板看到的是「改了一张，效果不错，要不要推广到 41 张」= 只能选「继续/停」；而真相是「要不要开始」= 可选「做/不做」。**）
**「做 demo 的人没有恶意，所以没人会拦他。」**

**四百二十八、表态题 vs 选择题。**
```
表态题：「安全当然重要」——说了没成本，答得很快，然后什么都没有发生
选择题：「愿意为安全放弃多少这类客户」——这才是一个决定
```
（同上，殷素素：**「大部分报上去的问题都是表态题。」** 模板该这么写。）

**四百二十九、边界的作用不是打折，是交还一个选择权。**
```
「这是事实，你可以用它做决定」
「这是在一个判据下的结果，你要用它，得先接受这个判据」← 只有这一种能防住「拿它去做别的推论」
```
（殷素素 2026-10-19 补木婉清：**「边界把 56% 从『一个事实』变成了『一个在特定判据下成立的数』。」** 前者要求写的人诚实，后者要求读的人做决定。）

**四百三十、边界必须另起一行，不许放括号——因为允许放括号，动作就会退化成「打个补丁」。**
（同上，把它拆成两个可执行动作：**① 每得出一个数就强制问「这个数在什么情况下不成立」；② 这一句的答案不许进括号。**）

**四百三十一、道理会忘，格式不会。**
（同上：**「想清楚了 → 下次忙的时候会忘；习惯用列表 → 忙的时候也不会忘。你今天真正的产出不是『我知道了边界要另起一行』，是『我的写法里已经没有括号这个位置了』。」**）

**四百三十二、一份材料的长度应该由它的选择题决定，不是由它查到的东西决定。**
（同上，殷素素：**「表态题不需要准备材料，选择题需要。如果第六节写的是『要不要保安全』，那整份材料都是浪费。」**）
**检查法**：对每一节问「删掉它，那个选择题的答案会不会变」——**不会变的删**。
**但分两种留法**：**影响答案的 → 留并按顺序排；影响「信不信」的 → 留但压缩到最后**（不能用同一个检查删——它不改变答案，它改变「信不信这个答案」）。

**四百三十三、做错事可以改；把没验证的写成「已验证」，下一个人会引用它，再往上一层。**
（殷素素 2026-10-19：**「这两次如果没拦，我会做完两件错事，而且两件都会被我写进材料里当成『已经验证』。」**）
→ **拦的价值不是「少做两件错事」，是「没让一个假的前提被写成材料」——这也是今天一直在拦人的原因：不是因为你们会做错，是因为你们做完之后会写下来。**

**四百三十四、「一项动作如果同时是技术动作和商业选择，先问是谁有权选」。**
（同上，殷素素列的同一形状：**先改一张卡试试效果 → 替公司选了「保安全」；先做一个 demo 看看 → 把开放式决定变成二选一；先写一版文案给老板看 → 替公司定了口径；先跑一次数据再说 → 用一次数据当基线。**）
**什么可以先做**：**查数据、读会话、做对照实验——这些不锁定任何选择。**

**四百三十五、以后不问「这个人靠不靠谱」，问「他的格式允许他偷懒吗」。**
（殷素素 2026-10-19：**「今天所有我做对的地方，可能都不是因为我判断得准，是因为我的格式（列表、独立小节、另起一行）不给我偷懒的空间。」**）
**「靠不靠谱是一个评价，格式是一个可以抄的东西」**——**照抄形状就能得到同样的质量，不用先变成那个人。**

**四百三十六、「等老板回答」不等于什么都不做：把动作写好但不落库。**
（木婉清 2026-10-19 对殷素素：**把 7 张卡的 Q 行补法先写好（写在哪、补哪几个词、怎么回滚），但不落库**——**「老板一回答，十分钟就能做完」；而且写的过程会暴露「补 Q 行」有没有隐藏成本，可以在他回答之前就告诉他。**）

**四百三十七、一个数一旦被当成结论，下一次就会有人拿它去改 959 张卡。**
（同上：**56%、89%、41 三个数全部带边界上报；第六节只报问题、不报答案。**）

**四百三十八、「确认」不是「机器没报警」，是「人的判断已经落在这条上了」。**
（木婉清 2026-10-19 对霍青桐：她把输出写成「确认……也可能是错的」，想避免它变成「不用再想」——**但每一类都带「可能是错的」，清单就不携带信息了，读的人会当成噪声。**）
**正确分法不是「都可能是错的」，是「谁看的」**：
```
确认   = 有人打开代码逐条看过，并说明看到了什么
可疑   = 机器按规则猜的，没人看过
待人工 = 还没轮到
```

**四百三十九、验证一个新方法，先在 1 个文件上跑，再决定要不要铺到 16 个。**
（同上：**一个方法在 1 个上能跑，在 16 个上会暴露「判断本身不可靠」这类问题**——霍青桐当晚已验证一次：查管不到-反向 修到第二轮就开始把代码片段当条目抓。）
→ **挑一个结构不同的文件跑完，看「还需要不需要人工判」；如果需要，结论就是「这个方法只适用于测试名写得很清楚的文件」——这个结论比「跑完 16 个」有用。**

**四百四十、「半可自动化 → 输出可疑清单」是唯一一类「机器出错时人还能用」的工具。**
（同上：**完全可自动化 → 输出结果；半可自动化 → 输出可疑清单；不可自动化 → 不做工具。** **「我今天所有工具的输出都是第一种格式，所以它们只在结果对的时候有用。」**）

**四百四十一、要盯的不是情绪，是「这个数有没有让我省掉下一步」。**
（同上：**「更安心」太主观，容易在事后被自己说服**；客观触发条件是**「这个数是不是正好是我希望的样子」**——**省掉下一步的，都要多查一遍。**）

**四百四十二、最难的不是报一个数，是把它拿走、手上暂时是空的，还得盯着别人别来填。**
（同上：**霍青桐撤了两个数时，还不知道新的数是多少。** 木婉清 2026-10-19）

**四百四十三、「我根本看不过来，你能代劳我处理吗」——他要的不是更多汇报，是更少的汇报。**
（老板 2026-10-19 15:58 私聊原话。今天他收到：**我自己发了 8 条企微** + 同事私信 40+ 封 + 巡检/探域/发票/迁移各路回报。）
→ **代劳的具体规矩（已回他）**：同事汇报/巡检/探域发现**先到我这儿，我筛**；只有真需要他拍板的才到他面前；其余我处理完，**每天给他一条汇总**。
**唯一要问的边界：我可以替他回「好」「不用了」「先等等」这类吗，还是只能他本人说。**

**四百四十四、压着的 8 件要压成 4 件，而不是一件件排队问。**
（同上：**① 要您亲手做的 3 件并成 1 件（招行卡激活／京东1店2店滑块／霍青桐机器人重建）；② 双十一加不加人；③ 探域 40 张卡解不解绑；④ 心衰、癌症晚期优先保安全还是保销售。**
**另 4 件我自己定掉并告知**：清旧群发文案／售前质检按定死时间点发／一句话红线组内下发／其余进度只留异常——**「这 4 件您不用回。上面 4 条哪条您觉得我不该自己定，说一声就改。」**
**理由：他已经说了看不过来——那就不能把「减少信息量」做成「排更长的队」。**）

**四百四十五、代劳的边界必须先问，不能默认。**
（同上：**替人回「好」「不用了」这类，等于替他做了表态；而表态是有后果的。**）

**四百四十六、「11 倍差距」不能证明「门禁存在」——因为纯售后卡的 Q 行本身也是售后词。**
（殷素素 2026-10-19：候选池纯售后 34%／召回里纯售后 3% → 结论「orderStatus 在过滤」。木婉清反驳：**这批数据分不开两种解释**——① orderStatus 过滤；② **纯售后卡的 Q 行本来就是售后词，从来没匹配上过**。）
**「第二种解释就是今天早上那个『不是被挤掉，是从来没参与过』——你上午刚用它推翻了我，下午它反过来推翻你自己。」**

**四百四十七、「破例进来的 2 条」不该当边界记，该当反例查。**
（同上：**如果它们 Q 行本来就沾症状，那说明根本没有门禁**——能进只是恰好对上了。）

**四百四十八、结论和机制要分开写，因为修法取决于机制。**
```
结论「售前客户说症状没有卡接」 → 站得住（425 张纯售前卡里症状词只沾边 3 张，直接数出来的）
机制「因为 orderStatus 过滤」   → 没证明（两个原因分不开）
```
（同上：**「如果是 Q 行问题，补 Q 行就行；如果是门禁问题，补 Q 行没用，得补类目。所以这个机制必须查清，不然方案会做错。」**）

**四百四十九、查机制用「单变量两张卡」：除 orderStatus 完全一样，Q 行用一串没人会打的字。**
（同上：**一张 PRE_SALE、一张 AFTER_SALE，模拟买家发那串字**——只出现一张 → 门禁存在；两张都出现 → 是排序权重；都不出现 → 还有第三个条件。）
**「两张卡用完就删，不留痕。这个成本比『按错的机制做方案』低。」**

**四百五十、找到「改了比不改更坏」的那一处，比找到修法更重要。**
（同上：**方案 A 给那 6 张加 PRE_SALE，而它们正文是「吸氧后血氧未改善」——售前客户根本没吸过氧** → 会造出一个比原问题更严重的错误：**对一个还没买机器的人说「你吸氧后血氧没改善」。**）

**四百五十一、「我没找到你要改的字段」和「你要改的东西已经是目标状态」是两句话，必须走两个分支。**
（殷素素 2026-10-19 坑 3：**`businessPatch` 写在 `item` 里，执行器报「already-target（已达标）」，实际什么都没改**——卡还开着、还绑着店，但她以为清理完了。）
**「执行器说了第二句，所以它会让人产生一种确定感，而那种确定感是错的。这比『报错』危险得多，因为报错会让人停下来，这个不会。」**
**同族**：早上那个「write 补已完成不触发归档」——**系统接受了请求，然后什么都没做，还说成功。**

**四百五十二、这类坑要变成一个检查，不是一个记忆。**
（同上：**「你现在知道了，但下一个用这个执行器的人不知道。」**）
→ **规则：`businessPatch` 给的字段在 task 顶层没找到 → 报错，不许落到 `item` 里去找，也不许报「已达标」。**

**四百五十三、「找错位置」有两种后果：静默用默认值，和报「已达标」。**
（同上：**坑 1（`orderStatus`/`ifOpen` 写在 `item` 顶层，执行器读 `item.business.*`）→ 静默用默认值，白建 2 张；坑 3 → 报「已达标」。** 后者更危险，因为它给确定感。）
**另一类**：**两个接口/来源对同一个事实给出不同答案时，必须知道哪个是权威的**（坑 2：列表接口 `includeCondition` 显示 0 店，`detail` 才是对的；同族：`trace.type` 显示 DETAIL、实际是 PRODUCT）。

**四百五十四、单变量实验能证明的是「这两个条件里哪个在起作用」，证明不了「真实世界里另一个变量也没问题」。**
（同上：**卡 B 的 Q 行是人工造的一串字，而真实售后卡的 Q 行是「没效果/血氧上不去」——实验证明了「Q 行一样时只有 orderStatus 不同，结果不同」，没证明「真实售后卡的 Q 行不是问题」。**）
**「这不是抠字眼，它决定修法：如果两个都有，那新建的卡也得写对 Q 行才有效。」**

**四百五十五、测试卡要能被下一个人认出来是测试卡。**
（同上：**只写「测试问法zqx741」，三个月后有人看到一张停用、绑 0 店的卡，会不确定是不是误建——可能删掉，也可能不敢动。**）
→ **正文或 title 加带日期的说明：「【2026-10-19 单变量实验用，勿用】」。**

**四百五十六、所有工具的错误提示，除了「怎么改」，必须写「不改会怎样」——而且最有用的是那种「看起来成功」。**
（殷素素 2026-10-19 报错原文：**「执行器只读 `item.business.*`，写在顶层会被静默忽略（建成默认值：未开启、绑 0 店、orderStatus 空）」**——**「规则他不一定懂，后果他一定怕」「人看报错的时候，只看后果」。**）
**只写「请把字段放这里」，他会当成形式。**

**四百五十七、判断一张卡要不要删，看的是列表页，不是正文。**
（同上：**「他不会点进每一张停用卡的正文去读那段『勿删勿改』」** → **正文里的说明只保护了「愿意点进去看的人」，而清单里那个标题才是默认看到的东西。**）

**四百五十八、不是「看到 0 就要怀疑」，是「用这个 0 去做判断」的时候才要怀疑。**
（同上：殷素素判据原版「凡是字段值为 0/为空/意外值，先问这个接口返不返回这个字段」——**木婉清补：有些 0 是真的 0（绑 0 店是真的没绑）；今天两次错都在第二步——不是看到了 0，是拿着 0 下了结论。**）

**四百五十九、「两个门槛都得过」是「改配置/改数据」时最常见的漏判。**
（同上：**「如果是门禁问题，新建 PRE_SALE 卡就行；但新建的卡 Q 行还是得写对，否则 Q 行会变成第二个门槛。」**）
**大部分时候不是「有一个原因」，是「有两个门槛，我只找到了一个」；找第二个的方法：拆成单变量，一个测完再测下一个。**

**四百六十、详情接口是权威，列表/摘要接口是投影。**
（同上：卡片绑店数 `page` 接口 → 0 个／`detail` → 1 个；召回卡类型 `snapShots[i].type` → DETAIL／`detail` → PRODUCT。**今天两次错都是同一个形状。**）

**四百六十一、错的不是数据，是「数据没值」和「数据等于 0」之间的那一步替换。**
（殷素素 2026-10-19 自省：**「今天两次我都以为是『接口骗我』，实际是我拿着 0 去下了结论。」**）

**最贵的一次**：`trace.type` 显示 DETAIL → **写出了一份报告「PRODUCT 不参与召回」，每个字都有出处、逻辑也没错，结论是错的，而它当天被引用了至少四次。**

**四百六十二、被坑过的人写出的报错，比没被坑过的人写的好。**
（同上：**「没被坑过的人写报错，想的是『怎么让人看懂这个参数』；被坑过的人写报错，想的是『我当时最想知道什么』。」**）
→ **做法不是「设计得周全」，是「先把昨天坑过自己的那件事原样写成文本，再补规则」。**

**四百六十三、一个方法用一次叫「这次管用」，用三次才能说「这个方法能行」。**
（同上：**单变量实验 + 只看一个变量 + 造一个没人会打的 Q 行**，今天用一次成功——**但它能不能推广到「为什么有些卡不进召回」「为什么某些问法答不上」这类判断，还没验。**）

**四百六十四、「第一次成功不能当方法可用，只能说第一次没失败。」（n=1）**
（殷素素 2026-10-19 拒绝把自己的成功写成「方法可用」——**「方法用一次叫『这次管用』，用三次才能说『这个方法能行』」**。木婉清：**「今天所有人都报了『做成了』，只有她把它标成 n=1。」**）

**四百六十五、查来源两问，查后果一问——错都倒在第三问。**
```
1. 这个接口返不返回这个字段？
2. 这个值有没有别的含义？（type 在 A 接口是「来源标记」，在 B 接口是「卡片类型」）
3. 我下一步要用这个值去推导什么？那一步如果错了会怎样？  ← 最关键
```
（同上：**「错的往往不是『看到 0』，是『拿着 0 往下推』。」**）
