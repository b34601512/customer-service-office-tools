## 目标
把「未发送 + 无需动作」的记录批量核销（标记已处理），**不动**「话术未生成」的记录。

## 范围（口径）
- **要标**（设计内正常）：`人工客服已回复`、`回复来自非可信知识`、`买家有新咨询`、`上下文存在相似话术`、`买家非当前客服接待`、`买家咨询售后相关内容`、`买家要求转人工`、`转人工*`、`人机协同`、`店铺未开启自动回复`（历史）、`买家已转交`、`人工接待状态`、`未开启自动接待` 等。
- **先抽检再定**：`风控话术拦截`（122 条）、`违禁词拦截`——随机抽 10 条读 trace 明细（`prohibitedWordHitDetail` / 命中知识），**若只是正常风控拦截 → 一并标**；若发现知识写法确有问题的 → 挑出来写回执、该条不标。
- **不标**：`话术未生成`（267 无召回等补卡后再标；186 有召回待专项）。

## 步骤
1. 用第一轮 JSON 分类出「要标」清单（按店分组，记录 id + 原因），dry-run 打印条数与样例。
2. 逐店 `--review "<逗号 id>" --commit --shop <店>`（一次一条接口调用；单店超 300 条可分两批）。
3. **等 60s 缓存**后 `--verify` 复查（抽样 ≥20 条 + 该店待处理数变化）；证据落盘。
4. 风控/违禁词抽检（10 条）：读明细 → 判断 → 结论写回执；确认无问题的照标。
5. 回执：各店标记数、复查结果（应有 vs 实有）、抽检结论、未标清单与原因。
