# 跟读环必须由 Monitor 拉起，否则「进程活着」也是瞎的

**日期**：2026-11-19 20:2x｜触发：Monitor #1 exit 127 + 李沅芷误杀 14832

## 事实
- 07:45 我挂的 Monitor #1（`node 跟读收件箱.mjs --接管`）子进程是 **14832**。
- 19:41 李沅芷清自己套件时把这个 14832 当孤儿杀了；同一分钟**别的东西**又把跟读拉起来成 **29092**（不是我的 Monitor 起的）。
- 后果：进程 29092 活着、心跳正常、游标跟平，**体检一路 HEALTHY**，但它不在 Monitor 下 → 输出不进事件流 → Loop #1 收不到 `monitor:output`，来消息不会唤醒我。表面全绿，实际聋了。

## 判据（以后就这么核）
1. 体检只看「PID 活 / 心跳新 / 游标平」是**不够**的，这三条只证明它自己在读，不证明**我能被叫醒**。
2. 真判据：**pid 文件里的 PID 必须是我这条 Monitor 的子进程**。核法：`MonitorList` 里有 output 增长 + pid 文件与新起进程对得上（MonitorCreate 之后立刻记下 pid）。
3. 所以：**跟读只能由 MonitorCreate 起，不能靠开机脚本/别人代起**。别处拉起来的那只，宁可杀掉重建。

## 做法（重挂顺序，别反）
1. `MonitorStop` 旧的（或杀掉游离进程）
2. `MonitorCreate`：`cd "D:/桌面/木婉清/工具/企微" && node 跟读收件箱.mjs --接管`，timeout=0
3. `node 工具/链条体检.cjs` 核 PID，并把 PID 抄进断点
4. Loop #1（event monitor:output）不用重建，它绑的是事件源不是进程
