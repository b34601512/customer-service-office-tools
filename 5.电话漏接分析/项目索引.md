## 一、这个项目干嘛的
从电话系统下载**呼损/呼入/呼出**三份报表，TUI 里原表直显（呼入/呼出附"映射姓名"列），并提供客服统计、趋势、月总览；用于安排漏接回访。

## 二、规矩 / 口径
- **回访只看「排队阶段」呼损**（客户进了排队没等到人工就挂）；**IVR 阶段只做参考**，唯一例外：同一客户统计窗口内**呼入 ≥10 次**才需关注（用户 2026-09-17 定稿，`CLAUDE.md`）。
- 「呼入次数」= 呼入表（已接通）行数 **+** 呼损表（未接通）行数，按呼入时间去重；实现 `scripts/query_queue_loss.py --ivr-threshold 10`，报告落 `电话漏接分析后台/runtime/queue_loss_report_<日期>.txt`。
- `052788120510` = **京东平台统一来电号码**：所有京东客户都显示它，无法回拨/区分 → 做回访分析时**忽略**（`AGENTS.md`）。
- 三页展示=下载原始表**不做聚合**；"映射姓名"按「7 配置 → 2 座席号映射」换算，改完映射要重新下载才生效。
- 投诉座席分机在本地 `complaint_config.json` 维护，**不入库**。
- **危险操作需用户确认口令「161323」；禁止硬删除文件**（一律移到根目录 `\备份文件夹`）——`AGENTS.md`。
- 本目录 git 可能有其他窗口 AI 的改动，**不要随意回滚**（`AGENTS.md`）。

## 三、经验 / 踩坑
- 每日「日常巡检」跑法：先「7 下载」拉最新数据 → 再看 `1呼入/3呼损`，**只看今天+昨天**的排队呼损（`../0.木婉清档案/日常流程/每日自动化流程.md`）。
