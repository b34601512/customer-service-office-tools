## 一、这个项目干嘛的
把京东客服业绩数据（**客服管家** + **魔方**）按整月批次**追加**进两张云端汇总表，给财务算提成：表A《京东客服询单业绩汇总（客服管家数据）》→『明细』；表B《京东客服询单业绩汇总（魔方数据）》→ Sheet1。**只追加、保留历史。**

## 二、规矩 / 口径
- 口径（README + 断点）：
  - 管家：去「已取消」；昵称去「(推算)」后缀后匹配客服实名。
  - 魔方：去「已取消」+ **去 0 金额**（2026-10-07 黎路遥定案：0 元没意义、多为虚拟物品无法算提成；默认即去，不用再问）。
  - 金额口径 = **单价×数量**（"单价直和"不对）。
- **涉工资必做金额校对**（2026-10-08 黎路遥定：导入后必做）：`node scripts/校对金额.cjs --年月 YYYY-MM`；差异率 ≥1% 标 ⚠ → **不许交付**，写回执报人；证据落 `runtime/校对-<年月>/`。
- 云端两脚本（《脚本大全》第 14/15 行 = `append_guanjia` / `append_mofang`）：**只从末行+1 追加，绝不覆盖/清空**；表头守卫、`allowWrite` 门、`expectedLastRow` 防重复、写完回读逐格比对。
- **日期列必须写文本格式**（v2026-10-07.2）：首跑踩坑 `2026-09` 被金山存成日期序列号 → 回读不一致停手；repair 模式可修已写坏区间。
- 导入默认 `--dry-run`；有未匹配昵称/跨文件重复键/回读不一致 → **停下、不自动重试**。
- 魔方同月多店分批导入时，单文件 `--send` 的自动核对不按店铺过滤（会误报多）→ 一次带全清单，或最后跑合并 `--verify`。

## 三、经验 / 踩坑
- 登录态：管家在 `kf.jd.com`；魔方 `joyi.yiyitech.com`（`joyi_token`）——失效走"现在登录"→京东 SSO 授权页（勾协议再点），**别直接开 OAuth 链接**（会落 `gwjoyi` 错误页）。
- 导出：管家走 `offlineDownload/addTask` + 轮询 `getTaskStatus`；魔方走「导出中心」建任务→等 **3~4 分钟**变「完成」→点该行下载。
- 下载工具与店铺端口：`runtime/state/browser-profiles/jd/<key>`、端口 9470-9475（2026-10-07 从 9号/22号 已登录 profile 引导复制）；**跑下载前别同时跑 9号/22号**。
- 魔方校验三连（读汇总/本地重算/对比生成）目前随批次放 `runtime/校对-2026-09-魔方/`（可选：固化进 `scripts/`，下次月初前做）。
- 失败先查 `../失败台账.md`（有"页面初开闪登录过期、20~60 秒自愈"观察项）。
