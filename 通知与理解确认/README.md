# 通知与理解确认（模板与工具 · 唯一一份）

> 为什么有这份（黎路遥 2026-11-03）：「形成个文件夹，专门用来处理这类临时性通知，目的是确保大家都理解了」。
> 适用：临时活动/流程/政策要通知一批人，且必须确认「他懂了没有」——不是发出去就算完。

## 一轮怎么跑（五步，别跳）

1. **建目录**：`通知与理解确认/<日期>-<事情>/`（例 `2026-11-03-拼3活动/`）。
2. **写草稿**：`草稿.md`，一条问法，**先给黎路遥确认**，他点头才发（他不点头就一个字都不发）。
   - 问法和判据模板见本目录 `模板-草稿与判据.md`。
3. **发名单**：`收件人.json`（谁是收件人、名字要带括号后缀，如 `韩某某（售前）`）。
4. **逐条发**：`node 逐个发通知.cjs --配置 <目录>/收件人.json`（自动间隔、限流重试、断点续发、落日志）。
5. **收话填清单**：`理解清单.md` 边收边填「回的原话＋懂／半懂／没懂／没回」，最后一轮给黎路遥一张总结。

## 三条硬规矩（都是踩出来的）

1. **一条一条发，不许群发**（黎路遥 2026-10-01：群发会连锁拉窗；这里同理，一发一大片）。
2. **企微 aibot 有配额**：2026-11-03 实测发到当天第 61 条开始报 `846607 frequency limit exceeded`，间隔 5 分钟也拦——**别硬刷**，剩下的记「明天补」。
3. **发出去 ≠ 他懂了**：只有回话能判。判据写进草稿时就定死，别事后改。

## 目录结构

```
通知与理解确认/
├─ README.md                ← 这份
├─ 模板-草稿与判据.md        ← 问法＋判定标准模板
├─ 逐个发通知.cjs            ← 逐条发、间隔、限流重试、断点续发
└─ <日期>-<事情>/
   ├─ 草稿.md               ← 给黎路遥确认的那条原文
   ├─ 收件人.json            ← 发给谁
   ├─ 理解清单.md            ← 谁问了、回了原话、判懂没懂
   └─ 发送日志.jsonl         ← 工具落的发送记录（不入库）
```
