# 体检：仓库里还有谁在「用自动化窗口承载人工登录」

> 2026-09-29 由黎路遥要求做（原话：「你看下现在项目里有没有其他项目也踩了这个坑根本没发现的」）。
> 判据：**人工登录/验证码发生在哪个窗口**。原生 Chrome（spawn `chrome.exe` + `--remote-debugging-port`）→ 安全；
> Playwright `launch`/`launchPersistentContext` 拉起的窗口 → 有风险（页面带自动化痕迹）。

## 结论一句话

**只有 20号「密码墙网页读取」是纯自动化窗口，也正是今天拼多多验证码失败的那个坑；其余项目要么用原生 Chrome+CDP（安全），要么虽有 Playwright 窗口但已加反检测参数（缓解，未出事）。**

## 现在怎么用（已留工具）

```powershell
# 风控平台人工登录（拼多多/淘宝/抖音/京东/快手/小红书/有赞）
node "20.经验大全/风控平台人工登录/打开原生Chrome.cjs" --url "<登录页>" --profile "<画像目录>" [--port 9337]
# 程序读页面：chromium.connectOverCDP('http://127.0.0.1:9337')
```

* 单测锁死「原生窗口不许出现自动化参数」：`node --test "20.经验大全/风控平台人工登录/测试/打开原生Chrome.test.js"`（4/4 通过，2026-09-29）。
* 金山文档 / 探域后台这类只读协作文档，仍可用自动化窗口（低风险，历史上没出过问题）。

## 建议的后续（要动 2号 需主管拍板，未动）

1. 2号 四个平台的 store browser 改成「原生 Chrome + CDP」（跟 9号 一样），把 `--disable-blink-features=AutomationControlled` 这类补丁彻底删掉；
2. 任何新工具只要出现「人工登录/验证码/滑块」，先按 `风控平台人工登录/README.md` 的口径选窗口方式。
