# 金山在线表格（排班表）无 GUI 读取经验

配套脚本：同目录 `金山在线表格排班表读取.cjs`（可直接跑，只读，不写入在线文档）。

## 适用场景

读取 `https://www.kdocs.cn/l/{shareId}` 形式的金山/WPS 在线**表格**（不是 Word 大纲文档），典型例子是客服部排班表：

- 每月一张工作表，名称为 `2026年9月` 这种格式（`${年}年${月}月`）。
- 需要读出整张月表的值矩阵，以及**每个单元格的有效背景色**（判断值班、分组等业务标记）。
- 排班表的底色来自**条件格式**，这是整件事最容易踩坑的地方。

只读工具：不写入在线文档，不保存/打印 Cookie 或 token。本文结论来自 2026-09-13 对真实排班表（`https://www.kdocs.cn/l/cga7jWGHxzkp`）的实测，以及 1 号项目「客服超时督办」、14 号项目「后台工单自动提醒」的落地代码。

## 核心结论（先看这 8 条）

1. 表格内容不在 DOM 里，`body.innerText` 和 `curl` 都拿不到。数据在页面运行时 `window.APP.workbook` 中。
2. 一次拿全部值：`sheet.loadSheetData()` → `sheet.getUsedRange()` → `await usedRange.getRangeContents()` → `result.Values`（二维数组，行 × 列）。
3. **读背景色必须用 `sheet.getAppliedXf(row, col)`（有效样式，含条件格式；绝对行列号）**；`sheet.getXfByCell(row, col)` 只能读基础样式。
4. 实测证据（2026-09-13，同一格）：`getXfByCell` 返回 `eftPatternNone`（无填充），`getAppliedXf` 返回 `eftPatternSolid`，`getBack().getRGB() = 14872793`（即 `#E2F0D9` 浅绿），`getFore().getRGB() = 0`（黑色）。**排班表的底色是条件格式，只有 `getAppliedXf` 读得到。**
5. 取色链：`getAppliedXf(r,c).getFill()` → `fill.getType()` → 非 `none` 时 `fill.getBack().getRGB()`。RGB 返回**整数**，要转 `#RRGGBB`。
6. `getAppliedXf` 用绝对行列号；`Values` 矩阵从已用区域左上角开始，需补偏移 `usedRange._ranges[0].rowFrom / colFrom`（本表是 0/0，但别省）。
7. **有颜色 ≠ 值班**：白底 `#FFFFFF`、无填充不算标记；且非员工行（如月份标记 `9月` + 红色 `#FF0000`）也有颜色。必须先过滤姓名和结构行，再结合班次文字按业务规则判断。
8. 读取失败时宁可降级（保留原提醒、只 @ 主管），不要猜值班目标。

## 运行方式

沿用 1 号项目已有的 `playwright-core`，不要为读一次文档重装依赖：

```powershell
$env:NODE_PATH = "D:\桌面\办公软件\1.客服超时督办\node_modules"
node "D:\桌面\办公软件\20.经验大全\金山在线表格排班表读取\金山在线表格排班表读取.cjs" --url "https://www.kdocs.cn/l/分享ID" --date 2026-09-13 --out "输出目录"
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--url` | 必填，金山表格分享地址 |
| `--date` | 选填，`YYYY-MM-DD`，默认今天；决定读哪张月表和哪一列 |
| `--sheet` | 选填，显式指定工作表名，默认 `${年}年${月}月` |
| `--out` | 选填，输出目录，默认当前目录 |
| `--browser` | 选填，`msedge`（默认）或 `chrome` |
| `--headful` | 选填，`true` 显示浏览器窗口，默认无头 |
| `--employee` | 选填，只打印该员工当天结果 |
| `--debug` | 选填，`true` 额外落盘每格原始取色（`type/fore/back/source`），排障用 |

环境：Windows + Node.js（CommonJS）+ `playwright-core` + 现代 Edge，`headless: true`，启动参数加 `--disable-blink-features=AutomationControlled`。该排班表**匿名可读**（分享链接不需要登录）；若换成人文档链接需要登录，则改用本机已登录的浏览器画像（参考《金山在线Word文档读取经验.md》）。

脚本输出（都在 `--out` 目录）：

- `schedule-values.json`：原始值矩阵
- `schedule-colors.json`：同形状 `#RRGGBB` 底色矩阵（空串 = 无填充）
- `schedule-snapshot.tsv`：矩阵 TSV 快照，人工复核用
- `schedule-report.json`：验收信息 + 当日有色人员 + 当日班次映射
- `schedule-colors-debug.json`：仅 `--debug true` 时生成

## 第一步：打开页面并等表格运行时就绪

```js
const { chromium } = require('playwright-core');

const browser = await chromium.launch({
  executablePath: 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe', // 或 channel: 'msedge'
  headless: true,
  args: ['--disable-blink-features=AutomationControlled']
});
const page = await browser.newPage({ viewport: { width: 1600, height: 1200 }, locale: 'zh-CN' });
await page.goto(scheduleUrl, { waitUntil: 'domcontentloaded', timeout: 60000 });

// 匿名访问金山表格会弹登录邀请层，先关掉，避免遮挡和干扰等待
await page.evaluate(() => {
  const button = document.querySelector('#util-popup .wps-login-panel__header__right button');
  if (button) button.click();
});

// 等表格运行时和目标工作表对象真正就绪；不要固定 sleep，后台页 rAF 会停摆，必须给 polling
await page.waitForFunction((sheetName) => {
  const workbook = window.APP && window.APP.workbook;
  if (!workbook || typeof workbook.getWorksheets !== 'function') return false;
  const worksheets = workbook.getWorksheets();
  if (!worksheets || typeof worksheets.getItemByName !== 'function') return false;
  const sheet = worksheets.getItemByName(sheetName);
  if (!sheet || typeof sheet.loadSheetData !== 'function' || typeof sheet.getUsedRange !== 'function') return false;
  const usedRange = sheet.getUsedRange();
  return Boolean(usedRange && typeof usedRange.getRangeContents === 'function');
}, sheetName, { polling: 250, timeout: 60000 });
```

## 第二步：读整张月表的值矩阵

```js
const result = await page.evaluate(async (targetSheetName) => {
  const workbook = window.APP.workbook;
  const worksheets = workbook.getWorksheets();
  const sheet = worksheets.getItemByName(targetSheetName);
  if (!sheet) throw new Error(`没有找到工作表「${targetSheetName}」。`);

  await sheet.loadSheetData();
  const usedRange = sheet.getUsedRange();
  const rangeContents = await usedRange.getRangeContents();
  const matrix = rangeContents && rangeContents.result && rangeContents.result.Values;
  if (!Array.isArray(matrix) || matrix.length === 0) {
    throw new Error(`工作表「${targetSheetName}」没有返回有效内容。`);
  }
  return matrix;
}, '2026年9月');
```

实测本表：工作表 `2026年9月`，矩阵 **47 行 × 57 列**；第 0 行是标题 `2026年9月客服排班表`，第 1 行含 `日期` + 日期数字，第 2 行是 `星期` 行，第 3 行起是员工行。

## 第三步：读有效背景色（关键步骤）

```js
const colors = await page.evaluate(async ({ targetSheetName }) => {
  const sheet = window.APP.workbook.getWorksheets().getItemByName(targetSheetName);
  await sheet.loadSheetData();
  const usedRange = sheet.getUsedRange();
  const rangeContents = await usedRange.getRangeContents();
  const matrix = rangeContents.result.Values;

  // getAppliedXf 用绝对行列号；矩阵从已用区域左上角开始，要补偏移
  const entry = Array.isArray(usedRange._ranges) ? usedRange._ranges[0] : null;
  const rowOffset = Number((entry && entry.rowFrom) || 0);
  const columnOffset = Number((entry && entry.colFrom) || 0);

  const toHex = (value) => {
    if (typeof value === 'number' && Number.isFinite(value)) {
      return `#${(value >>> 0 & 0xffffff).toString(16).padStart(6, '0').toUpperCase()}`;
    }
    const text = String(value || '').trim().toUpperCase();
    const match = text.match(/^#?([0-9A-F]{6})$/);
    return match ? `#${match[1]}` : '';
  };

  const readColor = (rowIndex, columnIndex) => {
    // 关键：必须 getAppliedXf；getXfByCell 读不到条件格式的底色
    const appliedXf = sheet.getAppliedXf(rowOffset + rowIndex, columnOffset + columnIndex);
    const fill = appliedXf && typeof appliedXf.getFill === 'function' ? appliedXf.getFill() : null;
    if (!fill) return '';
    const type = typeof fill.getType === 'function' ? String(fill.getType() || '') : '';
    if (/none/i.test(type)) return ''; // eftPatternNone = 无填充
    const back = typeof fill.getBack === 'function' ? fill.getBack() : null;
    const backColor = toHex(back && typeof back.getRGB === 'function' ? back.getRGB() : '');
    if (backColor && backColor !== '#000000') return backColor;
    const fore = typeof fill.getFore === 'function' ? fill.getFore() : null;
    const foreColor = toHex(fore && typeof fore.getRGB === 'function' ? fore.getRGB() : '');
    return foreColor && foreColor !== '#000000' ? foreColor : backColor;
  };

  return matrix.map((row, rowIndex) =>
    (Array.isArray(row) ? row : []).map((_cell, columnIndex) => readColor(rowIndex, columnIndex))
  );
}, { targetSheetName: '2026年9月' });
```

实测结果（同一天同一批格子）：

- `getXfByCell` 全部返回 `eftPatternNone`，`getAppliedXf` 返回 `eftPatternSolid` + 正确颜色 → **底色来自条件格式**。
- 实心填充的可见色在 `back`；`fore` 是 `#000000`。转换：`14872793` → `#E2F0D9`。
- 兼容回退（14 号项目实测）：个别版本直接用内部结构 `applied.private.fill.private`，读 `type` / `fore.rgbValue` / `back.rgbValue`。公开 API 可用时优先用公开 API。

## 第四步：解析排班矩阵（按表头定位，别硬编码列号）

排班表是"转置"布局（`日期` 在表头行，日期是列，员工是行）：

```js
const headerRow = matrix.find((row) => Array.isArray(row) && row.includes('日期'));
const nameColumnIndex = headerRow.findIndex((cell) => String(cell || '').trim() === '日期');
// 姓名列 = 「日期」表头所在列；左侧列（nameColumnIndex - 1）是分组列
const dayNumber = targetDate.getDate();
let dateColumnIndex = headerRow.findIndex(
  (cell, index) => index > nameColumnIndex && Number(String(cell || '').trim()) === dayNumber
);
```

实测（2026年9月表，列号为 JS 数组下标，0 起）：`日期` 在第 1 列；员工姓名也在第 1 列；`1..30` 日从第 2 列开始；9 月 13 日在第 14 列。

解析班次映射时注意：

- 空姓名行必须跳过；再跳过结构/汇总行标签：`月份、日期、星期、职务、售前、售后、早班、晚班、休息、年假、行政、剩余、实到、应到、备注、上班人数`。
- 分组列 `售前/售后` 是**合并单元格**，只有分组首行有值，其余为空，所以 group 不是必填字段（1 号项目的 `buildDailyShiftMap` 不依赖它）。
- 班次缩写映射：`早→早班`、`晚→晚班`、`年→年假`、`行→行政`、空→`休息`。
- 每人当天结果：`{ employeeName, rawShift, normalizedShift, backgroundColor, hasBackgroundColor }`。
- `hasBackgroundColor` 的判定：有有效颜色且不等于 `#FFFFFF`（白底和无填充都算"无标记"）。

## 第五步：业务层怎么用底色（1 号项目的落地规则）

1 号项目「超时自动转接值班售前」的做法（`src/features/timeoutAutoTransfer/timeoutAutoTransferPolicy.js`）：

- 值班售前 = `normalizedShift === 期望班次(早班/晚班)` **且** `hasBackgroundColor === true`，按排班表从上到下取第一名（`Object.entries` 保持插入顺序）。
- `backgroundColorAvailable !== true`（颜色读不到）时**不转接**，保留原有提醒，不猜目标。
- 排班文字里的"早/晚"本身不是值班标记；值班标记唯一依据是单元格有效背景色。

14 号项目的售后 @ 规则可作补充参考：组长在班 → @；其他售后当日有班且底色非空非白 → @；白色 `#FFFFFF` 列入"非标记色"名单。实测色值：`#E2F0D9` 浅绿、`#FFFF00` 黄、`#BDD7EE` 浅蓝、`#FBE5D6` 浅橙、`#FF0000` 红（月份标记行）。颜色语义由表格/主管约定，不要自行扩展含义。

**重要坑（实测）**：2026-09-13 矩阵第 9 行（0 起）值为 `9月`、底色 `#FF0000`，它是月份标记而不是员工；同一天还有 1 格 `#FFFFFF`。必须先过滤空姓名/结构行，再叠加"班次 + 颜色"两个条件，不能"凡是有色就算值班"。

## 第六步：验收是否真的读全

脚本 `schedule-report.json` 会给出：

- 页面标题（本表为 `2026年【排班】表-客服部`）与最终地址
- 工作表名、矩阵行数/列数、已用区域偏移
- `背景色可读取: true/false`
- 当日有色单元格数和有色人员（姓名/分组/班次/底色，按排班顺序）
- 当日班次映射（全部员工）

2026-09-13 实测基线：工作表 `2026年9月`，47 行 × 57 列，颜色可读，6 名员工当天有色（徐佳楠/刘秀文 `#E2F0D9`，李守耀 `#FFFF00`，柯紫婷 `#FBE5D6`，邓远祥/陈燕玲 `#BDD7EE`），另有 1 格白底和 1 格红色月份标记。

跨月核对时：换 `--date` 后工作表名、日期列、有色人员都应跟着变；如果没变说明工作表名或列定位写死了。

## 第七步：落盘快照与缓存（生产里怎么做）

1 号项目的相关文件与做法，供需要长期运行的程序参考：

- `src/features/scheduleQuery/scheduleSheetFetcher.js`：打开浏览器、等就绪、读矩阵 + 底色，`finally` 里关浏览器。
- `src/features/scheduleQuery/scheduleMatrixParser.js`：表头定位、日期列定位、班次映射、TSV 导出。
- `src/features/scheduleQuery/scheduleStyleParser.js`：颜色归一化（整数/`#RRGGBB`/`rgb()` 都支持）与"是否标记色"判定。
- `src/features/scheduleQuery/dailyScheduleService.js`：按月缓存矩阵、按天缓存班次映射，一次进程只拉一次浏览器。
- `src/features/scheduleQuery/scheduleSnapshotStore.js`：把矩阵落成 TSV 快照；每次启动先清旧快照。**Windows 下清目录要区分文件和目录**（普通文件用 `unlinkSync`，目录才 `rmSync recursive`，直接对普通文件递归删除可能把 Node 进程带崩）。
- 命令行：`npm run schedule 员工姓名 2026-09-13 [url]`。

## 常见失败点

- 只用 `curl` 或只看 `body.innerText`：表格数据不在 HTML/DOM 里。
- 用 `getXfByCell` 读底色：条件格式全部丢失，返回 `eftPatternNone`；必须 `getAppliedXf`。
- 忘记 `usedRange._ranges[0].rowFrom/colFrom` 偏移：取到别的单元格颜色。
- 把 `getRGB()` 当字符串：实际是整数（`14872793` → `#E2F0D9`）。
- 把 `#FFFFFF`、无填充算作值班标记。
- 把班次文字"早/晚"本身当值班标记（1 号 issue #016 明确禁止）。
- 不先过滤空姓名/结构行就看颜色：会把 `9月` 红色标记行、汇总行误当员工。
- 硬编码工作表名或列号：跨月/改版直接失效；工作表名必须由日期推导。
- 固定 `sleep` 等页面：后台页 rAF 会停摆，要用 `waitForFunction` + `polling: 250`。
- 读取失败后猜值班并自动转接：应降级为保留原提醒、只提醒主管。
- 同一进程反复开浏览器抓同一张表：按月缓存一次即可。
- 匿名链接弹登录层不关：会遮挡页面、干扰等待；先点 `#util-popup .wps-login-panel__header__right button`。

## 安全与边界

- 只读：不写入在线文档，不修改排班表。
- 不保存、不打印 Cookie/token；需要登录态时只用本机浏览器画像。
- 底色是值班等业务标记的真源，但"哪种颜色代表什么"必须与主管确认，不要按颜色名字猜业务含义。
- 颜色读取不可用时宁可不转接/只提醒，也不猜测目标。
