## 只读访问方法（本目录唯一保留的用法）

* Playwright 自启浏览器（headless）打开 `https://mms.pinduoduo.com/goods/goods_list` → **列表渲染不出任何行**（`tbody tr` = 0），搜索也返回 0 行；直接拼 `?goodsId=` / `goods_edit?goods_id=` 之类的 URL 会**被弹回商品列表**。
* 可行做法：**原生 Chrome（可见窗口）+ 调试端口 + CDP**
  `chrome.exe --remote-debugging-port=9338 --user-data-dir="<拼多多店铺画像>" --no-first-run --start-maximized --new-window https://mms.pinduoduo.com/goods/goods_list`
  然后 `chromium.connectOverCDP('http://127.0.0.1:9338')` → 列表 10 行正常渲染，能读到商品名/ID/价格/库存/行内动作。
* 教训同 20号《风控平台人工登录》：**平台识别自动化浏览器**，自启浏览器会被挡；探测/人工登录都用原生 Chrome + 调试端口。

## 只读能读到什么

* 商品列表（`tbody tr` 里含 `ID: <商品ID>`）；行内「编辑」可打开编辑页（URL 形如
  `https://mms.pinduoduo.com/goods/goods_add/index?id=<内部id>&goods_id=<商品ID>&type=edit`，
  **`id` 是点击时才生成的内部 id，缺了会弹回列表**）。
* 编辑页里 SKU 规格名 = `input[placeholder="请输入规格名称"]`（同一商品多个框，顺序与规格值一一对应）；用于**核对文案口径**（例如是否写了「9升流量+96%氧浓度」这类容易误导的写法），核对完**只记录、不改**。
* 商品/SKU 批量数据更适合走**只读接口**：`POST /vodka/v2/mms/query/display/mall/goodsList`（本目录相关产物见 `D:/备份文件夹/探域问答审核-20260929/`）。

## 不要做（踩过的坑，写死）

1. **不要点「提交商品」/「发布」**——哪怕只是想验证一下；错点一次就是一次线上提交。
2. 不要在「规格名称」输入框里 `fill()`/`type()` 试改：值会被框架回滚（受控组件），而且**下一步很容易误点提交**（2026-09-29 就是这么走偏的）。
3. 要改商品（文案/价格/库存/上下架）→ 交**运营部**或客服主管走人工流程；木婉清只写建议、工单。
