# Pi 上下文 20 万自动压缩方案（v3：空闲触发 + 摘要上限自愈）

> 2026-09-13 更新。v1 解决"20 万触发"；v2 修掉"摘要撞输出上限反复失败"；v3 修掉"压缩打断正在跑的 run（This operation was aborted）"。
> 旧版备份：`C:\备份文件夹\pi-compaction优化-20260913\`（本机）。另一台照本文件执行即可。

---

## 【任务】

把目标机器 pi 配成"上下文到 20 万、在真正空闲时自动压缩"，并保证：
① 压缩摘要不会因为输出 token 上限反复失败；② 压缩不会打断正在进行的 agent run。

## 【背景】

**v1 的问题（已解决）**：曾把各模型 `contextWindow` 谎报成 200000，导致压缩请求自身溢出、卡死。
现已改为"保留网关真实窗口 + 扩展在 20 万触发"。

**v2 修的问题**：压缩时报

```
Error: Compaction failed: Summarization failed: generation hit the token cap and the summary is incomplete
```

根因（按 pi 0.85.1 源码核对，`dist/core/compaction/compaction.js`）：

1. 摘要输出上限写死：`min(0.8 × compaction.reserveTokens, model.maxTokens)`。
   旧值 `reserveTokens=16384` → 摘要只有 **13107 tokens** 的输出预算，与待总结内容多大无关。
2. 压缩请求**继承会话思考等级**（常见 `max`）。推理 token 与正文共用这 13107 → 推理吃掉预算、正文被截
   → 提供商返回 `stopReason=length` → Pi 判定"摘要不完整"直接抛错。
3. `length` 属确定性失败：不重试、无降级；压缩失败后上下文继续增长，下次再撞 → 表现为"经常遇到"。
4. 更新提示要求"PRESERVE 全部旧信息"，摘要只增不减，越用越容易撞上限。

**v3 修的问题**：压缩时屏幕出现

```
上下文 223k ≥ 阈值 200k，自动压缩中…
Error: This operation was aborted
```

根因：`ctx.compact()` 内部会先 `await session.abort()`。v2 在 `turn_end` 触发，而 `turn_end` 是"每轮 LLM 回复 + 工具调用"结束时的事件，此时多轮 agent run **可能仍在进行** → 压缩把当前 run 掐断，于是报 `This operation was aborted`（Node/undici 的 AbortError 文案）。

**v3 的做法**：

- 只在 `agent_settled`（run 及其自动重试、排队消息都结束、真正空闲）时触发压缩，`ctx.isIdle()` 为真才动手；
  此时 `abort()` 无事可做，绝不打断任务。
- run 途中的上下文暴涨交给**内置溢出安全网**（窗口 − `reserveTokens`）——它是原地压缩、不中断 run。
- 摘要撞输出上限时自动降思考重试一次（自愈）；仍失败只报警、不循环。

## 【扩展完整代码，直接写到 auto-compact-200k.ts】

```ts
import type { ExtensionAPI, ExtensionContext } from "@earendil-works/pi-coding-agent";

/**
 * 全局自动压缩：上下文达到 20 万 token 即压缩，与模型窗口无关 → 新模型自动生效。
 *
 * 余量设计（避免"卡死"）：
 *   1. 压缩本身要把待总结内容发给模型，所以触发点必须低于窗口上限 → 预留 HEADROOM。
 *   2. 窗口 < 20万 的模型（如 128k）提前到 窗口−HEADROOM，且不低于窗口的 50%。
 *   3. 单轮内暴涨由内置阈值（settings.compaction.reserveTokens）做溢出安全网，本扩展不接管。
 *      注意：reserveTokens 必须 <= HEADROOM，内置阈值才不会抢在扩展前面触发。
 *   4. 压缩后仍超阈值时，需再增长 RETRY_SLACK 才重试，防死循环。
 *   5. 摘要撞输出上限（reasoning 占满 maxTokens）时，自动降思考重试一次；再失败只报警不循环。
 *
 * 触发时机（重要）：
 *   ctx.compact() 会先 await session.abort()。若在 turn_end 触发，会把正在跑的多轮 agent run
 *   掐断，屏幕出现 "This operation was aborted"。所以本扩展只在 agent_settled（run 及其重试、
 *   排队消息都结束、真正空闲）时压缩，绝不打断正在进行的任务；
 *   run 途中的上下文暴涨交给内置溢出安全网（窗口 − reserveTokens，压缩原地完成、不中断 run）。
 *
 * 可用环境变量 PI_AUTO_COMPACT_TOKENS 覆盖目标阈值（一般不需要）。
 */
const DEFAULT_TARGET = 200_000;
const HEADROOM = 65_536; // 给模型回复 + 压缩请求自身留的余量（激进：提早约 6.4万）
const RETRY_SLACK = 20_000;
const MIN_WINDOW_RATIO = 0.5;

/** Pi 对"摘要被输出上限截断"的报错文案（compaction.js → getSummarizationFailure） */
const TOKEN_CAP_ERROR = /token cap|output token limit/i;

function targetTokens(): number {
	const raw = Number(process.env.PI_AUTO_COMPACT_TOKENS);
	return Number.isFinite(raw) && raw > 0 ? raw : DEFAULT_TARGET;
}

export default function (pi: ExtensionAPI) {
	let compacting = false;
	let lastCompactedTokens: number | undefined;
	// 摘要撞输出上限的自愈状态：一次失败周期内最多降思考重试一次
	let capRetryArmed = false;
	let capRetried = false;

	const notify = (ctx: ExtensionContext, message: string, level: "info" | "warning" | "error") => {
		ctx.ui?.notify?.(message, level);
	};

	/**
	 * 触发压缩。temporaryThinking 有值时临时改思考等级，
	 * 结束后仅当等级仍是我们设的值才还原，避免覆盖用户压缩期间的手动修改。
	 */
	const startCompaction = (ctx: ExtensionContext, temporaryThinking?: "off") => {
		compacting = true;
		const previousThinking = temporaryThinking ? pi.getThinkingLevel() : undefined;
		if (temporaryThinking) pi.setThinkingLevel(temporaryThinking);
		const finish = () => {
			if (temporaryThinking && pi.getThinkingLevel() === temporaryThinking) {
				pi.setThinkingLevel(previousThinking!);
			}
			compacting = false;
		};
		ctx.compact({
			onComplete: finish,
			onError: finish,
		});
	};

	const maybeCompact = (ctx: ExtensionContext) => {
		const usage = ctx.getContextUsage();
		if (!usage || usage.tokens === null || usage.tokens === undefined) return;

		const window = usage.contextWindow || ctx.model?.contextWindow || 0;
		let threshold = targetTokens();
		if (window > 0 && window - HEADROOM < threshold) {
			// 小窗口模型：提前到 窗口−HEADROOM，且不低于窗口 50%（防微小窗口震荡）
			threshold = Math.max(window - HEADROOM, Math.floor(window * MIN_WINDOW_RATIO));
		}

		if (usage.tokens < threshold) {
			// 已明显回落（压缩生效/切换小窗口模型），解除重试基线
			if (lastCompactedTokens !== undefined && usage.tokens < threshold * 0.9) {
				lastCompactedTokens = undefined;
			}
			return;
		}
		if (compacting) return;
		if (lastCompactedTokens !== undefined && usage.tokens < lastCompactedTokens + RETRY_SLACK) return;

		lastCompactedTokens = usage.tokens;
		notify(
			ctx,
			`上下文 ${Math.round(usage.tokens / 1000)}k ≥ 阈值 ${Math.round(threshold / 1000)}k，自动压缩中…`,
			"info",
		);
		startCompaction(ctx);
	};

	// 只在真正空闲时压缩：此时 ctx.compact() 里的 abort() 无事可做，不会打断任何 run。
	pi.on("agent_settled", (_event, ctx: ExtensionContext) => {
		if (!ctx.isIdle()) return; // 其它扩展又起了新 run 时让路
		maybeCompact(ctx);
	});

	// 摘要失败且原因是"输出 token 用尽"：多半是 max 思考吃掉了 maxTokens。
	// Pi 的压缩请求继承会话思考等级（无法单独配置），这里降为 off 重试一次。
	pi.on("session_compact_failed", (event, ctx: ExtensionContext) => {
		if (event.aborted) return;
		if (!TOKEN_CAP_ERROR.test(event.errorMessage ?? "")) return;
		if (capRetried) {
			notify(
				ctx,
				"摘要仍被输出上限截断：请调大 compaction.reserveTokens（摘要上限 = 0.8 × reserveTokens）",
				"error",
			);
			return;
		}
		capRetryArmed = true;
		// 等当前压缩流程收尾（catch/finally 会清状态）后再重试，避免新压缩被旧流程清掉
		setTimeout(() => {
			if (!capRetryArmed) return;
			capRetryArmed = false;
			capRetried = true;
			notify(ctx, "摘要撞到输出上限，自动降思考重试一次…", "warning");
			startCompaction(ctx, "off");
		}, 0);
	});

	pi.on("session_compact", () => {
		capRetryArmed = false;
		capRetried = false;
	});
}
```

## 【常见坑】

- **不要在 `turn_end` 触发压缩**：`ctx.compact()` 会先 abort，当前 run 会被掐断（`This operation was aborted`）。要等 `agent_settled` + `ctx.isIdle()`。
- 不要用 `ctx.setThinkingLevel`：扩展上下文里没有这个方法，要用 `pi.getThinkingLevel()` / `pi.setThinkingLevel()`。
- 不要把 `reserveTokens` 调回 16384：摘要上限会缩回 13107，思考一多就复现 v2 的问题。
- 不要把 `reserveTokens` 调得比 `HEADROOM` 大：内置压缩会抢在扩展前面触发，绕过"20 万 / 50%"规则。
- `model.maxTokens` 很小的模型（如部分网关限 64k 输出）上限仍是它本身，改 reserveTokens 无用，只能走自定义压缩。
- 压缩进行中不要提交新 prompt（Pi 会拒绝："Cannot submit a prompt while compaction is in progress"）。
