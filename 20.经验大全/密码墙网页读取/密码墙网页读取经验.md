# 密码墙网页读取经验（本机可见 Edge + 持久画像）

> 关键词：加密文档、密码访问、请输入密码访问、飞书 wiki、JS 渲染空壳、受控浏览器、Cookie 取数。
> 配套脚本：同目录 `密码墙网页读取.cjs`（只读，不打印 Cookie，不落盘密码）。

## 适用场景

页面属于下面任意一种，直连（curl / 云模型 HTTP GET）拿不到正文：

1. **JS 渲染空壳**：curl 只拿到几十~几百 KB 的加载壳，`<title>` 为空，正文靠前端 JS 渲染；
2. **密码墙**：无密码进入时标题是「没有权限访问 - 飞书云文档」之类，正文只有「请输入密码访问」；
3. **需要真实点击**才能展开的内容（读页面前要过一次按钮/确定）。

典型对象：飞书 wiki 分享链接、探域后台页面。

**不适用 / 不要做**：

- 需要人工验证（滑块、验证码、短信、扫码）→ 停下来叫人，把窗口留在可见状态（见"安全边界"）；
- 任何会真实提交或发送的动作（回传发票、企微发送、后台保存）→ 先问用户，本经验只管"读"；
- 借本经验绕风控、爬付费内容 → 不允许。只读用户已获授权的页面。

## 一句话结论

**云模型只能 HTTP GET，所以被密码墙拦住；解法是"本机可交互浏览器"——用 playwright-core 拉起本机 msedge、独立持久化画像（登录态落盘可复用）、headless:false 让用户肉眼可见，脚本负责输密码、点「确定」、读正文、截图验收。**

与相邻经验的边界：

| 情况 | 用哪份经验 |
| --- | --- |
| 静态页 / 直连能拿到完整 HTML | curl 即可，不必上浏览器 |
| JS 渲染但**已登录**、要抓接口响应（金山/WPS 在线文档） | `../金山在线Word文档读取/`（headless:true + 监听 response） |
| **密码墙** / 要肉眼可见、要真实点击 | 本经验（headless:false + 输密码 + 四件套验收） |
| 需要 Cookie 调探域接口 | 本经验"扩展"一节 + `17.探域科技AI自动配置/01.通用/平台适配/探域/探域平台API无头执行手册.md` |

## 第一步：先 curl 判断是不是空壳/密码墙

```powershell
curl.exe -sL -m 30 -A "Mozilla/5.0" -D - -o page.html "https://my.feishu.cn/wiki/分享ID"
```

- 文件只有加载壳、`<title></title>` 空 → JS 渲染，直接转浏览器；
- 正文含「请输入密码访问」→ 密码墙，按本经验输密码；
- 实测（2026-09-04）：飞书 wiki 直连得到 91K 空壳，无密码进入时标题为「没有权限访问 - 飞书云文档」。

## 第二步：关键代码（照抄）

```js
const { chromium } = require('playwright-core');

const ctx = await chromium.launchPersistentContext(
  'C:/Users/b3460/.pi-edge-auto',
  { channel: 'msedge', headless: false, args: ['--start-maximized'], viewport: null },
);
const page = ctx.pages()[0] || await ctx.newPage();

await page.goto('https://my.feishu.cn/wiki/分享ID', { waitUntil: 'domcontentloaded', timeout: 60000 });
await page.waitForTimeout(6000); // 等 JS 把密码框渲染出来

// 输密码（密码从环境变量/本地文件取，不要写死在脚本里）
await page.locator('input[type="password"], input[type="text"]').first().fill(process.env.PAGE_PASSWORD);
await page.getByRole('button', { name: /确定/ }).click();
await page.waitForTimeout(8000);

// 读数
console.log(await page.title());
console.log(await page.url());
console.log(await page.evaluate(() => document.body.innerText.slice(0, 4000)));
await page.screenshot({ path: '页面截图.png' });
await ctx.close();
```

要点：

- `launchPersistentContext` + 独立 `user-data-dir`：登录态、设备信任落盘，下次免重复登录；
- `headless: false`：出问题时用户能直接看到现场，也便于人工接管验证；
- 密码框用 `input[type=password]`（飞书可能渲染成 `type=text`，故选择器带回退）；
- 按钮用 `getByRole('button', { name: /确定/ })`，不要用坐标点击；
- **等渲染要留时间**：`domcontentloaded` 之后再加 6s + 提交后 8s 是实测可用的量级。

上面这段已落地成脚本 `密码墙网页读取.cjs`（同目录），不要再重写一份：

```powershell
$env:NODE_PATH = "D:\桌面\办公软件\1.客服超时督办\node_modules"
$env:PAGE_PASSWORD = "<密码>"

node "密码墙网页读取.cjs" `
  --url "https://my.feishu.cn/wiki/分享ID" `
  --password-env PAGE_PASSWORD `
  --out "C:/Users/b3460/.pi-edge-work" `
  --profile "C:/Users/b3460/.pi-edge-auto"
```

密码三种给法（按推荐顺序）：

1. `--password-env 变量名`：推荐，密码不出现在命令行；
2. `--password-file 路径`：密码写在本地文件（该文件不入库）；
3. `--password 值`：会进命令行历史，仅临时用。

常用参数：`--keep-open`（读完不关浏览器，留给人看）、`--headless`（默认关闭，无头=看不见）、`--no-submit`（只打开不输密码，用于确认页面长什么样）、`--wait-before` / `--wait-after`（毫秒）、`--button-name`（按钮文字正则）、`--input-selector`、`--text-limit`。

脚本读完会落盘：`页面正文.txt`、`页面截图.png`，并打印 `TITLE` / `URL` / 正文开头；检测不到密码框或仍在"没有权限访问"页会以非 0 退出并明确报错。

## 第三步：验收四件套（只认真实产物）

每次读取都核对这四项，缺一不算成功：

| 项 | 应有值（示例） | 实有值（脚本打印） |
| --- | --- | --- |
| `page.title()` | 文档真实标题，不是「没有权限访问」 | `TITLE ...` |
| `page.url()` | 目标地址（可能带 ?from=... 之类，属正常） | `URL ...` |
| `document.body.innerText` | 正文片段，含关键小节/首末内容 | `TEXT ...` |
| 截图 | 肉眼可见内容，不是密码框 | `页面截图.png` |

常见坑：通过密码墙后 URL 可能变跳转地址、正文可能延迟渲染——所以"提交后 8s"是下限不是上限，内容多时用 `--wait-after` 加大；判定标准是**正文里找得到首末关键内容**，不是页面不报错。

## 扩展：同理读探域后台 / 取 Cookie 调接口

1. 打开页面后，F12 → 控制台 → `document.cookie` 拿 Cookie，再 `curl -b "Cookie"` POST `http://agent.tanyuai.com/api/...` 调接口。
2. 更稳的做法是**不导出 Cookie**，直接在已登录页面的上下文里发请求，让浏览器自己带凭证：

```js
const data = await page.evaluate(async () => {
  const r = await fetch('/api/...', { method: 'POST', credentials: 'include', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({}) });
  return r.json();
});
```

3. 要确认页面"确实点到、确实在该平台"，用同款 `launchPersistentContext` + `page.evaluate` + 截图，验收截图里 TITLE 应为「探域科技」。
4. 探域接口的完整只读模板见 `17.探域科技AI自动配置/01.通用/平台适配/探域/探域平台API无头执行手册.md`；Cookie 只留本机，不进分享包、聊天和日志。

## 弱模型照做清单

1. **先 curl 试**，拿到空壳/「请输入密码访问」再转浏览器，不要一上来就开浏览器。
2. **独立 user-data-dir**（`C:/Users/b3460/.pi-edge-auto`），`headless:false`，让用户肉眼可见。
3. 密码框用 `input[type="password"]` 定位（回退 `input[type="text"]`），按钮用 `getByRole('button', { name: /确定/ })`。
4. **每次 title/url/innerText/screenshot 四件套验收**，并给出"应有值 vs 实有值"。
5. 登录态/密码**只存本机**，不发云端、不写进笔记和提交记录。
6. 超过预期等待仍无新输出（无日志也无报错）= 按卡住处理，停下来查现场，不许静默干等。
7. 出现滑块/验证码/短信/扫码：**停下来叫人**，窗口留在可见状态，不要乱点。
8. 只读；要提交/发送/保存的动作先问用户。

## 常见失败点

- 只用 curl：永远只有空壳，误判为"页面没内容/没权限"。
- 用日常 Edge 主画像：既污染用户浏览器，又可能因已开进程导致 `launchPersistentContext` 报 user-data-dir 被占用；用独立画像。
- 选择器写死坐标/文案：页面改版即失效，优先 `type`、role、`placeholder` 等语义定位。
- 输密码后立刻读数：密码校验 + 正文渲染没跑完，拿到的是密码页；提交后固定留 8s 起步。
- 密码进脚本/命令行/笔记：本经验与配套脚本一律不存密码，示例里用 `<密码>` 占位。
- 把「没有权限访问」的标题当成功：脚本检测到标题仍匹配权限关键词会非 0 退出，人工复核不可省。
- 同一画像多个脚本同时跑：Edge 同 user-data-dir 只能一个进程，会直接报占用；串行执行。

## 安全边界

- 登录态、Cookie、密码仅保存在本机；不在日志、笔记、提交或云端消息中输出。
- 只读已授权的页面；读取成功 ≠ 授权修改/导出转发。
- 人工验证（滑块/验证码/短信/扫码）必须停下来叫人。
- 任何会真实提交或发送的动作（发票回传、企微发送、后台保存）必须先问用户。
