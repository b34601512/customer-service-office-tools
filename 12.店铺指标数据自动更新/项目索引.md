# 12.店铺指标数据自动更新 · 项目索引

> 开工先看：**本页** → `断点记录.md`（最新状态/观察项）→ `README.md`（完整用法）→ `CLAUDE.md`（模块）。
> 总规矩：根 `../AGENTS.md` + `../0.木婉清档案/规矩与红线.md`。最后整理：2026-10-09。

## 一、这个项目干嘛的
多平台多店铺（京东2 / 天猫3 / 拼多多2 / 抖音2）读取平台官方**店铺考核指标** → 覆盖/追加写入本地 `店铺指标数据源.xlsx` → 可一键**金山同步**「数据源」（12 列逐格镜像）。纯 CLI 控制台。

## 二、规矩 / 口径
- **平台后台只读**：只读考核页；要人工登录/验证/切店时自动切**可见 Chrome**，不绕过验证（`README.md`「运行边界」）。
- 浏览器固定 **Google Chrome**：京东直接可见窗口、复用原长期账号资料，不受 headless 开关影响；其他平台默认 hybrid；抖音同账号多店共享登录资料。
- **运行前必须关闭汇总表**：WPS/Excel 占用时在登录任何店铺前停止，不硬关表格（`README.md`）。
- 凭证：只存**文字**（URL+正文），**2026-09-16 起不存截图**；失败也要有"失败原因"凭证，不许失败却无凭证。
- 单项指标无值 → 写 `0` 并标注"无数据记0"，**不判整店失败**；整店失败继续下一家，最后列成功/失败。
- 当天同店、同统计方式、同来源已成功 → **skipped 复用缓存**；失败记录**不**阻止重试。
- 金山同步：先清空在线「数据源」，再从 A1 镜像本地 12 列，**旧尾行/旧列必须为空、逐格一致**才算成功。
- 数据源只留一个"采集日期"；平台自己的统计窗口写进"原始统计窗口"备注。

## 三、经验 / 踩坑
- **弹窗关闭口径**（2026-09-18 根因修复 `d3c5d5f`）：`src/shared/blockingPopupEngine.js` 统一用 computed style 判"弹层还在不在"；点击失败先读现场（已隐藏→按已关闭继续；仍在不推进→抛原始错误，**不猜点、不静默吞错**）。测试 `tests/blockingPopupSelfDismiss.test.js` 锁死；其它平台共用此引擎。
- **kdocs 回读与筛选坑**：目标表开着"筛选"会把整表回读误判成不一致 → `../20.经验库/kdocs回读与筛选/`。
- 观察项（断点 §四）：运行结束进程退出阶段 `libuv async.c` 断言、exit=127——产物正确但退出码误导，**再出现 1 次升级为规律**再动手。
- 失败先查 `../失败台账.md` 尾部同类条目（弹窗类先看上面口径）。

## 四、常用命令
```bash
cd "D:/桌面/办公软件/12.店铺指标数据自动更新"
node scripts/runSummaryAndKdocsSync.js   # 等价 TUI「2 开始汇总」+「5 一键同步数据源」
npm test                                 # 153 项
npm start                                # 或双击 启动控制台.bat
```
- 日志：`runtime/logs/p5-summary-kdocs.log`（每次覆盖）；数据源 `outputs/<id>/店铺指标数据源.xlsx`。
