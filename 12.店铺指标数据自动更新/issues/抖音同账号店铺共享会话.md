# 抖音同账号店铺共享会话

## 意图

抖音多个店铺属于同一个登录账号；同一批次首店完成登录并采集后，后续店铺复用当前会话，只校验当前店铺并执行切店。

## 背景

- 2026-09-10 抖音03店采集成功后，程序关闭了 Chrome，再为抖音05店重新启动登录流程。
- 05店现场仍停留在已登录的03店页面，但切店入口因页面初始化竞态未被识别，最终报“识别到0个可见切换组织/店铺”。
- 配置和浏览器资料目录已经是抖音共享账号，但批量调度没有共享浏览器生命周期。

## 验收清单

- [x] 同一批次抖音店铺只创建一个共享浏览器会话。
- [x] 首店登录/人工接管后的会话传给后续抖音店铺。
- [x] 后续店铺先复用已登录页面，再执行当前店铺身份校验和切换。
- [x] 切店入口延迟挂载时有限等待并重试，不使用坐标或强制点击。
- [x] 店铺 ID 读取兼容空格、冒号和异步渲染。
- [x] 定向测试通过（17/17）。
- [x] 全量测试通过（120/120）。
- [x] 现场重跑确认抖音05店最终成功写入14项；本轮抖音03店因今日已有数据被跳过。
- [ ] 用户现场强制重跑抖音03店、05店，并确认两店均成功。

## 边界

- 不把不同抖音账号合并到同一会话；本规则只适用于配置为同一共享登录资料的抖音店铺。
- 不绕过验证码、滑块或安全验证。
- 不修改本次问题无关的既有工作区改动。
