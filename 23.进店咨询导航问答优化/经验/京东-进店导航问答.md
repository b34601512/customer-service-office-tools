# 京东 · 进店导航问答（2026-09-21 实测 jd1 德达官方旗舰店）

## 一、入口在哪（本次花时间最多的点）

用户给的 URL `https://xi.jd.com/kf-manage-lite/#/UtilsSetting/AutoReply` 打开后**默认落在「欢迎语」模块**，左侧只有三个 tab：**基础欢迎语 / 常见问题库 / 商品卡片欢迎语**。

**「进店导航自动回复」不是独立菜单，它就叫「常见问题库」。**

「常见问题库」下有两个子 tab：
- **常见问题管理** —— 配置问题 & 回复，标题显示 `添加常见问题（7/10）最多可以添加10个`
- **常见问题数据** —— 每条问题的**近7日点击量** + **最近修改时间**

**怎么找到的**（可复用的排查法）：probe 页面 dump 文本 → 全文没有"进店导航"字样 → **看截图**发现左侧"常见问题库" → 点进去才看到问题列表和点击数据。

> 教训：菜单名可能和功能名不一致（叫"常见问题库"而不是"进店导航"），**找不到就先 dump 文本+截图看全貌**，不要死磕关键词。

## 二、页面结构（jd1 实测）

**常见问题管理**：序号 ｜ 问题 ｜ 回复 ｜ 图片 ｜ 操作（预览/编辑/删除）

## 四、分析口径（怎么判断"要不要优化"）

按这个顺序查：

1. **重复条目** —— 同一问题两种问法 → 客户只会点排在前面的 → 后面的删掉腾名额。
   （实例：第 3 条 28 次 vs 第 6 条 1 次，是同一个"24小时连续用"问题）
2. **低效条目** —— 点击 ≤1 且半年未改 → 候选删除。
   （实例：「如何申请国家补贴」1 次、「可以自动制氧吗」1 次）
3. **缺高频** —— 对照客户实际最常问的（来源：**效果预览图里的默认项**、客服聊天高频、售后工单），库里没有的就是空缺。
   （实例：预览图展示「发什么快递？/什么时候发货？」，但**库里根本没有这两条**；也没有退换货/保修/发票类）
4. **名额** —— 上限 10 条（7/10 → 加 3 条前要先删）
5. **改动前必须先问用户**，不要直接动后台。

## 五、踩坑

- **URL 是 hash 路由，tab 切换靠点击**：`goto` 同一个 URL 不会换视图（三个 tab 的 URL 完全一样）。
- **侧栏 tab 是 `div`，没有 `<a href>`** → 用 `a[href]` 找菜单是空数组，要按文本找元素再 `.click()`。
- **页面文本很短（312 字）不是白屏**：这个后台内容本来就少（欢迎语页 321 字）。别套用"200 字=白屏"的判断（那条针对的是**内容页**）。
- jd1 用的 CDP 端口 **9424**（与 22号、京东售后台账共用同一个浏览器 profile）。

## 六、给其他平台的通用方法（待扩展）

1. **找入口**：从「客服 / 客服管理 / 自动回复 / 机器人 / 接待设置」一类菜单里找「常见问题 / 导航 / 猜你想问 / 咨询导航」。
2. **找数据**：同一模块下一般有「数据 / 统计 / 效果分析」子 tab，重点看**点击量 / 曝光量 / 点击率**。
3. **判优化**：重复 → 低效 → 缺高频（再看名额是否满）。
4. **沉淀格式**：每平台一节，写清 ①入口路径 ②页面结构 ③实测数据 ④分析口径 ⑤踩坑。

## 七、客户端显示规则（2026-09-21 实测，重要）

点自家客服窗口看到的默认形态（商品页 → 客服图标 → `jdcs.jd.com`）：

> 德达旗舰店专注制氧15年…性能稳定。
> 制氧机要加制氧剂吗？ / 制氧机需要加水吗？ / 买了制氧机还需要买别的吗？ / 制氧机可以无限产氧吗？能24小时连续用吗？ / **查看更多**

- **只展示 4 条**，其余折叠在「查看更多」里
- **展示顺序按近7日点击量排**（后台表格顺序 ≠ 客户端顺序）
- **推论：点击量 0-1 的条目不进前 4 → 客户端根本看不到**。所以「0 点击」不等于客户不关心，而是根本没机会被点。
- 优化后新增的条目从 0 点击起步，**前 4 条不会立刻换**，要等点击积累。

## 十、写回复文案的硬规则

1. **不要 emoji / 特殊符号**（用户 2026-09-21 明确：容易乱码）。✅ ⭐ 📍 这类一律不用。
2. **问题 ≤30 字、回复 ≤400 字**（后台硬限制，超了存不进）。
3. **用客服真实话术**（来源：19号聊天质检 `runtime/outputs/raw-*.txt`），不要自己编时效和承诺。
4. 中文引号「」和波浪号～可保留（不是 emoji，不乱码）。

## 十一、踩坑：React 富文本框填不进去（务必看）

「添加/编辑常见问题」弹窗里，**回复是 contenteditable 富文本**。

- **用 `execCommand("insertText")` 或直接设 innerText** → 视觉上字进去了，**但 React 状态没更新**（字数计数仍显示 `0/400`），点「确定」无效：弹窗不关、数据不保存。
- **正确做法**：用 Playwright 原生 `locator.fill()`（会派发标准 input 事件），**并校验字数计数器**（`n/30`、`n/400`）确认 React 状态真更新了，再点确定。
- **每步操作后回读校验**（问题文本、回复前 20 字），不一致立即中止 + 截图，不要盲连点。

## 十二、jd3 优化实录（2026-09-21）

**9 条 → 10 条（名额满）**

- **去 emoji**：多条回复里共约 20 个 ✅/⭐/📍 全部清掉（用户要求：emoji 容易乱码）
- **两条 0 点击的书面问法改口语**（原本点击量 0 → 客户端根本看不到，等于白占名额）：
  - 「制氧机适用人群」→「**哪些人可以用？老人孕妇能用吗？**」
  - 「制氧机怎么选择？」→「**怎么选机型？几升够用？**」
- **补 1 条**：「买了制氧机还需要买别的吗？」（照 jd1 有 25 点击的经验）
- **改回复不改文案信息**：只做符号清理 + 排版整理，不重写内容（避免丢掉原文细节）
- **验证**：改问题文本/回复**不会重置点击量**（原名 0 点击的条目改名后仍是 0）

## 十三、jd-faq-apply.js 进阶用法

```bash
# 导出当前配置（逐条点「编辑」读回问题+回复）
node src/tools/jd-faq-apply.js --config <任一配置> --port 9425 --store jd3 --dump-config config/jd3-当前配置.json
```

- **keep 支持 `from` 字段**：`{ "from": "旧问题文本", "question": "新问题文本", "reply": "..." }`
  —— 用于**改问题文本**，`from` 只负责在页面里定位，`question` 是改后的文本。
- **幂等**：删不存在的跳过、加已存在的跳过、改的按问题前缀匹配 → 可以放心重跑。
- **坑**：导出时每条会读到 2 次（每行有 2 个「编辑」按钮），**导出后按 question 去重**。
- **坑**：填内容后必须校验 React 状态（字数计数器），否则会"看着填上了其实没保存"。

## 十四、文案来源与禁忌（2026-09-21 用户多轮纠正后定稿，重要）

### 文案必须有真实来源，按优先级取
1. **同品牌其他店的现成后台配置**（如 jd3 已有答案 → 直接搬过来）—— **最权威**
2. **客服聊天记录原文**（19号 `runtime/outputs/raw-*.txt`）
3. **用户直接给的口径**（如雾化条：「带L结尾或W结尾的支持雾化，比如Q5W,Q5L,1SW」）
4. 都没有 → **不要写具体数字/承诺**，写"可以咨询客服帮您确认"，或者直接问用户

**教训（我犯过）**：v1 自己编了「发票 1-3 个工作日」→ 实际是「**7 个工作日内**」；编了「滤芯 1-3 个月换」→ 实际是「**每 200 小时检查、变深黑就换、送一套备用**」。
**编的内容一定会被用户抓出来。**

### 禁忌（用户明确）
- **不要 emoji / 特殊符号**（容易乱码）
- **不要放「活动/赠品」这类会过时的条目** —— 写了等于没答
- **不要主动提产品弱势项**（如噪音多少分贝）—— **问了才答，不自己端出来**；且型号不明时这类问题根本答不了
- **问题要跟型号无关** —— 客户进店咨询时没说问的是哪款，型号相关的问题（几升、分贝、浓度）答不了

### 可用的"通用型"问题
怎么用／怎么清洁保养、哪些人适合用、买了还要不要配别的、滤芯等耗材多久换、质保政策、快递时效、发票怎么开、怎么退换货。
