# 一单多行（一单多主件 / 主件+赠品）怎么写（2026-10-08）

> 现场：表① 第 2781 行（拼多多02店 `260926-***********0863`）只登了逆变器、整单 697.96 全记在它头上，主机 DH22-C1L 漏登记。
> 根因=旧 `生成写表数据` 只有「主明细第 1 条 + 第 n 个赠品」两个口子，一单里**第 2 条非赠品明细没有写法**。
> 修法：`src/发票规则.js` 支持按行拆（`行列表`），测试锁死 `tests/发票规则-一单多主件.test.js`。

## 一、生成（`生成写表数据`）

- **`行列表`**：主件行按 **ERP 顺序**在前、赠品行在后；每行带 `行序号`（1 起）/`是否主行`。
- **金额**：多主件时主件行 `Y` = **该行** ERP `买家支付金额`（=让利后金额）；赠品行 `Y`=0；
  单主件（含赠品）照旧：主件行 `Y`=开票金额（平台覆盖金额也走这条），**老口径不变**。
- **对账**：`金额差额` = 订单金额（**平台金额优先**，没有平台金额才用开票金额）− 各行 `Y` 合计。
  ≠0 → `对账提示`，**不自动凑数**；差额**不塞进 `待人工`**（由上层决定：写备注还是问客服）。
  现场例：2 主件 104.70+593.30=698.00，平台 697.96 → `金额差额 = -0.04` + 提示。
- **选行**：`行序号`（1 起，优先于老参数 `明细序号`）；`明细序号` 仍照旧（1/2…=第几个赠品）。
- 老清单条目（没有逐行 `买家支付金额`/`让利后金额`）遇多主件 → 逐行报缺金额、`金额差额=null`，
  **不许写 0 顶替**；重跑 `node scripts/生成待登记清单.js …` 生成的新条目会带上这两列。

## 二、落表（逐行写，按 1..n 顺序）

1. `node scripts/干跑.js --订单号 <单号> --表 "<子表名>"` → 看 `行列表`、`金额对账`（只算不写、留证据）。
2. 第 1 行：`node scripts/写登记表.js --订单号 <单号> --表 "<子表名>" --行序号 1 --已确认`（**必须最先后写**；带全表查重）。
3. 第 2..n 行：`--行序号 2`、`3`…（**续行**：同订单号是预期的，跳过查重；回读走探针「末行=刚写那行」）。
4. S 备注：`node scripts/写同单备注.js --订单号 <单号> --表 "<子表名>" --行 <第 1 行> --已确认`
   （文本「同一个订单发票开一起」；写后回读确认）。
5. 合并：`node scripts/合并同单T列.js --订单号 <单号> --表 "<子表名>" --已确认`（默认只合并 **S**，
   要求行相邻——所以必须按行号顺序写、中间别插别的单）。
6. 验收：`node scripts/查登记表.js <订单号> --行 …` 逐行回读；确认 S/合并区间。

## 三、红线

- **顺序不能乱**：第 1 行没写就先写第 2 行 = 没查重就写（可能重复登记=重复交税）。续行跳过查重的前提是「第 1 行已写」。
- **差额 ≠0 先问客服**（怎么落：备注写差额还是改金额），没答案不写；原因读不到**不猜**。
- 公式列（C/D/E/T/W/X/AO）一律不写；U 型号照表里先例抄，拿不准问客服。
- 表①/表②列字母一致（2026-09-30 起）：S 都是备注列、T 都是品名公式列（**T 绝对不能碰**）。
