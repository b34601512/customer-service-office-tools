## ② 规矩 / 口径（一句话 + 出处）
- **六道闸门（不可变）**：字段不全拒写 → 未授权不写（连查重都不跑）→ 云端查重命中拒写 → 写入 → 写后回读恰好 1 行且行号一致 → 验收 4 条全过（目标行=期望、J=本单、其它行一字未变、下一可写行=目标+1）→ [`验收清单.md`](./验收清单.md)。
- **个人票 AA/AB = 收货人姓名**（抬头后台只写「个人」时填**收货人姓名**；AA 与 AB **同值**；不因缺税号拒写）——黎路遥 2026-10-09 重申 → [`经验/发票登记-口径笔记.md`](./经验/发票登记-口径笔记.md) §1。
- **金额按平台后台为准**（平台≠ERP → 备注写差额与原因，**不猜不编**、不单独登差额行）→ 口径笔记 §2。
- **写前查重（硬规则）**：表①/集团表**各自**用 AirScript 云端全表查（网页读会假阴性）；**重复登记=重复交税**，命中即停 → 验收清单 第 5 步 + `npm run 查重 -- <订单号>`。
- **ERP 查单两段式**：单不在数据源 → 先 ERP「订单查询」按单号**定日期** → 再导「订单商品明细统计」（或订单查询直接取数）→ [`../../20.经验库/ERP查单两段式/`](../../20.经验库/ERP查单两段式/)。
- **一单多行/一单多主件**：主件+赠品各一行、一单多主件逐行写、**按行号 1..n 顺序**（第 1 行带查重、续行跳过）；合并只合并 S 备注 → [`经验/一单多行-多主件怎么写.md`](./经验/一单多行-多主件怎么写.md)。
- **赠品**：ERP 能查到的赠品就一并登记（该行 Y=0）；**查不到就不登**（不猜、不硬凑）→ 同上 + 验收清单「赠品行」。
- **谁检查**：谁让登记就让谁检查；他下班才换值班同事并**写明原因** → 口径笔记 §3。
- **收尾**：写售后待办（`--owner` 提出人；不在岗才 auto）交人工检查；**平台点审核/同意我们不碰** → 验收清单「收尾」。

## ④ 常用命令（完整标准流程看 `验收清单.md`）
```bash
cd "2.发票自动化/7.自动登记发票"
npm test                                        # 单测（不触网、不写表）
node scripts/云端自检.js --表 "<子表名>" --写脚本 <w> --读脚本 <q>   # 粘/改云端脚本后先验
node scripts/干跑.js --订单号 <单号> --表 "<子表名>"                 # 只算不写
node scripts/写登记表.js --订单号 <单号> --表 "<子表名>" --已确认     # 唯一会写（要授权）
# 表① 默认脚本 write；表② 加 --脚本 write_jituan --读脚本 query_jituan
```

## ⑤ 红线
- 写表**逐次授权**；不重复登记；公式列（C/D/E/T/W/X/AO）一个不碰、**T 列绝对不能碰**。
- 平台后台只读；天猫「待同意」永不点；回传要当次授权；拿不到就停、问人，不猜不编。
- 真实链接/人名/订单号不进仓库（只落 `project-config/`，不入库）；失败不自动重试。
