# 7.自动登记发票

> 目标：把「客户要开发票」之后的**登记环节**自动化——从平台后台拉到待登记订单，按规则算好金额，写进（或先出清单给人确认）金山发票登记总表。
> 归属：`2.发票自动化` 的第 7 个子项目，复用根上的 `共享CLI/`、`共享订单状态/`、`共享发票回传/` 能力。
> 阶段（2026-09-30）：**v0.2 写入链路已就绪**——在 v0.1（只读算单）基础上补齐**登记写入**：
> 本地 `scripts/写登记表.js` + 云端 AirScript v4（写入模式，默认关闭）。四道闸门：字段不全拒写 → 未授权不写 → 云端查重命中拒写 → 写完回读必须 1 行。
> **还差一步：用户把 v4 脚本在文档里粘一次并保存**（脚本名/同步地址不变），然后就能真实写入。
> v0.1（2026-09-28）：「企微消息 → 拼多多发票中心 → 管易ERP → 按规则算 → 待登记条目」，29 项单测全过。
> 还缺：集团登记总表链接对应自己的同步地址（可选）。

## 写表前必读：店铺 ↔ 登记表映射（2026-09-30 用户提醒）

- **写错表 = 登记到别的公司主体**，比写错行更严重：写前必须按店铺查映射。

## 业务红线（继承 `2.发票自动化/CLAUDE.md`）

- **天猫发票「待同意」单：绝对不许自动点「同意」**（先登记、后同意，自动化抢点会导致漏处理）。
- **任何真实提交/写入的动作（登记发票、回传发票、企微发送）必须先问用户**。
  本项目的默认产物是**待登记清单**（只读 + 计算），写入动作单开一步、逐次授权。
- **禁止重复登记**（= 重复交税）：**写表前必须先按订单号全表查重**，且只能信 AirScript 云端结果
  （网页匿名读只加载窗口，会“假未登记”，2026-09-28 实测：真实 7910 行、匿名只回 489 行）；
  命中 → 停止，不写；同时核对是否已开电子发票。命令：`npm run 查表 -- <订单号>`。
- 滑块/验证码/短信登录 → 停下来叫人。

## 验收清单（每单必须逐项过）

| # | 检查项 | 怎么看 | 不通过怎么办 |
|---|---|---|---|
| 1 | 消息解析齐全 | 店铺/订单号/票种/抬头/税号 都解析出来（缺项会报） | 缺项回问客服，不自编 |
| 2 | 平台金额 | 拼多多发票中心「应开金额」= 平台口径 | 读不到就停，不猜 |
| 3 | ERP 金额 | ERP CSV `买家支付金额`（注意平台单号尾部有 `\t`，要 trim） | 单子不在本次导出范围 → 重新导 ERP，不自编金额 |
| 4 | 金额规则 | 开票金额=买家支付，两位小数；平台支付/其他服务费不开；差额=平台应开-开票金额 | 差额≠0 或赠品/退款/作废 → 标「待人工确认」 |
| 5 | **先查重（硬规则）** | `npm run 查表 -- <订单号>`（AirScript 云端全表；**不许用网页读法当依据**） | **命中 → 停止，不写表**（重复登记=重复交税） |
| 6 | 写表数据（含 O 列登记客服=**AI助手**） | `npm run 写表数据` → 只出我们该填的 12 列；公式列（C/D/E/T/W/X/AO）一个都不写 | 拿不准的列留空并标出来 |
| 7 | 写表动作 | **逐次问用户**（业务红线） | 用户没回 → 只停在待登记清单 |
| 8 | 写完回读 | 再查一次订单号，确认只出现 1 行（不是 2 行） | 出现 2 行 → 立即报告用户（涉及交税） |

> 单字段数据来源与列字母：`经验/登记表字段与数据来源.md`（2026-09-28 拿第 2751 行真实登记逐项核对过）。

## 登记写入（v0.2，2026-09-30）——唯一会真写的入口

```bash
cd 2.发票自动化/7.自动登记发票
node scripts/写登记表.js --订单号 <订单号>              # 只出「将要写入的列」，一个字不写（不触网）
node scripts/写登记表.js --订单号 <订单号> --已确认      # 用户当场点头后才带这个参数
```

四道闸门（顺序不能改，单测锁死 `tests/登记写入.test.js`）：
1. **字段不全拒写**：`生成写表数据` 报任何「待人工」项 → 停（不自编字段）。
2. **未授权不写**：没有 `--已确认` → 连云端查重都不跑，只把要写的列打出来。
3. **云端查重**：写前用 AirScript 全表查订单号，命中 → 拒写并回报命中行号（**重复登记=重复交税**）。
4. **写完回读**：订单号必须恰好 1 行且行号=写入行；出现 2 行/行号不符 → 报错要人工核对。

云端脚本：**读/写分两份**（用户 2026-09-30 定：读脚本不动）。
- 读：`AirScript-只读查询订单号.md`（已生效，勿动）——查重展示/按行读/诊断。
- 写：`AirScript-登记写入-独立脚本.md`（**本机文件，不入库**）——**新建**一个 AirScript 脚本「登记写入」，粘全文保存，再生成**它自己的同步 webhook**，填进本机 `project-config/kdocs-airscript.json` 的 `scripts.write.webhookUrl`。
- 写入脚本自带安全探针：`node scripts/写登记表.js --探针` → 只回 `scriptVersion/lastDataRow/nextWriteRow`，**一个字节都不写**（用来确认已保存生效）。

写入协议（本地 → 云端）：
```json
{"Context":{"argv":{"orderNo":"260903-…","writeCells":{"A":46295,"F":"正常","G":"普票","I":"拼多多02店","J":"260903-…","O":"AI助手","U":"DH22-C1","V":1,"Y":374.12,"AA":"抬头","AB":"税号","AK":46268},"allowWrite":true,"sheets":["德达医疗器械发票登记 --毛叶红"]}}}
```
返回：`{mode:'write',written,row,writtenColumns,failedColumns,readBack,duplicate}`；查重命中时 `{written:false,duplicate:true,row:命中行}`。
可写列只有 14 个：`A/F/G/I/J/K/L/O/U/V/Y/AA/AB/AK`（公式列 C/D/E/M/T/W/X/AO 一个都不碰）。

## 一单多行 / 一单多主件（2026-10-08 补，组合商品/套装）

> 背景：工具原来只有「主明细第 1 条 + 第 n 个赠品」两个口子，一单里第 2 条非赠品明细写不出来
> （现场：表① 第 2781 行只登了逆变器、整单 697.96 全记在它头上，主机 DH22-C1L 漏登记）。

`生成写表数据` 现在返回 `行列表`（**主件按 ERP 顺序在前、赠品在后**，每行带 `行序号/是否主行`）：
- 多主件时主件行 `Y` = **该行** ERP `买家支付金额`（=让利后金额）；赠品行 `Y`=0；单主件老口径不变（`Y`=开票金额）；
- `金额差额` = 订单金额（**平台金额优先**）− 各行 `Y` 合计；≠0 时连同 `对账提示` 返回，**不自动凑数**。

落表步骤（**逐行、按 1..n 顺序，别跳行**）：

```bash
# 1) 看全量行列表与差额（只算不写）
node scripts/干跑.js --订单号 <单号> --表 "<子表名>"
# 2) 第 1 行（必须最先后写；带全表查重）
node scripts/写登记表.js --订单号 <单号> --表 "<子表名>" --行序号 1 --已确认
# 3) 第 2..n 行（续行：同订单号是预期的，跳过查重，回读走探针）
node scripts/写登记表.js --订单号 <单号> --表 "<子表名>" --行序号 2 --已确认
# 4) 备注 S + 合并（行相邻才能合并）
node scripts/写同单备注.js --订单号 <单号> --表 "<子表名>" --行 <第 1 行> --已确认
node scripts/合并同单T列.js --订单号 <单号> --表 "<子表名>" --已确认   # 默认只合并 S
```

- `--行序号`：1 起 = 行列表第几行（优先于老参数 `--明细序号`）；`--明细序号` 仍照旧（1/2…=第几个赠品）。
- `金额差额 ≠ 0` 时**先问客服怎么落**（备注写差额还是改金额），没答案不写；原因读不到不许猜。
- 详见 `经验/一单多行-多主件怎么写.md`。

cd 2.发票自动化/7.自动登记发票

### 查重：走 AirScript 云端读全表（别信浏览器读法）

网页版 WPS 只把「当前窗口」的数据加载进内存（22号 实测：真实 46503 行、匿名读只回 29412 行），所以**浏览器读法查重会假阴性**。查重必须用文档里的 AirScript（云端读全表）：

| 角色 | 文件/命令 |
|---|---|
| 文档里的只读脚本（用户在文档里粘一次、保存、生成同步 webhook） | **本机私有**：`project-config/kdocs-scripts/AirScript-只读查询订单号.md`（含公司链接与表结构，**不入库**，用户 2026-09-28 拍板） |
| 调用端 | `src/金山脚本客户端.js` + `scripts/查登记表.js` |
| 本机配置（不入库） | `project-config/kdocs-airscript.json`（`scripts.query.webhookUrl` + 令牌，令牌可回退读 12号） |
| 诊断（看表到底有多少行、最后一行几号） | `node scripts/查登记表.js --尾部` |
| 查重 | `node scripts/查登记表.js <订单号>` |

> 脚本里**一个等号比较都不能有**（金山粘贴会吃掉 `==`/`===`，见 22号 经验）；改脚本后别引入 `>=`、`<=`、`==`。

流程与命令：

| 步骤 | 命令/模块 | 说明 |
|---|---|---|
| 1 解析消息 | `src/解析登记请求.js` | 从消息里取店铺/订单号/发票类型/抬头/税号，缺项会报出来 |
| 2 平台金额 | `scripts/读拼多多发票中心.js` | 只读搜拼多多发票中心，拿「应开金额」+票种/抬头/税号 |
| 3 ERP 金额 | 10号 管易ERP 导出的「订单商品明细统计」CSV | 默认取最新一份；找不到单会明确报错 |
| 4 算金额+校验 | `src/发票规则.js` | 开票金额=买家支付金额；2 位小数；与平台对差额；赠品/搭配销售提示；退款/作废拦截 |
| 5 出条目+查重 | `scripts/生成待登记清单.js` | 追加到本机 `project-config/待登记清单.jsonl`（不入库）；同订单号不重复追加 |

注意：
- 金额仍以 ERP「订单商品明细统计」为准；若订单不在当月数据源里，**按下面两步查（2026-10-09 黎路遥纠正的坑）**：
  1. 先到 ERP **「订单查询」按单号搜** → 看这单**是什么时候的**（确定日期）；
  2. 再回 **「订单商品明细统计」报表**，按那个日期**选对应制单时间范围**导出 → 从 CSV 取字段。
  - 别跳过第 1 步直接猜范围导出（今天实例：报表直接导 2024-01 / 09-01~10-10 两轮都没命中，而订单查询里两单都能搜到）。
  - **实测（2026-10-09）：订单查询可以直接取到登记字段**（SO 单号/商品/让利后金额/发货时间），不必再导报表——接口路径、`dateType` 三档、多 ERP 单坑见 `20.经验库/ERP查单两段式/`。
  - 另：10号 导出工具有两个已修缺陷（2026-10-09，`auto_report_erp.py`）——制单时间日期框必须回车提交（否则开始时间被还原成旧值）、必须点「查询」等明细网格加载完再导出（否则出 787 B 空表）。
- **写金山登记表、发企微消息都还没接**（等表链接/字段 + 用户逐次授权）。
