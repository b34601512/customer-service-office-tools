# 登记写入验收清单（用户 2026-09-30 要求：写前记录 → 写后记录 → 对比，避免覆盖别人）

> 一句话：**没有「写前/写后两份记录 + 对比通过」，就不算写完。**
> 实现：`scripts/写登记表.js --验收`（`src/写入验收.js` 负责对比，测试 `tests/写入验收.test.js`）。

## 一、写前记录（before）——写之前先存证

| 项 | 内容 | 存哪 |
|---|---|---|
| 目标行 | 云端探针返回的 `nextWriteRow`（不靠猜） | `runtime/登记写入-<订单号>-写前.json` |
| 邻行现场 | 目标行 ±2 行的每行内容（重点 `J` 订单号） | 同上 |
| 探针 | `scriptVersion` / 子表名 / `lastDataRow` / `nextWriteRow` | 同上 |
| 要写的列 | 12 列（A/F/G/I/J/O/U/V/Y/AA/AB/AK）逐列打印 | 同上 + `runtime/登记写入-<订单号>.json` |
| 查重 | 云端全表按订单号查，命中即拒写（重复登记=重复交税） | 写入结果 |

## 二、写后记录（after）

| 项 | 内容 | 存哪 |
|---|---|---|
| 同区间快照 | 与写前**完全相同的行区间**（目标行 ±2） | `runtime/登记写入-<订单号>-写后.json` |
| 再探针 | `lastDataRow` / `nextWriteRow`（行数应 +1） | 同上 |
| 对比结论 | 逐列比对结果 + 问题清单 | 同上 |

## 三、对比判据（4 条全过才算通过）

1. **目标行**：要写的每一列都等于期望值（数字按数值比、长订单号按文本比）；
2. **目标行** `J` 列 == 本单订单号；
3. **除目标行外的所有行一字未变** —— 这是「不覆盖别人」的硬判据，动了就点名哪一行哪一列；
4. **下一个可写行** == 目标行 + 1（本单占 1 行）。

任一不过：退出码 1 + 打印问题清单 → **人工核对金山表**，不许当成功。

## 四、命令（集团表为例）

```bash
# 探针（不写）
node scripts/写登记表.js --探针 --表 "科技--唐雪梅" --脚本 write_jituan
# 干跑（不写，只列要写的列）
node scripts/写登记表.js --订单号 <单号> --表 "科技--唐雪梅" --脚本 write_jituan
# 写 + 写前/写后验收（要用户点头）
node scripts/写登记表.js --订单号 <单号> --表 "科技--唐雪梅" --脚本 write_jituan --读脚本 query_jituan --已确认 --验收
```

## 五、红线

- 写入必须**逐次授权**（`--已确认`），没有授权连云端查重都不跑；
- **公式列 C/D/E/M/T/W/X/AO 一个不碰**，只写 A/F/G/I/J/O/U/V/Y/AA/AB/AK；
- 写错表 = 登记到别的公司主体（见 `经验/店铺-登记表映射.md`），写前必查映射；
- 验收不通过**不许**自行重写/补写，先停下来报人。
