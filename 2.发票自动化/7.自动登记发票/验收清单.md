# 登记一单的流程（照着做，**做一个打个钩**）

> 用户 2026-09-30 定：**一步一步照清单做，做一个打个钩**；脚本**一个脚本一个动作**。
> 任何一步不过 → **停手报人**，不许硬闯；写错的行**人工在金山里改**（不改用脚本）。
> 命令里的 `--表`/`--脚本` 按目标表填：表① `--表 "德达医疗器械发票登记 --毛叶红"`（默认 `--脚本 write`）；表② `--表 "科技--唐雪梅" --脚本 write_jituan --读脚本 query_jituan`。

## 准备（3 步）

- [ ] **0. 这单登记到哪张表？** 看两张登记表**文件名**里的店铺代码（**直接读文件名，别检索**）：`tm01/tm03/jd08/albb02/pdd02/pdd03/pdd05/抖音两店` → 表①；`tm02/**tm06**/tm08/jd01…DY08/有赞/albb01` → 表②。→ 详见 `经验/店铺-登记表映射.md`
- [ ] **1. 拿齐字段**：抬头/税号/票种/金额（平台详情页**只读**读，`4.天猫发票回传/scripts/读发票详情.js`）+ 型号/数量/发货日期（ERP CSV）→ 写进 `project-config/待登记清单.jsonl`
- [ ] **2. 列位置核对**：表②比表①**从 O 列起右移一列**（P=客服、V=型号、W=数量、Z=金额、AB=抬头、AC=税号、AL=发货日期）；公式列（表② C/D/E/U/X/Y）**一个不碰**

## 写前（5 步，全只读）

- [ ] **3. 云端自检** `node scripts/云端自检.js --表 "科技--唐雪梅" --写脚本 write_jituan --读脚本 query_jituan` → 两个脚本都「✓ 编译通过」；**云端脚本每次粘贴/保存后必须先跑这步**（粘坏/版本旧 → 停手）
- [ ] **4. 探针** `node scripts/探针.js --表 "科技--唐雪梅" --脚本 write_jituan` → 记下「**下一个可写行**」；版本号应是 2026-09-30.11
- [ ] **5. 干跑** `node scripts/干跑.js --订单号 <单号> --表 "科技--唐雪梅"` → 核对 12 列**列字母和值**（这一步就是抓「列写错」的）
- [ ] **6. 查重** `node scripts/查重.js --订单号 <单号> --表 "科技--唐雪梅" --脚本 write_jituan` → 必须「**未登记过 ✓**」（命中=已登记，绝不写第二遍：重复登记=重复交税）
- [ ] **7. 写前快照** `node scripts/快照.js --订单号 <单号> --表 "科技--唐雪梅" --脚本 query_jituan --行 <目标行> --标签 写前` → 目标行 **J 必须是空的**，邻行 J 记下来（防覆盖别人）

## 写（1 步，要用户点头）

## 出错怎么办

1. **任何一步不过 → 停手**，把现场（命令 + 输出 + 证据文件）发给用户；
2. 表里写错的格子：**人工在金山里改**（清值 / 改值 / 恢复公式 U=`=BS<行>&BU<行>`、Y=`=Z<行>/W<行>`；或删整行 / 回退版本）；
3. 改完从 **第 5 步（查重）** 重跑，别跳步。

## 六道不可变的闸门（脚本里已实现，别绕过）

字段不全拒写 → 未授权不写（连查重都不跑）→ 云端查重命中拒写 → 写入 → 写后回读必须恰好 1 行且行号一致 → 验收 4 条全过。
