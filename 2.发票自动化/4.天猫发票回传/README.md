当前先实现天猫多店铺登录底座：每个店铺、每个账号使用独立浏览器资料目录，自动填入账号密码，但不自动点击登录。项目管理入口为 CLI，不启动本地管理网页。

## 配置

复制 `data/stores.example.json` 为 `data/stores.json` 后修改，每个店铺一条：

```json
{
  "stores": [
    {
      "id": "tmall-store-1",
      "name": "天猫店铺1",
      "username": "你的账号",
      "password": "你的密码",
      "enabled": true
    }
  ]
}
```

## 登录

```powershell
npm run login
```

登录全部启用店铺：

```powershell
npm run login:all
```

CLI 会按需打开受控 Edge，填好账号密码后等待人工完成滑块、验证码或短信验证。登录成功后会把该店铺账号的浏览器资料保存在 `runtime/store-profiles`。

## 日常订单流程

CLI 的发票处理区按以下顺序使用：

1. “同步待处理订单（只读取）”：只打开天猫待回传列表、读取订单并保存到 `data/invoice-order-records.json`，不下载发票、不上传、不点击提交。
2. “订单状态管理（四个直接队列）”：在待处理、处理中、发票已登记、已处理之间按单步规则推进，可写备注。
3. “正式回传发票已登记订单”：只消费本地“发票已登记”且未成功回传的订单；成功自动变为“已处理”，跳过或失败保留原阶段以便重试。

选择多家店铺时会逐店继续执行；CLI 输出逐单进度、文件/截图对应、逐店结论和总汇总。正式回传会在提交真实发票前再次要求确认。
