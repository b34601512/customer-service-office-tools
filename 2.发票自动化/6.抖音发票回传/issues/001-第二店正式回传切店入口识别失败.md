# Issue 001：第二店正式回传切店入口识别失败

## 意图

按真实一键流程复现抖音多店发票回传，确认判断依据后根治第二店正式阶段失败；不照搬其它平台结论，不弱化店铺身份校验。

## 背景与已采集证据

- 2026-08-31 真实运行中，两家店只读同步均成功：第一店读取 2 单，第二店读取 1 单。
- 第一店正式流程已到下载中心，2 单因尚无发票正常跳过并留截图。
- 第二店同步完成后，正式流程复用同一浏览器上下文，随后报错：`抖音切店入口不唯一：识别到 0 个可见“切换组织/店铺”`。
- 第二店订单因此记录为 `error`，没有进入下载、上传或提交阶段。
- 当前两个专用资料目录均无浏览器残留；浏览器复用机制本身已有生效日志。
- 后续只读复现采集到真实 DOM：页面刚加载时没有店铺 ID 节点，也没有“切换组织/店铺”；打开顶部店铺信息后，会出现唯一结构化节点 `label="店铺ID" value="29502951"`，但仍没有“切换组织/店铺”。
- 同一路径再次运行有时成功，说明菜单过渡状态会影响固定文案入口是否可见；结构化店铺名称与 ID 始终能精确确认当前身份。
- 根因确认：`读取当前抖音店铺身份` 把“读取当前身份”和“发起切店”混成一个动作，读取身份时错误要求切店按钮存在。

## 最终结果

- 店铺身份改为读取顶部店铺控件内唯一的结构化 `label="店铺ID" value="..."`；只有身份不一致时才查找切店入口。
- 真实运行中，第二店同步读取 1 单，复用浏览器后精确识别店名与店铺 ID，并成功到达下载中心。
- 当前订单尚无诺诺发票，按业务规则跳过；截图确认页面、店名、店铺 ID 与订单均正确。
- 本次验证停在上传前，没有不可逆提交；两家店专用浏览器均已关闭，无残留进程。
