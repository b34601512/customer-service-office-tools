# Issue 006：切店入口一次性扫描导致点击打在已失效元素上

## 意图

修复抖音多店切换时「切换组织/店铺」入口偶发点不动的问题；保留店铺身份精确校验，不加模糊兜底。

## 背景与证据

- 2026-09-20 11:43:38 真实运行（店铺5 切店）报错，Playwright call log 原文：
  - `waiting for getByText('切换组织/店铺', { exact: true }).first()`
  - `locator resolved to <div class="index_descTitle__IpE5P">切换组织/店铺</div>`
  - `element is not stable`（2 次）→ 之后一直 `element is not visible` → `locator.click: Timeout 5000ms exceeded`
- 代码路径：`src/browser/douyinStoreIdentity.js` 的 `查找可见切店入口`（一次性可见性扫描）→ `确保店铺菜单打开不处理弹窗`（入口已可见时直接返回该元素）→ `点击切店入口`（一次性 click，5 秒）。
- 根因：扫描到点击之间弹层动画/收起，元素已失效；只有「菜单未打开」分支才有 `等待唯一可见切店入口` 的 10 秒轮询，已可见分支没有稳定性等待与重解析，一次失败即终止整店。
- 与 issue 001 的关系：001 修的是「读身份时不当地要求切店按钮存在」；本次是切店动作本身的元素失效，属同族但不同环节。

## 修复

- `点击切店入口(page, 选项)`：每次尝试都重新解析入口（必要时重新点开 `.headerShopName` 菜单），失败记录日志并重试，默认最多 3 次；全部失败才抛出最后一次错误。
- 未改动店铺身份校验、未引入模糊匹配或兜底跳过。

## 边界

- 不弱化店铺身份（storeId + storeName）校验，不按模糊店名兜底。
- 不删除或覆盖店铺登录资料，不强杀来源不明的浏览器。
- 不引入第二套状态真源或长期兜底开关。
