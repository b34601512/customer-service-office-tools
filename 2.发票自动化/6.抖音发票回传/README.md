抖音项目复用「通用发票下载中心」下载发票，不在本项目内重复实现取票功能。

## 配置

在 CLI 菜单选择「配置店铺手机号和地址」，每个店铺配置一条。手机号决定登录资料归属：同手机号共用一个专用 Edge，不同手机号隔离；平台店铺 ID 和名称用于切店核验，业务处理必须配置。

```json
{
  "stores": [
    {
      "id": "douyin-store-1",
      "name": "抖音店铺1",
      "targetUrl": "https://fxg.jinritemai.com/",
      "phoneNumber": "登录手机号",
      "platformStoreId": "平台店铺ID",
      "platformStoreName": "平台完整店名",
      "enabled": true
    }
  ]
}
```

## 启动

登录资料统一位于 `runtime/account-profiles/msedge/account-手机号摘要`，批量登录按手机号去重。处理多店时串行切换、核验店铺身份，订单仍按店铺分别保存；不要在执行过程中手动切店。旧的按店铺资料目录已停用，不会回退读取。

```powershell
npm start
```

CLI 可按需执行登录、页面采集和回传；配置入口为 `node src/cli/startCli.js`。CLI/TUI 的发票回传共用同一个逐店流程：A 店完整同步并回传后，再切换 B 店，所有店处理完即结束，不再先同步全部店再回传全部店。

每店先读取完整订单报表并保存到 `data/invoice-order-records.json`，仅回传本轮快照中尚未成功的订单。抖音无需人工登记发票；开始下载时进入“处理中”，成功进入“已处理”并保留历史凭证。下载缺失或失败会记录原因，下一轮可重试。

完整同步失败时不覆盖本地订单、不回传该店旧队列，并继续下一店；不会把当前页当作完整报表清理订单。执行期间输出逐单进度、逐店结论和总汇总。点击“发票回传”会执行正式提交，核对店铺配置后再运行。
