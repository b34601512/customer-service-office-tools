本工具用于打开京东常规开票列表，识别带有「催促开票」标识的订单号，并把订单永久记录到本机。

## 启动

双击 `启动催票后台.bat` 进入命令行菜单。

也可以在项目目录运行：

```powershell
npm start
```

## 使用顺序

1. 在 CLI 菜单确认店铺配置，目标地址默认是 `https://shop.jd.com/jdm/finance/consumerInvoice/cinvoiceOrder`。
2. 选择「人工登录并识别」或「自动识别全部启用店铺」。
3. 如果京东要求登录，工具会打开受控 Edge 窗口、自动填好账号密码并点击「立即登录」；只有出现滑块、验证码或短信验证时才需要人工完成。
4. 识别到的催票订单会进入 CLI 订单列表，可以标记状态、安排客服和写备注。
5. 如果要批量回传发票，先确保「通用发票下载中心」已配置好诺诺账号，再选择「批量回传待开票发票」。本轮涉及的京东店铺都会打开可见页面并保留到控制台退出；即使暂未下载到发票，也可直接核对京东状态。

首页会保留最近一次批量识别总览，包含处理开始、结束时间、成功/失败店铺和催票数量；单店识别会单独记录，不会覆盖批量总览。

订单相关入口：

- 「查看和处理订单状态」先显示待处理、处理中、发票已登记、已处理四个固定入口；点进状态后立即列单，不强制先筛选或搜索。
- 每条订单同时显示本地处理阶段和京东后台开票状态。
- 正式回传只消费京东后台处于“待开票”且尚未成功回传的订单；成功自动进入“已处理”，发票缺失或上传失败时保留原人工处理阶段。
- 「查看已处理记录」查看已完成订单；「导出客服跟进表」导出处理中和发票已登记订单。

凭证相关入口：

- 「打开凭证文件夹」直接打开最近一轮识别的凭证目录。
- 凭证目录按批次、日期保存，文件名包含店铺、场景、尝试次数和成功/失败结果；截图生成失败会明确提示。

本项目只保留 CLI 管理入口。Edge 只用于京东真实页面登录和自动化，不再作为管理界面。

订单状态保存在 `data/invoice-urge-orders.json`，`workflowStatus` 是唯一人工状态真源；京东字段、客服、备注、回传文件、截图、消息和已处理归档索引继续保留，不会因为重启后台而丢失。
