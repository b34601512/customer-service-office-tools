# 发票识别过程可视化：最终拍板为"无额外网页，TUI 即验收面"

## 意图

识别（巡检）运行时，用户能核实程序工作属实；任务期间页面不自动关闭，只有程序退出统一关闭。

## 背景与拍板过程

- 现象：控制台显示"正在读取…25/79页"，但打开的京东页面纹丝不动。根因：数据链路是 `invoiceApiReader.js` 接口直读（页面上下文 fetch 京东内部接口），设计上不操作京东列表 DOM（旧"分页控件+行文本"链路已废弃，禁止复活）。
- 曾实现方案A衍生：自制"发票识别核对视图"网页（随读取翻页展示接口真实数据）。
- 用户否决自制网页："是否有必要再造一个网页，还是可以直接把结果显示在TUI"；并确认效率优先。
- **最终拍板：B = 接口快读保持现状，不造任何额外网页；验收面就是现有 TUI"2.订单"明细（每单识别日期/申请日期/发票状态/金额/最近消息）+ 顶部实时分页进度条。核对视图全链路已删除，代码回到与本 issue 讨论前一致。**
- 页面不自动退出：原本已满足——单店识别 `wait`、批量识别/批量回传 `keep`，程序退出由 `browserContextHub.关闭全部浏览器上下文()` 统一回收。

## 边界

- 不复活京东页面分页控件点击/行文本解析链路。
- 不为展示再造独立网页或第二套数据加工。
- headless 自动排查不打开任何额外窗口。
- 不触碰 dist/ 分发包副本与其他项目。
