# 客服培训课件制作助手（13号项目）

把"聊天记录 → 培训课件 HTML"做成流水线。**取数全自动，AI 只做解析，渲染与自检由程序完成。**

## 新流水线（三步）

```
[步骤1·程序] 取数：从京东抓取 / 手动导入 → 标准聊天记录文件
             runtime/chat/<基名>.chat.json
[步骤2·AI]   读聊天记录 + 场景意图 → 产出"解析数据文件"
             runtime/review/<基名>.review.json   （按 SKILL.md 填写）
[步骤3·程序] 生成课件：读两个文件 → 成品 HTML + 铁律自检
             runtime/outputs/<月份>/<文件名>.html
```

> 说明：AI 全程驱动，但只负责"挑教学点 + 写当时 vs 建议话术"（可变内容）；
> 样式、渲染、格式与铁律自检全部由程序保证。AI 通过 `src/cli.js` 命令或直接 require `src/services/*` 完成全部步骤（唯一业务真源，无界面层）。

## 使用方式（AI 驱动，无界面）

所有命令在 `D:\桌面\办公软件\13.客服培训课件制作` 目录下执行，做法看 **SKILL.md**：

1. 取数：`node src/cli.js fetch:full <顾客ID> --save <sid>`（京东，全量含机器人自动回复；自动回复会画成灰框）或 `node src/cli.js import <文件>`（手动）。
2. AI 按 SKILL.md 契约写解析文件 `runtime/review/<基名>.review.json`。
3. 出片自检：`node src/cli.js generate`。

## 京东抓取（步骤1·程序）

- 需 Chrome 已登录京东客服后台，并以**带调试端口 + 专用 profile** 启动（别用日常 profile，避免占用）：
  ```
  chrome.exe --remote-debugging-port=9223 --user-data-dir="D:\桌面\办公软件\13.客服培训课件制作\runtime\browser-profile-jd6"
  ```
- 配置在 `runtime/config/config.json`（调试端口/页面标题匹配/接口地址/每页条数；不入库），模板见 `config.example.json`。
- 取数一律走 `fetch:full`（CDP 驱动页面「查询 → 查看 → 切换为该用户全部聊天信息」并抓 `queryLastLogs`，含机器人自动回复；日期范围程序会自动放开）。旧接口 `kf.jd.com/chatLog/queryList.action`（单日、旧口径）**已不作课件取数用**。
- 2026-09-15 页面改版（V13.8.0）后两个易踩点：日期默认只查「今天」、面板默认「列表视图」不含机器人——都已写进程序，报错先看这两处。
- 程序列出会话供你选择；抓完会打印前若干条，**请通读确认会话主题与教学场景匹配**再继续（见铁律 8、9）。

## 导入聊天记录（步骤1·程序，备用取数）

- **粘贴文本**，每行格式（`|` 或 `｜` 均可，`#`/`//` 开头为注释）：
  ```
  2026-08-05 15:07:34|客户|怎么涨价了
  2026-08-05 15:07:52|客服|您看的哪一款呢
  15:08:04|客户|5升医用        ← 只写时分，自动复用上一条日期
  ```
- **从文件**：支持 `.json`（标准聊天记录 或 京东原始 JSON）、`.txt`/`.md`。

## 架构（业务唯一真源，无界面层）

- `src/services/*`：全部业务真源（纯逻辑，无界面）：抓取、转换、导入、存储、渲染、自检、生成编排。
- `src/cli.js`：命令入口（AI 驱动），只做参数解析与输出，业务全部调用 services。
- `SKILL.md`：AI 指导书（流程四步 + 解析契约 + 铁律 + 验收清单）。
- 规则文件：`runtime/config/config.json`（真值，不入库）；`config.example.json` 为模板。
- 原 TUI 版（启动 bat 菜单）已归档至 `历史资料备份/TUI版备份/`，不再维护。

## 铁律速览（AI 制作解析时务必遵守）

1. 所有解析必须用 `<details class="insight">` 就地嵌在对应消息**正下方**、点击才展开；**不要**独立结尾总结卡片、**不要**加目录/锚点栏。
2. 消息顺序 = 真实对话顺序；客服蓝右、客户白左。
3. 转义时把 `<br/>` 还原为换行，**不要**出现字面 `<br/>` 或乱码 `�`。
4. 客户 ID/pin 默认脱敏（程序已用 `.cid` + 眼睛按钮处理），不要在别处写死真实 ID。
5. 去具体客服姓名与"领导要求"等内部措辞。
6. 聊天图片由程序自动下载内嵌；商品链接若消息里含链接，做成"图+标题"可点击卡片（当前版本支持文字/图片，商品卡片为后续增强）。
7. 抓取/导入后先通读确认场景，别硬套。
8. 课件**不要顶部大标题/红色摘要卡**（用户 2026-09-14 要求）：打开即正文（会话回放）；标题只进浏览器标签页。解析文件 `sub`/`tagline` 仅存档，不渲染。
9. **取数要看含自动回复的全量口径**（2026-09-14 踩坑）：列表/`waiterSession/queryChatLog` 不含机器人（`@im.jd.com`）、欢迎语、商品卡片；一律用 `fetch:full`（CDP 驱动「查看」并抓 `queryLastLogs`），课件把系统消息画成灰框；否则会把「机器人已答、客服只发了个表情」误判成客服不答问题、**误伤客服**。详见 SKILL.md 铁律 8。
10. **课件里不写口径/排查类解释**（2026-09-14 用户要求）：按"第一次看"写，只放真实会话 + 就事论事解析；不要出现"不是客服敷衍""旧口径/全量口径""别冤枉客服"这类内部排查语气。详见 SKILL.md 铁律 9。
11. **「点击展开」必须一眼可见**（2026-09-15 用户要求）：解析块展开按钮由渲染器统一注入（**绿色**胶囊「点击展开解析／点击收起」+ 轻微呼吸光晕，移动端也不隐藏；红色版用户反馈“有点吓人”，已改绿），AI 不要手写 `sum-hint` 文字提示；自检项「解析块有显而易见的『点击展开』按钮」缺按钮判 fail。详见 SKILL.md 铁律 10。
12. **收尾必须是逼单，不要问「需要吗？」**（2026-09-15 用户要求）：客户关注过配件/赠品就用它做钩子——「您现在下单，我帮您备注好赠品」（订单已绑定，但备注了客户才放心）；收尾句用 `<b class="closer">…</b>` 标出，渲染器高亮成绿底；自检项「建议话术收尾不用开放式问句」出现「需要吗/要不要」判 fail。详见 SKILL.md 铁律 11。
13. **版式已定稿（美化版）**（2026-09-15 用户验收：“以后 AI 直接按新方法搞”）：新课件直接用 `renderCourseware.js` 的默认样式出片，**不用再问要不要美化，也不要改回旧的暖黄块版式**；样式只在那一个文件里改，不给单份课件写内联样式；旧课件保持原样不重出。详见 SKILL.md「版式（已定稿）」。
14. **赠品/权益按宣传物料，不增不减**（2026-09-15 领导口径：“按宣传图来，宣传的是什么就是什么”）：宣传图写了几件就报几件（例：活动是“晒图加送 血氧仪＋额温枪”，只报血氧仪就是漏）；不许凭空承诺赠品/时效/加急，时效与快递公司以店铺实际口径为准。详见 SKILL.md 铁律 12。
15. **尽量发现做得好的地方并鼓励（引导，不是硬指标）**（2026-09-17 用户要求：“尽量发现好的地方就鼓励”；同日补充：“也不一定是至少吧，万一没有做得好的地方会不会强行尬聊”）：有真实可夸的（具体动作/话术、对结果真有用）就写出来鼓励；**没有就不写、绝不硬夸**（尬夸比不夸更伤信任）；有就写成“当时怎么说 + 为什么好 + 可直接抄的说法”，不挂 `bad`、挂在客服那句话之后。自检只报个数（`正面 X / 解析 Y`），**不给 warn、不阻断**。详见 SKILL.md 铁律 13。

## 常见问题

- **连不上调试端口**：确认 Chrome 以 `--remote-debugging-port=9223 --user-data-dir=…\runtime\browser-profile-jd6` 启动且已登录（端口以 `runtime/config/config.json` 为准；本机 9号/19号项目占用 9333，别混用）。
- **查不到会话（NO_ROW）**：多半是页面日期筛选停在「今天」或面板停在「列表视图」——`fetch:full` 会自动处理，仍失败就先手动在页面上点「近30天」并确认能看到目标行。
- **登录错店铺**：先核对会话内容是否匹配教学场景，别硬套。
