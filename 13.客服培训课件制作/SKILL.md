# SKILL.md — 客服培训课件制作（AI 驱动版）

> 这是「13.客服培训课件制作」项目的 AI 指导书。**什么时候用**：老板说"做一份 XX 培训课件"、或要基于聊天记录出教学 HTML。
> 机械步骤全部由本项目的程序（`src/services` + `src/cli.js`）完成，你**只负责内容创作**（挑点、点评、话术）。
> **真源层级（避免新旧混用）**：本文件 = 唯一「怎么做」的真源（流程/契约/铁律/版式/验收）；`README.md` 只是概览；`历史资料备份/` 里**全部是历史存档，已标「已废弃」，任何做法与本文件冲突时一律以本文件为准、不要照做**；`断点记录.md` 只记当前进度与待办。

## 流程（四步，缺一不可）

```
1 取数 → 2 读记录确认教学场景 → 3 写解析文件 → 4 出片 + 自检 + 验收
```

### 第 2 步：读记录、定教学场景
- 通读聊天记录，向老板确认/自己判断**教什么**（如 涨价应对/议价/三通识别/安抚情绪/挽留话术）。
- 记录 `meta.window / meta.store / 场景名`，第 3 步会用到。

### 第 3 步：写解析文件（你唯一要"创作"的部分）
按严格契约写 JSON，保存为 **`runtime/review/<与聊天记录同基名>.review.json`**：

```jsonc
{
  "format": "courseware-review/1",
  "scenario": "涨价应对",            // 场景名
  "title": "老客户一句“怎么涨价了”，怎么接住？",
  "sub": "案例看点：不直接承认涨价……（可含 <br/>）",
  "tagline": "客服培训 · 老顾客涨价敏感场景",
  "window": "2026-08-05",
  "store": "dedakj自营",
  "outputName": "涨价应对案例演示.html",

  // overlays：按消息下标挂标记。i = messages 数组下标，不重复、必须在范围内。
  "overlays": [
    { "i": 3, "bad": true, "insight": "r1" },
    { "i": 5, "note": "价格敏感", "bad": true, "insight": "r3" }
    // { "i": 2, "textOverride": "（脱敏/改写的文本）" }
  ],

  // insights：被引用的解析块，<details class="insight"> 结构
  "insights": {
    "r1": "<details class=\"insight speech-insight\" id=\"r1\">…</details>"
  }
}
```

解析块推荐结构（`insight-body` 内可用 `compare`(bad/good 两栏对比)、`arrow-note` 要点、`ul.tips` 补充话术，可加 `speech-insight` 类；注意转义双引号）。
**「点击展开」按钮不用你写**：渲染器会自动在每个 `<summary>` 末尾注入绿色按钮（`点击展开解析` / 点击后变 `点击收起`），所以**不要手写 `sum-hint` 之类的文字提示**（旧文件里的会被自动去掉）：

```html
<details class="insight speech-insight" id="r1">
  <summary><span class="sum-ico">🔥</span><span class="sum-main">标题</span></summary>
  <div class="insight-body">
    <div class="compare">
      <div class="col bad"><div class="col-label"><span class="ico">✖</span> 当时客服这么回</div><p>原文</p><div class="why">为什么不对</div></div>
      <div class="col good"><div class="col-label"><span class="ico">✔</span> 建议这样回</div><p>建议话术（可含 <b>重点</b>），最后一句必须是<b class="closer">逼单收尾</b></p></div>
    </div>
    <div class="arrow-note">要点说明</div>
    <ul class="tips"><li><span class="num">+</span><span>补充话术/赠送配件等</span></li></ul>
  </div>
</details>
```

## 铁律（第 3 步逐条对照，别违反）

1. 每个解析 `details` 只对应**一条**消息；**不要**做独立结尾总结卡片、**不要**加目录/锚点栏。
2. 消息顺序 = 真实对话顺序（overlays 只挂下标，不改顺序）。
3. 原文里的 `<br/>` 表示换行，保留语义；**不要**出现字面 `<br/>` 或乱码 `�`。
4. 别写具体客服姓名、别写"领导要求"等内部措辞（客户 ID 程序已默认脱敏）。
5. 只对"值得教学"的消息挂解析（一般每课件 2~4 个），别每条都挂。
6. `bad` 的解析必须有 `insight`；`i` 不重复且必须在消息范围内。
7. **不要顶部大标题 / 红色摘要卡**（2026-09-14 用户要求）：课件打开即正文（会话回放），标题只放浏览器标签 `<title>`。解析文件里的 `sub`/`tagline` 只当存档备注，渲染器不再输出它们，也不要往 `insights` 里塞标题头/案例看点。
8. **取数必须用含自动回复的全量口径**（2026-09-14 踩坑，务必遵守）：京东聊天记录列表 / `waiterSession/queryChatLog` **只有客服与客户的消息，不含机器人自动回复、欢迎语、商品卡片**。做课件一律用：
   ```
   node src/cli.js fetch:full <顾客ID>                      # 列出全量会话（含自动回复条数）
   node src/cli.js fetch:full <顾客ID> --save <sid> [--tag 主题]   # 保存（文件里带 role=system 消息）
   ```
   - 实现：CDP 驱动页面「填顾客ID → 查询 → 查看 → **切换为该用户全部聊天信息**」并抓 `api.m.jd.com/client.action?functionId=queryLastLogs`（带 h5st 签名，只能页面自己发）；同顾客重复抓取会自动刷新页面重试。
   - ⚠ 2026-09-15 页面改版（V13.8.0）：点「查看」后默认是「列表视图」（不含机器人），**必须再点面板里的「切换为该用户全部聊天信息」**（程序已自动做）；同日另一坑：页面日期筛选默认是「今天」，老会话的行根本查不到，程序会先点「近30天」放开范围。
   - 机器人消息不止 `@im.jd.com`：以店铺账号名义下发、带 `action.code=cfg.welcome.new` 的菜单自动答案也是自动回复（都会被标成 `role:'system'`）。
   - 课件会把系统消息画成**灰色虚线框**（标「自动回复/欢迎语/商品卡片」），自检铁律：系统消息条数必须和记录一致，否则判 fail。
   - 为什么要这样：否则会把「机器人已经答完、客服只是发个表情打招呼」误判成「客服只回了个表情不回答问题」，**误伤客服**；也可能把机器人引导/自动生成的提问当成客户真实提问。
9. **课件里不写"口径 / 排查"类解释**（2026-09-14 用户要求）：课件是给客服看的，按"第一次打开"的视角写——只放真实会话 + 就事论事的解析（当时怎么说 / 建议怎么说）。
   - 不要出现"机器人已答完、不是客服敷衍""旧口径/全量口径""避免误判""别冤枉客服"这类**我们内部排查的自述**；机器人消息用灰框自然呈现即可。
   - 同理：解析里的 `sub`/`tagline` 也只写案例本身（它们不进页面，但别把排查语气留在里面）。
10. **「点击展开」必须一眼可见**（2026-09-15 用户反馈：原来的按钮不明显，别人不知道能点）：展开按钮由渲染器统一注入并做成**绿色**胶囊（`点击展开解析` / `点击收起` + 轻微呼吸光晕、悬停高亮、移动端不隐藏；用户觉得红色吓人，2026-09-15 已改绿），AI **不要手写** `sum-hint` 文字提示。自检项「解析块有显而易见的『点击展开』按钮」必须为 ok，缺按钮直接 fail。
11. **收尾话术必须是逼单，不要问「需要吗？」**（2026-09-15 用户要求）：建议话术的最后一句**不要**把决定权丢回给客户（「需要吗？」「要不要？」「还需要什么吗？」都不行）。
   - 客户前面关注过什么，就用什么做钩子：配件、赠品、耗材、延保、颜色、发货时效……直接给动作：
     「您现在下单，我帮您备注好赠品（订单本身已绑定，但要让客户放心）」；「您今天拍下，我给仓库备注主机+赠品一起发」；「现在下单，下午就给您安排发出」。
   - 没有可挂钩的点，就用权益/时效/保障收尾（今天下单今天发、全国联保），**不要凭空承诺**（赠品/价格必须是店铺真实有的）。
   - 逼单句用 `<b class="closer">……</b>` 包起来，渲染器会高亮成绿底，学员一眼看到「收尾怎么说」。
   - 自检：建议话术/要点最后一句出现「需要吗/要不要」判 fail；有 good 对比栏但没写 `.closer` 会 warn。
12. **赠品/权益一律按宣传物料来，不增不减**（2026-09-15 领导口径原话：“按宣传图来，宣传的是什么就是什么”）：写建议话术时，宣传图/商品页上写了几件赠品、什么条件、什么时候给，就**照原样报全**。
   - 不能漏：例——活动是「晒图加送 血氧仪＋额温枪」两件，只报血氧仪会让客户以为只有一件，事后容易被拿活动图对质（真实案例：jd_51164c4a52cb5）。
   - 不能加：不许凭空承诺赠品、时效、加急；时效/快递公司这类（如湖南总工厂 1-2 个工作日、默认邮政或韵达）一律以店铺实际口径为准，拿不准先问用户。
   - 宣传图里写的是“晒图加送”，就必须把“什么条件”一并说清；**“只说送、不说条件”是最常见的漏法**（真实案例：客服只答一句“有送血氧仪”，客户隔了一天才在追问中第一次听到“晒单”——发过活动图 ≠ 讲过了，客户按我们嘴里说的话理解）。详见铁律 11 与解析模板。
   - **先听懂客户在问什么**：客户不一定知道赠品的名字（真实案例：“这款带血氧，心率检测吗？”其实是在问“**送不送血氧仪**”）——先把“有没有送”听懂，再把“有送 + 什么条件”两件一起答清楚，别答偏成机器参数。
   - **话术内部不能打架**（易错）：条件是“晒单送”，动作就不能写成“今天就帮您登记、发出”——条件 / 动作 / 时间必须在同一条时间线上：下单 → 收货 → **确认收货** → 晒图评价 → 客服登记 → 湖南工厂发出 → 发单号。写完自己读一遍，看前后两句能不能同时成立。
   - **对内授权、对外只讲规则**（2026-09-15 用户口径：“内部这种小事情不需要主管审批，客服自己操作就好，只是对外需要有规则说明”；“客户纠结一次就可以特殊处理，不需要两次”）：客户**一纠结（不愿意晒单、有异议）**，或确实是我方漏讲、漏登记时，**客服直接登记补发、不再要求晒单，内部不需要主管审批**；但对客户**只讲规则和结果**（这个礼品本来是什么规则 + 我这边给您什么结果），**不要说“这次给您破例”“不用审批”**这类内部口径，否则会被当成规则传开。
13. **尽量发现做得好的地方，就鼓励**（2026-09-17 用户要求：“尽量发现好的地方就鼓励”；同日补充：“**也不一定是至少**吧，万一没有做得好的地方会不会强行尬聊”）——这是**引导，不是硬指标**：
   - **有真实可夸的**（具体动作/话术、对结果真有用、别人能照拄）→ 写出来鼓励到位，客服也需要知道自己哪里做对了。
   - **没有就不写**：**不许硬夸**——尬夸比不夸更伤信任，客服一眼就能看出来；宁缺毋滥。
   - 有就按这个写法：**当时怎么说的（原话）+ 为什么好 + 可以直接抄的说法/动作**，不挂 `bad`，挂在**客服那句话之后**。
   - 自检只报个数（`正面 X / 解析 Y`），**不给 warn、不阻断**，不得为了消灭提醒去硬凑正面解析。
14. **解析只讲“到它为止”的内容（就地视角，别当事后诸葛亮）**（2026-09-17 用户要求：“每个解析必须只讲过往聊天记录到解析截止为止的内容”）：每个解析只能引用**它挂的那条消息为止已经发生**的事（客户说过的话、客服做过的事）；**不许**在解析里写“后来客户答 3-5”“这就是后来选 5 升机的依据”这类后面才发生的内容——要讲后续，放到**后面那个解析**里讲。
   - 为什么：解析是“就地”看的——学员读到这一条时，后面还没发生；提前拿结果去评论，就成了“事后诸葛亮”，也让人误以为当时就知道结果。
   - 范围：**标题、why、arrow-note 要点、tips** 都算；允许写“收到货后……”这类**给客户的正常流程承诺**（建议话术里的动作），受限的是引用**本场后面才发生的对话内容**。
   - 落地：自检项「解析只讲‘到它为止’的内容」会把“提前引用后面消息原话”的地方报 warn（非阻断）。
15. **别把“先回一句短话抢响应时间”当成缺点**（2026-09-17 用户：客服为了响应时间先发“您好”，真人不可能一瞬间打那么多字）：客服先回“您好／在的／亲”再接话，是**正常的响应策略**（后台看响应时长），不算“只回两个字、没回答问题”；解析里**不要**拿这个当可优化点。
   - 真正要看的是：**后面有没有接上正事**（把客户的问题答清、把需求问清）。客户发了链接/问题而全程只停留在“您好”，那才是问题。
   - 落地：自检项「开场短句不算缺点」——当“当时客服这么回”引用的是单句问候类短话（≤ 6 字，如“您好”“在的”）时给 warn，提醒换成后面真正要改的那句。
16. **到手价口径：以主图显示的为准**（黎经理 2026-09-17）：“我们到手价都是以主图显示的为准，麻烦跟客服同事强调下。客户显示没有这个价的话，可能是哪些促销优惠没有领到，补差价或者下单改价都行。现在流量大部分都是付费来的，也不是很便宜，有机会转化能提高些最好。”
   - 客户问到手价：**就说主图上那个到手价**；**禁用“以手机下单价格为准／以页面为准”这种把人推走的话**。
   - 客户说“上边不是写的 X 吗／我这里没这个价”：先当着客户核一遍——**多半是促销优惠没领到**（券/活动没点），带客户把优惠领到。
   - 还是对不上：**可以补差价，也可以下单改价**（内部授权，两条路都行）；对客户只说“**我帮您按主图这个到手价处理**”，**内部怎么操作不写进对客话术**。
   - 目的：流量大多是付费买的、不便宜，**能转化就转化**，别用“以页面为准”把客户聊走（京3 客户沟通挺久的尤其如此）。

## 版式（已定稿：美化版，2026-09-15 用户验收）

用户 2026-09-15 确认“美化效果比之前好，以后 AI 直接按照新方法搞”——**新课件一律用这套样式，不用再问、不要改回去**：

- 打开即正文：无顶部大标题/摘要卡，顶部只有一条浅蓝信息条（“点击展开解析”的提示由渲染器给）
- 解析卡：白底 + 左侧绿色色条 + 柔和阴影；展开按钮是绿色渐变胶囊「点击展开解析／点击收起」
- 对比栏：圆角卡 + 胶囊标签（✖ 当时客服这么回 / ✔ 建议这样回）
- 逼单收尾：`<b class="closer">…</b>` 绿底高亮（铁律 11）
- 气泡：客服蓝渐变带投影、客户白底细边；系统/机器人消息是灰虚线框
- 要点：卡片行 + 渐变数字块；手机 375 宽不溢出、按钮不隐藏
