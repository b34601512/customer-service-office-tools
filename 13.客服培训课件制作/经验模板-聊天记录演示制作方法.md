## 一、最终效果长什么样（先看成品）

单文件 HTML（12.5KB，零外部依赖，双击即开）：
- **左侧固定目录栏**：3 个锚点（对话回放 / 议价点·话术对照 / 培训要点）+ 案例信息卡片
- **对话回放**：微信式气泡——**客服蓝色靠右、客户白色靠左**，带时间、节点标注（如"产品咨询"）、议价点红色标记
- **就地解析**：对话中的关键消息下方内嵌**可折叠块**（`<details>`，点击展开）：
  - 议价点处 → "当时怎么回 vs 建议怎么回"左右对照
  - 回复可优化处 → "培训要点"编号列表
- 头部红色渐变卡片：案例标签 + 主标题 + 案例看点

## 二、数据从哪里来（京东聊天记录）

### 2.1 页面入口
- 京东客服管家——聊天记录/会话查询：`https://kf.jd.com/#/212`（**注意**：入口哈希可能因店铺/版本不同而变化，如 `#/212`、`#/213`、`#/364` 等；`#/212` 已实测是会话查询页，`#/364` 常常不是。**务必以页面上正在显示的功能为准，且确认登录的是用户要的那家店**）
- 实际查询页面（iframe）：`https://xi.jd.com/customerassistant/filterCustomer.html?menu=ddQuery&content=chatLog`
- 登录态：京东商家后台登录后（shop.jd.com），此页面直接可用；需 Chrome 调试端口（见第 3 节）才能自动操作

### 2.2 查询接口（关键）
```
GET https://kf.jd.com/chatLog/queryList.action
参数：
  page=1 & pageSize=50
  startTime=2026-08-03 & endTime=2026-08-03   ← 单日查询！全范围(如2024-2026)反而查不到
  customer=jd_kvqlmnqcbndo                    ← 客户pin（可选：关键字/商品id/订单号/技能组/客服等）
```
- 需带登录 Cookie（withCredentials）
- 返回 JSON：`chatLogList[]`，每条含 `chatLogMessageList[]`（该会话全部消息）

### 2.3 消息数据结构
```json
{
  "content": "消息内容（换行是 <br/> 标签）",
  "created": "2026-08-03 16:11:15",
  "customer": "客户pin",
  "waiter": "客服账号",
  "waiterSend": 0或1,        // 0=客户发，1=客服发
  "type": "text",
  "sid": "会话id", "mid": 消息id,
  "closeTypeDesc": "会话关闭原因"
}
```

### 2.4 登录态复用（Chrome 调试端口）
京东和知你客服一样：Chrome Cookie 库被独占锁定、运行中浏览器无调试端口。方法：
```
温和关闭 Chrome → 带参重启：
chrome.exe --remote-debugging-port=9222 --user-data-dir="C:\Users\<用户>\AppData\Local\Google\Chrome\User Data" --restore-last-session
```
重启后让用户重新登录京东后台，然后 CDP（`http://127.0.0.1:9222`）在页面上下文 fetch 调接口。

## 三、演示 HTML 制作要点（复现核心）

> **⚠️ 排版铁律（务必先读，违反会被打回）：**
> 1. **所有解析/知识点必须用 `<details>` 折叠块，就地内嵌在对应消息的下方**，点击才展开。
>    —— 学员点开折叠条，直接就能看到"这个知识点对应的是上面哪条消息"。**不要**把解析抽出来集中做成"结尾总结卡片"，也不要平铺展示让学员来回对不上号。
> 2. **不要加目录（sidebar / nav.toc / 左侧锚点列）**。解析都在对话流里就地呈现，目录既多余还容易让学员误解知识点是独立章节。要放目录和 info 卡也只放客户/店铺/时间信息（可选），别放"跳转到某解析点"的锚点目录。
> 3. 生成后做一次**自检**：确认每个 `details` 都挂在对应消息正下方、顺序没乱、且都能「点击展开/收起」。
> 4. **客户 ID/pin 默认脱敏 + 眼睛按钮**：会话标题里的客户 pin 用 `<span class="cid">` 包起来，CSS `.cid{display:none}` 默认隐藏；页面右上角放一个**眼睛切换按钮**，点击给 `<body>` 加 `show-cid` 类（`body.show-cid .cid{display:inline}`）才显示客户 ID。默认状态 = 脱敏不露客户 ID，培训需要核对时再一键切换。

### 3.1 页面骨架
```
.wrap { max-width: 900~980px; margin:0 auto }   ← 单栏即可，一般不需要 sidebar
├── .header：红色渐变（#b91c1c→#e1251b→#ff5a3c）标题卡（写案例看点 + 使用方法）
└── .card
    └── .chat-area：对话回放（所有就地解析块都内嵌在此，随消息走）
footer
```
> 说明：早期示例（议价案例）有左侧 sidebar 目录，那是**旧风格**。现统一为**单栏对话流、无目录、解析就地内嵌**，更直观、不产生误解。

### 3.2 气泡布局（微信式）
```css
.msg{display:flex;margin-bottom:8px}
.msg-body{max-width:76%}
.from-cus{justify-content:flex-start;margin-right:auto}  /* 客户：靠左 */
.from-kf {justify-content:flex-end;  margin-left:auto}   /* 客服：靠右 */
.from-cus .bubble{background:#fff;border:1px solid #e2e8f0;border-top-left-radius:3px}   /* 客户白，尾巴左上 */
.from-kf  .bubble{background:#3b82f6;color:#fff;border-top-right-radius:3px}              /* 客服蓝，尾巴右上 */
.from-kf .msg-meta{flex-direction:row-reverse}  /* 客服的名字时间在右 */
```
> 尾巴技巧：四角 12px 圆角，发送方一侧角改为 3px。

### 3.3 就地解析折叠块（核心亮点，必须做到）
> **每个解析块都是一条 `<details>`，紧跟在其所讲解的那条消息（msg）之后**（DOM 里是 msg 的下一个兄弟节点）。点开它，学员抬眼正对刚才那句话，自然知道这条知识点讲的是哪一处。
> 
> **关键：折叠块默认必须"收起"**（`<details>` 不加 `open` 属性），点击才展开——对话流保持干净，需要时才调出解析。
> 禁止把解析抽出来集中做成结尾总结卡片，也禁止平铺展示。
```html
<!-- 对话框里的一条消息 -->
<div class="msg from-kf">…bubble…</div>
<!-- 紧跟着它的就地解析块（msg 的兄弟节点） -->
<details class="insight" id="anchor-speech">
  <summary>💡 议价点解析：当时怎么回 vs 建议怎么回 <span class="sum-hint">点击展开</span></summary>
  <div class="insight-body">
    <!-- 左右对照：✖当时回复(红) / ✔建议话术(绿) -->
    <!-- 或：培训要点编号列表 -->
  </div>
</details>
```
```css
.insight summary{list-style:none;cursor:pointer;display:flex;align-items:center;gap:10px}
.insight summary::-webkit-details-marker{display:none}
.insight summary::after{content:'▾';transition:.2s}
.insight[open] summary::after{transform:rotate(180deg)}
```

### 3.4 数据渲染规则
- `waiterSend:0` → 客户（白、左）；`waiterSend:1` → 客服（蓝、右）
- 内容转义时处理 `<br/>`：先 HTML 转义，再把 `&lt;br/&gt;` 还原为 `<br/>`（否则显示成字面文本）
- 时间显示 HH:MM，可加"产品咨询"等节点小标签
- 议价/价格/置换等关键消息加红色 `◆ 议价点`（或 `◆ 价格点`）标记，帮助学员定位重点节点
- **客户 ID 默认脱敏**：会话标题里的客户 pin 用 `<span class="cid">（pin）</span>` 包裹，CSS 默认 `.cid{display:none}`；右上角眼睛按钮点击切换 `body.show-cid` 后显示（实现见 `scripts/make_need_diagnosis_demo.js` 的 `.cid-toggle` + `cidToggle` 脚本）
- **聊天图片下载内嵌**：接口消息里 `type:"image"` 的消息带 `imgUrl` 字段，把图片下载后 base64 内嵌到对应气泡里（`<img>` 点击放大），**不要只写"[图片]"占位**（实现见 `scripts/make_santong_demo.js` 的 `IMG_URLS` + `downloadImage`）
- **商品链接做成卡片**：商品链接消息渲染成可点击的卡片（商品图 + 标题 + "查看商品详情"），让学员一眼知道链接是什么，**不要只写"谁发了个链接"**（实现见 `scripts/make_santong_demo.js` 的 `PROD` + `.prod-card`）；**卡片图务必用商品第 1 张主图**（缩略图列表第 1 个），并做预览页请用户确认，不要用 `#spec-img` 当前显示的那张（可能不是第 1 张，见常见坑 9）

## 四、常见坑（务必注意）

1. **查询日期**：单日查询有效，跨度过大（如一年）返回空——先向用户确认咨询日期，或让用户在页面上搜到后读取其查询条件
2. **`<br/>` 换行**：数据里是 HTML 标签，直接输出会显示字面 `<br/>`，需"转义后还原"
3. **敏感信息**：培训材料去掉具体客服姓名（避免对号入座有压力）、去掉"领导要求"等内部措辞
4. **排序**：会话/消息按时间正序展示（接口返回可能是倒序或跨会话）
5. **ChatGPT/Claude 等直接看成品 HTML 即可学会气泡与折叠实现**（样式全内嵌）
6. **CDP 页面卡住**：咚咚页面等可能主线程繁忙导致 evaluate 超时，可新建标签页重试；调试端口需 Chrome 带 `--remote-debugging-port` + 显式 `--user-data-dir` 启动（Chrome 136+ 要求）
7. **解析内容不许抽成结尾总结卡片**：所有知识点必须 `<details>` 就地嵌在对应消息下方、点击展开。曾踩过把"培训要点/话术对照"集中平铺到对话结尾卡片的错，学员对不上号（不知道哪条讲的是哪句）；**也勿加目录锚点栏**。生成后自检每个 details 与消息的（兄弟）相邻顺序。
8. **抓取前必须确认登录的是正确店铺，并核对会话内容是否匹配目标场景**：京东客服管家 `kf.jd.com/#/212` 才是聊天记录/会话查询页（`#/364` 可能是别的功能/错店铺，返回不同数据）。曾因登录错店铺、又未核对内容，抓到的全是不相关会话，还硬套了涨价教学上去。抓完先读一遍每条消息，**确认会话主题确实是用户要的场景**（如"涨价诉求"）再动手做课件。
9. **商品卡片图必须用"第 1 张主图"，且要跟用户确认**：曾用商品页 `#spec-img` 抓主图，结果抓到的是**第 2 张配件图**（页面加载时 `#spec-img` 不一定显示第 1 张），被用户打回。正确做法：抓**缩略图列表第 1 个**（spec-list 第一张），并把下载的图做成带编号的预览页让用户确认哪张是产品本体图，再定稿；确认后把这套"选图流程"也用于后续课件。

## 五、给下一个 AI 的操作步骤（每次做课件照此走，可闭环）

> 目标：不依赖本对话，独立从"取数"做到"出成品"。每一步都有验收点。

1. **取数（3 步）**
   a. 确认 Chrome 已登录京东后台且有调试端口（没有就按 2.4 重启）。
   b. 打开**正确的聊天记录页** `kf.jd.com/#/212`（非 `#/364`），确认登录的是用户要的那家店。→ ✅ 验收：页面显示的是"会话/聊天记录查询"，且是目标店铺。
   c. 用 `queryList.action` 按 customer/日期拉 `chatLogList`（单日或窄窗口；跨度过大返回空，分段查）。→ ✅ 验收：**通读每条消息，确认会话主题确实是用户要的场景**（如"涨价诉求/议价/售后"）。若对不上，别硬套——先问用户，或重查店铺/日期。

2. **做课件（2 步）**
   a. 用通用脚本 `scripts/make_chat_demo.js` 为主模板（比 `make_jd_demo.js` 更通用、就地解析更标准）。
   b. 只改 ①② 两处配置区：①输出配置（标题/副标/店铺/客户/文件名的），②MESSAGES 数组（真实消息）+ ③按场景写 INSIGHTS 解析块。不要动渲染/样式部分。
   → ✅ 验收：脚本跑通，生成 HTML。

3. **自检（打开 HTML 逐条核对，全绿才交付）**
   - [ ] 无左侧目录 / 无独立"结尾总结卡片"
   - [ ] 每个解析 `<details>` 紧跟在对应消息正下方（兄弟节点）、默认收起、点击才展开
   - [ ] 消息顺序 = 真实对话顺序；客服蓝右、客户白左
   - [ ] `<br/>` 换行正确、无字面 `<br/>`、无乱码 `�`
   - [ ] 聊天图片已下载内嵌到对应气泡、点击可放大；商品链接已做成卡片（商品图+标题+可点击）
   - [ ] 客服具体姓名已脱敏（用"客服"）；无"领导要求"等内部措辞
   - [ ] 客户 ID 默认脱敏（`.cid` 隐藏），右上角眼睛按钮点击可切换显示/隐藏
4. 输出到 `2026年8月/` 等日期目录，命名 `场景-日期-客户pin.html`，用户验收。

## 附录：京东官方机器人（aics.jd.com）话术自动配置方法

适用：批量配置/更新京东 AI 客服机器人的问答话术（"千店话术通"思路）。

### 接口（全部 POST 到 https://aics.jd.com/api）
| 用途 | 接口 | 关键参数 |
|---|---|---|
| 建问题 | `kCustomController/submitCustomQuestionBasic` | `{secondClassify:{secondClassifyName}, groupInfo:{firstGroup,secondGroup}, whiteQuestionList:[问法字符串]}` |
| 查询初始化 | `kCustomController/getCustomQuestion` | `{secondClassify:{secondClassifyId}}`（**建问题后必须查一次**，否则加答案报"问题名称不能为空"） |
| 加答案 | `kCustomController/submitCustomQuestion` | `{checkContent:true, secondClassify:{secondClassifyId}, addAnswerList:[{serviceType:0, detailList:[{answerType:0, content_html}], effectiveWare:1, period:{timeageId:"forever2000",status:3,...永久生效}}]}` |
| 删问题 | `kCustomController/deleteCustom` | `{secondClassifyList:[{secondClassifyId}]}`（注意是 List） |
| 分组 | `knowledgeGroup/getGroupTree` | 一级/二级分组 ID 结构 |

### 关键坑（务必注意）
1. **必须用 XMLHttpRequest，不能用 fetch**（京东拦截层对 fetch 返回不同结果，加答案会失败）
2. **建问题后必须先 getCustomQuestion 查询一次**（触发服务端识别），否则加答案报"问题名称不能为空"
3. 判断成功看 **`state==='SUCCESS'`**，不是 code（code 恒为 success）
4. 问法重复：返回 `forceSaveRepeat` token，带上重新提交即强制保存
5. 问题名称重复：复用已有问题 ID（返回 `data.classifyId`）直接加答案
6. 同一问题相同触发条件只能有一个答案（再加报"触发条件重复"）——重复执行工具是安全的
7. 分组用"售前咨询/其它"，`serviceType:0`（机器优先）、`effectiveWare:1`（全部商品）、period 永久生效

### 实测
议价 5 条话术（统一底价/对比别家/太贵/差一点就买/要赠品）已在"德迩杰官方旗舰店"自动配置成功并验证。
工具：`scripts/qianDian_tool.js`（页面注入 `window.__qianDian`，`batchConfigure(SPEECH_LIB)` 批量执行）。
