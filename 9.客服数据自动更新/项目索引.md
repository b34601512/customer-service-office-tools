# 9.客服数据自动更新 · 项目索引（开工先看）

> 自动采集天猫/京东/拼多多/抖音各店客服指标 → 写汇总表「数据明细」→ 同步金山在线表 + 透视筛选。
> 最后更新：2026-10-09。本项目无 `断点记录.md`：状态看根 [`断点记录.md`](../断点记录.md)。

## ① 开工先看什么
1. 本索引 → [`CLAUDE.md`](./CLAUDE.md)（结构、数据流、**注意事项全在 §6**）→ [`README.md`](./README.md)（常用脚本/无头模式）。
2. 口令「日常巡检」的 9号 步骤：汇总(2) → 金山同步(5) → 设透视筛选=最新 → [`每日自动化流程.md`](../0.木婉清档案/日常流程/每日自动化流程.md) §一。

## ② 规矩 / 口径（一句话 + 出处）
- **跑汇总前必须保存并完全关闭汇总表**（WPS/Excel），否则独占写入检查拒启动 → `CLAUDE.md` §6。
- 「开始全部汇总」= 全新一轮：清空明细、重置历史、清理今天以前的源文件；**当天失败单店重跑不清其他店** → `CLAUDE.md` §6。
- **金山同步前**：确认本地表已保存、「数据明细」非空；**在线表开着筛选会让整表回读不一致**（会误判保存失败）→ **先清筛选再同步** → [`../20.经验库/kdocs回读与筛选/`](../20.经验库/kdocs回读与筛选/)（2026-10-09 根因）。
- 验收 = **9 店成功 / 金山行数 = 本地行数 / 数据源是今天的**；跑完汇报总售前业绩 → `每日自动化流程.md` §一。
- 抖音：所有店共用同一账号，切换店铺直接切、**不需要重新登录**；其他平台登录态按各平台流程（人工过验证码）→ `每日自动化流程.md` §三。
- 无头分支：需要人工处理时**明确报错、不隐藏等待**；只关可确认的营销弹层，未知弹窗不猜点 → `README.md`。

## ④ 常用命令
```bash
cd "9.客服数据自动更新"
npm run cli                                   # 控制台（汇总/金山/设置菜单）
node scripts/runSummaryAndKdocsSync.js        # 汇总 + 金山同步一条龙（日常巡检用）
node scripts/同步金山明细.js                   # 只同步金山（不采集，换数据源后用）
node scripts/retryFailedStores.js <店...>      # 单店补跑（人工判定后才用，不自动重试）
npm test                                      # 单测
```

## ⑤ 红线
- 平台后台只读；登录滑块/验证码停下叫人；失败**不自动重试**、现场写 [`失败台账.md`](../失败台账.md)。
- 不改汇总表「数据明细」表头/列顺序/结构；`project-config/`、`runtime/` 不入库。
