# 第 3 个独立 AirScript：客服姓名确认

关联 issue：`b34601512/office-software-backup#522`。

## 解决的问题

金山文档仪表盘存在刷新 BUG：透视表数据或日期刷新后，仪表盘可能不跟着刷新。用户发现，打开“客服姓名”筛选、保持原有勾选不变并直接点击确认，会触发仪表盘刷新。

`AirScript-原样确认客服姓名勾选.txt` 只做这一件事：

1. 遍历“透视结果”的全部透视表，并在任何刷新前读取每张表“客服姓名”的 `Visible` 状态。
2. 对原来隐藏的客服执行“显示 → 隐藏”；如果原来全部可见，则对首项执行“隐藏 → 显示”；最终勾选结果保持不变。
3. 刷新每张透视表并逐表输出成功/失败，最后保存在线工作簿。

它不写“数据明细”、不修改“统计结束日”、不合并菜单 `[1]` 或 `[5]` 的动作。

## 加入菜单的方式

项目已经按菜单 `[5]` 筛选脚本的模式接入，相关代码在 `src/cli/cliKdocsSyncMenu.js`：

- `[7]` 调用 `runKdocsCustomerServiceNameFilterReapply`，通过独立的 `customerServiceNameWebhookUrl` 和 `customerServiceNameApiToken` 执行本脚本。
- `[8]` 打开 `src/kdocsSync/AirScript-原样确认客服姓名勾选.txt`，用于复制到金山文档 AirScript 编辑器。
- 菜单 `[2]` 的设置页为客服姓名脚本单独填写 webhook 和令牌；不要复用菜单 `[5]` 的筛选 webhook/令牌。
- 首次配置时，在同一份在线文档中新建独立“文档共享脚本”，粘贴 `[8]` 文件内容并按 `Ctrl+S` 保存，再把该脚本自己的 webhook/令牌填入 `[2]`。

推荐执行顺序是：菜单 `[1]` 同步数据明细 → 菜单 `[5]` 设置“统计结束日”并刷新透视 → 菜单 `[7]` 原样确认“客服姓名”勾选。日期筛选完成后必须单独执行 `[7]`，否则仪表盘可能仍不刷新。

## 不能在本地做的验证

AirScript 的 `Application.Worksheets`、`PivotFields`、`PivotItems` 和在线仪表盘只存在于金山文档环境，本地只能做语法/模拟调用验证；真实效果需要按上述菜单顺序在目标文档中执行。
