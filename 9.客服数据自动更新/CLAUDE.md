# 项目说明

## 1. 一句话目标

自动下载天猫、京东、拼多多、抖音各店铺的客服报表，统一整理并写入客服数据汇总表，方便主管查看每位客服的综合表现。

## 2. 技术形态

- Windows 本地 Node.js 18+ 命令行工具，代码采用 CommonJS。
- 使用 `playwright-core` 驱动受控 Chrome，完成登录辅助、切店、日期选择和报表下载。
- 使用 `xlsx`、`jszip`、`@xmldom/xmldom` 读取源表并原子更新 `.xlsx` 汇总表。
- 使用 JSON 保存项目配置；运行日志、浏览器状态、下载文件和任务历史位于 `runtime/`。
- 可选通过金山文档 AirScript 三个独立 webhook 将本地“数据明细”同步到在线表格，并分别调整日期筛选与客服姓名勾选。

## 3. 模块清单

- `src/cli/`：程序入口、终端界面、菜单、任务启动和安全退出；`src/cli/tui/` 是默认的全屏 ANSI 终端界面（总览/汇总/店铺/设置/金山/帮助六页，零依赖，重量级模块按需加载），非 TTY 环境自动回退旧 readline 菜单（`--no-tui` 可强制旧界面）。
- `src/controlCenter/`：按当前配置生成店铺任务清单，维护本轮运行状态。
- `src/config/`、`project-config/`：默认配置、平台规则、配置校验与持久化、运行目录管理。
- `src/summary/`：多店铺顺序调度、日期范围、源文件复用、下载凭证和失败隔离。
- `src/platforms/{tmall,jd,pdd,douyin}/`：各平台的登录、切店、页面操作、日期设置和下载逻辑。
- `src/engine/`：Chrome/Playwright 会话、进程、日志和文件系统基础能力。
- `src/shared/`：弹窗处理、下载事件、凭证命名、任务历史等跨平台能力。
- `src/summaryData/`：读取各平台源表、映射客服与指标、生成明细行、写入汇总表。
- `src/kdocsSync/`：读取本地“数据明细”并同步金山文档，更新在线透视筛选。
- `tests/`：日期、下载安全、重试/复用、汇总写入、CLI、凭证和金山同步测试。
- `scripts/`、根目录 `.bat`：便携版打包及 Windows 快捷启动。

## 4. 数据流

`CLI 读取配置` → `按平台/店铺/报表生成任务` → `检查汇总表可独占写入` → `开始全部汇总时清空数据明细、重置运行历史、清理今天以前的源文件` → `逐店复用今天源表或用浏览器重新下载` → `解析源表并统一客服姓名/指标` → `写入汇总表数据明细` → `原子保存并记录任务历史/凭证` → `按需同步金山文档`。

核心指标包括业绩、平均响应时间、3 分钟响应率和客户满意度；实际执行范围由 `project-config/platform-config.json` 决定。

## 5. 运行与测试

```powershell
# 首次安装依赖
npm ci

# 启动（也可双击“启动控制台.bat”）
npm run cli

# 运行全部自动化测试
npm test
```

制作便携版时双击 `打包便携版.bat`。

## 6. 重要注意事项

- 运行汇总前，必须先保存并完全关闭汇总表（包括 WPS/Excel），否则独占写入检查会拒绝启动。
- 不要随意修改汇总表“数据明细”的表头、列顺序或表格结构；解析和写入依赖固定模板。
- 登录滑块、安全验证等需在程序打开的业务浏览器中人工完成；任务运行时不要手动关闭该浏览器。
- 每次「开始全部汇总」都是全新一轮：清空数据明细、重置运行历史、清理今天以前的源文件，只保留今天的源文件；当天重复跑会重新写入每家店，不做历史累积。
- 源文件复用只认"今天下载且文件仍在"；当天失败店铺用「回车=单店重跑」复用今天源表重写该店，不清空其他店铺数据。确需忽略今天源表时使用 `[F] 全部强制重新下载`。
- `project-config/platform-config.json`、`runtime/` 可能包含本机路径、登录状态或令牌，不应提交、外传或打入公开包。
- 金山同步前应确认本地汇总表已保存且“数据明细”非空，并分别配置同步、筛选和客服姓名确认脚本的 webhook 与令牌。
- 优先从 CLI 正常退出，让程序关闭受控浏览器并完成资源清理。
