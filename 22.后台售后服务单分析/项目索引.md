# 22.后台售后服务单分析 · 项目索引（开工先看）

> 角色：**管理层的检查秘书**——只去后台**检查**有没有漏处理的售后服务单、汇报给用户；**不做**任何售后业务动作。

1. 本索引 → [`README.md`](./README.md)（工具台账）→ [`断点记录.md`](./断点记录.md)（各平台进度）。
2. **口径先读** [`../29.售后经验库/售后口径/判漏口径.md`](../29.售后经验库/售后口径/判漏口径.md)（四平台都在这）+ 对应平台采集文档。

## ② 规矩 / 口径（一句话 + 出处）
- **判漏**：金山对接表查不到 + 已签收超 24h ⇒ 算漏；各平台另有计数口径（“待处理/临期 = 0 即无漏”）→ `29号/售后口径/判漏口径.md` + [`催促通用原则.md`](../29.售后经验库/售后口径/催促通用原则.md)。
- **抖音待商家审核**：临期待处理/投诉至监管/仲裁全 0 即无临近超时；待商家审核**逐单读备注、由模型语义判断，不许关键词判**（用户 2026-09-21）→ [`平台后台-采集/抖音.md`](../29.售后经验库/平台后台-采集/抖音.md) + 断点记录。
- **备注已有实质处理动作**（如「已通知拦截」「已发起协商」）= 已处理：可帮勾「是否完成」，**不再跟催、不另开单**（黎路遥 2026-09-30）→ [`规矩与红线.md`](../0.木婉清档案/规矩与红线.md) §六。
- **拼多多数字口径**：「24小时内平台同意退款」= 近 24h **平台已同意**（过去时）；可筛 `operateType:2` 落到单 → [`平台后台-采集/拼多多.md`](../29.售后经验库/平台后台-采集/拼多多.md)。
- 业务判断（能不能退/怎么赔）归售后；我只写清楚问题、出清单/工单 → `规矩与红线.md` §五/§六。
- 群消息/真 @ 按 27号 口径；**发给人之前先问用户**（除非他当次明确要发）。

## ⑤ 红线
- 后台只做**读**；金山只读（不改、不保存、不触发同步）；「同意/退款/提交/发送」先停下来问用户。
- 需要人工登录/验证码/滑块 → 停下叫人、窗口留可见；失败不自动重试（现场写 [`失败台账.md`](../失败台账.md)）。
- `project-config/stores.json` 不入库。
