# 京东售后/纠纷后台-采集（2026-09-18 首次打通）

## 一、入口（实测）
- **自主售后**（售后单）：`https://shop.jd.com/jdm/trade/after-sale/independent-after-sale/list`
  - tab：全部 / 待审核 / **待收货** / **待处理** / 催收；筛选项里有 **即将超时 / 催审 / 临近超时**
  - 首页「客服」浮层还有卡片：取消订单 / 待审核售后 / 待收货售后 / 待处理售后
- **交易纠纷**：`https://shop.jd.com/jdm/trade/after-sale/trade-dispute/list`
  - tab：待回复 / 待举证 / 待执行 / 可申诉 / 已申诉
  - **每一行都带倒计时**：如「待商家处理 还剩23小时21分」「待商家执行 还剩17小时33分」
- 首页：`https://shop.jd.com/jdm/home`（顶部菜单：交易 → 自主售后/交易纠纷/先行赔付；客服 → 售后与纠纷计数）

## 二、判漏口径（与天猫同理）
- **「即将超时」= 0 且「待处理」= 0** ⟹ 没有临近超时/积压的售后单 = 售后无漏；
- **「待收货」** = 客户已寄回、等商家签收（在途，不算漏）；「催收」= 催客户寄回，同样不算漏；
- **纠纷**：看 待回复 / 待举证 / 待执行 三个 tab，每单带「还剩X小时Y分」——**未到期不算漏，但要在时限内处理**。

## 三、自动登录（用户 2026-09-18 授权）
`node src/tools/jd-login.js --store jd1`：
- 账号密码运行时从 **12号**（找不到再 9号）`platform-config.json` 的 `jd.stores` 读；
- 表单：`#loginname` + `input[type=password]` + **登录按钮必须是 `button.password__submit`**
  （拿 `button:has-text('登录')` 点不动，实测第一次就是这样失败的——这个选择器抄自发票项目 `jdLoginForm.js`）；
- 实测 jd1 登录成功、未触发滑块；遇到滑块/验证码一律停下叫用户。

## 六、检查 + 通知的标准打法（用户 2026-09-18 拍板）
1. **一个店一条通知，不合并**（用户原话：「一个店一个店通知，别攒到一起通知，不然阅读压力很大」）；
2. 消息**必须带店名**（如「【京东1店 · 德达官方旗舰店】」），让人一眼知道是哪家店；
3. @ 人照 1号 规则：14:00 前 @李守耀（组长优先）/否则早班值班；**14:00 后 @晚班值班**（售后晚班 14:00-22:30）；
4. 只报**要做动作的事**：即将超时/待处理售后、纠纷待回复/待举证/待执行；「待收货」「催收」是在途或等客户，不催商家；
5. 发之前先 `--file` 预演，确认无误再 `--send`（企微发送要用户点头）。
