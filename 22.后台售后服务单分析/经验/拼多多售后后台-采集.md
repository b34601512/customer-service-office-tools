## 三、判漏口径（实测得出）
售后工作台顶部「售后数据」是**平台实时算的**（用 `node src/tools/pdd-aftersale-overview.js --store pdd02` 一次读全）：

| 指标 | 含义 | 判据 |
|---|---|---|
| **24小时内将逾期订单数** | 未来 24h 内会逾期 | **= 0 ⟹ 无漏**（与天猫「24小时内待处理」、京东「即将超时」同理） |
| 24小时内待商家举证 | 24h 内要举证 | >0 要看 |
| 24小时内平台同意退款 | 平台已同意、商家要执行 | >0 要看 |
| 24小时内将逾期工单数 | 工单将逾期 | >0 要看 |
| **投诉预警** | 客服没及时解决、消费者可能投诉 | **>0 要处理** |
| 待商家处理 / 退货待处理 | 积压量（倒计时还有好几天） | 不算漏，只看积压 |
| 待买家处理 | 等买家 | 不用管 |

**关键认知**：拼多多售后系统的自动退款时限是 **7 天**，列表每行原文自带倒计时：
`（6天23时33分2秒未处理，系统将自动退款）`——天+时+分+秒都在，可直接算出谁最急。

### 抓具体单子的正确姿势（2026-09-22 沉淀）
- 默认进列表是 **「全部(0) / 暂无售后单」**，直接抓接口 `mercury/mms_afterSales_queryList` 会拿到 total=0，**必须先点快速筛选**（文案带计数，如「待处理即将逾期2」/「投诉预警1」）再等接口。
- `probe-page --click` 用 `button,a,div,span,li,label` 且要求 `innerText === 文案`，**计数黏在文案后面时匹配不到**；自写脚本遍历 `document.querySelectorAll("*")` + `startsWith` 才点得中。

## 七、与金山退款表交叉验证（用户 2026-09-18 实操）
- 拼多多这单 `260830-368448642611283`（制氧机 ¥598，买家反馈噪音大）：**用户核对金山退款表 —— 已收到该退货**；
- 所以提醒话术 = **「客户已退货（退款表已登记），请尽快给客户退款」**，而不是泛泛的"尽快处理"；
- 要点：**通知前先和金山对接表对一遍**（有退货记录 = 货已回 = 该退款），这样客服看到就知道该做什么。

## 八、坑 3：pdd03 进工单列表的正确方式（2026-09-18）
- `goto /aftersales/work_order/list` 会被弹回首页；**正确姿势 = 在首页用 JS 点侧栏「工单管理」**，
  它跳到的地址带尾巴：**`/aftersales/work_order/list?msfrom=mms_sidenav`** —— 这个 URL 直接 goto 也行；
- 工单列表字段：订单号 / **订单问题** / 创建时间 / 工单状态 + **倒计时**（如「剩47时24分0秒」）/ 立即处理；
- 工单页顶部还有工单数据：工单量 / 违规处理量 / 完结率 / 有效完结率，以及「待处理 N / 2小时内将逾期 / 处理中 / 违规已处理」筛选。
