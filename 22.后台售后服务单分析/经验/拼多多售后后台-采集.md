## 三、判漏口径（实测得出）
售后工作台顶部「售后数据」是**平台实时算的**（用 `node src/tools/pdd-aftersale-overview.js --store pdd02` 一次读全）：

| 指标 | 含义 | 判据 |
|---|---|---|
| **24小时内将逾期订单数** | 未来 24h 内会逾期 | **= 0 ⟹ 无漏**（与天猫「24小时内待处理」、京东「即将超时」同理） |
| 24小时内待商家举证 | 24h 内要举证 | >0 要看 |
| 24小时内平台同意退款 | 平台已同意、商家要执行 | >0 要看 |
| 24小时内将逾期工单数 | 工单将逾期 | >0 要看 |
| **投诉预警** | 客服没及时解决、消费者可能投诉 | **>0 要处理** |
| 待商家处理 / 退货待处理 | 积压量（倒计时还有好几天） | 不算漏，只看积压 |
| 待买家处理 | 等买家 | 不用管 |

**关键认知**：拼多多售后系统的自动退款时限是 **7 天**，列表每行原文自带倒计时：
`（6天23时33分2秒未处理，系统将自动退款）`——天+时+分+秒都在，可直接算出谁最急。

- 24小时内将逾期 **0** ｜ 待商家举证 0 ｜ 平台同意退款 1 ｜ 将逾期工单 0 → **无漏**；

### 坑 1：店名以**页面显示**为准，别用 username 猜
- pdd02 页面右上显示「德达医疗旗舰店」，pdd03 显示「DEDAKJ医疗器械官方旗舰店」——和 username 前缀（德达旗舰店 / dedakj旗舰店）都不一样，已按页面显示改名。

### 坑 2：有的店进不了售后工作台列表页
- pdd03 直接 `goto /aftersales/aftersale_list` 会被**重定向到 `/aftersales/setup?tab=3`（售后设置引导）**，读不到列表；
- 这时**改读后台首页卡片**即可判：首页有 **「售后过期预警」**（0 = 无漏）、**退款/售后 N**、**待处理工单 N**、**即将逾期发货 N**；
- 设置引导属**修改类操作**，按红线**不代做**，只读首页判定。

- `pdd-aftersale-overview.js` 的「首页兜底」补丁目前没生效（条件块插入位置不对，pdd03 仍输出 null），修法是：把兜底判断放到 `try` 块末尾、`finally` 之前，条件用 `Object.values(result.risk).every(v => v === null)`。
