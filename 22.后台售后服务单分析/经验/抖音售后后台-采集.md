# 抖音（抖店）售后后台-采集（2026-09-21 首次打通）

## 一、登录（含本次踩坑）
- ✅ **正确入口**：`https://fxg.jinritemai.com/login/common` —— **手机号 + 验证码**
- ❌ **别点**「其他登录方式 → 抖音图标」：会跳 `open.douyin.com/platform/oauth/pc/auth`，那是**抖音开放平台 OAuth 授权页**（给巨量引擎用的），**不是抖店后台**（用户当场纠正过一次）
- 登录页元素：`input[type=number]` 两个（手机号、验证码）+「发送验证码」+「登录」+ **「同意协议」复选框（要先勾，否则点登录没反应）**
- **自动填手机号**：号码存在**不入库**的 `project-config/stores.json` 的 `loginPhone` 字段（douyin3/douyin5 都有）；填完点发送验证码，**用户只需输验证码**；实测无滑块
- **不要靠拷 profile**：Chrome 新版 Cookie 加密绑定，把 12号 的 `store-chrome-profiles/douyin/shared-login-account`（528M）robocopy 过来后**登录态无效**，必须人工登录一次
- 9号/12号/2号 三个项目的抖音**都是人工登录**（9号 注释原文「人工完成手机号验证码后…」），**没有**自动填手机号的现成实现
- 店铺名读页面头部 `.headerShopName`

## 三、判漏口径
| 指标 | 含义 | 判据 |
|---|---|---|
| **临期待处理** | 快到处理时限的售后单 | **= 0 ⟹ 无临近超时**（对标天猫/京东/拼多多同款指标） |
| **投诉至监管** | 消费者投诉到监管 | 必须 0 |
| **仲裁待协商 / 仲裁待举证 / 仲裁平台处理中** | 纠纷要商家动作 | 0 才干净 |
| 待商家审核（未发货退款/已发货退款/退货退款/换货/补寄/维修） | 要商家点同意或驳回 | 列表行自带倒计时「X小时X分X秒后自动同意」 |
| 待商家收/发货（退货待收货） | 在途 | 不算漏 |
| 待消费者处理（待退货） | 等买家 | 不算漏 |

## 五、多店切换（2026-09-21 实测打通）
一个抖音登录账号下挂多个店，**共用同一个 profile**，切换步骤（照 12号 `douyinStoreIdentity.js` 的做法）：
1. 点顶部店铺名 `.headerShopName`；
2. 等菜单出现（判据：页面文本出现 **「店铺ID」** 或 **「切换组织/店铺」**）；
3. 点文字为 **「切换组织/店铺」** 的元素；
4. 面板出现 **「请选择店…」**，点目标店名（如 `DEDAKJ医疗器械旗舰店`）；
5. 切换后读 `.headerShopName` 确认已换店。

## 八、坑：窗口停在**另一家店**（2026-09-22 实测，已根因修复）
- 现象：`probe-page --store douyin5` 打开的 9432 窗口**停在上次那家店**，douyin5 的概览读到的全是 douyin3 的数字（**两店计数一模一样、服务体验分同为 84** 才露馅；真 douyin5 是体验分 **91**、退货待收货 5）。
- **判据**：概览打印用 `pageShopName || name`，打出**别家店名**就是踩坑了；两店数字完全相同也应立刻怀疑。
- **修复**：新增 `src/tools/shop-identity.js` 的 `校验当前店(目标, 页面)`，`douyin-aftersale-overview.js` / `douyin-pending-remarks.js` 在店名不符或读不到店名时 **退出码 1、拒绝出结论**（落盘带 `shopIdentity` 标记）；测试 `tests/shopIdentityMustMatch.test.js`（4 例），`npm test` 28/28。
- **现场验证**：把 9432 切到 A 店 → `--store douyin5` 退出码 1 且打印“本轮结论不作数”；切回 DEDAKJ → 退出码 0、数据为体验分 91。
- 切店必须真用鼠标点 `.headerShopName`（`el.click()` 不冒泡，菜单弹不出来），判据是页面出现 **「店铺ID」/「切换组织/店铺」**。

## 九、退货**签收时间**怎么读（2026-09-22 打通）
- 列表行只有 `买家退货 已签收/运输中/已揽件`，**没有时间**；进详情页 `detail-v3?aftersale_id=<售后编号>`，抓接口 **`/v1/aftersale/pc/detail`** 的 `return_logistics_info.data[0]`：`state="已签收"` + `time="2026-09-22 15:01:58"` 即签收时刻。
- 同接口还会给系统日志：**「因退货物流状态转为‘已签收’，商家审核截止时间更新为 2026-09-24 15:03:31」**（签收 + 48h）——比列表倒计时更准。
