## 三、判漏口径
| tab | URL 参数 | 含义 | 判据 |
|---|---|---|---|
| **待商家处理** | `extra=wait_seller_todo` | 要商家审核/退款的单 | **= 0 ⟹ 没有卡住没人管的** |
| **退款异常** | `extra=refund_failed` | 资金异常 | 必须 0 |
| **有赞客服介入中** | `extra=has_involved` | 平台介入的纠纷 | 0 才干净 |
| 待商家收货 | `extra=wait_seller_receive` | 等买家寄回 | 在途，不算漏 |
| 待买家处理 | `extra=wait_buyer_todo` | 等买家动作 | 不算漏 |

- 列表列：商品 / 发货状态 / 订单金额 / 退款金额 / 申请时间 / **超时时间**（= 每单处理时限）/ 售后原因 / 售后状态
- 筛选器：订单编号 / 时间（近7天/30天/90天）/ 售后编号 / 退款类型 / 有赞客服介入 / 售后方式 / 发货状态 / 售后状态 / 退货物流 / 商品名称 / 退款资金状态 / 售后原因 / 订单来源

## 五、待商家收货的判漏流程（用户 2026-09-21 拍板）
**步骤**：
1. **先看物流是否已签收**（详情页「退货物流」段里有「物流状态」+ 轨迹）→ **未签收 = 在途，不提醒**；
2. **已签收** → **查金山退货退款表**（`node src/tools/kdocs-query.js <订单号>`）：
   - **表里已登记** ⇒ **提醒客服去后台确认收货并退款**（登记说明客服知道这单，就差后台动作）；
   - **表里没登记** ⇒ **看签收是否超 24 小时**，**超了才提醒**（同天猫口径）；
3. 未超 24h 不提醒。

**详情页打开方式（重要，踩过坑）**：URL 必须带全三个参数
`/v4/trade/refund/detail?orderNo=<订单号>&itemId=<商品ID>&refundId=<售后编号>`
——只带 orderNo 会白屏（页面文本只有 198 字 = 光剩框架）。
`itemId` / `refundId` 从列表页「处理退款」链接的 href 里读，或用 `context.waitForEvent("page")` 捕获点击后新开的标签（链接是 `target=_blank`）。
